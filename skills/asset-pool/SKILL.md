# Asset Pool 素材处理

AgentWithU 把客户端传入的图片和非文本文件先暂存在「素材池」里，
再交给你处理。素材池是一个滚动缓冲区——新素材进、旧素材自动淘汰，
被 pin 的素材不会被淘汰。

## 如何知道有哪些素材

每轮对话的上下文中会出现一段 `[素材池 / Asset Pool]` 清单，形如：

```
- <asset-id> · image/png 1280x720 · 登录页截图 · tags=ui [pinned]
  file: /home/user/.agent-with-u/asset-pool/<asset-id>.png
  url:  http://127.0.0.1:<port>/api/assets/<asset-id>
```

每条素材给出两种寻址方式：
- `file:` — 本地绝对路径，用 **Read** 工具直接读取（图片可被视觉模型查看）。
- `url:`  — 本机 HTTP 地址，需要把图片喂给外部接口时使用。

如果上下文里没有素材清单，说明池子是空的，请如实告诉用户。

## 常见处理方式

1. **查看 / 识别图片**：用 Read 工具读 `file:` 路径，图片内容会直接进入你的视觉输入。
2. **OCR / 提取文字**：先 Read 查看；需要更精确时用 Bash 调 `tesseract <file> -` 之类的命令行工具。
3. **裁剪 / 缩放 / 转换格式**：用 Bash 调用 ImageMagick（`convert` / `magick`）或 Python Pillow。
4. **多图合成 / 拼接 / 转 PDF**：用 Bash 调 ImageMagick 或 `img2pdf`。
5. **回写结果**：把处理产生的新文件写到素材池目录
   （`file:` 路径所在的同一个目录），用户即可在素材池中看到。
   注意：直接写文件不会生成元数据条目，仅供临时引用；
   若需要正式入池请提示用户在界面里重新添加。

## 注意事项

- 处理前先确认素材确实存在（Read 失败说明已被滚动淘汰）。
- 不要删除或覆盖原始素材文件，除非用户明确要求。
- 素材 id 是稳定引用，回复用户时可用 id 指代具体素材。
