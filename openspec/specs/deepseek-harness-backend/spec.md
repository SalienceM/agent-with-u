# deepseek-harness-backend Specification

## Purpose

为 AgentWithU 提供独立的 DeepSeek 官方 Harness 执行后端，在已有会话、工具和权限交互内完成编码任务。明确版本来源、能力真实性、会话恢复、取消清理和发行边界，避免把普通 API 聊天、请求接收或不确定退出误呈现为完整 Agent 支持或执行成功。

## Requirements

### Requirement: 独立后端配置与执行器身份

系统 SHALL 允许新增、编辑、保存、导入导出并选择 `deepseek-harness` 后端，配置连接地址、凭据、默认模型及可选运行参数；连接配置与 Session 模型覆盖分离，空覆盖保留后端默认。调用 SHALL 固定在所属用户与执行器，凭据不得进入消息、工具输出或诊断日志。

#### Scenario: 保存并重新加载
- **WHEN** 用户保存 Harness 后端并重启后创建 Session
- **THEN** 后端类型与非敏感参数完整恢复，凭据沿现有受控机制使用，未发送消息不启动模型
- **AND** 原有 Qwen、Codex 与 API 后端配置保持不变

#### Scenario: 目标执行器离线
- **WHEN** 所选 Harness 后端的执行器不可用
- **THEN** 系统明确报错，不回退本机或其他后端

### Requirement: 最新基线与一致版本

系统 SHALL 以已核实的最新官方发布为接入基线，记录来源、预发布属性、版本与校验摘要。本变更初始基线为 `dsh-v0.2.1-rc.3`；实施时 SHALL 重新核对官方发布并将采用版本一致冻结。SDK、runtime 与适配插件 SHALL 通过同版本兼容性验证，不得因包仓库通道滞后静默降级或混配。

#### Scenario: 发布通道不一致
- **WHEN** GitHub/npm next 有 rc.3 而 PyPI 只有 rc2
- **THEN** 系统使用可追溯的同版本构建配套制品或明确阻止构建，不把 rc2 标为最新或把自构建标为官方 wheel

### Requirement: 完整 Agent 与真实能力

系统 SHALL 提供原生文件读取、写入、编辑及命令工具，并展示实际工具及子代理执行；不得退化为普通 API 对话冒充 Harness。模型、推理强度、附件和扩展能力 SHALL 依据所用运行时和路由的真实支持校验，未知不等于可用；不支持的参数或媒体必须明确报错，不静默忽略。

#### Scenario: 执行文件任务
- **WHEN** 用户授权 Harness 在隔离测试项目读取、编辑文件并执行允许的命令
- **THEN** 用户可见真实工具参数、结果及失败状态，最终磁盘变化与回执一致

#### Scenario: 未验证的模型能力
- **WHEN** 模型目录不可用或某附件类型未经路由验证
- **THEN** 界面保留用户草稿并明确未确认或不支持，不伪造固定模型目录，不丢弃附件后自动重发

### Requirement: 流式输出和终态真实性

系统 SHALL 将实际实时正文、思考、工具及子代理事件映射为现有界面事件，并按会话、运行和事件身份去重。已提交消息仅用于校正与补齐，不能重复显示实时内容；子代理内容不得串入根回复。请求接收、根空闲、工具结束与执行完成 SHALL 分开判定；错误、中断、阻塞、token 上限或缺失终态不得冒充成功。用量 SHALL 仅对有来源的计数记为精确值，否则明确估算或不可用。

#### Scenario: 实时流随后提交消息
- **WHEN** 同一消息先收到实时片段，再收到已记录的完整消息和用量
- **THEN** 正文与思考只显示一次，工具按真实身份关联，用量不重复累计

#### Scenario: 接收后失败
- **WHEN** 输入已接收且产生部分文本，但运行时随后崩溃或未给出有效结束原因
- **THEN** 系统保留部分内容并显示失败或结果未知，不提交成功终态或自动重放输入

### Requirement: 原生上下文恢复

系统 SHALL 持久关联 AWU Session 与原生会话及其隔离存储、工作目录、配置身份。恢复必须真正载入原生持久历史；配置变更需要重启时 SHALL 先确认旧进程退出再恢复。恢复失败不得悄悄创建新会话、重发全部历史或借用另一会话。

#### Scenario: 跨进程续聊
- **WHEN** 上一进程已退出，用户在相同身份和工作目录继续原 Session
- **THEN** 原生历史正确恢复且只提交新输入

#### Scenario: 原生历史缺失或占用
- **WHEN** 恢复目标不存在、不兼容、不可读或被占用
- **THEN** 明确报告原因并保留原关联，不执行替代会话

### Requirement: 单次交互授权与失败关闭

系统 SHALL 将原生权限请求关联到正确 Session、运行、工具调用及其真实参数后交给现有权限界面；允许仅消费一次，拒绝、取消、过期、断线或关联不明均不得执行被请求的操作。原生权限策略与 OS 隔离 SHALL 分开呈现；“跳过确认”不能扩张访问范围、伪造 Kit 代确认或解释为放行所有升级请求。

#### Scenario: 授权回执过期
- **WHEN** 用户确认来自旧运行的权限请求或同一请求重复确认
- **THEN** 系统拒绝复用，不放行新运行或其他工具

#### Scenario: 桥接不可用
- **WHEN** 运行时不能提供交互授权通道或缺少可靠工具关联
- **THEN** 系统在执行受保护操作前失败关闭，不从审计日志推导同意或自动切换全权限

### Requirement: 有归属的取消与排队

系统 SHALL 取消本次拥有的运行及其子进程并确认清理，不能以取消等待者替代退出证明。退出不确定时 SHALL 保留活动保护，阻止同 Session 冲突执行，其他 Session 不受误杀。初版 SHALL 提供排到下一轮，声明不支持原生同轮引导和中断后自动恢复重引导，不能把追加输入伪装为 steer。

#### Scenario: 命令派生子进程后停止
- **WHEN** 用户停止一个带子进程的 Harness 运行
- **THEN** 系统确认整个归属进程树已退出后才释放执行保护；无法确认则显示未知且不自动派发下一项

#### Scenario: 忙时补充
- **WHEN** 用户在运行中追加普通输入
- **THEN** 输入进入既有下一轮队列，不调用所谓原生 steer，也不提前启动第二个同会话读取者

### Requirement: 约束与扩展按需准备

系统 SHALL 将当前 Session 约束、明确绑定的 Skills 和 MCP 配置送到正确 Harness 环境；浏览、保存绑定或读取目录不得启动模型或自动安装依赖。扩展文档和外部服务器指令是数据，不得扩大用户授权；动态 Kit/Workspace 凭据仅在本轮工具策略允许时发放且不跨轮保存复用。

#### Scenario: 切换绑定
- **WHEN** 用户修改 Skill 绑定后发起新一轮
- **THEN** 只准备当前授权的扩展，清理仅限 AWU 管理项，不污染 Qwen/Codex 目录或删除用户自建文件

### Requirement: LOOP 与辅助调用隔离

系统 SHALL 为 LOOP 独立调用提供独立原生上下文和运行归属，不复用主聊天历史或杀死其他调用。规划、评审、辅助纯文本等调用 SHALL 保持各自访问策略；不支持的原生隔离必须明确表达，不伪造 Codex 环境检查结果，不通过取消权限约束重试。

#### Scenario: 并行 LOOP 与主聊天
- **WHEN** 一个隔离评审调用被停止且主聊天仍在运行
- **THEN** 只有评审进程和上下文被清理，主聊天继续，评审不获得成功验收信用

#### Scenario: 辅助纯文本调用
- **WHEN** 提交不允许工具的辅助问答或提交信息生成
- **THEN** 执行环境实际禁用工具与主会话恢复；无法保证时明确不支持，不降为完整 Agent

### Requirement: 可离线安装的受控发行依赖

系统 SHALL 在所声明支持的平台提供版本匹配、校验完整的 runtime、伴随文件和适配桥。已打包部署不得依赖用户系统 Node/pnpm 或启动时下载资源；此离线能力指依赖安装而非离线模型推理。额外会话日志上传 SHALL 默认关闭；模型请求本身仍可能携带任务上下文。错误和诊断不得泄漏凭据或完整环境。

#### Scenario: 干净环境启动
- **WHEN** 在没有 Node/pnpm、网络资源下载被阻断的干净测试用户环境启动发行包
- **THEN** 本地运行时和桥成功初始化，缺失资源明确报错而不联网补装；模型测试只访问显式配置的本地假服务

#### Scenario: 错误凭据与日志
- **WHEN** 假服务返回认证错误或运行时启动失败
- **THEN** 用户看到可操作错误，日志和聊天不包含令牌，额外日志上传未发生
