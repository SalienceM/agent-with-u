# deepseek-harness-backend Specification

## Purpose

为 AgentWithU 提供独立的 DeepSeek 官方 Harness 执行后端，在已有会话、工具和权限交互内完成编码任务。明确版本来源、能力真实性、会话恢复、取消清理和发行边界，避免把普通 API 聊天、请求接收或不确定退出误呈现为完整 Agent 支持或执行成功。

## Requirements

### Requirement: 独立后端配置与执行器身份

系统 SHALL 允许新增、编辑、保存、导入导出并选择 `deepseek-harness` 后端，配置连接地址、凭据、默认模型及可选运行参数；连接配置与 Session 模型覆盖分离，空覆盖保留后端默认。调用 SHALL 固定在所属用户与执行器，凭据不得进入消息、工具输出或诊断日志。

#### Scenario: 保存并重新加载
- **WHEN** 用户保存 Harness 后端并重启后创建 Session
- **THEN** 后端类型与非敏感参数完整恢复，凭据沿现有受控机制使用，未发送消息不启动模型
- **AND** 原有 Qwen、Codex 与 API 后端配置保持不变

#### Scenario: 目标执行器离线
- **WHEN** 所选 Harness 后端的执行器不可用
- **THEN** 系统明确报错，不回退本机或其他后端

### Requirement: 最新基线与一致版本

系统 SHALL 以已核实的最新官方发布为接入基线，记录来源、预发布属性、版本与校验摘要。本变更初始基线为 `dsh-v0.2.1-rc.3`；实施时 SHALL 重新核对官方发布并将采用版本一致冻结。SDK、runtime 与适配插件 SHALL 通过同版本兼容性验证，不得因包仓库通道滞后静默降级或混配。

#### Scenario: 发布通道不一致
- **WHEN** GitHub/npm next 有 rc.3 而 PyPI 只有 rc2
- **THEN** 系统使用可追溯的同版本构建配套制品或明确阻止构建，不把 rc2 标为最新或把自构建标为官方 wheel

### Requirement: 完整 Agent 与真实能力

系统 SHALL 提供原生文件读取、写入、编辑及命令工具，并展示实际工具及子代理执行；不得退化为普通 API 对话冒充 Harness。模型、推理强度、附件和扩展能力 SHALL 依据所用运行时和路由的真实支持校验，未知不等于可用；不支持的参数或媒体必须明确报错，不静默忽略。

系统 SHALL 对用户提交的图片区分支持、不支持和未知，准入结果绑定实际执行节点、运行时版本、Backend 配置与本轮有效模型路由。明确支持、通过输入校验且满足远端副作用安全边界的图片 SHALL 能够提交，不能继续因存在图片而一律拒绝；不支持或未知的路由 SHALL 在提交图片给模型前拒绝并说明原因。图片能力支持 SHALL 不被当作远端删除授权；无法保证阻止未授权删除时 SHALL 按安全边界拒绝并说明原因，而非伪称路由不支持图片。SDK 提供图片协议、接收请求或本地假服务测试通过 SHALL 不被呈现为生产模型识图能力已验证，模型名称或手工填写的模型选项不得独立构成图片能力证据。

#### Scenario: 执行文件任务
- **WHEN** 用户授权 Harness 在隔离测试项目读取、编辑文件并执行允许的命令
- **THEN** 用户可见真实工具参数、结果及失败状态，最终磁盘变化与回执一致

#### Scenario: 未验证的模型能力
- **WHEN** 模型目录不可用或某附件类型未经路由验证
- **THEN** 界面保留用户草稿并明确未确认或不支持，不伪造固定模型目录，不丢弃附件后自动重发

#### Scenario: 当前路由明确支持图片
- **WHEN** 本轮有效路由提供可信的图片能力信息，图片类型和输入规模均在支持范围内，且远端副作用防护有效
- **THEN** 系统允许图片进入原生提交路径，不返回无条件的“附件能力尚未验证”错误
- **AND** 请求接受仍不代表模型完成或成功识别图片

#### Scenario: 当前路由明确不支持图片
- **WHEN** 本轮有效路由声明仅支持文本，用户尝试发送图片
- **THEN** 系统在模型提交前说明该路由不支持图片，而非泛化为缺少依赖
- **AND** 文字和图片仍可由用户继续编辑，不自动删图发送、切换 Backend 或调用 OCR

#### Scenario: 能力未知或目标不可用
- **WHEN** 节点离线、旧节点缺少所需能力反馈、能力信息缺失或读取失败
- **THEN** 系统分别说明离线、不支持能力查询或图片能力未确认，不把未知当作支持或断言一定缺少 SDK
- **AND** 不回退本机、默认节点或另一模型，不凭之前其他路由的成功记录放行本次图片

#### Scenario: 路由变化使旧结果失效
- **WHEN** 检查之后执行节点、运行时、Backend 配置或本轮模型覆盖发生变化
- **THEN** 系统不能将旧能力结果作为新路由的准入依据，实际提交使用当前路由重新核对
- **AND** 旧身份或旧请求的迟到结果不能更新新对象的能力状态

### Requirement: 流式输出和终态真实性

系统 SHALL 将实际实时正文、思考、工具及子代理事件映射为现有界面事件，并按会话、运行和事件身份去重。已提交消息仅用于校正与补齐，不能重复显示实时内容；子代理内容不得串入根回复。请求接收、根空闲、工具结束与执行完成 SHALL 分开判定；错误、中断、阻塞、token 上限或缺失终态不得冒充成功。用量 SHALL 仅对有来源的计数记为精确值，否则明确估算或不可用。

#### Scenario: 实时流随后提交消息
- **WHEN** 同一消息先收到实时片段，再收到已记录的完整消息和用量
- **THEN** 正文与思考只显示一次，工具按真实身份关联，用量不重复累计

#### Scenario: 接收后失败
- **WHEN** 输入已接收且产生部分文本，但运行时随后崩溃或未给出有效结束原因
- **THEN** 系统保留部分内容并显示失败或结果未知，不提交成功终态或自动重放输入

### Requirement: 原生上下文恢复

系统 SHALL 持久关联 AWU Session 与原生会话及其隔离存储、工作目录、配置身份。恢复必须真正载入原生持久历史；配置变更需要重启时 SHALL 先确认旧进程退出再恢复。恢复失败不得悄悄创建新会话、重发全部历史或借用另一会话。

#### Scenario: 跨进程续聊
- **WHEN** 上一进程已退出，用户在相同身份和工作目录继续原 Session
- **THEN** 原生历史正确恢复且只提交新输入

#### Scenario: 原生历史缺失或占用
- **WHEN** 恢复目标不存在、不兼容、不可读或被占用
- **THEN** 明确报告原因并保留原关联，不执行替代会话

### Requirement: 单次交互授权与失败关闭

系统 SHALL 将原生权限请求关联到正确 Session、运行、工具调用及其真实参数后交给现有权限界面；允许仅消费一次，拒绝、取消、过期、断线或关联不明均不得执行被请求的操作。原生权限策略与 OS 隔离 SHALL 分开呈现；“跳过确认”不能扩张访问范围、伪造 Kit 代确认或解释为放行所有升级请求。

#### Scenario: 授权回执过期
- **WHEN** 用户确认来自旧运行的权限请求或同一请求重复确认
- **THEN** 系统拒绝复用，不放行新运行或其他工具

#### Scenario: 桥接不可用
- **WHEN** 运行时不能提供交互授权通道或缺少可靠工具关联
- **THEN** 系统在执行受保护操作前失败关闭，不从审计日志推导同意或自动切换全权限

### Requirement: 有归属的取消与排队

系统 SHALL 取消本次拥有的运行及其子进程并确认清理，不能以取消等待者替代退出证明。退出不确定时 SHALL 保留活动保护，阻止同 Session 冲突执行，其他 Session 不受误杀。初版 SHALL 提供排到下一轮，声明不支持原生同轮引导和中断后自动恢复重引导，不能把追加输入伪装为 steer。

#### Scenario: 命令派生子进程后停止
- **WHEN** 用户停止一个带子进程的 Harness 运行
- **THEN** 系统确认整个归属进程树已退出后才释放执行保护；无法确认则显示未知且不自动派发下一项

#### Scenario: 忙时补充
- **WHEN** 用户在运行中追加普通输入
- **THEN** 输入进入既有下一轮队列，不调用所谓原生 steer，也不提前启动第二个同会话读取者

### Requirement: 约束与扩展按需准备

系统 SHALL 将当前 Session 约束、明确绑定的 Skills 和 MCP 配置送到正确 Harness 环境；浏览、保存绑定或读取目录不得启动模型或自动安装依赖。扩展文档和外部服务器指令是数据，不得扩大用户授权；动态 Kit/Workspace 凭据仅在本轮工具策略允许时发放且不跨轮保存复用。

#### Scenario: 切换绑定
- **WHEN** 用户修改 Skill 绑定后发起新一轮
- **THEN** 只准备当前授权的扩展，清理仅限 AWU 管理项，不污染 Qwen/Codex 目录或删除用户自建文件

### Requirement: LOOP 与辅助调用隔离

系统 SHALL 为 LOOP 独立调用提供独立原生上下文和运行归属，不复用主聊天历史或杀死其他调用。规划、评审、辅助纯文本等调用 SHALL 保持各自访问策略；不支持的原生隔离必须明确表达，不伪造 Codex 环境检查结果，不通过取消权限约束重试。

#### Scenario: 并行 LOOP 与主聊天
- **WHEN** 一个隔离评审调用被停止且主聊天仍在运行
- **THEN** 只有评审进程和上下文被清理，主聊天继续，评审不获得成功验收信用

#### Scenario: 辅助纯文本调用
- **WHEN** 提交不允许工具的辅助问答或提交信息生成
- **THEN** 执行环境实际禁用工具与主会话恢复；无法保证时明确不支持，不降为完整 Agent

### Requirement: 受控发行与外部运行依赖

系统 SHALL 在桌面及独立 Web 冻结包中保留版本匹配、校验完整的轻量 SDK 和适配桥，但不内置 Harness 完整运行时、其 Node 载体及伴随执行资源。使用 Harness 时 SHALL 要求所属执行节点已安装受支持的外部 CLI；普通 AWU 启动和其他 Backend SHALL 不因可选 CLI 缺失而失败。缺少依赖时 SHALL 给出明确的节点、依赖类别和固定兼容版本安装指引，不自动下载、安装、升级或执行临时下载型启动。已有源码/Docker 配套运行环境及明确选择的旧运行时 SHALL 保持验证后的兼容行为，不清理用户安装。

额外会话日志上传 SHALL 默认关闭；模型请求本身仍可能携带任务上下文。错误和诊断 SHALL 不泄漏凭据或完整环境。外部安装完成 SHALL 不被视为协议、权限、恢复或图片安全能力已验证。

#### Scenario: 干净环境启动
- **WHEN** 用户在没有 Node/Harness 且网络资源下载被阻断的环境启动新的冻结发行包
- **THEN** AWU 本体正常启动，其他已满足依赖的 Backend 不受影响
- **AND** 用户实际调用 Harness 时收到缺失依赖与安装指引，系统不联网补装、不创建替代会话或自动重发输入

#### Scenario: 外部依赖已就绪
- **WHEN** 所属执行节点已安装兼容的外部 CLI 且资源及协议检查通过
- **THEN** 系统使用该 CLI 和包内匹配适配层运行原生 Harness，保留工具、权限、取消、恢复和图片安全边界
- **AND** 不因为使用外部安装就打开遥测、放宽权限或绕过准入

#### Scenario: 错误凭据与日志
- **WHEN** 假服务返回认证错误或运行时启动失败
- **THEN** 用户看到可操作错误，日志和聊天不包含令牌，额外日志上传未发生

#### Scenario: 旧配套部署
- **WHEN** 已有源码/Docker 部署使用其配套运行时，或用户明确配置仍受支持的旧配套运行时
- **THEN** 系统继续执行该模式要求的版本和完整性检查，不卸载资源或静默改写配置
- **AND** 冻结包缺少外部 CLI 时不自动转用其他节点、其他 Backend 或下载旧 runtime

### Requirement: 外部 CLI 定位与安装指引

系统 SHALL 在实际调用或用户显式检查时，在 Session 所属执行节点按显式路径优先于自动发现的顺序定位 Harness。显式配置无效 SHALL 明确报错，不尝试另一个运行时。系统 SHALL 区分 Node 缺失、CLI 缺失、版本不兼容、安装不完整和协议失败；初始安装指引 SHALL 使用已核对存在的 `npm install -g @deepseek-ai/dsh@0.2.1-rc.3`，不将 `latest` 等浮动通道当作兼容承诺。浏览、选择和保存 Backend SHALL 不触发安装、模型请求或配置改写。

#### Scenario: npm shim 或带空格的路径
- **WHEN** 支持的平台使用 npm 入口、符号链接或带空格路径
- **THEN** 系统安全解析属于同一安装的入口并保持参数边界，不把路径拼成可注入的 shell 命令

#### Scenario: 同名命令或错误版本
- **WHEN** PATH 中存在非目标发行的同名 dsh，或外部版本/资源与适配层不兼容
- **THEN** 系统报告实际问题并拒绝提交，不仅凭名称或版本自报放行，不自动降级、安装或删除软件

#### Scenario: 远端执行节点缺依赖
- **WHEN** 控制端有 CLI，但目标执行节点缺少 CLI 或离线
- **THEN** 系统在对应节点范围报告缺失或离线，不借用控制端运行时，不把安装指引中的目标描述为另一台机器

#### Scenario: 安装后继续已有会话
- **WHEN** 用户自行安装兼容 CLI 后再次显式提交
- **THEN** 系统重新核对依赖并保留原生会话关联，仅提交新的输入，不自动重放此前失败请求

### Requirement: 图片附件的原生传输与有界校验

系统 SHALL 在已准入的 Harness 路由上以原生图片内容提交本轮文字及全部有效图片，保留图片顺序与输入关联，并支持没有文字的纯图片输入。图片 SHALL 不被替换为仅控制端可访问的地址、普通文本占位符或另一个模型生成的说明。系统 SHALL 校验实际图片字节与声明格式的一致性，对图片数量、单图大小、解码尺寸和编码后的请求总量设置明确且有限的上限；任一附件无效或超限时拒绝整笔模型提交并说明限制类别，不静默丢弃部分附件、截断数据或取消协议资源上限。

#### Scenario: 文字与多张图片一起发送
- **WHEN** 用户在支持图片的路由提交文字和多张通过校验的图片
- **THEN** 原生请求包含本轮文字以及对应顺序的全部图片内容，模型服务接收到可解析的图片而非图片 URL 提示文本
- **AND** 输入框和消息展示中的原始附件不会因传输而被替换或删除

#### Scenario: 纯图片输入
- **WHEN** 用户只附加有效图片而未输入文字
- **THEN** 系统提交有效的原生图片输入，不因文字为空而忽略操作或自动添加与用户意图无关的指令

#### Scenario: 图片损坏或格式不符
- **WHEN** 图片编码无效、实际内容不是可解码图片、声明格式与实际格式不符，或该格式不受当前路由支持
- **THEN** 系统在提交模型前拒绝并提示对应原因，保留原输入供用户替换图片
- **AND** 多附件中的一张无效不会导致其余图片或文字被自动单独发送

#### Scenario: 图片或请求超过限额
- **WHEN** 图片数量、字节大小、解码尺寸或包含编码开销的请求总量超过适用上限
- **THEN** 系统在模型提交前明确指出触及的限制类别，提示用户减少或替换附件
- **AND** 不发送被截断的请求、不静默缩减附件集合、不通过无限放大协议限制继续发送；边界内有效输入仍可正常通过

#### Scenario: 附件携带路径或外部地址
- **WHEN** 附件元数据包含任意本地路径、跨节点地址或外部 URL
- **THEN** 系统只使用当前授权请求已提供的图片内容或受控附件引用，不据此读取任意文件或拉取外部内容
- **AND** 无法取得合法图片内容时明确拒绝，不在其他节点寻找替代文件

### Requirement: 图片发送反馈与草稿保留

系统 SHALL 区分未提交、提交中、已接受、已失败及结果未知，不能在调用发送入口时就认定图片请求已被接受。明确尚未接受的拒绝 SHALL 保留同一用户、执行节点和 Session 未被编辑的原文字与图片，提供可操作提示；用户后来输入的新草稿 SHALL 不被原请求的迟到结果清除、覆盖或拼接。模型接受后的错误或无法确认是否接受的结果 SHALL 保留真实状态且不得自动重发。重复点击、迟到响应和重连不得导致同一次操作被重复发送或重复入队。

输入区 SHALL 不增加独立的图片状态栏、格式／限额说明、能力声明、详情入口、刷新状态或恢复输入按钮；正常添图、发送、排队及完成不额外弹出状态提示。拒绝、发送失败及结果未知 SHALL 复用既有错误反馈，图片校验、草稿保护和防重复提交行为不因界面简化而移除。

#### Scenario: 正常图片流程不增加提示区
- **WHEN** 用户附加图片、发起发送，或请求获得平台接单、排队、原生接收及完成回执
- **THEN** 输入区不出现独立图片提示、详情或刷新／恢复控件，图片仍沿用既有缩略图展示
- **AND** 仅在得到有效队列或原生接收证据且草稿未修改时清理对应输入，不因隐藏提示而提前清空或重复发送

#### Scenario: 准入拒绝且草稿未变化
- **WHEN** 图片能力或输入校验明确拒绝请求，且用户未修改提交时的草稿
- **THEN** 同一 Session 的输入框保留原文字及全部图片缩略图，并通过既有错误反馈显示拒绝原因
- **AND** 不将该输入标为已提交给模型，用户无需从历史消息重新找回附件

#### Scenario: 拒绝到达前用户已编辑新内容
- **WHEN** 用户在提交等待期间修改了文字或图片，随后原请求返回明确未接受的拒绝
- **THEN** 新草稿保持不变，原请求的输入快照及回执仍限定在同一身份范围内，不自动覆盖或拼接到新草稿
- **AND** 输入区不提供单独的恢复入口，保留关联不构成自动恢复、重新发送或复制旧授权的许可

#### Scenario: 切换 Session 或身份后收到回执
- **WHEN** 请求在途期间用户切换 Session、执行节点或账号，旧请求随后返回
- **THEN** 回执只归属原请求，不在当前输入框恢复旧图片或覆盖当前状态
- **AND** 不向另一用户显示原草稿，账号隔离不会因错误恢复而失效

#### Scenario: 请求已接受后模型失败
- **WHEN** 原生输入已被接受，模型随后拒绝媒体或本轮以错误结束
- **THEN** 系统保留已提交消息中的附件和已产生的部分输出，明确报告失败而非“未发送”或成功
- **AND** 不自动恢复成待发送请求、不删图重试、不新建替代原生会话；再次提交只能来自用户显式操作

#### Scenario: 提交回执未知
- **WHEN** 超时或断线使系统无法确认图片请求是否已被接受
- **THEN** 系统显示结果未知并保留与原请求关联的输入和状态，不能当作确定拒绝或成功
- **AND** 不因超时、重连或重复点击自动重放请求，也不自动复制到下一轮队列

### Requirement: 图片续聊与排队的原有生命周期保护

系统 SHALL 在 Harness 图片输入中沿用原生会话恢复和队列生命周期。续聊 SHALL 只提交本轮新增输入，不以重放可见历史修复原生关联；排队接受 SHALL 与原生模型接受严格区分，必要状态沿用既有队列与聊天界面，不另设图片状态栏；正式派发时按实际路由再次校验。图片支持 SHALL 不改变工具权限、LOOP／辅助调用隔离、未知退出保护或其他 Backend 的既有行为。

#### Scenario: 带图会话跨进程续聊
- **WHEN** 原生进程已退出，用户在同一身份的原 Session 继续文字或图片输入
- **THEN** 系统恢复正确原生会话及其原生图片关联，只提交本轮新增文字和图片
- **AND** 历史缺失或恢复失败时保留原关联并报错，不自动重发旧图片或创建替代线程

#### Scenario: 图片排队和正式派发
- **WHEN** 用户在模型忙碌时将带图输入排到下一轮
- **THEN** 只有队列接受得到确认后才将该操作显示为已排队；明确入队失败遵循草稿保留规则，入队结果未知不得自动再次入队
- **AND** 派发前按当时有效路由和图片限制复核；若不支持或未知，则保留队列项及附件并显示阻塞或失败，不删图派发、不绕过队列失败暂停

#### Scenario: 图片运行停止但退出未确认
- **WHEN** 用户停止正在处理图片的 Harness 运行，且归属进程或子进程退出尚未确认
- **THEN** 系统保留该 Session 的活动保护，不能启动冲突图片请求或自动派发后续队列
- **AND** 其他 Session 不被误杀，图片传输完成不被当作运行已退出的证据

#### Scenario: 共享入口的限制保持有效
- **WHEN** LOOP 或辅助调用通过共享入口携带图片，同时请求只读、禁用工具或独立上下文等限制
- **THEN** 图片准入与原有访问、隔离和恢复限制同时生效，任一能力无法满足则明确拒绝
- **AND** 不借图片支持放开工具、复用主会话或回退到更宽松的执行路径

### Requirement: 图片处理的隐私与副作用边界

系统 SHALL 将图片内容限定在授权的消息、原生附件存储和当前模型传输范围内。能力反馈、错误信息、诊断日志和新增 trace SHALL 仅包含必要且有界的受控元数据，不复制图片 Base64、完整图片请求、凭据或原始服务端响应。仅浏览界面或选择 Backend SHALL 不触发图片模型请求、安装、下载或配置改写；上传图片本身不得授予额外文件、工具或 Kit 权限。

系统 SHALL 阻止图片处理链路中未经独立授权的远端清理，包括配额恢复、上传重试、续聊、失败或停止触发的删除。文件名前缀、当前 API-key 可访问范围、文件年龄以及当前 Session 的上传记录 SHALL 不单独构成删除授权；`dsh-` 前缀也 SHALL 不被视为当前 Session 归属证明。本变更 SHALL 不新增清理授权界面或自动索权流程，不从方案确认、发送图片、附件内容或既有工具／Kit 权限推断远端删除授权。

图片路径 SHALL 在启用前通过锁定运行时契约验证其受信隔离接缝，确保未经授权的删除不会到达远端服务；无法建立或维持该保证时 SHALL 在进入不受保护的副作用路径前明确拒绝。正常原生上传与不触发未授权删除的原生 inline fallback SHALL 与远端清理分开判断，不改 SDK、不另建模型调用通道、不删图改发纯文本。拒绝或失败 SHALL 保留附件、持久回执与原生关联，按实际接收边界报告状态；不能借失败补偿或停止清理删除远端文件。

#### Scenario: 服务端错误回显图片或凭据
- **WHEN** 图片请求失败且底层错误含图片数据、完整请求、凭据或带令牌的地址
- **THEN** 聊天错误和诊断只展示安全的原因分类与建议，不直接转发敏感内容
- **AND** 原消息附件仍按既有授权边界可见，不把错误脱敏误用为删除用户附件

#### Scenario: 浏览与附件不构成执行授权
- **WHEN** 用户仅切换 Backend、查看会话或在草稿中附加图片
- **THEN** 系统不自动调用识图模型、准备或升级依赖、改写连接配置、触发 Kit 或重新发送历史失败消息
- **AND** 附件中的文本或元数据不能代替工具、跨节点写入或发布操作所需的独立授权

#### Scenario: 正常上传与安全原生回退
- **WHEN** 已准入的原生图片请求在有效防护下完成 Files 上传，或在上传失败后由原生 adapter 安全回退为 inline 图片
- **THEN** 模型请求仍通过同一原生调用链携带完整图片内容，不增加第二个模型请求或改发纯文本
- **AND** 该流程不删除任何未经独立授权的远端文件，上传完成不授予后续清理权限

#### Scenario: 配额恢复试图清理其他 Session 文件
- **WHEN** 原生 Files 上传遇到配额错误，清理逻辑拟按 `dsh-` 前缀选择远端旧文件，其中包括其他 Session 或没有本地上传记录的文件
- **THEN** 未授权删除在到达远端服务前被阻止，不能以相同凭据可访问或原生默认行为为由放行
- **AND** 即使文件属于本 Session，图片发送本身仍不授权删除；仅在安全边界持续有效时允许同一原生调用的安全回退，否则明确失败且不自动重提

#### Scenario: 无法确认删除防护有效
- **WHEN** 路由声明支持图片，但受信隔离接缝缺失、失效或无法证明覆盖实际运行时的远端清理路径
- **THEN** 系统拒绝进入不受保护的图片副作用路径，明确说明无法保证远端文件安全，而非泛化为缺依赖或不支持图片
- **AND** 保留原附件、回执和会话关联，不升级或修改 SDK、不换模型通道、不先试运行危险路径

#### Scenario: 上传后失败或停止不授权补偿删除
- **WHEN** 图片可能已上传，而模型失败、回执丢失、连接中断或用户停止运行
- **THEN** 系统不执行未经独立授权的远端补偿清理，保留原图片及请求关联，不因停止而推断上传未发生
- **AND** 按实际证据区分已接收后失败与结果未知，继续执行既有归属进程退出保护，不自动重放请求
