# codex-backend-model-catalog Specification

## Purpose

允许用户在每个 Codex 官方类型 Backend 的配置界面手工维护或点击从 Codex 同步模型候选项，模型更新时无需等待 AWU 升级。同步只填入草稿并如实显示来源，所有相关模型选择入口在保存后使用同一份对应 Backend 的配置，同时保留手填模型、默认继承、已有会话和节点隔离行为。

## Requirements

### Requirement: 按 Backend 编辑有序模型候选列表

系统 SHALL 在每个 `codex-office` Backend 的配置界面提供模型候选列表，允许新增、编辑、删除及调整顺序。每项 SHALL 包含模型 ID 和可选显示名称；名称为空时 SHALL 显示模型 ID。固定的“Codex 官方账户”与用户创建的同类型 Backend SHALL 支持相同的候选列表操作。修改 SHALL 随 Backend 显式保存提交，取消编辑 MUST NOT 改变已保存配置。

#### Scenario: 新增新版模型并保存
- **WHEN** 用户为某 Codex Backend 增加未内置的模型 ID 和显示名称、调整其位置并保存
- **THEN** 该 Backend 的候选列表按保存顺序展示该项，无需修改源码、重启 AWU 或调用真实模型

#### Scenario: 取消编辑不污染来源
- **WHEN** 用户编辑或复制 Backend 时修改候选项，然后取消保存
- **THEN** 原 Backend 的候选项、顺序及默认模型保持不变

### Requirement: 内置候选与显式空列表有不同语义

系统 SHALL 对未配置候选列表的 Backend 使用内置候选；用户自定义列表 SHALL 完整替代内置候选，不与之自动合并。用户 SHALL 能显式清空候选，或通过独立的“恢复内置候选”操作返回内置模式。以上操作 MUST NOT 修改 Backend 默认模型、Session 模型覆盖值或 LOOP 角色模型配置。

#### Scenario: 旧 Backend 未配置列表
- **WHEN** 读取不含 `modelOptions` 字段或其值为 `null` 的旧 Backend 配置
- **THEN** 使用内置候选列表，原有模型选择和继承行为不变

#### Scenario: 清空候选
- **WHEN** 用户保存空数组 `modelOptions: []`
- **THEN** 该 Backend 不再展示内置候选，但模型输入仍可手填、留空继承

#### Scenario: 恢复内置候选
- **WHEN** 用户随后执行“恢复内置候选”并保存
- **THEN** 恢复内置候选，而非选中某个内置模型

### Requirement: 所有模型入口消费对应 Backend 的列表

系统 SHALL 在 Backend 默认模型输入、新建 Session、聊天模型运行参数以及 LOOP 各角色的模型选择入口使用其实际所选 Backend 的候选列表。当前窗口成功保存配置后，同节点相关入口 SHALL 更新候选，不要求刷新整页；单纯刷新候选 MUST NOT 清空正在编辑的模型值。候选保存与读取 SHALL 使用目标执行节点，不能以全局默认节点或同名 Backend 替代；其他窗口重新打开或重新加载相关入口时 SHALL 读取目标节点的已保存配置。

#### Scenario: 同节点保存后多个入口一致
- **WHEN** 用户保存某 Backend 的候选列表后查看该窗口中已打开的聊天参数和新建会话入口
- **THEN** 这些入口展示同一顺序和名称的候选，已输入但未提交的模型值不变

#### Scenario: LOOP 角色使用不同 Backend
- **WHEN** 规划角色和执行角色分别选择两个候选列表不同的 Codex Backend
- **THEN** 各角色展示自己所选 Backend 的候选，不继承另一 Backend 的列表

#### Scenario: 两个节点存在同名 Backend
- **WHEN** 用户在节点 B 保存与节点 A 同 ID Backend 的候选列表
- **THEN** 只有节点 B 的相关候选更新，节点 A 的配置与选择不受影响；节点 B 不可达时显示失败，不回退节点 A

### Requirement: 候选列表不构成运行白名单

系统 SHALL 继续允许手填未列入候选的模型 ID，并保留留空继承语义。删除或重命名候选 MUST NOT 自动改写 Backend 默认模型、已有 Session/LOOP 的模型值、原生 thread 标识或正在执行的请求。界面 SHALL 明确候选可由用户维护或显式同步导入，不代表账号一定可用；候选保存 MUST NOT 发起模型调用、认证探测或自动替换请求模型。

#### Scenario: 删除正在使用的候选
- **WHEN** 用户从候选列表移除仍被某 Session 使用的模型
- **THEN** 该 Session 继续显示并使用原模型值，不自动切换、清空或重建 thread

#### Scenario: 手填未来模型
- **WHEN** 用户在运行参数中手填未出现在内置或自定义候选中的模型 ID
- **THEN** 仍按既有模型运行参数流程保存和传递该值，不因不在候选列表中被拒绝

### Requirement: 候选输入得到一致且原子的校验

系统 SHALL 在配置界面和配置写入边界校验候选数据：列表最多 100 项，模型 ID 去除首尾空白后非空、最多 200 字符且不包含内部空白或控制字符，显示名称去除首尾空白后最多 120 字符且不包含控制字符。ID SHALL 按去除首尾空白后的精确值去重判定；重复项和非法结构 SHALL 拒绝保存并指出问题，而非静默删除或截断。模型 ID MUST NOT 被固定版本、品牌前缀或内置列表限制。校验或持久化失败 MUST NOT 产生部分配置覆盖。

#### Scenario: 非法或重复候选
- **WHEN** 用户保存空 ID、超限项、重复 ID，或导入非数组、元素结构错误的候选数据
- **THEN** 显示可定位错误，已保存配置、内存中生效列表和其他 Backend 配置保持不变

#### Scenario: 名称可重复但 ID 不重复
- **WHEN** 两个不同 ID 使用同一显示名称，或有效模型 ID 含有普通版本号以外的路径分隔符
- **THEN** 只要符合长度和字符规则即可保存，列表仍以 ID 区分各项

### Requirement: 持久化、复制与兼容更新保留候选

Backend 候选配置 SHALL 随对应节点的配置持久化，重启后保持模式、内容和顺序。复制 Backend SHALL 创建独立候选副本；导出和允许的导入 SHALL 保留 `modelOptions` 的值。向新版服务保存或覆盖导入旧格式配置时，若已有同类型 Backend 且请求省略 `modelOptions`，系统 SHALL 保留已有候选；显式 `null` SHALL 恢复内置模式，显式空数组 SHALL 清空候选。现有导入冲突、跳过和固定 Backend 保护规则 SHALL 保持不变。

#### Scenario: 重启及导出导入往返
- **WHEN** 用户保存自定义候选后重启，或将支持该字段的导出配置导入为可导入 Backend
- **THEN** 候选 ID、显示名称、顺序及空列表/内置模式与保存前一致

#### Scenario: 旧客户端更新其他字段
- **WHEN** 旧客户端更新已有 Codex Backend 的名称或代理但不发送 `modelOptions`，或旧导入文件覆盖相同类型的可导入 Backend
- **THEN** 已维护的候选列表保留，不因缺省字段被清空

#### Scenario: 固定官方 Backend 导入保护
- **WHEN** 导入文件包含固定“Codex 官方账户”的候选配置
- **THEN** 按既有受保护 Backend 规则跳过导入，不以新增字段绕过保护；其候选仍可在配置界面直接编辑

#### Scenario: 旧执行端丢弃新字段
- **WHEN** 保存自定义候选后回读发现目标执行端未保留该字段
- **THEN** 界面提示候选未保存或执行端需升级，保留编辑草稿，不宣称候选保存成功

### Requirement: 变更不扩展到其他 Backend 能力

系统 MUST NOT 因新增 Codex 候选配置而改变其他 Backend 类型的模型选择方式、Codex 推理档位、认证信息、权限设置或运行参数优先级。本能力 SHALL 只管理候选，仅在用户显式触发时查询目录，MUST NOT 在启动或后台定时同步、修改 Codex 原生配置文件或登录状态。

#### Scenario: 其他 Backend 和推理档位保持原样
- **WHEN** 用户维护一个 Codex Backend 的候选后查看 Qwen、API 类型 Backend 或 Codex 推理档位
- **THEN** 原有选项、继承和执行行为不受该候选列表影响

### Requirement: 显式从目标 Codex Backend 同步目录

系统 SHALL 在固定“Codex 官方账户”和普通 `codex-office` Backend 配置页提供“从 Codex 同步”，使用用户有权访问的目标执行节点及该 Backend 对应的 CLI、环境、认证和 provider 配置查询目录。系统 MUST NOT 回退到其他节点或账号，MUST NOT 隐式保存连接配置。若连接相关草稿尚未保存，界面 SHALL 提示先保存这些字段，不能以旧环境的结果冒充新环境结果。打开配置界面本身 MUST NOT 触发目录查询。

#### Scenario: 固定和普通 Codex Backend 都可同步
- **WHEN** 用户在任一受支持的 Codex Backend 编辑页点击“从 Codex 同步”
- **THEN** 查询使用该 Backend 在目标节点的配置环境，不要求用户手工查找模型 ID，也不自动发起推理

#### Scenario: 远端同 ID Backend 的目录隔离
- **WHEN** 用户对节点 B 的 Backend 发起同步，而节点 A 有同 ID Backend
- **THEN** 仅查询节点 B；其离线或无权访问时显示失败，节点 A 不被查询或修改

#### Scenario: 未保存连接修改
- **WHEN** 用户改变了影响 Codex 目录来源的连接字段且未保存，就尝试同步
- **THEN** 提示先保存连接修改，不悄悄保存草稿、不拿旧连接返回的目录替换候选

### Requirement: 同步成功仅填入候选草稿

系统 SHALL 仅在获取到完整、非空且通过现有候选校验的目录后，一次性用实际模型 ID 和可选名称按来源顺序替换候选草稿，转为自定义列表。同步结果 SHALL 保持可手工编辑，并提示保存后生效。同步本身 MUST NOT 修改已保存候选；只有用户按既有配置保存流程提交后，候选才持久化。同步及候选保存 MUST NOT 自动选择首项或改写默认模型、Session/LOOP 运行值、推理档位、thread 或活动请求。

#### Scenario: 填入草稿后正常保存
- **WHEN** 同步成功且用户随后保存 Backend
- **THEN** 保存前仅编辑页草稿变化；保存及回读校验成功后，同节点相关入口使用该有序列表，原默认模型和运行值不变

#### Scenario: 同步后取消或继续编辑
- **WHEN** 用户同步成功后继续手工修改候选，或直接取消编辑
- **THEN** 手工修改保留到草稿供正常保存；取消则丢弃未保存结果，生效配置不受影响

### Requirement: 同步失败和不完整结果不覆盖候选

系统 SHALL 对超时、节点离线、权限错误、认证不可用、不支持的 Codex 版本、空目录、非法数据、重复 ID、超限及分页不完整提供明确失败反馈，保留现有草稿和已保存列表。查询 SHALL 有有界的执行时长和结果规模；MUST NOT 以部分结果、静默截断、静默去重或内置列表替代完整查询成功。失败后用户 SHALL 仍可手工维护候选。

#### Scenario: 不支持或认证失败
- **WHEN** 目标 Codex 无目录查询能力或现有认证无法完成查询
- **THEN** 显示对应限制且保留草稿，不修改登录状态、不自动安装升级、不回退其他账号

#### Scenario: 空目录不是清空授权
- **WHEN** 查询返回空目录或非法、重复、超出候选数量上限的数据
- **THEN** 显示失败，不把结果当作显式空列表或部分成功覆盖原候选

#### Scenario: 分页中途失败或超时
- **WHEN** 尚未取得完整目录时查询失败、达到安全上限或超时
- **THEN** 整次同步失败，已取得的页面不应用到草稿，查询占用的资源被释放且不影响活动请求

### Requirement: 迟到同步结果不覆盖新的编辑状态

系统 SHALL 显示同步加载状态并阻止同一编辑实例的重复提交。切换执行节点或 Backend、关闭编辑、保存、取消或用户产生新草稿修改后，先前请求结果 MUST NOT 覆盖新的状态；可取消的查询 SHALL 取消，无法及时取消的结果 SHALL 被安全丢弃。归属判断 SHALL 区分同 ID 不同节点及新建、复制、重新打开的编辑实例。

#### Scenario: 同步期间切换编辑目标
- **WHEN** 同步未结束时用户切换到另一节点或 Backend，原请求随后返回
- **THEN** 原结果不写入当前编辑页，也不改写任何已保存列表

#### Scenario: 用户编辑优先于旧请求
- **WHEN** 同步期间用户手工编辑候选、恢复内置或保存/取消草稿，先前请求随后返回
- **THEN** 新状态保留，旧结果不覆盖用户动作；仍在原编辑页时按适用情形提示可重新同步

#### Scenario: 重复点击同步
- **WHEN** 同一编辑实例已有未完成同步而用户再次点击
- **THEN** 不产生重复查询，加载状态在成功或失败后正确结束

### Requirement: 来源新鲜度及查询副作用如实可见

系统 SHALL 展示同步结果可核实的来源及读取时间，将上游目录新鲜度未知明确标为未知。读取时间 MUST NOT 被当作上游目录更新时间，缓存或内置数据 MUST NOT 被宣称为“官方最新”，列出模型 MUST NOT 被视作账号一定有使用资格。同步后的手工修改 SHALL 与原始同步结果区分。目录查询 MUST NOT 创建模型 thread/turn、发起推理或改变活动请求；界面和日志 MUST NOT 暴露认证凭据或敏感环境配置。

#### Scenario: 目录可能来自缓存或内置
- **WHEN** Codex 返回缓存/内置目录，或未提供足以确认来源、新鲜度的信息
- **THEN** 界面展示已知来源或未知状态及本次读取时间，不标注“官方最新”或“账号全部可用”

#### Scenario: 同步后手工修改及重新打开
- **WHEN** 用户修改同步得到的草稿，或保存后重新打开编辑页但没有可保留的来源证据
- **THEN** 修改后的草稿不冒充原始目录；重新打开时展示已保存候选，不伪造来源与上游更新时间

#### Scenario: 查询不干扰正在运行的会话
- **WHEN** 相同 Backend 有活动模型请求时用户同步目录，无论同步成功还是失败
- **THEN** 活动请求、模型和原生 thread 保持不变，不启动额外推理；响应及日志不输出认证秘密
