# loop-execution-environment Specification

## Purpose

为自动 LOOP 提供与真实执行节点、工作区、Backend 及原生访问策略一致的工具环境准备与证据，区分宿主发现、受限检查和实际调用结果。环境受阻时给出可信的原因、影响范围和恢复条件，防止无效重复执行、虚假就绪及权限绕行，同时保持普通聊天和通用 LOOP 的兼容行为。

## Requirements

### Requirement: 执行环境身份与实际调用一致

系统 SHALL 为自动 LOOP 的环境证据标识实际执行节点、Session、工作区、Backend、传输方式、调用角色、原生访问策略及相关工具链修订。证据 MUST 仅适用于相同身份与有效期；人工调用成功、宿主终端成功或另一角色的成功 MUST NOT 替代当前调用环境证据。

#### Scenario: 人工可用但自动受限
- **WHEN** 同一工作区的人工接管可以运行 CLI，而自动规划或执行使用不同原生访问策略
- **THEN** 系统分别展示两种模式，不继承人工成功为自动就绪，也不把 Session 的旧沙箱显示开关或跳过确认开关等同于原生全权限

#### Scenario: Backend 或阶段切换
- **WHEN** 实际路由的 Backend、工作区、工具链修订或调用访问策略发生变化
- **THEN** 系统使不匹配的检查结果失效，以实际调用身份重新核对，不借用配置中未实际使用的 Backend 结果

### Requirement: 依赖声明不等于任务来源或授权

系统 SHALL 仅对当前明确工作流、有效声明或实际调用证据所关联的依赖做定向检查，保留依赖来源及适用范围。安装或绑定 Skill、历史文本出现工具名称或模型建议 MUST NOT 单独形成必需依赖、正式 change 绑定或新的执行授权；不明确的工作流选择 SHALL 允许用户显式指定且不启动任务。

#### Scenario: 未绑定来源的明确工作流
- **WHEN** LOOP 没有正式任务来源绑定，但当前有可重新核对的显式 OpenSpec 工作流选择和有效 CLI 声明
- **THEN** 系统检查该工作流的 CLI 依赖，仍保持任务来源未绑定，不猜测最新 change、不扩大原工作流阶段

#### Scenario: 通用 LOOP 绑定了多个 Skill
- **WHEN** 普通探索 LOOP 只是安装或绑定了 OpenSpec Skill，没有选择该工作流且没有实际依赖证据
- **THEN** 系统不因 OpenSpec 缺失而阻塞该 LOOP，也不探测所有已绑定 Skill 的 CLI

#### Scenario: 声明被修改或选择不明确
- **WHEN** 已选择工作流的命令声明失效、发生冲突，或旧交接无法可靠定位当前工作流
- **THEN** 系统标明声明失效或工作流未确认，只对明确受影响工作等待选择，不执行旧声明、不解析历史授权，用户选择依赖不会自动绑定来源或运行工作流

### Requirement: 工具入口准备可复现且不绕过权限

系统 SHALL 按当前工作区及实际 Backend 配置解析已有工具入口，并向相应隔离调用提供有界、可追溯的入口信息。入口存在、运行时依赖可用和原生策略内可执行 SHALL 分开核验；拒绝访问 MUST NOT 被忽略或通过更换权限、工具通道、节点及宿主代执行来绕过。

#### Scenario: 项目本地入口可用
- **WHEN** 当前工作区已有有效声明所指的本地 CLI，且对应调用策略下的固定只读检查通过
- **THEN** 系统使用该已核对入口及其必要运行时信息，隔离调用无需再次猜测全局 PATH，检查不安装依赖、不修改项目配置

#### Scenario: 仅 Backend 路径存在入口
- **WHEN** 项目没有本地 CLI，而实际 Backend 的环境可以定位用户目录中的 CLI
- **THEN** 系统将其作为宿主候选并在原生策略内检查，只有当前范围内的通过证据才能标注可用；目录访问被拒绝时保留拒绝事实，不报告为肯定未安装

#### Scenario: Windows 包装脚本或运行时不可用
- **WHEN** 工具入口是 Windows npm 包装脚本，路径含空格，或该包装脚本需要的运行时不能解析
- **THEN** 系统采用经验证的参数传递方式，分别报告包装入口与运行时问题，不把声明或路径字符解释为任意 shell 命令，不在拒绝后改用其他工具通道运行同一操作

### Requirement: 原生检查有界且忠实声明覆盖范围

系统 SHALL 使用已验证支持的原生执行入口，在实际调用的工作区、环境和访问策略下运行固定、只读的定向检查，限制时间、输出、重试与并发。检查 SHALL 不产生额外模型调用、不执行工作流动作、不触发网络安装；宿主发现或不同工具路径的结果 MUST NOT 冒充完整的实际调用就绪证明。

#### Scenario: 相同边界重复请求
- **WHEN** 同一执行身份在同一边界收到重复检查请求
- **THEN** 系统合并在途检查，复用仍有效的有限结果，不重复启动检查进程，打开面板或流式更新不触发检查

#### Scenario: 原生协议不支持或只覆盖部分路径
- **WHEN** 当前 Backend/传输不支持相同策略的确定性检查，或检查入口不能证明与模型实际命令工具等价
- **THEN** 系统显示不支持或部分覆盖而非通过，不改用宿主全权限检查作为替代；未有阻塞的新调用维持原受限路径和真实事件观察，已有确认的环境阻塞不因覆盖不足而解除

#### Scenario: 检查超时或取消
- **WHEN** 环境检查超时、输出超限、用户取消或控制权转交
- **THEN** 系统结束受控检查并确认退出，报告未确认或相应失败，不留孤儿进程；退出未确认时不启动依赖它的新写调用

#### Scenario: Windows 原生缓冲与结果接受上限不同
- **WHEN** 经版本验证的 Windows 原生路径不支持自定义输出上限，但支持有界默认捕获
- **THEN** 系统显式区分原生捕获缓冲与 AWU 每流 32 KiB 结果接受上限，在解码前限制协议帧，并拒绝超限或不完整结果；未经验证的默认行为不能作为检查通过依据

#### Scenario: 原生不支持主动终止
- **WHEN** Windows 受限检查不支持 terminate，而用户取消或检查超时
- **THEN** 系统停止后续检查，保持活动锁并有界等待原生超时和退出确认；取消请求、协议错误或连接关闭不能单独解除未退出阻塞，也不能改用全权限完成检查

#### Scenario: 原生检查通过但实际工具失败
- **WHEN** 原生检查通过后，真实模型工具调用出现初始化失败或访问拒绝
- **THEN** 系统立即使相关就绪证据失效并保留更具体的运行失败，不以先前检查通过覆盖新故障或继续调度依赖步骤

### Requirement: 环境分类依据可靠事件而非模型猜测

系统 SHALL 区分入口未解析、已配置入口缺失、权限拒绝、执行器初始化失败、检查不支持及证据不足，并记录证据来源、时间、影响范围和可操作的解除条件。确定分类 MUST 来源于受控检查或可识别的原生事件；模型总结及任意工具正文仅可作为待核对线索，不能证明安装状态或故障内部根因。

#### Scenario: 命令找不到但缺少其他证据
- **WHEN** 唯一可靠结果是当前策略下命令无法解析
- **THEN** 系统报告当前环境无法解析及所需检查，不断言整台机器未安装，不自动建议或执行重装

#### Scenario: 明确的权限拒绝
- **WHEN** 受控检查在访问已发现入口时返回权限拒绝
- **THEN** 系统记录拒绝发生的环境和入口引用，给出“在相同策略下恢复合法访问后复查”的条件，不能将其归为 CLI 缺失或普通网络故障

#### Scenario: 执行器初始化失败
- **WHEN** 可识别的原生进程建立事件报告初始化未完成，命令尚未实际执行
- **THEN** 系统记录 runner 初始化失败及原生错误类别，不把它归因于 OpenSpec 未安装，也不声称已确定 helper 的内部失败原因

#### Scenario: 模型暂停没有可靠环境证据
- **WHEN** 模型要求暂停并声称工具缺失，但系统没有对应可靠事件或检查结果
- **THEN** 系统保留暂停及原始详情入口，标记原因待核对，不伪造确定的环境故障，不因无法分类而继续执行

### Requirement: 环境阻塞保持安全和任务范围

系统 SHALL 在已确认环境阻塞后停止调度受影响及依赖调用，保持成果和任务验收状态，并以明确的环境解除条件等待。真实局部依赖问题 MUST NOT 自动冻结已证明独立的工作；安全/授权暂停、共享 runner 故障或影响范围无法确定时 SHALL 保守停止相关自动调度。系统 MUST NOT 自动提高权限、修复全局环境或以新轮次重试同一持续阻塞。

#### Scenario: 自动权限与人工不同
- **WHEN** 用户知道人工接管可用，自动调用仍被原生策略拒绝
- **THEN** 系统保留自动访问策略，提供人工处理及重新检查说明，不复制人工全权限配置、不切换 Backend 或调用通道以规避拒绝

#### Scenario: 局部工具依赖失效
- **WHEN** 一个步骤的独有 CLI 不可用，但已有可靠依据证明另一就绪步骤不依赖它且没有更高优先级暂停
- **THEN** 系统保留该局部阻塞及受影响任务，只在原有 Auto、授权与预算允许时继续独立工作

#### Scenario: 共用执行器不能启动
- **WHEN** 当前自动调用共用的 runner 被确认不能创建命令进程
- **THEN** 系统停止依赖该 runner 的调度，报告环境处理条件，不借增加轮数、解析备用计划或包装成探索任务绕开故障

### Requirement: 环境状态轻量展示并安全持久化

系统 SHALL 在 LOOP 面板、流程详情及恢复后展示一致的访问策略、检查覆盖、原因和解除条件，提供空闲时的显式重新检查入口。记录 SHALL 按用户、节点、Session 及修订隔离，使用有界摘要和按需详情，不保存完整环境变量、凭据、授权令牌或额外历史正文；旧记录 SHALL 保持未知。

#### Scenario: 重新检查不等于执行
- **WHEN** 用户在空闲且有操作权限的 LOOP 点击重新检查环境
- **THEN** 系统仅运行所选环境的固定只读检查并更新证据，不开启 Auto、不发送任务模型调用、不自动恢复暂停；运行中或人工接管只读视图不提供此操作

#### Scenario: 延迟响应与配置修订
- **WHEN** 用户切换 Session、节点或环境配置后旧检查返回
- **THEN** 旧结果只属于原身份和修订，不覆盖当前就绪状态、不解除新暂停，重复推送和隐藏视图不形成详情轮询

#### Scenario: 旧记录及敏感信息
- **WHEN** 加载无环境字段的旧记录，或异常包含密钥、完整环境和私有正文
- **THEN** 系统显示旧环境未知；新记录仅保留白名单化类别及必要身份引用，敏感正文不进入环境详情、紧凑推送或日志

### Requirement: 用户数据写测试具有明确隔离前置

系统 SHALL 在 LOOP 计划中为已识别的可能写入用户目录、存档或数据库的测试记录任务级前置：独立测试数据根、实际数据路径的核对方式、证据引用、适用执行身份和消费该前置的任务。前置未核实、身份失效或实际路径未知时 MUST NOT 调度依赖它的测试调用。创建测试隔离环境与运行应用测试 SHALL 分开编排；只读规划或复核不执行会写缓存/用户数据的探测。

#### Scenario: 在测试矩阵前发现前置缺口
- **WHEN** 计划包含会写用户数据的应用矩阵，但没有独立目录或实际写入位置的有效证据
- **THEN** 系统先安排授权范围内的隔离准备及核对，不先启动应用矩阵；无法核对时仅记录受影响任务并按阻塞规则调度

#### Scenario: 配置了测试目录但实际路径不明
- **WHEN** 只有环境变量或启动参数声明，没有适用证据确认应用实际数据位置，或路径指向真实目录/其别名
- **THEN** 系统不将声明视为隔离通过，不用启动可能写真实数据的应用来试探；保留测试阻塞及核实条件

#### Scenario: 原生工具检查并非测试隔离证明
- **WHEN** CLI 的固定原生检查通过，或只读评审核对了文件，但测试使用不同的写策略、配置或工作目录
- **THEN** 系统保留检查各自的覆盖范围，不把 CLI 可用、模型自述或规划只读成功等同于测试隔离/写权限已验证

### Requirement: 真实用户文件基线不是隐式通用门槛

系统 MUST NOT 仅因为要求保护用户数据，就给所有测试添加读取真实存档或建立全量基线的前置。若用户、项目规则或正式规格明确要求真实文件基线，系统 SHALL 保留其依据和验收范围；读取被拒时不绕过拒绝、不伪造基线，也不自动删除此验收项。

#### Scenario: 无真实基线要求且隔离证据有效
- **WHEN** 当前验收没有真实用户文件基线要求，并且原授权与策略内的独立测试隔离已核实
- **THEN** 系统可调度该隔离测试，不另行访问真实存档，不把无关真实目录不可读当作新的全局授权缺失

#### Scenario: 真实基线是明确验收要求
- **WHEN** 指定验收必须比较真实用户文件基线，而合法读取不可用
- **THEN** 相关验收保持受阻并说明所需最小条件；系统可复核其他独立就绪任务，但不以隔离测试成功代替该验收

### Requirement: 测试前置与阻塞证据不跨身份放行

系统 SHALL 将测试前置和任务阻塞证据绑定到工作区、Backend、执行节点、访问策略、计划及相关配置/产物修订，标记观察、模型评审和确定性检查的区别。证据过期或影响范围不确定 MUST NOT 为测试提供放行依据；原生环境故障或权限拒绝不能被较弱的任务级复核清除。

#### Scenario: 配置或执行身份改变
- **WHEN** 隔离配置、工作区、实际 Backend、访问策略或任务来源修订在核对后发生变化
- **THEN** 相关前置失效并要求重新核对，不复用人工模式、旧节点或旧目录的通过结果

#### Scenario: 异常正文仅提供原因线索
- **WHEN** 模型报告访问拒绝，但没有对应可靠事件区分原生策略、ACL 或执行身份原因
- **THEN** 系统如实显示当前访问失败及证据级别，不断言具体内部根因；不更换通道、宿主、节点或权限重试同一被拒资源

### Requirement: 局部复核不改变原生环境检查与授权

系统 SHALL 将任务级阻塞复核与既有固定原生环境检查分开。复核只可读取当前授权与策略内的任务/证据，不运行应用、修复 ACL、安装工具或读取已被拒资源；复核仍受停止、超时、输出预算和旧调用退出确认约束。

#### Scenario: 共享执行器失效或安全风险存在
- **WHEN** runner 被可靠证据判定不可用、进程退出未确认或存在未遏制安全风险
- **THEN** 系统保持原高优先级阻塞，不通过创建新复核、换 Backend 或重规划逃避限制
