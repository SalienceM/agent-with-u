# Proposal

## Why

现有 Session 历史、原生线程续接、Prompt 模板和模型表现台账，尚不能把用户跨任务表达的判断与认可逐步积累成可复用的协作习惯。需要建立属于用户的轻量记忆：当前任务保持强意图，长期经验作为柔性引导，通过保守更新和持续积累，让结果逐渐更贴合用户而不增加逐条审批负担。

## What Changes

- 建立按用户隔离的事务树，支持工作、生活及其细分主题；项目是可关联的节点之一，不以工作目录限制记忆范围，并允许任务类型、受众和产物风格等轻量跨节点关联。
- 保留三类来源：T0 是用户真实表达的想法、判断与取舍；T2 是有用户认可依据的模型成果；T1 是结合 T0 和 T2 凝练出的思路、口味和半模板。三类不是事实真伪等级，也不构成对当前任务的强制命令优先级。
- 使用小幅、可修正的积累机制：独立反馈逐渐增强倾向，单次行为不立即全局定型；沉默、重复注入和模型自述不制造用户认可。默认应用低强度相关倾向，不为每一条候选记忆要求确认。
- 在正常会话的模型发送边界，为当前请求和绑定 Prompts 自动关联少量适用记忆；当前明确要求覆盖冲突习惯，未交代的组织方式、关注点和表达风格可由记忆补足。
- 提供轻量的“本次参考了什么”、本次不用、纠正、停用积累/引用和遗忘入口；用户需要时才进入事务树管理，不新增常驻审批面板。
- 首版以本执行节点、同一用户跨 Session/项目复用为边界，事务树不限定为代码项目；独立持久化、检索、归纳预算、版本和删除传播由应用负责，Skill 仅可辅助凝练流程。
- 用代码走查、表格梳理和 PPT 叙事/风格三个场景验证少重复交代、少返工、低误用与有界成本，而不是以记忆条数或画像分数作为成功指标。

## Capabilities

### New Capabilities

- `personal-memory-model`: 用户事务树、T0/T1/T2 来源与关联、版本化存储、隔离及遗忘。
- `adaptive-memory-learning`: 基于反馈的保守积累、T1 凝练、矛盾修正、反自强化和有界后台作业。
- `memory-context-integration`: 任务优先的相关检索、Prompt 关联、逐轮输入组合及轻量用户控制。

### Modified Capabilities

无。现有主规格没有覆盖个性化记忆；本 change 不改 LOOP 决策、控制权或来源验收规格。

## Impact

- 新增独立记忆存储/学习/检索模块及 BridgeWS 的身份受控 RPC，关联 `Session`、`session_store.py` 与正常聊天完成/发送边界。
- 对接现有 `prompt_store.py` 和 `Session.abilities.prompts`，但不把个人记忆写入当前全局 Prompt 模板正文或项目 Skill 文件。
- 前端影响提示词绑定、消息反馈和记忆管理入口；Native Agent 与直接 API 路径分别验证逐轮注入，不假设一次写入 `session.constraints` 后恢复线程即可看见变化。
- 首版采用 Python 标准库支持的本地存储与词项/结构检索，不引入向量数据库、外部记忆服务或模型训练依赖。学习调用使用用户可见、可停用的 Backend/预算配置；测试使用 fake Backend 和隔离数据目录。
- 与 `refactor-loop-workbench` 独立实施；首版不自动从 LOOP 的模型规划/评审中学习用户偏好，不改变其授权或验收。

## Non-goals

- 不把个人习惯做成强制规则库或逐条确认工作流，不承诺精确量化人的口味，也不进行模型权重训练。
- 不在首版实施跨执行节点自动同步、团队共享画像、全历史自动扫描或外部账号资料抓取。个人全局指同一用户的语义适用范围，不代表首版已跨设备同步。
- 上下文压缩是独立的会话长度管理问题；本 change 不重写 `/compact` 或原生线程压缩，也不把截断摘要当作 T0 原始证据。
- 本 change 当前只生成规划工件；实现需另行 apply。
