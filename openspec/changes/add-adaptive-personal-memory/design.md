# Design

## Context

动机和三类记忆的含义见 `proposal.md`。以下是 2026-10-10 已检查的实现事实，不表示新能力已经存在：

- `Session.owner_id` 和 BridgeWS 的认证上下文已隔离 Session；个人记忆的无 Session 查询仍需显式 owner 门槛，不能只依赖现有按参数名识别的 Session RPC 授权。
- `PromptStore` 在 `paths.sub("prompt-library")` 保存 Markdown 和名称索引，没有个人记忆模型。`_apply_session_abilities` 将绑定 Prompt 组成持久化 `session.constraints`；`_compose_constraints` 另加运行时信息。
- Codex/Qwen 恢复路径可能不重发初始 constraints。正常发送路径已为当轮工具信息设置实际输入边界，记忆同样需要在真实提交处接入，而不是只修改初始约束。
- `compress_messages` 是字符截断式历史拼接，`/compact` 还会移除应用层早期消息；直接 API 的发送路径可能同时携带历史和摘要。这里不能充当长期记忆的来源账本，也不能承诺新增记忆会自动降低总 token。
- `model_ledger.py` 是模型表现台账，LOOP stage 是任务状态，`@SESSION` 是显式历史引用，均不直接等同于用户偏好记忆。
- `openai_compat.py` 和 BridgeWS 现有调试路径会打印输入前缀。新增私人片段前必须处理该边界，不能把记忆正文带入普通诊断日志。

## Goals / Non-Goals

**Goals:**

- 以当前任务为强意图，用可解释的小幅积累形成柔性倾向；来源可信度、适用范围和引用影响分开表达。
- 首版先闭环“捕捉 → 凝练 → 有界引用 → 用户纠正”，以正常聊天覆盖代码走查、表格和 PPT 使用场景。
- 将后端身份隔离、作业幂等、遗忘传播和输入开销做成应用能力；保持数据模型小而可演进。

**Non-Goals:**

- 不训练基础模型，不建设知识图谱平台或通用向量检索服务，不把事务树当作固定的人格分类体系。
- 不把记忆升格为工具授权、工作流指令或任务验收，不把原生 Agent 的内部记忆文件读写纳入首版。
- 不实现跨节点同步；同一中心 Relay 下仍可能有多个独立记忆空间，界面必须说清楚。
- 不顺带重写上下文压缩。长期记忆和会话摘要可在未来组合，但各自的来源、预算和效果独立验证。

## Decisions

### 1. 事务树提供组织，轻量关联提供复用

使用稳定 `nodeId`、可选 `parentId`、名称、状态和修订表示主题。初始可以只有“未归类”，不强迫用户先建完整工作/生活目录。系统根据新事件渐进建议/归类到已有节点，低把握放未归类，不自动无限新建分支；用户可移动、合并、调整关联。

记忆保存一个主要主题和少量关联节点/标签，包括任务类型、产物和受众。项目/工作目录是可选关联，不是 owner，也不是全局边界。`personal` 代表语义上适用于该用户，`topic/task` 代表局部适用；一条证据不能因为进入两个节点被重复计权。移动节点只改导航，范围拓展需要独立证据或用户编辑。

选择树加关联而非纯目录，是为了同时支持“业务甲的表格”与“用户整理表格的通用思路”；选择轻量关联而非图数据库，是因为首版只需主题定位、关系去重和来源回溯。

### 2. 用独立 SQLite 存储保留来源和派生关系

使用 Python `sqlite3`，在数据根的 `personal-memory/<安全编码的owner>/memory.sqlite3` 保存；路径由后端认证身份映射，禁止客户端传路径。连接和 I/O 不占用 WebSocket 主循环，短事务提交，模型调用期间不持有数据库锁。采用版本化 schema 和外键，不复制 Session 大正文。

核心数据：

| 对象 | 必要信息 |
| --- | --- |
| 主题 | 稳定 ID、父节点、名称、语义范围、修订 |
| 证据 | 原事件 ID、Session/消息定位、用户/模型角色、认可目标与类型、有限原文片段、时间、内容修订 |
| 记忆 | T0/T1/T2、摘要、适用/排除条件、主题关联、状态、版本 |
| 关系 | 记忆与证据、派生来源、替代/否定关系、Prompt 关联；不得循环互证 |
| 作业/回执 | 冻结证据及配置修订、预算、状态、幂等键、结果版本；无工具授权 |

T0 只关联真实用户事件，保持猜测/决策等语境。T2 必须有目标可归因的认可；泛泛“收到”不是接受全部。T1 包含适用场景、关注点、组织方式、可变部分和例子引用，可先很薄，积累后逐渐清晰。T0 的重要性体现为用户表达不被模型归纳篡改，以及纠正优先；不意味着一次表达立即跨场景成为最高权重规则。

SQLite 使证据去重、关系撤销和版本更新可在同一事务完成。只用散落 Markdown 更易发生跨文件半提交；向量数据库在首版不能解决来源归因和删除一致性，因此不引入。

### 3. 分开开关、事件捕捉与后台凝练

设置提供“积累新经验”和“在回答中引用”两个独立开关；旧用户首次升级均关闭，明确启用一次后无需逐条审批。启用页说明范围、存储节点、学习 Backend 和费用/用量预算。允许只引用既有记忆而暂停学习，也允许先积累暂不引用。本次不用只覆盖单次提交。

首版事件来自正常聊天（含人工接管的正常消息）中已提交的用户文本、对明确回答/选区的轻量认可/纠正，以及用户手动记住的片段。自然语言认可通过有界归因处理；无法定位对象只保留短期候选。自动 LOOP 的规划/执行/评审、工具输出、隐藏推理、模型声称用户喜欢某内容都不成为用户证据。附件和外部文件不自动读取；认可文件先记已知引用，内容学习需用户明确提供有界材料。

发送主链只做廉价事件登记，结束边界将相关事件合并成后台作业；不对每个 token 或每句话发模型调用。语义提取和 T1 更新可在同一个无工具文本请求中产出结构化候选，回写前核对引用真实存在、角色、范围、来源片段和版本。用户纠正/遗忘先由确定性状态处理，不等待模型。

后台归纳采用独立、无工具的文本能力适配，不继承主会话 agent_session_id、MCP、Skills、Kit 或权限。首版默认支持已有 OpenAI-compatible/Anthropic 直接 API 的无 tools 请求；配置为原生 CLI 时，只有已测试能强制无工具的专用适配才可启用，否则明确显示“归纳不支持”，保留手动记录、用户反馈和已存记忆引用，不自动换模型。正常回答使用原生 Agent 不妨碍消费记忆。

这是能力边界而非逐条审批：用户选定受支持的学习配置之后，普通低强度候选自动积累。社区 Skill 可在以后承载凝练提示，但首版不要求安装，不把持久化、身份和回执交给 Skill。

### 4. “权重”是有界启发式，不是用户喜好的精确概率

保留候选、渐稳、停用/被替代等内部状态；候选不等于待审批，允许以低强度在狭窄范围使用。成熟度由独立的用户事件和跨任务一致性决定，不由注入/阅读/模型重复次数决定。引用强度与来源类别分开，T0 的项目判断不必压过更相关的其他主题经验。

首版采用可测试、可调整的简单规则：

- 首个有效信号只建立局部弱倾向；同一事件、同一来源副本及多个标签只计一次。
- 每个任务边界最多贡献一次同方向增强，多个独立任务的重复证据逐级增强；从局部向个人级拓展，需要不同任务语境的一致支持，不能只看同一长会话的重复次数。
- 最近性、独立支持、适用范围和明确反证共同排序，旧记录不因时间流逝自动删除；具体任务事实可过期，协作习惯优先因新反证而修正。
- “这次换一种”只覆盖本次，不默认削弱其他场景；“以后这类不要再这样”立即停用对应旧范围。直接用户编辑优先于历史累计。
- 未获新增用户反馈的模型答案不进入独立支持集；由 T1 引用而产生的 T2 仍需新的真实用户认可，且保留同源标记，不能循环叠加虚假独立样本。

不向用户展示“喜欢这种风格 87%”等伪精确画像。详情只说明“来自这几次选择”“当前仅用于代码走查”等可理解依据。比较更复杂的贝叶斯/嵌入方案，简单规则更容易发现错误强化；以后有真实评估证据再升级。

### 5. 在实际发送边界组合少量记忆

候选池先按 owner、节点和启用/遗忘状态过滤，再按主题/任务/Prompt 关联及词项相关性筛选。首版使用标题、摘要、标签和中文短词/双字词项的轻量索引，支持词项与结构加权，不依赖数据库扩展或 embedding。关联不足允许空结果，不为凑满预算注入。

Prompt 暂无稳定不可变 ID，因此个人关联表记录名称、创建标记、内容指纹与关联修订，每次引用前核对。已知重命名可在当前用户空间内版本化更新关联；删除、导入替换、同名重建或身份不确定时使关联失效，由用户重新关联，不尝试跨所有用户数据库与全局 Prompt 文件做伪原子事务。Prompt 正文仍是原模板，导出只导模板。学习不得写入 AGENTS.md、Skill 或共享提示词。

`memory_context` 在 `_handle_send_message` 的实际 Backend 调用前构造动态参考包，与用户原文分离，顺序表达为“历史柔性参考 + 当前请求”，明确当前任务与显式约束优先。API 和原生路径都在 `send_content` 的当轮上下文接口接入，不能放进被“必须遵守”包装的持久化 constraints；适配器对真实出站 payload 做断言，避免已有历史/约束拼接再次带入相同包。

每个实际请求至多一个记忆包，包含记忆 ID、版本、摘要和适用条件；用户正文仍保存原文。重试冻结选择但每次提交前重验删除/停用代次，失效则移除；内部工具回合不重新检索。原生线程可能保留旧注入内容，新版包及必要撤销说明只影响后续输入，不能保证删除提供方历史。长期累积带来的 native context 成本单独观测，不将本功能称为压缩。

发送成功建立有界引用回执，区分已准备、已提交和结果未知；“本次参考”显示当时实际包，不能重新检索冒充历史依据。检索失败使用无记忆路径并给出轻提示，不把普通聊天变成依赖记忆服务可用性的任务。

### 6. 初始预算给效率一个可验证边界

下列为可配置的首版默认值，是资源上限而非用户心理分数：

| 环节 | 默认边界与超限处理 |
| --- | --- |
| 单次检索 | 最多 50 个候选，最多选 8 条，最多 2 个 T2 例子；本地读取等待 150ms 后本次不用，不增加网络请求 |
| 输入参考包 | 最多 6000 字符，另受可得 token 预算约束；不足时逐条移除低相关候选，不挤掉当前任务 |
| 学习批次 | 最多 20 条证据、合计 24000 字符，输出最多 8000 字符；来源片段必须定位完整，不能把截断当成完整事实 |
| 学习调度 | 每 owner 最多一个在途作业，每日默认最多 10 次；每次逻辑调用至多一次明确瞬态失败重试，总传输尝试最多 2 次，禁止与适配器内层重试相乘 |
| 学习超时 | 45 秒；结果未知只核对/标记，不自动重放或换 Backend；达到调用或用量额度等待后续额度或显式调整 |
| 持久化 | 每 owner 默认 10000 条活跃记忆、100MiB 内容额度；接近上限提示，停止新增而不静默删除 T0；作业输入在成功或 7 天失效后清理 |

数量、字数、延迟和用量都可测；未提供 token 使用量的 Backend 明确记为不可得，不把字数估算说成账单。旧候选不无限增长，重复证据归并，过期临时线索可清理，已形成记忆的正文删除遵循用户控制。预算调整与单条记忆审批无关。

### 7. 遗忘、隔离和隐私从第一版闭环

所有无 Session 的记忆 RPC 通过 `_current_owner_id` 解析空间；引用消息仍核验 Session 归属。后台作业冻结 owner、节点实例、证据与配置代次，回写时再次核对。缓存和前端事件按相同身份隔离，不能广播所有用户的记忆变化。

删除先在事务中停用相关记录并提升记忆代次，使检索立即排除；清理正文、旧版本内容和索引，并标记派生 T1 待重新凝练。保留不含正文的记录/来源事件 tombstone 和幂等回执，阻止旧作业、重连或来源重放复活；其保留策略不能在后台重新扫描仍存在的会话。管理界面区别“取消一次引用”“停止学习”“遗忘”，并说明原聊天、原生上下文和外部备份不会因此消失。

不保存凭据、动态 token、授权、隐藏推理；普通日志只记 ID/数量/长度/状态。需修改已有输入前缀调试打印使记忆正文不泄露；显式开启的调用证据功能遵守其原有用户开关与访问边界，并清楚包含发送上下文，不作额外无声复制。本地数据库不宣称加密保险库，OS 管理员/已发送提供方不在应用用户隔离保证内。

### 8. 用场景序列评估整体拟合效果

自动夹具关注可确定行为：同一事件去重、跨任务增强、当前指令覆盖、一次例外不毁掉其他场景、直接纠正立即生效、同源循环不增强、预算限制、遗忘后迟到结果不复活、两个用户不串记忆、native/API 实际 payload 有且仅有一个动态包。

体验验收使用三组事先写好的连续任务，分别比较无记忆和有记忆的后续任务：

- 代码走查：从“风险和影响先说”的反馈，逐步形成审查组织方式；遇到教学请求立即切换为逐步解释。
- 表格整理：积累某项业务所需字段与排序思路，迁移到相关新任务；换业务不机械复制旧列。
- PPT：积累叙事/旁白组织与视觉倾向，允许受众、页数和风格成为变量，不要求像素级复制模板。

记录重复交代次数、纠正/返工次数、错误套用、参考包开销与额外学习调用。可自动核验来源/预算/优先级，但“更顺手”仍需真实用户试用；没有这部分证据时只能报告机制通过，不能宣称已经更懂用户。测试采用合成文本、临时数据根和 fake/本地假 provider，不调用付费模型或读取生产历史。

## Risks / Trade-offs

- [首版词项检索遗漏语义近似] → 主题与任务标签提供结构召回，允许空结果，以三个场景的漏召回证据决定是否增加 embedding。
- [自动归纳误解口味] → 小幅局部候选、来源可查、明确纠正立即生效；不通过逐条审批消除所有不确定性。
- [异构 Backend 能力不齐] → 消费与归纳能力分离，归纳仅展示已验证的无工具路径，不借用主会话权限。
- [跨设备期望落差] → 明示“当前执行节点的个人记忆”，数据格式预留空间 ID，首版不伪装中心同步。
- [加入记忆使上下文更大] → 小包、少例子、空结果优先，单独计量；既有压缩问题另行处理，不靠堆历史提高命中。
- [认可已个性化答案造成偏好固化] → 记录注入来源、去同源强化，保留不同场景及新反证；只把真实新增用户选择计入证据。

## Migration Plan

1. 新增独立数据目录、版本化能力 RPC 和默认关闭的设置，不迁移或扫描旧 Session，不改旧 Prompt 正文。
2. 先完成存储/隔离/遗忘与确定性反馈，随后接入有界学习和实际发送适配；前端通过能力协商显示支持范围，旧执行端不显示伪可用入口。
3. 完成假数据回归及三类场景的试用说明后，由用户显式启用；记录节点、Backend、预算和覆盖范围。本规划不启动后台作业。
4. 回退关闭记忆引用/积累并保留新库；旧程序忽略新 Session 设置，不自动丢弃记忆库或重放作业。未知数据库版本只读/禁用，不降级覆盖。重新启用仍尊重遗忘代次与已完成事件。
