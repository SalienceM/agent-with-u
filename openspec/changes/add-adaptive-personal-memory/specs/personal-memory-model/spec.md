# Spec Delta

## Purpose

为用户建立跨会话、跨项目且可包含工作与生活主题的个人记忆，保留真实表达、认可成果与凝练经验之间的来源关系，使长期协作倾向可以积累、查阅、修正和遗忘，同时保护用户身份隔离及当前任务的自主性。

## ADDED Requirements

### Requirement: 事务树不等同于项目目录

系统 SHALL 以同一用户的事务主题树组织记忆，支持项目、工作事务和生活主题节点，以及任务类型、受众或产物等轻量关联。一个经验 SHALL 能关联多个适用主题而不复制为互不相关的多条事实；工作目录只能作为关联依据之一，不能成为唯一范围。节点重命名或移动 MUST NOT 丢失来源、身份或静默扩大全局适用性。

#### Scenario: 跨项目复用同类工作方式
- **WHEN** 同一用户在另一个项目开展代码走查，已有经验适用于代码走查这一任务类型
- **THEN** 该经验可以成为相关候选，不因目录不同被排除，项目专属事实仍受原范围约束

#### Scenario: 主题有交叉
- **WHEN** 一份汇报 PPT 同时属于某项业务和面向管理层的表达方式
- **THEN** 系统保留一个主要主题及交叉关联，用户可调整归类，不因多个关联重复累计同一证据

### Requirement: T0 T1 T2 保留各自来源

系统 SHALL 将 T0 表达为用户实际说过的想法、判断或取舍，将 T2 表达为有用户认可依据且可复用的模型成果，将 T1 表达为依据用户方向对成果凝练的思路或半模板。记录 SHALL 保存所属用户、原始事件引用、适用语境、版本及必要证据片段，区分原话、猜测和模型归纳。T1/T2 MUST NOT 自动冒充用户原话；来源类别 MUST NOT 被当作事实真伪证明或永久指令等级。

#### Scenario: 用户陈述尚未证实的判断
- **WHEN** 用户表达“我觉得可能是缓存的问题”
- **THEN** T0 保留其为当时判断及语境，不将“缓存是根因”记录为已验证事实或全局习惯

#### Scenario: 从认可成果形成思路
- **WHEN** 用户认可某个方案的结构，系统据此凝练出适用的方法
- **THEN** 成果以 T2 关联认可证据，方法以 T1 关联相关 T0/T2，后续用户亲自修正产生新的 T0 证据而非修改旧原话

### Requirement: 记忆按用户和执行节点隔离

首版系统 SHALL 在当前执行节点内按认证用户隔离存储、检索、作业和事件，支持该用户跨 Session 的个人级复用。身份 MUST 来自已验证的连接/会话归属而非客户端提供的 owner 字符串。同机其他用户、旧 local 身份和未授权 Session 的记忆 MUST NOT 被返回、注入或广播；不同执行节点的记忆空间 SHALL 明确标注而不宣称已自动同步。

#### Scenario: 共享执行节点
- **WHEN** 两个 Relay 用户在同一后端使用相似项目名或 Prompt 名
- **THEN** 各自仅能获得自己空间内的记忆与关联，猜测记录 ID 或主题名不能读取另一用户内容

#### Scenario: 切换节点或身份
- **WHEN** 用户切换执行节点或登录身份后原请求/后台归纳完成
- **THEN** 结果只属于原空间，不覆盖新空间的列表或输入上下文；界面显示当前节点的可用记忆而不回退借用其他用户/节点数据

### Requirement: 修正和遗忘具有版本与派生传播

系统 SHALL 支持修正适用范围、停用记录、删除记忆及遗忘主题，使用版本核对避免并发覆盖。遗忘 SHALL 立即停止后续检索并使依赖该证据的派生记忆失效或重新凝练，清理对应正文与检索缓存，阻止旧作业或来源重放复活已遗忘内容。用户 SHALL 获知应用记忆删除不等于删除原会话、已发送模型上下文或外部备份。

#### Scenario: 遗忘已用于 T1 的材料
- **WHEN** 用户遗忘某个 T0/T2，而 T1 引用了它
- **THEN** 该材料立即不再参与新引用，派生 T1 在以剩余合法证据重新核实前不能继续引用；迟到作业不能将旧结论写回

#### Scenario: 并发修改
- **WHEN** 两个客户端基于同一旧修订分别修改范围和删除记录
- **THEN** 系统按版本返回冲突或最新状态，不将删除静默覆盖为更新，操作结果不确定时先核对原请求

### Requirement: 最少内容保存与渐进启用

系统 SHALL 提供清楚的积累与引用开关及数据范围说明；旧用户默认不进行全历史扫描或后台模型归纳，启用后不要求逐条批准普通低强度记忆。系统 MUST NOT 将凭据、授权令牌、隐藏推理或工具许可作为记忆内容，不自动读取附件/项目文件来补全用户画像。持久化 SHALL 有事务一致性、容量边界和故障反馈，不因写入失败将会话标成失败。

#### Scenario: 首次启用
- **WHEN** 用户启用记忆并选择学习 Backend 与预算
- **THEN** 系统从后续符合条件的交互渐进积累，不追溯扫描全部历史，也不弹出逐条记忆审批队列

#### Scenario: 敏感或超量内容
- **WHEN** 候选内容包含认证信息、超出容量或存储失败
- **THEN** 系统排除敏感内容或报告记忆未保存/等待处理，不静默丢失已有 T0，不扩大读取范围，正常任务可以继续
