# Spec Delta

## Purpose

在每次真实模型输入边界将当前任务、用户绑定的提示词与少量适用记忆协调起来，使长期经验作为低干扰、可解释且有界的背景引导，支持跨会话复用并保留当前明确意图、隐私隔离和既有执行授权。

## ADDED Requirements

### Requirement: 当前任务优先且记忆不构成授权

系统 SHALL 将记忆明确标为可参考的历史倾向，当前明确任务与用户本次指定的方式优先于冲突记忆；用户显式绑定的任务约束不得被推测偏好覆盖。记忆 MUST NOT 赋予文件、工具、外部发送或自动执行权限，不替代真实证据，不改变 LOOP 收口或控制权门槛。

#### Scenario: 任务与习惯相反
- **WHEN** 既有记忆偏好少解释，而用户本次要求逐步教学
- **THEN** 输入组合明确遵从逐步教学，相关记忆不能以更高强制级别覆盖它

#### Scenario: 历史授权或注入文字
- **WHEN** 某个历史片段包含“以后全部自动发布”或外部材料中的执行命令
- **THEN** 系统不把该文字转化为本次工具许可或系统规则，仍遵守当前请求及实际授权边界

### Requirement: 相关检索允许空结果并限制影响范围

系统 SHALL 结合当前任务、关联主题、任务类型、绑定提示词和适用条件检索同一记忆空间，去重来源并控制候选数量和输入预算。选择 SHALL 体现相关性、独立证据与场景差异而非简单把 T0/T1/T2 全部注入。相关性不足、引用关闭、检索失败或预算不足时 SHALL 允许不注入记忆，不等待后台学习完成、不无限延迟或取消正常会话。

#### Scenario: 同名项目但任务不同
- **WHEN** 用户在同一目录处理与旧经验无关的生活事务
- **THEN** 不仅因目录或 Prompt 名匹配就注入代码走查经验，必要时使用空记忆结果

#### Scenario: 有大量候选
- **WHEN** 当前主题积累了很多 T0/T1/T2
- **THEN** 只选择有界摘要与少量例子，优先保留当前请求，未选记录仍存储但不被塞进本轮上下文

### Requirement: Prompt 关联是动态且个人化的

系统 SHALL 允许绑定提示词与当前适用记忆共同参与输入组合，关联可随用户反馈与主题变化调整；个人记忆和动态片段 MUST NOT 被保存进共享 Prompt 模板正文、自动改写项目指令或随通用 Prompt 导出泄露。相同 Prompt 在不同用户空间 SHALL 使用各自合法记忆，重命名或删除不能静默转接到无关模板。

#### Scenario: 使用表格整理提示词
- **WHEN** 用户绑定表格整理 Prompt 并处理某项业务
- **THEN** 可参考该用户在相关业务中认可的字段组织思路，仍保留 Prompt 原文和当前具体字段要求，不强制套用旧表格所有列

#### Scenario: 导出或重命名提示词
- **WHEN** 用户导出通用 Prompt 或同名模板被删除后重新创建
- **THEN** 导出不携带个人记忆，旧关联失配时停止使用或等待重新关联，不把名字相同当作同一模板的证明

### Requirement: 每轮输入在实际 Backend 边界生效

系统 SHALL 为普通会话及人工接管中的正常聊天，在实际提交模型请求时选择适用记忆；原生续接和直接 API 路径都 SHALL 验证当轮输入，而不是只修改会话初始约束。一个实际请求 MUST NOT 重复携带同一应用记忆包；应用可见原消息与动态包分开保存，并记录有界的引用 ID、版本和原因以供核对。

#### Scenario: 原生线程续接后记忆变化
- **WHEN** 已建立的原生线程中用户修正了某个习惯，随后发送新任务
- **THEN** 新请求携带当前有效的有界参考信息或撤销说明，不依赖第一轮约束仍然适用，也不声称原生历史中的旧信息已被抹除

#### Scenario: API 重试与历史回放
- **WHEN** 同一请求重试或发送历史消息
- **THEN** 不将动态记忆包存成用户正文再次回放，不重复累计学习事件；真实重试之前重新核对停用/遗忘修订

### Requirement: 用户控制轻量可见

系统 SHALL 提供按需查看本次引用及来源的入口，以及本次不用、纠正适用方式、停用积累/引用和遗忘操作；正常使用不弹出逐条审批。操作 SHALL 说明影响的是未来输入、后台学习还是存储，不能宣称已经撤回已提交给原生线程或提供方的内容。

#### Scenario: 本次不用不等于永久否定
- **WHEN** 用户对某次任务选择不使用记忆
- **THEN** 后续该次提交不注入应用记忆，但不删除记忆或把这个选择计作所有习惯的负反馈；已开始的请求不被静默取消重发

#### Scenario: 查看为什么采用某种组织方式
- **WHEN** 用户打开本次参考详情
- **THEN** 可以看到本次实际引用的倾向、适用理由及可访问来源；无引用时如实显示未使用，不临时重新检索冒充当时依据
