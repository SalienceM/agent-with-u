# Proposal

## Why

文件面板上传目录时重复发送内容完全相同的文件，浪费节点传输时间；现有上传不清理目标独有文件，无法让执行端目录跟随本机目录。旧清单允许漏读，不能作为删除依据。

## What Changes

- 文件面板上传前按真实 SHA-256 和字节数比对，仅传新增、变化文件，相同文件明确显示跳过。
- 增加本机目录到执行端的“镜像同步”模式，普通上传保留目标独有文件；镜像模式预览并显式确认删除范围。
- 完整扫描、冻结计划、提交前复核、分块哈希验收和结果核对保护已有数据。扫描失败和旧端能力缺失不得回落为无检查覆盖。
- 镜像排除 Git 元数据和忽略项，不调用 Git，不改变独立项目交接的新建/回传语义，也不改变逐文件差异审阅的删除限制。

## Capabilities

### New Capabilities
- `checked-directory-transfer`: 已有远端目录的增量上传与显式镜像同步。

### Modified Capabilities

无。`directory-sync-review` 仍仅做逐文件推拉，镜像是文件面板的独立操作。

## Impact

FileTreePanel、LocalFs 浏览器/桌面扫描、传输控制器与确认框、严格路由 RPC、Python 分块暂存/计划执行、隔离测试。无外部依赖，不访问生产项目或 Git 远端。
