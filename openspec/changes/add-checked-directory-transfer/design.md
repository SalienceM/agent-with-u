# Design

## Context

FileTreePanel 的 push 直接按 localManifest 逐文件调用无版本分块覆盖。普通 manifest 允许漏读并复用 mtime 缓存。directory-sync-review 有严格逐文件协议但限于文本审阅，不能承载目录删除和大文件。

## Goals / Non-Goals

**Goals:** 文件面板本机→执行端上传增量化；目录镜像明确预览和删除，复用传输中心及既有写保护。

**Non-Goals:** 跨节点项目交接依旧新建独立项目；不加入定时同步、Git push、双向自动合并或下载方向删除；不把空目录结构当文件成果。

## Decisions

- 新增独立版本化传输 RPC，严格节点路由；不扩充旧 RPC 可被旧端忽略的可选参数。后端冻结源/目标清单和计划，按用户、Session、实际工作目录隔离。
- LocalFs 新增专用完整扫描：浏览器绕过哈希缓存、目录读取错误直接失败；Tauri 独立命令拒绝漏读/链接；托管副本读取全部记录正文。仅扫描所选子树，忽略规则来自实际执行端，不复用比对筛选。
- 后端重新哈希目标，计划包含 add/update/skip/delete。正文只传 add/update，先暂存于独立临时空间；提交前前端重扫源、后端重扫目标，验证全部正文后才逐文件原子替换，最后执行删除并验证最终清单。
- 计划/暂存/原请求回执有限保存在当前服务实例内；重启后未知不重放。按工作目录互斥；现有项目写门禁在提交时重查。失败返回已完成路径，不自动回滚已写文件。
- 预览默认“上传变化”，独立“镜像同步”目录入口；使用现有 WorkflowControls，删除列表可滚动，Git 高级复制保留，但镜像始终关闭 Git 元数据参与。

## Risks / Trade-offs

- 重新哈希有磁盘成本 → 只扫所选范围，不卡 UI/服务事件循环，省去相同文件网络传输。
- 跨机器无原子快照、外部进程可能在最后复核后竞争 → 每文件提交前复核、最终核验并明确部分失败，不声称全事务隔离。
- 暂存占磁盘 → 限制清单/总字节/并发计划，完成或取消释放；进程重启不重放提交。
- 忽略项并非不存在 → 两端固定同一规则且保护 .git；目录只删确定多余普通文件，不递归删除未知内容。

## Migration Plan

前后端及 Tauri 同步升级，新协议不可用时明确提示更新，不调用旧写路径；旧下载和逐文件审阅保持原语义。
