# Spec Delta

## Purpose

让已有远端工作目录的上传只发送实际变化的文件，并允许用户通过独立的镜像模式显式清理目标多余文件；完整比对、明确范围和真实结果反馈防止漏读、过期状态与断线导致误删或误报成功。

## ADDED Requirements

### Requirement: 按内容跳过相同文件
系统 SHALL 在文件面板上传文件或目录前重新读取源和目标的内容哈希及大小；相同文件 MUST 不发送正文、不改写目标、不改变目标时间。无哈希或过期的大小/时间缓存 MUST NOT 作为相同证明。预览 SHALL 显示新增、覆盖、跳过数量及实际待传字节。

#### Scenario: 相同内容与同大小不同内容
- **WHEN** 目标已有一个完全相同文件和一个大小相同但内容不同的文件
- **THEN** 只传输后者，前者计入跳过，零字节文件也按存在性和真实哈希处理

### Requirement: 普通上传与镜像明确分开
系统 SHALL 默认保留目标独有文件；用户主动选择目录的镜像模式时，SHALL 展示具体来源、目标、范围、完整删除清单，并在确认后仅删除该范围内源缺失的普通文件。单文件上传和逐文件审阅 MUST NOT 推断删除。镜像 MUST 排除 .git、忽略项及范围外内容，不执行 Git 操作。

#### Scenario: 首次镜像删除目标多余文件
- **WHEN** 无同步基线，源目录已完整扫描且目标范围有多余文件
- **THEN** 镜像预览列出这些文件，取消不写入，确认后删除；普通上传仍保留它们

#### Scenario: 空目录与相邻目录
- **WHEN** 用户确认将真实存在的空源目录镜像到指定目标子目录
- **THEN** 仅清理该子目录范围内普通文件，保留忽略文件、Git 元数据、相邻目录和目标根目录

### Requirement: 不完整或变化中的范围拒绝提交
系统 SHALL 使用相同排除规则完整扫描所选范围；读取失败、源目录消失、链接/联接、特殊文件、预算超限或文件目录碰撞 MUST 阻止执行，不能当作源文件缺失。提交前 SHALL 复核源完整清单及目标冻结版本；任何变化要求重新预览。正文 SHALL 完整暂存并校验，上传失败 MUST NOT 继续执行删除。

#### Scenario: 预览后发生变化
- **WHEN** 源增加/删除/修改文件或目标文件发生变化
- **THEN** 旧计划被拒绝，保留目标新内容，不自动更新计划并沿用旧确认

#### Scenario: 读取失败或损坏分块
- **WHEN** 扫描失败或正文哈希与冻结源版本不同
- **THEN** 报错且不进入目标提交和删除阶段

### Requirement: 传输结果和身份保持真实
系统 SHALL 将计划和结果绑定当前用户、节点、Session/工作目录与副本身份，沿用项目写保护和已知草稿检查。旧端不支持 MUST 明确失败，不回落旧覆盖接口或其他节点。关闭预览不提交，已提交操作的反馈 SHALL 保留；断线或超时 SHALL 仅核对原操作，不自动重放，无法核对保持未知。成功 SHALL 基于真实文件验收，部分失败 SHALL 显示实际已完成和未完成情况，不承诺跨文件原子事务。

#### Scenario: 提交响应丢失
- **WHEN** 提交已经发出后连接断开
- **THEN** 使用原请求只读核对，不能发第二次写请求；结果未确认不得标成功

#### Scenario: 紧凑交互
- **WHEN** 用户在桌面或窄屏打开传输预览
- **THEN** 能看到方向、统计和可滚动删除清单、明确确认/取消按钮，支持键盘和关闭后焦点返回，不增加常驻 Session 状态或后台轮询
