# Proposal

## Why

当前文件面板把文件导航、本机副本配置、同步、常驻说明和 Git 管理叠在文件树之前；即使目录没有 Git，也显示重复状态及禁用操作，占据大量浏览空间。Engine 复用这一面板后又增加了一套快速打开入口，让信息冗余和来源不清的问题更明显。

## What Changes

- 将 Chat 与 Engine 共用的文件面板改为文件优先：默认仅显示紧凑目录身份/工具行、文件搜索和文件树，不通过缩小字体或整体缩放压缩内容。
- 目录标题保留可辨识的目录名、执行节点及必要连接状态；明确“执行端在线/离线”和“本机副本”是不同概念，完整路径按需查看。
- 本机目录绑定/更换、比对、仅不同、导入、离线空间及高级同步进入“本机副本与同步”；已有能力、绑定和显式传输语义不删除，活动比对/筛选仍有可见状态和退出入口。
- Git 有仓库时显示紧凑分支/变更摘要，按需展开暂存、提交、拉取、推送、Stash、历史等操作；非仓库不常驻“无 Git”重复说明或禁用工具栏，检测未知/失败不能被当成非仓库或干净。
- 去掉正常态“目录按需读取”等常驻说明；将传输、冲突、离线、错误和操作结果纳入紧凑可定位反馈，折叠工具不能隐藏真实问题或取消已提交操作。
- Engine 移除独立的宽幅快速打开条，Ctrl/⌘+P 与文件面板搜索复用同一入口和状态；明确执行端/本机副本来源，保留下载后优先打开副本及显式查看执行端能力。项目内容搜索与文件名搜索保持区别，纠正“项目搜索”使用文件夹图标的误导。
- 将旧“预留所有多行槽位”的稳定布局约束替换为“紧凑头部稳定、延迟回执不挤动文件树、用户显式打开工具按需展示”；保持懒加载、手动刷新、无闲置轮询和安全读写边界。

本变更不调整同步算法、Git 语义、文档保存协议、LOOP 控制权、执行节点、权限或 Backend；不自动初始化 Git、扫描比较、传输、运行模型、打包或发布。

## Capabilities

### New Capabilities

- `workspace-file-panel`: Chat/Engine 共享文件浏览器的信息层级、紧凑稳定布局、按需同步/Git 工具、来源明确的统一文件导航及异常反馈。

### Modified Capabilities

无。当前主规格未包含文件面板能力；在途 `add-session-engine-workbench` 的 `session-workbench-modes` 和 `workspace-document-editing` 仍定义模式、导航能力及文档安全，本变更补充其面板呈现契约，不重复建立编辑能力或改写该在途变更。

## Impact

- 前端：`FileTreePanel.tsx`、`WorkbenchFileCommands.tsx`、`WorkbenchChrome.tsx`、`SessionWorkbench.tsx` 及必要的共享搜索/面板状态；Sidebar 只需适配同一共享面板，不能另建一套行为。
- 回归：`file-panel-layout.spec.ts`、`session-engine-workbench.spec.ts`、`engine-actions.ts`、文件搜索与文件树相关单测；新增信息密度、键盘/触屏、来源、反馈与请求计数断言。
- 文档：实施时同步修订 `AGENTS.md` 的旧固定槽位说明与相关 Engine 验证说明，保留无轮询、来源隔离和安全保存的约束。
- 无预期后端 RPC、持久化协议或新增依赖变更；工作区既有未提交修改不纳入本变更成果。
