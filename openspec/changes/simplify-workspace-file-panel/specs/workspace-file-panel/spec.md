# Spec Delta

## Purpose

为 Chat 与 Engine 提供以浏览文件为主的共享文件面板，将目录身份、搜索、同步及 Git 操作按使用频率和真实状态分层呈现。在减少常驻信息和重复入口的同时，保持文件来源明确、异常可见、异步布局稳定与现有读写安全边界。

## ADDED Requirements

### Requirement: 默认文件面板以紧凑导航和文件树为主

系统 SHALL 在 Chat 与 Engine 使用同一文件面板信息层级，默认只保留目录身份/工具行、单一文件名搜索入口和文件树；同步配置、完整 Git 工具和说明文本 MUST NOT 默认展开或以空白多行槽位占位。系统 MUST NOT 通过缩小正文/文件名字体、整体缩放或降低触屏可操作性达成精简。

#### Scenario: 正常进入已绑定副本的非 Git 目录
- **WHEN** 用户在 Chat 或 Engine 打开在线、无活动操作且没有 Git 的工作目录，即使已有本机副本
- **THEN** 文件树之前只有紧凑身份/工具行和搜索行，不出现本机路径操作块、高级同步说明、常驻正常提示、无 Git 说明或禁用 Git 按钮栏

#### Scenario: 桌面默认布局可量化验收
- **WHEN** 桌面使用默认密度、100% 页面缩放，文件栏宽度至少 240 CSS px，且没有展开工具或活动搜索结果
- **THEN** 面板顶部到文件树滚动区顶部不超过 80 CSS px，长目录名/节点名不增加行数，字体大小与现有密度约定保持一致

### Requirement: 工作目录与副本身份可辨识

系统 SHALL 在紧凑标题中显示可辨识的工作目录名及执行节点身份，并通过可点击、键盘/触屏可用的详情展示完整路径。连接状态 SHALL 明确归属执行端；本机副本路径、权限或离线可用性 MUST NOT 被标为执行端在线状态，也不能被展示为另一个执行工作目录。

#### Scenario: 远端工作目录有本机副本
- **WHEN** 用户查看远端工作目录并展开身份或副本详情
- **THEN** 工作目录、执行节点、执行端连接状态与本机副本实际位置分别标明，不再把“执行端在线”放在无归属说明的本机目录状态旁

#### Scenario: 执行端离线且副本仍可访问
- **WHEN** 远端连接中断但已有可读取副本
- **THEN** 面板直接显示执行端离线，并保留明确的本机副本入口；副本可用不等于执行端已连接、文件一致或远端已保存

### Requirement: 本机副本和同步工具按需展开

系统 SHALL 通过“本机副本与同步”提供原有适用的绑定/更换、比对、仅不同、导入、离线空间和高级同步能力，保留操作前置、Git 元数据默认排除及显式传输边界。打开或关闭该工具 MUST NOT 自动比较内容、传输、修改绑定或取消已提交任务；已开启筛选和已知冲突 SHALL 在工具关闭后仍可辨识。

#### Scenario: 打开配置但未选择操作
- **WHEN** 用户打开并关闭“本机副本与同步”，没有点击具体操作
- **THEN** 可查看已有副本状态及适用操作，未发生新的完整扫描、比对、上传、下载、目录更换或 Git 写入

#### Scenario: 开启仅不同后收起工具
- **WHEN** 用户完成显式比对并启用“仅不同”，随后关闭工具
- **THEN** 文件树仍显示活动筛选状态和直接清除入口；筛选后没有命中不显示为真实空目录，未比对不能显示为“已同步”或“零差异”结论

#### Scenario: 高级选项及既有副本保留
- **WHEN** 用户在升级后展开同步工具并选择更换副本或查看高级同步设置
- **THEN** 既有 Session 绑定及已下载文件仍在，适用的设备目录/托管离线空间入口仍可访问，包含 Git 元数据仍是独立显式选择

### Requirement: Git 状态与操作按仓库能力分层

系统 SHALL 只在检测到仓库时展示紧凑分支和已知变更摘要，完整 Git 操作由该入口按需展开。非仓库状态 MUST NOT 常驻重复“无 Git”说明或禁用操作栏；检测中、失败和非仓库 SHALL 区分，首次成功状态返回前 MUST NOT 显示工作区干净。展开工具 SHALL 保留原暂存、提交、拉取、推送、Stash 和历史能力及其前置限制。

#### Scenario: 检测确认非仓库
- **WHEN** Git 检测成功返回非仓库
- **THEN** 面板不显示分支摘要及完整 Git 操作栏，用户可在按需详情得知未启用 Git，系统不自动初始化仓库

#### Scenario: 状态尚未返回或刷新失败
- **WHEN** Git 检测/状态请求延迟，或已知仓库的刷新失败
- **THEN** 目录浏览与刷新保持可用；Git 状态为读取中/未确认或明确失败，不变成“干净”“无 Git”，旧摘要存在时标识其未更新且危险操作维持原门槛

#### Scenario: 用户展开并执行 Git 操作
- **WHEN** 用户从分支/变更摘要进入 Git 工具并显式选择一项操作
- **THEN** 原适用能力可访问且遵循原确认与禁用条件，单纯展开不会自动暂存、提交、拉取、推送或恢复 Stash，操作反馈在工具关闭后仍可查到

### Requirement: 文件名搜索与快速打开共用入口

系统 SHALL 在 Engine 将 Ctrl/⌘+P 指向文件面板的同一文件名搜索状态、结果和打开路径，而不是保留第二个宽幅快速打开条或启动另一套文件名查询。查询 SHALL 支持未展开目录、结果有界、加载/空结果/错误/截断反馈、键盘选择及退出；查询变更或作用域失效后，旧结果 MUST NOT 打开文件或覆盖当前结果。

#### Scenario: 面板输入与快捷键交替使用
- **WHEN** 用户已在面板输入查询，又在 Engine 文档区按 Ctrl/⌘+P
- **THEN** 同一个查询获得焦点并保留结果，当前查询不重复请求，中间不再出现独立快速打开栏

#### Scenario: 窄屏或目录区域隐藏
- **WHEN** 用户在 Engine 窄屏文档区域按 Ctrl/⌘+P
- **THEN** 系统显示文件导航区域并聚焦同一搜索；退出搜索或打开结果后可回到原文档操作上下文，不创建第二个文件面板、文档或 Session

#### Scenario: 查询变化时旧请求迟到
- **WHEN** 用户更换关键词、清空搜索、切换 Session/节点/工作目录或隐藏所属视图，之前的结果随后到达
- **THEN** 旧结果不覆盖当前列表或触发文件打开，取消/退出不会清除已有文件草稿，隐藏视图不响应新的全局快捷键

### Requirement: 搜索合并保持真实来源和既有打开语义

系统 SHALL 明确标注执行端与本机副本来源，不把统一入口等同于统一存储。下载后的同路径文件 SHALL 保留优先打开独立本机副本的既有行为，并提供显式查看执行端的可访问动作；执行端检索失败时可保留真实副本结果，但 SHALL 说明执行端结果未取得，MUST NOT 默默换节点、假称完整搜索成功或把副本写入当成远端保存。

#### Scenario: 同路径两端均存在
- **WHEN** 文件查询命中执行端文件及已下载的同路径本机副本
- **THEN** 结果清楚标识两种来源，默认打开副本并显示副本身份；显式查看执行端打开独立执行端来源，不共享错误的保存目标或草稿

#### Scenario: 执行端搜索失败但有副本命中
- **WHEN** 当前执行端搜索失败且本机副本有匹配文件
- **THEN** 副本结果继续可打开，失败原因和执行端结果不可用可见；不以副本结果充当远端完整结果，也不回退其他节点

### Requirement: 项目内容搜索和空态入口语义准确

系统 SHALL 保留 Engine 项目内容搜索、Git 只读差异、跳转行及文件内查找/替换等适用操作，同时明确区分文件名搜索与项目内容搜索。项目内容搜索 SHALL 使用搜索语义的图标、名称和快捷键提示，不再使用暗示打开目录的文件夹图标。桌面已显示文件树时，文档空态 MUST NOT 提供无实际效果的重复“打开文件目录”主按钮。

#### Scenario: 搜索项目内容
- **WHEN** 用户点击“搜索项目内容”或按 Ctrl/⌘+Shift+F
- **THEN** 进入标明执行端范围的内容搜索而非文件选择或目录切换，保留结果预算、取消及行列定位；不把文件名查询内容暗中解释为另一种搜索

#### Scenario: 空文档且文件目录已可见
- **WHEN** Engine 桌面中间尚未打开文件而左侧文件树已显示
- **THEN** 空态提供简短的点击文件/快捷键引导，不显示重复打开目录按钮；目录隐藏时才提供明确的“显示文件目录”动作

### Requirement: 精简不能隐藏反馈或引入布局抖动

系统 SHALL 将传输进度、操作结果、离线、冲突及错误保持为直接可见、可定位的紧凑反馈，而不是只放进关闭的工具或悬停提示。正常静止状态不显示说明条；首次及后续异步元数据返回 MUST NOT 插入或删除文件树上方的多行区域。关闭工具不改变后台任务状态，错误 MUST NOT 被误报为目录为空、操作完成或不存在问题。

#### Scenario: 元数据延迟返回
- **WHEN** 目录、本机副本或 Git 状态以不同顺序完成或失败，用户没有展开工具
- **THEN** 文件树滚动区顶部位置保持稳定，已有目录、选择与滚动不被重置，进度/错误更新紧凑反馈而非挤出新的顶部说明行

#### Scenario: 传输期间收起工具且随后失败
- **WHEN** 用户显式提交传输后关闭同步工具，任务继续并返回失败
- **THEN** 可见的进度转为明确失败，保留查看详情和适用取消/处理入口；关闭、超时或仅接受请求均不被当成任务已成功

#### Scenario: 多种问题同时存在
- **WHEN** 同一文件面板同时存在目录读取失败、传输错误或比对冲突
- **THEN** 反馈显示最高优先级问题及其余问题数量，详情可分别定位；某个成功结果不清除其他未解决问题

### Requirement: 渐进工具保持可访问和作用域隔离

系统 SHALL 提供键盘、指针及触屏均可操作的刷新、更多、搜索及展开工具入口，不依赖仅悬停显示的按钮。展开层 SHALL 支持明确关闭、Escape、合理焦点管理及回焦，窄屏不超出视口；工具草稿和迟到结果 SHALL 绑定所属用户、执行节点、Session 和工作目录，切换时不能串用。

#### Scenario: 触屏和键盘展开工具
- **WHEN** 用户在 390px 触屏视口点击更多，或用键盘展开同步/Git 工具并退出
- **THEN** 无需 hover 即能完成操作，面板不造成整页横向滚动，Escape/关闭后焦点回到有效触发点或当前工作区，文件浏览与文档草稿保持

#### Scenario: 工具打开时切换作用域
- **WHEN** 用户切换 Session/执行节点/工作目录，旧工具仍有未提交输入或迟到回执
- **THEN** 旧工具不悬浮在新工作区上，草稿/回执留在原作用域，不改变新目录绑定、查询、Git 状态或文件保存目标

### Requirement: 界面整理不增加后台工作或改变写入权限

系统 SHALL 保持懒加载、显式刷新、在途读取合并和无闲置轮询。打开面板或工具 MUST NOT 自动比较完整文件内容、上传下载、初始化/写 Git、启动模型/终端/LSP、切换 LOOP 控制权或提升权限；现有安全文档、草稿恢复、显式传输和节点路由边界保持不变。

#### Scenario: 闲置与重复开关工具
- **WHEN** 面板闲置、连接状态变化，或用户重复开关同步/Git 工具且没有主动刷新或执行动作
- **THEN** 不发生周期读取、额外全目录/内容扫描、重复在途读取或写请求；首次必要的按需详情读取有界，既有缓存和展开层级保持

#### Scenario: 从统一入口打开文件
- **WHEN** 用户从搜索、文件树或诊断链接打开某个文件
- **THEN** 原有来源隔离、只读/编辑资格、完整性和版本校验保存、未保存关闭保护与 LOOP 权限仍生效；界面精简没有新增自动上传或弱校验保存路径
