# Design

## Context

动机见 `proposal.md`。本设计基于当前实现及回归夹具，而不是新建文件浏览器：

- `FileTreePanel.tsx` 同时拥有目录缓存、副本绑定/比对、文件查询、Git 和文档预览/编辑状态。顶部无条件渲染状态槽及两行 Git 槽；远端还渲染副本身份、动作和高级同步。`gitActionDisabled` 只禁用按钮，不移除无用区域。
- `panelStatus` 正常态是“目录按需读取，可手动刷新”；副本行的 `sessionOnline` 实际描述执行端。头部的分支徽标和 Git 区域在非仓库时重复说明。
- 左侧搜索使用 `api.searchFiles` 加本机 manifest 的有界排序/合并，支持未展开目录；`WorkbenchFileCommands.tsx` 独立使用 `WorkspaceDocuments.search('files', ...)` 实现另一套快速打开。内容搜索和 Git 只读比较也在后者中，不能随快速打开一并删掉。
- Engine 通过 `documentHost` 将已有文档面放入中央区域；`SessionWorkbench` 管理窄屏区域。左树、原 ChatPane、文档状态及其来源/权限保护都已有生命周期，不能为视觉整理重挂载。
- `AGENTS.md` 和 `file-panel-layout.spec.ts` 曾要求七个固定区域及非 Git 时保留工具栏，以避免回执到来后布局跳动。这是本次必须显式替换的呈现约束，不是继续维护的验收目标；其“目录先可用、失败保留已有树、无闲置轮询”目标继续保留。
- 在途 `add-session-engine-workbench` 的 `session-workbench-modes`、`workspace-document-editing` 已定义模式、来源和文档安全。新 `workspace-file-panel` 只补充导航表面契约，不重写上述能力；其他在途修改和人工验收任务不归入本次完成度。

## Goals / Non-Goals

**Goals:**

- 同一共享面板在两种展示模式中采用相同信息层级，借助按需工具保留已有能力。
- 将异步稳定性从“保留多行占位”改为“固定紧凑几何与独立反馈”，给文件树让出空间。
- 合并文件名查询的交互所有权，同时保留不同来源、内容搜索及文件打开的真实语义。
- 将变更限制在前端呈现、共享状态、测试及对应文档，不触及执行授权。

**Non-Goals:**

- 不更换编辑器、搜索引擎、同步算法或 Git 后端，不引入 VS Code 扩展体系。
- 不为简化 UI 删除副本管理、显式传输、Stash/历史、草稿恢复或已有写保护。
- 不迁移 Session、目录绑定、文档草稿和 LOOP 状态，不自动扫描比较或新增后台轮询。

## Decisions

### 1. 紧凑两行头部，详细工具脱离常驻布局

`FileTreePanel` 保持现有数据所有权，提取必要的呈现组件与纯状态投影，不复制第二个面板。首行是可点击目录名/身份、刷新、更多；次行是文件名搜索，尾部使用有界的上下文摘要位。桌面默认字号、栏宽至少 240px 时，两行总高度连同边距/边框不超过 80px。

目录身份弹层展示完整工作路径、节点与明确的“执行端在线/离线”；本机副本身份在同步工具单独展示。目录和节点标签可截断，但详情不依赖浏览器 title，键盘/触屏均可打开。摘要位为已知 Git 分支/变更或活动筛选提供短标签，长分支名只影响截断，不换行。非仓库不显示 Git 摘要；检测中仅有紧凑读取指示，错误进入反馈。有限宽度下保留最小分支标识与更多入口，完整名称/计数点击可读，不通过缩小字体塞下全部信息。

刷新和更多始终可见，全部折叠、草稿恢复等低频功能放进更多。同步工具从更多里的“本机副本与同步”进入；有仓库时 Git 摘要直接打开工具，更多保留同等键盘路径。弹层采用现有 `WorkbenchChrome`/Session 可见性基础设施，桌面有界、窄屏适配视口，只有用户主动展开才显示完整工具；不能额外永久显示一排分类标签或折叠标题。

**替代方案：** 只在 Engine 隐藏几行会让 Chat 保持同样问题；继续缩小间距仍不能消除无 Git 的空操作；全部塞进一个无标识菜单会损失来源和活动状态。采用共享两行头部兼顾浏览空间和必要可发现性。

### 2. 同步与 Git 是按需工具，不是另一份状态源

工具复用既有回调、请求和缓存。同步工具保留副本绑定/更换、比对、仅不同、导入/离线空间的能力条件，以及高级 Git 元数据选项；不触发打开即比对。已启用“仅不同”在搜索行尾显示可清除筛选标签；不能将 `differentPaths.size === 0` 当作未比对时的一致结论。比对未发生、正在比对、已有结果及结果错误明确区分，文件行状态仍沿用原证据语义。

Git 工具使用既有 detect/status 结果。已检测仓库才显示分支摘要，状态未确认不显示干净；非仓库原因仅在更多/身份详情中可见。暂存、提交、拉取、推送、Stash、历史保留原前置、确认、回执及刷新行为；首次打开确有需要的 Stash/历史详情可按需读取，但重复开关复用有效缓存并合并在途请求，不能因为工具重新挂载触发重复查询。

工具草稿留在面板所属作用域中，关闭不丢提交说明，也不取消已提交动作；身份改变关闭可见层，旧数据不安装到新作用域。不同 Session 的草稿、结果和连接状态不能共用。

**替代方案：** 新建工具控制器同时重写传输/Git 生命周期会扩大回归面；本次只整理呈现与必要的读取缓存，沿用原操作边界。

### 3. 文件名搜索单一所有者，内容搜索仍独立

保留文件面板现有文件名搜索和打开逻辑作为唯一所有者，封装可调用的聚焦/显示入口。`WorkbenchFileCommands` 去除第二份文件名搜索状态及宽幅按钮；其 Ctrl/⌘+P 事件改为委托面板，避免双监听、双请求。`SessionWorkbench` 负责在窄屏/目录隐藏时先显示文件区域，再聚焦同一输入；记录原区域/焦点，Escape 退出或打开结果时恢复合理文档上下文。可见/聚焦检查限定当前 Session，弹层和编辑器原有快捷键优先关系保持。

文件名查询保持现有防抖、有界结果、未展开目录检索、忽略及 Git 元数据开关语义。持续输入、取消/清空、隐藏和作用域变化废弃旧 generation；后端支持取消时沿用取消，否则只丢弃迟到结果，不伪称请求已在执行端停止。再次 Ctrl+P 只聚焦，不重发相同查询。搜索逻辑如需提取为 hook，只提取所有者，不把两个实现都留着。

命中数据继续携带执行端/副本可用信息，结果与打开后的文件标签明确实际来源。同路径两端命中合并为一条具有两种来源标识的结果：默认沿用下载后副本优先，显式“查看执行端”打开独立执行端文档；仅一端可用不伪装另一端存在。执行端失败可保留副本结果，但同时显示不完整范围，不回退节点。新增入口不能绕过 `openPreview`/文档导航的版本、草稿及只读检查。

内容搜索继续使用 `WorkspaceDocuments.search('content', ...)` 及既有预算/取消。`WorkbenchFileCommands` 保留紧凑文档命令区，内容搜索采用搜索语义图标和“搜索项目内容”可访问名称，快捷键不变；Git 只读差异与编辑导航保留，不再把文件夹图标用于内容搜索。文件名和内容查询分开标识，不悄悄重解释输入。

Engine 文档空态桌面仅提示点击左侧文件或 Ctrl+P；目录区域隐藏时才显示“显示文件目录”，避免已显示目录时出现无效果按钮。

**替代方案：** 直接删左侧搜索、全用中央搜索会丢失 Chat 导航和本机副本结果；保留两套输入只改名字仍有重复且来源不同。复用已有文件面板语义能降低行为变化。

### 4. 反馈位于树底部的紧凑区域，不在树上方堆消息

移除正常态说明槽。将已有 directory/Git 错误、比对冲突、传输、离线和操作回执投影为有界、带来源的反馈列表，不新增定时查询。需要处理时，树底部出现一行紧凑反馈，可展开完整详情；无问题/活动/未读结果时不渲染。底部行可以减少树的底部可见高度，但不改变树顶部；维持滚动和选择，不能遮住末行。目录首次加载用树内骨架，失败保留上次目录，不以空列表覆盖。

优先级采用错误/冲突 > 执行端离线 > 活动操作 > 已完成回执；同时显示其余项数量，传输仍有短进度标识及适用取消入口。解决一个问题只清除该来源项，不清除其他错误。错误和未解决冲突不会自动消失；成功回执可关闭，关闭是清理反馈而非撤销或证明其他状态。详情显示具体目标、方向及结果，不把“已提交”当“完成”。技术说明移到帮助或工具内，不长期占位。

**替代方案：** 所有状态隐藏到菜单会损失可观察性；在顶部按错误/进度不断插行重新制造抖动；固定预留旧多行则保留冗余。底部按需反馈同时保留直接可见与顶部稳定。

### 5. 明确替换旧布局验收，保留性能和安全验收

`file-panel-layout.spec.ts` 当前断言七块区域首帧占位、非 Git 仍有两行按钮，实施时替换为两行高度预算、树顶稳定及工具展开/关闭行为。不能为了通过旧几何断言留下隐形空行。保留延迟 Git 不阻塞目录、失败不清树、请求计数、仅刷新展开层、传输后不全扫描及卸载后不启动读取的断言。

扩展 `session-engine-workbench.spec.ts` 与 `engine-actions.ts` 验证快捷键只聚焦一次、默认/显式来源、窄屏回焦、中央宽幅快速打开消失及空态语义。相关纯状态/搜索合并逻辑写入 home 单测；测试仍采用隔离浏览器、fake RPC 和虚拟传输，禁止用户目录写入、真实 Git 变更、模型、LSP/终端及发布调用。

**替代方案：** 仅截图验证不能防止节点串用或请求增加；仅保留逻辑测试又无法量化“仍然啰嗦”。采用布局、键盘、来源、请求计数和既有文档回归联合验收。

## Risks / Trade-offs

- [高级操作发现成本上升] → 保留明确“本机副本与同步”名称，Git 摘要直达；活动筛选、冲突和操作进度始终可见，不新增常驻大面板。
- [紧凑头部在 240px 下拥挤] → 标题/分支截断、有界摘要位及按需详情；测试长路径、长节点和长分支，窄屏使用原触屏密度，不降字号。
- [弹层挤压或遮挡文档、焦点丢失] → 使用现有可见性/定位设施，明确 Escape、关闭回焦与视口限制；模式切换保留文档实例。
- [统一搜索误改来源] → 固定既有副本优先，显式执行端路径独立测试；失败不跨节点、不改变保存后端。
- [重挂载工具导致多读] → 回调/状态在原所有者，详情按身份缓存并合并在途；空闲、反复开关、离线和迟到回执增加计数断言。
- [旧文件/Engine 工作与本次同时修改] → 实施前核对当时差异，只变更面板相关区域，不覆盖已有未提交工作，不借此宣布旧变更剩余人工任务完成。

## Migration Plan

1. 先新增紧凑状态投影和交互测试，再调整共享面板呈现；原副本配置、文档状态及操作句柄不迁移。
2. 将 Engine 快速打开委托至同一文件面板，替换误导图标及空态入口，保留文档命令与内容搜索。
3. 替换旧多行占位断言并同步 `AGENTS.md` 的布局段落、`docs/engine-workbench-verification.md` 中相关验收说明；不改写安全/路由契约。
4. 运行限定回归、TypeScript 与生产前端构建，检查桌面/390px、深浅主题、无 Git/有 Git/异常/传输截图。真实设备目录授权对话框仅在隔离目录进行人工验收，不以浏览器夹具代称。
5. 回滚仅回退本变更的呈现/搜索委托代码及对应测试文档，无数据迁移，无副本/草稿/仓库恢复动作，也不回滚其他未提交内容。
