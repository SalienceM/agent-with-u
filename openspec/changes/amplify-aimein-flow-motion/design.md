# Design

## Context

现有 R3F 场景使用 demand 渲染，子目标从完整详情投影，整体覆盖已有三方报告门槛。LOOP 推送携带摘要和步骤状态，详情懒加载；步骤没有稳定的 targetId 关联。保留现有目标瓶、观察区、静态场景和执行协议。

## Goals / Non-Goals

**Goals:** 把运行状态与有限阶段事件分开；更强烈的方向电流、更密集的方块队列和可解释的保存产出堆积，且保持历史与降级可靠。

**Non-Goals:** 不模拟生产执行、不从活动时间生成完成度、不修改模型评审/步骤调度、不新增任务和目标的猜测关联、不引入后处理依赖。

## Decisions

1. 纯函数投影身份（尝试、阶段）、运行资格、步骤保存输出、独立席位状态和已核实覆盖。比较同一最新尝试的已加载快照，仅把语义变化转成有界事件；初次加载与历史跳转建立基线。
2. 新动画层使用地图航线式细弧线、共享实例化小方块、低强度光晕、细长拖尾和轻微到达光环。保留快速传递的节奏，但不以粗光柱和大面积曝光强调动作，遵循用户后续提出的克制航线风格。每帧只修改 Three 对象，避免 React 状态刷新；每条路径粒子上限固定，轻量模式减半。相较全屏 bloom，局部光晕成本较可控且不洗白场景。
3. 持续搬运只在真正 running、当前记录未完成、所选为最新尝试且场景可见时运行。暂停停止持续队列；隐藏清空瞬态，回到可见不补播。历史没有持续搬运；有限的镜头、状态过渡结束后停止绘制，reduced-motion 直接显示状态。
4. 已保存步骤输出形成最多 24 个展示方块，计数显示实际总量；这些是实施产出不是目标验收。三方报告仍是瓶内覆盖唯一依据。无步骤/目标关联时搬运只在工坊、基础设施和成果区之间示意。
5. 发光路径映射现有 AimeinAnchor，点击或 HTML 等价按钮进入现有证据和意见流程，不新增 RPC。复用现有拆分聚合视觉回放，和真实状态转换分开。

## Risks / Trade-offs

- 高密度动态在软件渲染下较重 → 有界实例数、低 DPR、轻量档、按需停帧；实际记录渲染器和限制，不承诺硬件帧率。
- 动画误导验收 → 明示活动/已保存产出/共同核实三种语义；无输出不堆积，未知报告不入瓶。
- 延迟详情或历史切换误触发 → 只有同身份已加载快照比较；隐藏时更新基线并清空事件。
- 路径遮挡对象 → 细底线、透明光晕、局部高亮；等价按钮保持可达。

## Migration Plan

仅前端与说明更新，无存储迁移。静态视图和减少动态为运行时降级入口。验证使用隔离 QA 后端的状态序列，录制真实页面，不调用生产模型。
