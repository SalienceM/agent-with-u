# Proposal

## Why

用户要求验证真实推进链路。隔离实测发现：目标包含「无需历史存档基线、外部工具或 OpenSpec 来源」时，仅因关键字命中便启动来源发现，在空项目中被错误阻塞。之前的浏览器状态夹具没有覆盖真实请求与后台执行。

## What Changes

- 未绑定来源时，明确否定使用 OpenSpec 的目标不触发原生 OpenSpec 驱动；后续明确恢复使用仍生效，已有绑定保持权威。
- 补充意图判定与 AIMEIN 生命周期回归。
- 未核实的隔离前置声明允许空证据列表；实际测试仍须独立准备步骤的完整证据回执。澄清没有真实基线要求时 baselineBasis 应为空。
- 自动 Qwen 调用将运行配置写入调用专用临时配置，不修改被评审工作区，保持成果指纹严格核对。
- 使用当前配置的三个真实模型，在独立项目从真实按钮跑目标拆分、实施、评审及阶段推进；记录实际结果与阻塞，不将状态注入或模型自述作为成功依据。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `loop-openspec-task-reconciliation`：补充明确排除来源的识别，保持绑定与安全边界不变。
- `loop-execution-environment`：区分规划声明与执行放行证据，消除先有证据才能准备证据的循环依赖。

## Impact

影响 `loop_openspec.requested`、相关回归及 AIMEIN 验证文档。真实测试使用独立数据目录和工作目录，凭据仅在临时运行目录使用，不进入交付记录。若后续实测发现其他推进问题，先更新本变更再修复。
