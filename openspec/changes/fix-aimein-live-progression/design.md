# Design

## Context

`requested` 当前对完整用户意图做关键字命中，导致否定说明也触发来源发现。已有绑定及来源保护独立存在，不得通过自然语言否定解除。

## Goals / Non-Goals

**Goals:** 识别明确的中英文不用/无需使用语句及后续恢复；补齐真实链路证据。

**Non-Goals:** 不建立通用自然语言分类器，不自动解绑，不解除权限或未知退出，不因评审不通过篡改目标。

## Decisions

- 已绑定立即保持 OpenSpec。未绑定时按原始想法、当前目标、较新补充顺序识别来源提及，明确排除覆盖先前提及，明确恢复覆盖先前排除。
- 采用有界、可测试的明确表达匹配；保留普通提及原有语义。否定跳过不能误当作排除，否定其他动作不能覆盖后来的「使用 OpenSpec」。
- 在现有驱动测试中验证正反意图与已绑定来源，在 AIMEIN 生命周期中验证否定来源时走通用 prepare/execute。无真实模型的自动化回归与实际模型运行记录分别报告。
- 实测又发现 `freeze_plan` 对未核实前置使用了实际证据的非空校验，模型连续三次拒绝伪造证据而无法进入准备。仅声明允许显式空数组（缺失、错误类型、超限仍拒绝），状态保持 unverified；`isolation_receipts` 的非空引用、文件哈希、实际路径、身份和先后步骤校验全部保留。
- 提示明确声明引用不是准备完成证据；无真实基线要求时 `baselineBasis` 必须为空字符串，不能写“无需基线”的说明，否则会错误建立真实基线门槛。需要基线的既有计划及回执要求不变。
- 真实执行又发现准备回执把 `method` 写成过程摘要，而校验器要求与冻结 `verificationMethod` 相同。提示明确关联字段须原样复制，实际过程放证据文件；不放宽配置/机制匹配校验。
- 实测中通用 planner 又将已冻结的 Sprint 缩成单个原子任务，误把执行前依赖门禁理解为禁止规划后续步骤。澄清可编排顺序依赖，仍在实际调用前核验前步证据；AIMEIN 明确当前完整验收条件就是本次增量范围，避免重复缩小后立即送审。
- 代码核对发现 Qwen 在每次调用前写项目 `.qwen/settings.json`，会改变成果指纹。自动调用传入 isolated_context，使用 CLI 支持的 `QWEN_CODE_SYSTEM_SETTINGS_PATH` 指向临时设置，保留原系统设置及 defaults 路径，只覆盖现有 Backend 路由/令牌策略。普通聊天保持既有行为；运行结束清理临时配置。读取失败不得静默丢弃系统配置。测试证明产品文件与指纹不变，仍检测真实产品修改。
- 实测使用已交付冻结后端、构建后前端、真实 WebSocket 与独立临时目录；通过按钮启动，核对阶段文件、实际代码/测试输出与各路模型记录。失败如实保留，修复后补验。

## Risks / Trade-offs

- 自然语言多义 → 仅匹配明确排除，未匹配的普通提及维持原语义；绑定始终优先。
- 真实模型成本与耗时 → 使用小型标准库 CLI、有限尝试和明确人工推进，不启用 Auto，不读取用户工程。
- 外部模型或执行环境失败 → 保留具体失败与阶段边界，不把模拟评审作为真实成功。
