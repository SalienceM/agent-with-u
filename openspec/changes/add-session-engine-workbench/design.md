# Design

## Context

动机与功能范围见 `proposal.md`。本设计基于当前代码检查，不将拟新增能力描述成已存在：

- `App.tsx` 与 `utils/workbench.ts` 已有标签、分屏和会话保活，但唯一渲染实例只在一个页面内成立，存储还没有多窗口归属协议。`useStreamState.ts` 的累积器是窗口内模块状态，不能假设新窗口天然共享流。
- `detachedWindow.ts` 已支持浏览器/Tauri 工具窗口，但桌面创建成功只代表窗口存在。`main.tsx` 尚无独立会话入口；`ChatInput` 的草稿/附件需要单独纳入交接。
- `FileTreePanel.tsx` 同时管理目录、预览弹窗、渲染器和编辑；文本预览在约 200,000 字符处截断。当前编辑入口没有完整性门槛，保存缺少磁盘版本比较，迟到回执可能清掉新编辑。`CodeEditor.tsx` 已有 CodeMirror 6 基础编辑能力，不是从零做编辑器，但 `.vue` 仍按 HTML 处理且没有工程语义服务。
- `BridgeWS` 的同步读返回 SHA256，现有 `syncWriteFile` 直接写目标文件。普通传输接口与安全编辑的契约不同，不以此次改造悄悄改变所有同步调用。
- 项目尚无集成 PTY/LSP 基础设施。Tauri 主窗口关闭默认隐藏到托盘，sidecar 属于应用；现有 capability 主要授权主窗口，新会话窗口需要最小授权。
- LOOP 已有权威控制提交、活动保留和未确认结果核对。`loop-execution-environment` 不接受人工命令成功替代原生调用证据。当前工作区已有其他修复，不能在本变更内覆盖或归功为新实现。

## Goals / Non-Goals

**Goals:**

- 将展示布局、窗口驻留、文档内容和执行活动拆开，使窗口移动不成为业务重启。
- 先建立可测试的身份、版本及生命周期边界，再接 UI 和四类工程能力；所有写入口共用安全编辑和 LOOP 准入。
- Web 与 Tauri 共享工作台核心，保留平台适配层及准确的能力降级。
- 使用真实隔离工程验证语义能力和终端，而不是仅测试按钮存在或模拟响应。

**Non-Goals:**

- 不重写模型 Backend、引入第二套执行端或复制 Session；不以窗口可见性判断模型是否运行。
- 不实现完整 IDE 扩展主机、调试协议、多用户实时协同或跨文件磁盘事务。
- 不把终端/LSP 包装成模型沙箱，不承诺任意外部编辑器与文件系统间存在全局原子比较交换。
- 不由打开 Engine 触发项目构建、依赖下载、全局环境修改或发布。

## Decisions

### 1. 会话、工作台和活动采用不同身份与存储层

在 Session 增加兼容字段 `view_mode: chat | engine`，缺省为 Chat；字段缺失的更新保留已有值。它不复用 `session_type`、人工控制字段或 Backend 配置。旧执行端缺少能力时，客户端可明确标示模式仅本地记忆，不能伪报服务端持久化成功。

新增共享 `SessionWorkbench` 壳层：Chat 路由保持原状；Engine 组合可调整的目录区、文档区、既有 ChatPane/LoopPanel 和底部终端。文件打开、诊断跳转和命令入口经过统一工作台接口，而不是各自唤起弹窗。

按用户 2026-10-09 的 UX 修订，模式入口位于 Session 右键菜单。Chat 移除重复会话工具栏及占位，将模式/窗口/恢复功能集中在上方 Session Tab 右键菜单；外部标签提供定位及回焦锚点，支持 Shift+F10/Escape，菜单不新增常驻按钮。异常/进行中/待恢复交接仍独立显示。Engine 当前会话标题保留可键盘操作的菜单，并隐藏全局会话侧栏与整个工作总览/Session 标签条，只显示当前 Session 的单工程面板；其他会话、总览、分屏及扩展标签导航不得绕过该边界。Chat 原标签/分屏状态只隐藏而不销毁，退回 Chat 后恢复；该约束是视图隔离，不是新的执行或文件授权。Engine 目录根容器须填满可调整的栏宽，不能只调整外框。

状态分层：

| 层 | 身份/寿命 | 内容 |
| --- | --- | --- |
| Session 元数据 | 用户 / 执行节点 / Session | 展示模式，既有执行类型与控制字段仍独立 |
| 客户端工作台 | 客户端实例 / 窗口 / Session / 修订 | 标签归属、栏宽、活动文件、折叠状态等导航信息 |
| 文档 | 用户 / 节点 / 工作区修订 / 规范化路径 / 来源 | 磁盘基线、缓冲区版本、编码、草稿和编辑状态 |
| 执行资源 | 执行端实例 / 所属用户与 Session / 资源代次 | 终端、语言服务、在途保存及可核对回执 |

工作目录或身份改变时创建新文档命名空间，旧草稿保留恢复入口而不重新绑定新目录。Engine 初始宽度建议目录 240px、对话 360px，其余给文档；空间不足时改为区域切换，不强制系统全屏。具体尺寸为可调默认值，不构成固定分辨率要求。

**理由及替代方案：** 复用现有 Chat 内容组件可降低回归；仅给现有分屏网格再加一种排列，无法解决文件生命周期。把模式塞进 `session_type` 会把布局选择错误地变成运行类型转换。

### 2. 窗口移动是带确认和隔离代次的交接

建立客户端实例级工作台归属登记，通过已认证的执行端连接协调同一实例的主/子窗口；BroadcastChannel/Tauri 事件只负责唤醒与有界状态传递，不单独承担排他保证。归属记录使用用户、节点、Session、客户端实例、窗口、操作 ID、generation 和修订。相关交互请求携带当前归属代次并在入口核验，避免两个窗口在确认丢失时同时发送、保存或输入终端；该登记不取代 Session 控制权，更不允许抢占其他用户。

交接顺序为：

`源可用 → 准备目标并短暂冻结变更 → 传递状态 → 目标核验并 ACK → 提交新归属 → 撤下源视图`

流式接收持续进行。源冻结的是新的发送、保存和终端输入，不中断模型任务；在途操作以原请求身份核对。目标 ACK 包含身份、交接代次和已接收状态版本，不以 `window.open` 或 `tauri://created` 作为成功。提交前失败可返回源；提交结果未知则只核对原交接，不能开启两个可写实例。断线、窗口心跳缺失或过期只允许发起核对，不证明后台进程退出。恢复归属时提升代次，旧窗口后续写请求被拒绝。

交接包包含文本草稿、附件引用/必要的有界临时数据、文档状态与可序列化撤销历史、选择/光标、滚动和运行引用。流式恢复使用单调事件位置与有界快照衔接，不能重复追加；若现有推送缺少序列，在桥接推送中兼容增加序列/恢复信息，不扩大正常历史镜像上限。权威待确认事项重新读取；未提交的一次性委托开关清空，不传递凭据或审批能力。URL 仅包含无授权效力的路由标识，不包含正文或附件。

Tauri 新增会话路由与最小 scoped capability，应用内菜单和 Chat 标签拖出/拖回共用交接路径，不创建顶部原生“会话”菜单栏。Engine 隐藏 Session 标签后保留显式分离/合并入口。Web 在用户手势中同步预开空窗口，支持显式 Detach/Attach，并解释浏览器跨窗口拖拽限制。独立窗口正常关闭先请求合并；主窗口缺失或浏览器异常关闭依赖可靠草稿恢复，不承诺拦截所有浏览器关闭事件。主窗口托盘隐藏不撤销独立窗口；真正退出应用需单独告知 sidecar/终端影响。

**理由及替代方案：** 只传 Session ID 并重挂载会丢草稿和窗口内流累积器；仅依赖 localStorage 最后写入会形成竞争副本。引入更广泛的实时多人协同不符合当前范围。旧执行端无法提供安全归属协调时，分离入口应明确不可用，不能退回不可靠复制。

### 3. 文档服务独立于预览容器，继续使用 CodeMirror 6

从 FileTreePanel 提取目录查询、文档状态和专用预览适配器。Chat 保留现有弹窗外观，Engine 使用常驻标签，两者共用新的文档模型和安全保存；PDF/Office 等保留专用只读或结构化预览，不能放入通用覆盖保存。

每个文档保存 `baseRevision`、完整性、编码/BOM/EOL、磁盘基线、缓冲区与缓冲区版本、dirty、读取/保存身份和编辑状态。保存后留在编辑器；文件切换用独立 EditorState，窗口交接序列化并恢复兼容的撤销历史。预览与编辑读同一缓冲区；Markdown/HTML 默认预览，并排不建立第二份真相。HTML 继续使用现有信任/隔离边界，不为 IDE 外观放开脚本。

完整可编辑文本默认上限建议 8 MiB（按原始字节而非字符判断），与截断预览上限分离；仅完整且可无损解码的受支持编码可保存。未知编码、含损坏替换字符、二进制或超限文件明确只读。默认支持 UTF-8、UTF-8 BOM 及经测试的 UTF-16 BOM 路径；其余格式需可证明的往返编码支持后再开放。混合换行若无法无损回写也保持只读，而非静默规范化。

草稿采用按身份隔离的本地持久存储（Web/Tauri WebView 共用 IndexedDB 适配接口），包含恢复所需基线和缓冲区版本，不进入 Session 聊天历史。干净缓存可按配额淘汰，脏文档不能静默淘汰；配额或写入失败立即提示持久恢复不可用并保留内存及导出入口。注销后不向新用户暴露旧草稿；提供清理入口，说明浏览器存储不是加密保险库。布局仅存导航信息，不混存正文。

**理由及替代方案：** CodeMirror 已具备基础搜索、折叠、撤销等能力，首版增强状态管理和项目语义比更换 Monaco 更直接。把所有内容继续塞进预览组件，或以 localStorage 无界保存全部文件，都会扩大数据丢失/性能风险。

### 4. 新增版本化文档接口，不暗改文件传输语义

通过 BridgeWS 增加文档能力协商、完整读取、版本化保存与结果核对接口，继续复用现有认证、节点路由和安全路径校验。文档版本以完整字节哈希为核心并包含可核对的来源；保存请求带预期基线、缓冲区版本、请求 ID 和当前工作台/控制代次。对新建、删除后重建、路径变化及符号链接/大小写别名均按规范目标重新校验。

保存取得会话活动准入与规范文件锁，在提交边界重新核对控制权、路径和磁盘版本；以同目录临时文件写入、同步并原子替换，处理权限/属性保留与失败清理。回执仅确认被保存的缓冲区版本，新输入仍 dirty。同一请求重试复用 ID；未知结果先读取回执/当前版本。保存全部按文件返回结果，不伪装全项目事务。

这能串行化 AWU 内部写者，但不能锁住任意不合作的外部程序：读取校验尽可能靠近原子替换，发现变化立即冲突，保留基线用于恢复；明确最后校验与替换之间仍有外部竞争窗口。不得在 UI 宣称绝对防止所有外部覆盖。普通 `syncWriteFile` 的用途保持明确；工程编辑在旧节点不支持安全接口时只读，不以旧传输接口绕过校验。

外部变化使用当前打开文档的事件通知/有界刷新与保存前校验，不全仓库持续轮询。干净文件可更新，脏文件保留三方比较（基线/磁盘/草稿）。快速打开和项目搜索在实际工作区执行，遵循忽略规则、结果/字节预算和取消；Git diff 是读取，不隐式 stage/reset/commit。路径来自消息/诊断也要经过同一路由与授权。

**理由及替代方案：** 直接为旧同步接口强加基线会破坏原传输调用；前端先读再无条件写仍有竞争，原子替换只能解决半文件，不能单独解决旧内容覆盖。

### 4.1 本机离线副本使用独立安全适配

本轮用户明确修订来源策略：Chat/Engine 通过 Relay 或浏览器访问的执行端文件始终只读，
桌面本机执行端保留原安全编辑。已下载时目录/搜索/文件定位优先打开本机副本；
显式远端标签及“查看远端”仍保留原来源。下载后可直接打开副本，保存不自动上传。
只读适配器同时约束完整读取、缓存缓冲区与保存调用，旧草稿只保留恢复/导出，
历史未知保存仅可查回执。语言服务不接纳远端只读或副本为可写执行端缓冲区，
不以格式化/重命名绕过来源边界；这不改变 Agent、终端和显式传输的既有授权。

（实施确认：本机副本安全编辑）原 Chat 本机副本与执行端文件使用同一缓冲区协议、
完整性/编码门槛和保存回执，但具有独立的本机来源与目录绑定身份。Tauri 在 Rust
侧执行有版本基线的同目录原子替换；浏览器目录句柄使用同源跨窗口锁、实际句柄
核验和 `createWritable` 临时写提交；托管离线空间使用 IndexedDB 事务内的版本比较。
不以目录显示名称作为身份，不自动请求提升权限，不把保存副本变成上传。
未知提交结果先核对原请求/实际版本，不重复写；不合作的外部写者仍存在最后核验与
提交间的竞争窗口，不能宣称全局 CAS。原明确传输接口保持既有语义。

本机副本混合换行不再以 `mixed_eol` 拒绝编辑。读取向编辑器提供 LF 文本；
保存在锁内重新读取并核对原始字节版本，使用原始行及换行序列做有界行锚点映射，
保留未改行的换行、新增行沿用邻近样式，再按原编码/BOM重建。该格式元数据不进入传输正文，
草稿恢复仍从匹配基线恢复；损坏编码、二进制、截断、只读属性及冲突保护保持。

### 5. 语言服务在执行端监督运行，按提供器暴露真实能力


建立执行端语言服务管理器与版本化前端协议适配。请求绑定 user/node/session/workspace/documentVersion/providerGeneration；诊断、补全和编辑结果只应用到匹配版本。提供器进程使用独立、可清理的缓存目录，并可从新窗口重订阅；限制未完成请求、消息大小、诊断条数和输出，不循环重启失败服务。初始化、项目索引和普通请求使用不同超时，提供显式停止/重试。

首版提供器族如下（为设计选择，不代表本轮已安装或验证版本）：

| 工程 | 语义服务方向 | 格式化方向 | 夹具验收重点 |
| --- | --- | --- | --- |
| Java | Eclipse JDT LS | JDT 格式化 | 受支持 JDK、Maven 与 Gradle 工程的跨文件类型/引用 |
| Python | Pyright | Ruff | 解释器/虚拟环境、跨模块导入、诊断与重命名 |
| React JS/TS | TypeScript 服务的 LSP 适配 | Prettier | JSX/TSX 组件、属性、导入与 TS 类型检查 |
| Vue | Vue language server 与兼容 TS 集成 | Prettier 的 Vue 支持 | template/script 联动、组件 props、重命名与引用 |

实现前的具体兼容任务固定提供器/适配器版本、运行时要求和许可证/打包矩阵，并用预置离线依赖的最小夹具验证。Vue/TS 插件协议可能随版本变化，不能用“进程启动成功”替代能力验收。Java 运行提供器的 JDK 与项目目标 JDK分别展示，Python 解释器和项目 Node/TypeScript 来源明确选择；缺失时编辑器保留基础能力，不自动下载。

首次用户显式启用工作区语言服务后才允许启动；需要执行工作区插件、构建导入、网络访问或产生项目写入时，进一步展示冻结的范围并取得相应许可。不能假设所有 LSP 都只读：按提供器及配置声明/验证副作用，无法证明不写工作区的服务保守计入 LOOP 活动；交还前停止并确认所属进程树退出，交还后不得因重连自动重启此类服务。只有经验证不写工作区、无项目执行权限的服务可持续只读诊断。

格式化进入可撤销缓冲区；重命名先生成跨文件变更预览，整体校验各目标版本再应用到缓冲区。遇到未支持的资源操作或越权目标整份拒绝，磁盘保存仍按各文件安全接口执行并报告部分失败。

**理由及替代方案：** 不在渲染进程或 Relay 启动语言工具，防止节点错位；不把一个语言服务所有能力硬编码为全部可用。仅加高亮不满足工程语义要求；完整扩展宿主扩大信任面且不是本次目标。

### 6. 终端是受监督的真实 PTY，不是命令按钮

新增前端终端渲染（拟采用 xterm 系列）与执行端 PTY 适配：Windows 使用 ConPTY，POSIX 使用 PTY。选定 Windows 适配依赖后必须验证 PyInstaller 冻结产物及原生 DLL/进程清理；支持平台在能力协商中声明，不支持时拒绝创建，不能以普通 stdout 管道冒充完整终端。

创建请求显式指定 Session 和允许的 Shell，初始目录来自已核验会话工作区；展示实际节点和 Shell。Shell 使用执行端当前用户权限，不请求提升、不自动 source 项目脚本。用户明确创建 Shell 的行为与系统自动运行项目配置区分展示，既有用户 Shell profile 的执行语义也需说明。只在用户显式创建后启动，恢复时只重新附着资源。

管理器持有不可猜测资源 ID、启动代次、所属身份、原生进程句柄/受管理进程组、尺寸和输出序列。Windows 复用或扩展现有 owned process tree 原则，POSIX 用受管理进程组并核验退出；禁止只按 PID 推断存活或结束。输入按连接代次/序号去重，不落盘重放；创建/停止有幂等请求 ID，断线时禁止盲目重发未确认输入。多行粘贴先预览确认。

输出保留有界尾部（建议每终端 2 MiB 可调），采用序号、流量窗口和背压。恢复位置早于缓存时发送明确 gap 标记；吞吐过高不得把内存推到无界。仅解析允许的终端显示控制序列，禁用自动 OSC 剪贴板、文件操作及自动链接打开。应用日志不记录输入、环境变量或完整终端输出；暂存输出可能包含敏感内容，按身份保护且不默认持久化，应用不额外收集密码。

关闭区域和模式切换只 detach 视图；停止必须等待受管理进程退出。仅发送 Ctrl+C 不能证明 Shell 退出。后端重启后原实例不可恢复时显示中断/未知，不自动重启命令。真正退出应用的提示需要列出存活终端及未保存文档；正常独立窗口关闭不终止终端。

**理由及替代方案：** 普通 subprocess 输出框无法可靠支持 REPL、控制键和尺寸；使用 SSH 去“模拟远端终端”会绕开现有节点权限/路由。终端仍拥有实际 OS 权限，不是新文件系统沙箱；由用户输入的 `cd` 或命令可能访问进程本来有权访问的位置，不能以初始 cwd 暗示更强隔离。

### 7. 新活动进入统一 LOOP 准入，窗口不取得控制权

文件提交、终端创建/输入和可能写工作区的语言任务在执行端共用工程活动登记，并与 `loopControl` 的会话预留串行准入。交还在活动锁内冻结准入，再走既有有序持久提交；不能先检查为空、释放锁、再允许新写进入。已开始的保存保留到可核对终态，取消等待不释放提交中的活动。

存活终端即使 Shell 空闲仍保守视为潜在写者。停止/取消但清理未确认时保留保护；是否隐藏或分离窗口与保护无关。草稿和只读视图不算已授权写者，交还时提示未保存草稿不会自动落盘，之后按新控制权限制保存。需要写权限的 LSP 不能仅靠“当前没有请求”绕过保护。

前端按用户/节点/Session 共享并核对 receipt，工作台交接阶段与 LOOP 交接阶段分开。已提交控制权但视图加载失败只能重试读，旧 Get 失败不能降低新 receipt 的阶段。已有检查记录指出这一迟到读取竞态，新增跨窗口测试必须覆盖，并在本变更实施时明确核对修复归属，不能假定已由历史归档消失。

**理由及替代方案：** 仅禁用 Engine 按钮不能拦住其他窗口或迟到请求；把所有常驻服务都当写者会让只读预览永远阻塞交还。保持既有空人工轮、旧队列、Auto 和原生环境判定，不用新终端推导模型可用。

### 8. 分层交付，但验收覆盖完整首版范围

实施顺序为协议/身份与安全文档底座 → Engine 布局与窗口交接 → 语言服务和终端 → LOOP 整合与回归。窗口、语言和终端可逐步接线，但“只完成布局”“只有语法高亮”“终端以后再做”都不构成本变更完成。

测试沿用现有 `workbench`、`file-panel-layout`、`session-recovery`、文件读写/预览及 LOOP 测试，新增：

- 协议层假时钟、错误注入及 fake LSP/PTY，覆盖乱序、超时、崩溃、停止未确认和节点/用户变化。
- Web 双窗口和 Tauri 原生窗口交接：dirty 文件、撤销历史、附件草稿、流式输出、待确认事项、主窗口托盘及真实退出。
- 四类实际工程夹具与真实 PTY 冒烟；使用固定已准备依赖，手工验收只补充原生拖拽等自动化难覆盖的行为，不代替基本自动化。
- 所有测试先验证独立测试数据根和临时工程；不得连接生产 Session、写真实用户目录或调用付费模型。缺少环境时报告未验证，不能将 skip 记为通过。

### 9. 已完成交接的展示收敛

按用户截图要求，`LoopControlStatus` 仅承载仍待处理的反馈。接管/交还已提交且目标视图就绪后，
无错误和工程阻塞时直接不渲染，不保留高度；历史 Auto/检查点说明不单独占据工作区。
共享控制权状态机、回执和检查点字段不变，不添加定时消失、轮询或写重试。
视图加载中/失败和结果未知仍明确展示；成功后新的核对失败或工程活动只展示当前可处理问题。

## Risks / Trade-offs

- [跨窗口归属增加桥接协议复杂度] → 协商能力、单一状态机、代次隔离和确定性故障测试；旧端显式降级。
- [任意外部进程不服从文件锁] → 近提交重新校验、原子替换和基线恢复；明确不提供全局 CAS 保证。
- [Java/Vue 导入可能执行构建或插件] → 固定版本夹具、分级信任和保守活动登记，未经许可不导入/联网，不宣称 LSP 默认只读。
- [终端与 LSP 子进程失控或冻结构建缺失依赖] → 持有原生所属句柄、确认退出、冻结包验收；清理未知保留锁，不自动提升权限重试。
- [安全保护使交还多一步停止终端] → 提供具体活动、定位及显式停止入口，不用错误的“画面空闲即安全”减少步骤。
- [草稿恢复可能含源代码或敏感信息] → 按身份隔离、容量提示、清理入口、无凭据/授权持久化；共享 OS 账户的本地存储不被宣称强加密隔离。
- [大仓库索引与远端高延迟影响交互] → 目录/搜索按需、请求与输出预算、取消和状态可见；不轮询完整仓库和历史。
- [既有 LOOP 迟到读取竞态被多窗口放大] → 按活动请求身份/阶段过滤错误和回执，单列回归；保留旧语义和现有未提交修复。

## Migration Plan

1. 增加能力协商、兼容 Session 字段和独立工作台存储；旧数据默认 Chat，旧客户端省略字段不重置。
2. 先启用完整文档与安全保存，再让 Chat 编辑入口复用底座；保留原预览外观和普通传输功能。
3. 接入 Engine 与归属交接；只有支持新协议的执行端开放有状态分离，旧端解释限制。恢复旧布局不抹掉新草稿。
4. 用户显式启用已配置语言服务和创建终端；开发依赖锁定/打包与运行时自动安装是两回事，应用运行时不自行安装。
5. 完成四类工程、双平台 PTY 支持矩阵及 Web/Tauri/LOOP 回归后开放完整能力。任一平台未实测必须标记未验证，不能作为已完成验收。
6. 回退 UI 时保留草稿与安全保存版本数据；提示并由用户结束受管理活动，确认退出后才撤除服务。回到 Chat 不隐式丢草稿、杀终端或恢复旧控制字段；旧版无法读取新草稿时先提供导出。
