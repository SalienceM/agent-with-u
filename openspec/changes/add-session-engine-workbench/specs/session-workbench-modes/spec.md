# Spec Delta

## Purpose

让每个会话能够在保留原有聊天体验的同时，选择面向工程开发的文件优先工作台。展示模式与会话执行类型、窗口位置及控制权相互独立，用户可以同时查看目录、文件和对话，切换或恢复布局时不丢失工作进度。

## ADDED Requirements

### Requirement: 会话展示模式独立且向后兼容

系统 SHALL 为会话提供 Chat 与 Engine 展示模式，未设置时使用 Chat。模式变更 MUST NOT 新建或复制会话、改变普通/LOOP 类型、执行节点、Backend、控制权、Auto 或发送消息；旧客户端未提交该字段时 SHALL 保留已存模式。

#### Scenario: 旧会话继续使用 Chat
- **WHEN** 用户打开没有模式字段的既有会话
- **THEN** 系统显示既有聊天/LOOP 布局，不自动打开终端、语言服务进程或新窗口

#### Scenario: 两个会话分别选用不同模式
- **WHEN** 用户将会话 A 设置为 Engine 而会话 B 保持 Chat
- **THEN** 各自保留选择，切换及重新打开后互不覆盖模式、执行身份和草稿

#### Scenario: 旧客户端更新会话
- **WHEN** 旧客户端修改已有 Engine 会话的标题但没有提供展示模式
- **THEN** 已保存的 Engine 选择不被重置；新客户端连接不支持模式持久化的旧执行端时明确说明仅本地记忆，不伪报服务器已保存

### Requirement: Engine 默认使用文件优先的常驻工作区

系统 SHALL 在足够宽的窗口中默认以左侧目录、中间文件、右侧对话或 LOOP 面板展示 Engine，并提供底部可展开终端区域。中间文件 SHALL 是可与其他区域同时操作的常驻工作区而非模态弹窗；进入 Engine MUST NOT 强制系统全屏或自动运行任何命令。

#### Scenario: 首次切换 Engine
- **WHEN** 用户在桌面宽度的 Chat 会话切换至 Engine
- **THEN** 显示三栏布局及清晰的当前会话、节点和工作目录，中间无文件时显示打开文件入口，终端尚未创建进程

#### Scenario: LOOP 使用 Engine
- **WHEN** 用户为 LOOP 会话选择 Engine
- **THEN** 右侧遵循现有自动 LOOP 面板与人工聊天的路由，切换布局不自动接管、不交还、不开放未获准的写入

### Requirement: Engine 使用单 Session 导航

系统 SHALL 从 Session 右键菜单提供 Chat/Engine 模式选择，并为当前会话保留键盘及触屏可用的同等菜单。Engine SHALL 隐藏全局会话侧栏和工作总览/Session 标签行，将当前窗口限定为单 Session 工程面板；返回 Chat 才恢复多标签/分屏导航，MUST NOT 销毁其他会话草稿或停止后台任务。

#### Scenario: 进入单 Session 工程窗口并返回
- **WHEN** 用户从 Session 菜单进入 Engine，再从当前会话菜单返回 Chat
- **THEN** Engine 不显示或开放其他 Session 的切换入口，Chat 恢复原标签与分屏，当前和后台会话编辑状态保持

#### Scenario: Engine 收到其他会话导航
- **WHEN** Engine 窗口收到其他 Session 的工作区链接或应用导航请求
- **THEN** 系统不切换当前工程、不自动改变模式，提示先返回 Chat；原工程草稿及执行身份保持

### Requirement: Chat 操作集中于 Session 标签菜单

Chat SHALL 不再显示或预留重复的会话工具栏。模式切换、窗口分离/合并、安全合并关闭及恢复功能 SHALL 位于上方 Session Tab 的右键菜单，支持 Shift+F10 打开与 Escape 回焦，按实际标签和视口定位。菜单打开 MUST NOT 自动移动窗口或启动命令。Engine 没有全局标签行，SHALL 保留自己的工程工具栏。失败、进行中及待恢复的交接提示 MUST NOT 因工具栏移除而消失。

#### Scenario: Chat 无重复行且标签菜单可操作
- **WHEN** 用户打开普通或 LOOP 的 Chat 会话并右键上方 Session Tab
- **THEN** 对话区域不被重复工具栏或空白占位挤压，菜单显示该会话的模式和窗口操作，关闭后焦点可回到该标签，草稿与对话实例保持

#### Scenario: 标签菜单进行窗口交接
- **WHEN** 用户从 Chat 标签菜单分离或合并窗口
- **THEN** 操作沿用原受保护交接流程，待确认/失败仍可核对，已移出视图不能再次竞争写入，恢复包仅按需展开

### Requirement: 按文件类型选择预览或编辑

系统 SHALL 在 Engine 中将可完整读取且允许写入的代码、配置和纯文本直接打开为编辑器；Markdown/HTML 默认渲染预览并提供源码与并排入口；图片、PDF、Office 等使用适合该格式的预览。系统 MUST 区分内容预览与代码编辑，并如实标明只读、截断和不支持的能力。

#### Scenario: 点击源代码文件
- **WHEN** 用户打开允许编辑的 Java、Python、Vue 或 JSX/TSX 文件
- **THEN** 文件在中间编辑器打开并可直接输入，无需先点击编辑按钮，保存后继续留在编辑器

#### Scenario: 文档预览与源码并排
- **WHEN** 用户打开 Markdown/HTML 并选择源码并排
- **THEN** 预览与源码同时可见并关联同一份缓冲区，明确显示未保存状态；HTML 脚本执行仍受现有显式信任边界约束

#### Scenario: 打开不能编辑的文档
- **WHEN** 用户打开 PDF、图片或不支持编辑的 Office 格式
- **THEN** 系统提供真实预览或具体不支持原因，不展示会覆盖二进制内容的通用文本保存入口

### Requirement: 布局和文件工作进度可恢复

系统 SHALL 允许调整、折叠和恢复三栏及终端区域，并按当前用户、节点、会话和客户端工作台恢复合适的布局。模式切换、会话切换和窗口移动 MUST 保留打开的文件、未保存内容及终端引用，不自动保存、丢弃或终止运行。

#### Scenario: Engine 返回 Chat 后再进入
- **WHEN** 用户带着未保存文件和运行中的终端切换 Chat 后再返回 Engine
- **THEN** 恢复文件标签、草稿及已有终端状态，不创建第二个进程、不重复执行命令，Chat 本身仍保持既有布局

#### Scenario: 窄屏恢复桌面布局
- **WHEN** 用户把 Engine 窗口缩小到无法合理容纳三栏的宽度
- **THEN** 系统提供目录/文件/对话/终端的可访问切换入口，不把三栏压成不可操作区域，放宽窗口后可恢复之前的尺寸

#### Scenario: 目录内容随栏宽变化
- **WHEN** 用户用指针或键盘拖宽、缩窄 Engine 目录栏，或从窄屏恢复
- **THEN** 目录标题、搜索与树内容填满实际栏宽，右边缘跟随分隔线，不在已加宽容器内留下旧宽度的空白区域
