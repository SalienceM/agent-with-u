# Spec Delta

## ADDED Requirements

### Requirement: 工程工作台写活动参与控制权交接保护

系统 SHALL 将正在保存文件、应用已确认的磁盘修改、会写工作区的语言服务任务，以及存活或退出未确认的人工终端纳入会话活动检查。活动准入与控制权交接 SHALL 相互排斥，并由执行端在提交边界重新核验；前端禁用按钮不能代替该约束。只读预览、内存草稿和经验证不写工作区的语义服务 MUST NOT 仅因存在永久阻塞交还。

#### Scenario: 文件保存与交还同时到达
- **WHEN** 同一人工 LOOP 会话的文件保存和交还请求竞争
- **THEN** 只有满足当前权威状态的一方可先进入提交边界；交还不能越过未确认写活动，迟到的旧人工保存不能在交还后落盘

#### Scenario: 写服务停止尚未确认
- **WHEN** 可能写工作区的语言服务或终端收到停止请求但退出未确认
- **THEN** 系统保留保护，交接反馈指明具体活动；窗口关闭、取消等待和 UI 超时都不能被当作进程已退出

#### Scenario: 只有内存草稿和只读诊断
- **WHEN** 用户有未保存草稿及经验证只读的语言服务，没有其他阻塞活动，并选择交还
- **THEN** 系统先提示草稿不会自动保存并保留它们，用户可继续交还；交还后写入口重新按控制权判定，不把草稿悄悄丢弃或自动保存

### Requirement: 工程视图共享同一交接结果且不改变执行语义

系统 SHALL 在 Chat、Engine、独立窗口和主窗口中呈现同一会话的权威交接状态，按用户、节点、会话、操作标识和修订隔离迟到事件。窗口移动、刷新或本地显示失败 MUST NOT 重试控制权写请求、释放预留或回退已提交的归属；视图恢复只能核对读取。工程活动结束后 SHALL 继续遵循既有空人工轮、排队任务和 Auto 规则。

#### Scenario: 交还提交后目标视图加载失败
- **WHEN** 控制权交还已持久提交，但 Engine 或独立窗口加载失败，或旧读取失败迟到
- **THEN** 保留已提交归属，显示视图恢复失败及只读重试入口，不把旧错误当作新交接未完成、不再次请求交还

#### Scenario: 无新人工消息的工程会话交还
- **WHEN** 人工接管后只查看文件或完成合法编辑，工程活动已结束，没有新人工聊天请求，且旧队列仍有历史项
- **THEN** 系统依现有空人工轮规则处理交还，不因历史队列阻塞，不消费队列，不启动模型，也不自动开启 Auto

### Requirement: 已完成的控制权交接不占据常驻工作区

系统 SHALL 在接管或交还成功且目标视图加载完成后移除顶部结果条及其布局占位；历史成功、Auto 关闭或检查点不可用 MUST NOT 单独导致常驻提示。系统 MUST 保留权威回执及检查点记录，并继续显示处理中、结果待确认、真实失败、视图加载失败和当前工程阻塞，不通过清空状态或重发请求隐藏问题。

#### Scenario: 无检查点交还完成
- **WHEN** 交还成功、检查点不可用且 LOOP 面板加载完成，没有其他错误或工程阻塞
- **THEN** 顶部成功结果条及其占位消失，LOOP 面板使用腾出的空间，回执仍记录检查点不可用，不启动模型或 Auto

#### Scenario: 成功后出现可处理异常
- **WHEN** 历史交接已成功，但当前状态核对失败或出现新的工程阻塞活动
- **THEN** 显示当前错误或具体活动及处理入口，不重新展示历史成功说明，也不回退归属或重复交接
