# Spec Delta

## Purpose

为 Java、Python、Vue 和 React 工程提供基于项目上下文的代码理解与修改辅助，而不仅是语法着色。语言服务必须与实际执行节点、运行时和文档版本一致，在依赖不足、项目不受信任或服务异常时明确降级，不扩大文件权限或自动运行项目。

## ADDED Requirements

### Requirement: 四类工程提供可验证的语义能力

系统 SHALL 为已配置且受支持的 Java、Python、Vue 单文件组件和 React JSX/TSX 工程提供项目级补全、定义跳转、引用查找、诊断、格式化和重命名预览。语法高亮或单词补全 MUST NOT 被标记为项目语义服务已就绪；提供器不支持的操作 SHALL 明确不可用。

按本轮用户修订的远端只读策略，下列语义编辑场景适用于可写的本机执行端工程。远端只读视图 SHALL 不开放格式化或重命名；本机下载副本 SHALL 保持来源隔离，不自动上传其草稿给执行端语言服务，也不得将基础高亮标为项目语义就绪。

#### Scenario: Java 工程解析跨文件符号
- **WHEN** 用户打开运行时与依赖已准备好的受支持 Java 工程
- **THEN** 可补全并跳转到项目类型或方法、查找跨文件引用、看到类型错误，并预览重命名影响；受支持的构建系统和运行时版本在能力说明中可查

#### Scenario: Python 使用所选解释器环境
- **WHEN** 用户在已配置解释器环境的 Python 工程打开模块
- **THEN** 补全、导入解析和诊断使用该环境，支持跨模块跳转/引用及格式化；更换环境后旧结果失效，不将控制端的环境冒充执行端环境

#### Scenario: Vue 同时理解模板与脚本
- **WHEN** 用户打开含类型化脚本、组件导入和模板属性的 Vue 单文件组件
- **THEN** 获得关联组件及属性的补全、跳转、诊断、格式化和重命名预览，而不是仅按 HTML 文本处理

#### Scenario: React 解析 JSX 和 TSX
- **WHEN** 用户打开依赖已准备好的 React 工程中的 JSX 或 TSX 文件
- **THEN** 组件、导入和属性获得项目语义补全与跳转/引用，TSX 类型错误可定位，并支持格式化与可预览的重命名

### Requirement: 服务运行于实际节点并明确依赖与信任边界

系统 SHALL 将语言服务、解释器和项目配置绑定到会话实际执行节点和授权工作区，展示所选运行时及提供器能力状态。缺少依赖时 SHALL 给出具体原因和用户可执行的配置指引，MUST NOT 自动安装、提权、修改全局环境、切换节点或触发联网下载。项目导入、插件、构建脚本等可能执行代码或写工作区的行为 SHALL 在发生前获得独立且范围明确的用户许可。

#### Scenario: 进入 Engine 但未启用工程服务
- **WHEN** 用户首次进入 Engine，尚未启用该工作区的语言服务
- **THEN** 可使用基础文本编辑，系统展示启用和环境检查入口，不因切换布局启动提供器、构建导入或依赖安装

#### Scenario: 远端缺少 Java 运行时
- **WHEN** 会话执行节点缺少提供器所需运行时，而控制端已安装
- **THEN** 服务标记不可用并说明远端缺失项，基础编辑仍可用，不使用控制端运行时冒充远端解析

#### Scenario: 项目配置要求执行插件或构建脚本
- **WHEN** 启用服务需要执行来自工作区的配置代码或导入任务
- **THEN** 用户先看到节点、目录、潜在执行/写入和网络影响；拒绝后仅保留可安全提供的能力，不能把一次启用服务视为无限制执行许可

### Requirement: 语义结果与当前文档版本一致

系统 SHALL 为语义请求关联节点、工作区、文件和缓冲区版本，诊断覆盖未保存内容，并在身份或版本不匹配时丢弃迟到结果。诊断 SHALL 可按文件和严重程度汇总并准确定位；错误定位不得覆盖现有草稿。

#### Scenario: 输入后旧诊断才返回
- **WHEN** 用户产生新编辑，先前版本的诊断或补全随后到达
- **THEN** 旧结果不能覆盖新版本诊断或插入不匹配的编辑，服务中断和暂无诊断有不同提示

#### Scenario: 从问题列表打开未保存文件
- **WHEN** 用户点击另一已打开文件的有效诊断
- **THEN** 聚焦该文件当前缓冲区和位置，不重新读取磁盘并覆盖未保存内容

### Requirement: 语言辅助修改经过预览和版本校验

系统 SHALL 将格式化和重构结果作为可撤销的缓冲区编辑，而不是直接静默覆盖磁盘。跨文件重命名 SHALL 先显示涉及文件和差异、核验全部目标的身份/路径/版本并由用户确认；不支持的文件创建、删除或移动等操作 MUST 被明确拒绝，不能部分静默执行。持久保存 SHALL 遵守统一文档保存与控制权规则。

#### Scenario: 预览后文件已改变
- **WHEN** 用户准备应用重命名，而任一目标文件版本已不同于预览
- **THEN** 系统使本次修改计划失效并要求刷新比较，不自动套用过时编辑，也不先修改部分文件后宣称成功

#### Scenario: 应用格式化但尚未保存
- **WHEN** 用户确认对当前文档格式化
- **THEN** 结果进入当前缓冲区，可撤销且标为未保存；磁盘只有在合法保存完成后改变

### Requirement: 服务生命周期有界且故障可见

系统 SHALL 提供不可用、待许可、初始化、就绪、失败及已停止等可区分状态，支持用户停止和显式重试。请求、索引资源和诊断量 SHALL 有界并可取消；崩溃或失联不引发无限自动重启。窗口移动和布局切换 SHALL 复用已归属当前工作区的服务，不重复导入项目。

#### Scenario: 服务卡住或崩溃
- **WHEN** 请求超过时限或提供器异常退出
- **THEN** 基础编辑继续可用，用户看到失败与重试入口；系统不将无诊断结果解释为代码通过，也不无限积累请求或重启进程

#### Scenario: 移动窗口后恢复服务连接
- **WHEN** 已启用语义服务的会话分离或合并
- **THEN** 新视图恢复同一服务引用并核对文档版本，不创建重复服务或再次执行受信任导入

### Requirement: 服务活动不绕过控制权和环境判定

系统 SHALL 区分经验证不写工作区的语义服务与可能执行项目代码或写工作区的活动。后者 SHALL 参与现有 LOOP 控制权及活动保护；只读诊断视图和经验证的只读服务不得仅因存在永久阻塞交还。语义能力就绪 MUST NOT 清除模型调用环境故障或自动启用 Auto。

#### Scenario: 自动 LOOP 中申请会写工作区的导入
- **WHEN** 用户尚未人工接管就请求执行会修改工作区的项目导入
- **THEN** 系统拒绝该操作并解释需要的控制权，不因请求来自语言服务而绕过人工接管

#### Scenario: 只读服务在交还后仍可展示结果
- **WHEN** 已确认服务不会修改工作区且没有其他保护活动，用户交还 LOOP
- **THEN** 服务存在本身不阻塞交还；显示的诊断不改变既有环境就绪结论、不启动模型或队列
