# Spec Delta

## Purpose

让用户从普通分支副本直接理解并完成合回主 Session 的流程，在同一面板掌握变化、冲突、验证和真实结果。整合空间按需可达，保留隔离、独立确认和失败恢复边界，避免用户把后台候选误认为最终目标或已经完成的合并。

## ADDED Requirements

### Requirement: 单一面板固定真实目标并恢复既有操作

系统 SHALL 从副本的“合并到主 Session”入口固定真实来源、父 Session 和目标分支，持续展示合并方向。打开面板 SHALL 优先恢复唯一关联的未完成操作；若有多条，SHALL 展示状态、创建时间和来源/目标提交供选择，不按同名或列表位置猜测。读取、返回面板和查询旧记录 MUST NOT 创建新合并、启动模型或改变原操作归属；用户明确新建才可创建另一条预览。

#### Scenario: 再次进入已准备的合并
- **WHEN** 同一副本与主 Session 已有一条未完成合并且用户再次打开入口
- **THEN** 面板显示原 operationId 对应的当前阶段、真实目标分支和下一步，不要求再次选来源/目标，也不新建整合空间

#### Scenario: 多条同名历史记录
- **WHEN** 多条未完成记录匹配同一真实来源/目标
- **THEN** 面板提供有区别的信息供选择，已完成、取消和旧失败记录可查，未选择前不提交新的写操作

#### Scenario: 从主 Session 查询副本发起的记录
- **WHEN** 用户从主 Session 的关联入口查看副本发起的合并
- **THEN** 系统只展示权限范围内的关联状态并提供原入口，保留原发起会话归属；不能以当前聊天身份冒用原记录、跨节点重试或直接绕过执行服务

#### Scenario: 统一分支与合并入口
- **WHEN** 用户打开主 Session 的右键菜单
- **THEN** 系统只提供一个“分支与合并”管理入口，在同一面板切换副本、合并和分支图；副本保留“合并到主 Session”，不重复列出两个含义重叠的合并记录入口

#### Scenario: 副本页只呈现最新记录
- **WHEN** 用户打开副本页且没有指定副本或正在处理的操作
- **THEN** 系统 SHALL 默认显示服务端最新更新的一条副本记录，详情占满可用宽度，不显示历史侧栏或“更多任务”；编辑、确认、创建中和结果未知时保持本条，不能因另一记录更新而丢失原操作核对入口；移除预览后显示最新剩余记录，后台历史及其他副本保持不变

### Requirement: 连续流程保留必要的独立确认

系统 SHALL 按实际阶段突出一个下一步动作，并在同一面板保留差异、进度和结果。无冲突时 SHALL 自动衔接已授权准备后的 Git 核对；有冲突时 SHALL 提供显式处理入口。准备独立空间及将候选应用到目标 MUST 分别展示并确认对应冻结计划；普通跳过确认、聊天正文、Kit 委托或前一步确认 MUST NOT 替代后一步确认。应用只更新冻结的原目标分支，发生变化时拒绝旧计划。

#### Scenario: 无冲突的正常流程
- **WHEN** 用户审阅变化并确认准备，独立候选准备成功且核对通过
- **THEN** 同一面板转到“确认合并到主 Session”，无需用户打开第三个 Session 或手动寻找核对按钮；确认前目标 HEAD 不变

#### Scenario: 冻结目标已改变
- **WHEN** 准备或最终应用前来源/目标身份、分支、提交或工作树不再匹配计划
- **THEN** 面板指出变化侧并要求显式更新预览与相应确认，不沿用旧授权、不切换目标分支、不 stash/reset

### Requirement: 整合空间按需可达且不冒充普通副本

系统 SHALL 保留真实独立整合 Session 和成果，但默认从普通分支副本树及副本计数中区分出来，以合并记录中的“处理空间”入口呈现；普通副本仍是具有全部正常功能的子 Session。整合 Session 的既有父关系、标签、深链接、历史和运行状态 MUST 保留；打开它不自动启动修复，隐藏它不取消运行或删除成果。关联信息缺失时 SHALL 保留可见恢复入口，不能隐藏成不可达孤儿。

#### Scenario: 无冲突时查看左侧树
- **WHEN** 用户准备一个无冲突的副本合并
- **THEN** 主项下仍呈现普通副本，不新增一个同等含义的“分支 3”；用户可从原合并记录按需打开整合空间

#### Scenario: 旧整合会话仍在运行或已打开
- **WHEN** 新界面加载旧整合 Session，且它正在运行或已有标签
- **THEN** 标签保持可用，合并入口显示实际活动和打开/返回入口；普通列表收拢不终止运行、不改写 Session ID

#### Scenario: 侧栏明确显示当前操作
- **WHEN** 关联操作等待确认、候选审阅、冲突处理或结果核对
- **THEN** 系统 SHALL 显示具体状态而不是笼统“需处理”，点击按真实 operationId 打开对应记录；合并更新事件只刷新显示，不执行合并或修复

#### Scenario: 旧记录不形成永久待办
- **WHEN** 同一执行节点、发起 Session 和同一双方存在较新创建的合入或同步记录
- **THEN** 普通侧栏提醒 SHALL 使用较新记录，失败和已结束历史不继续显示为待办；运行中、应用中、结果未知或仍在输出的旧处理空间始终保留，缺少创建时间时不猜测顺序；所有原记录和写入保护仍保留，不自动取消或结清旧操作

### Requirement: 自动核对有界且不自动执行写操作

系统 SHALL 在面板可见且整合空间已确认空闲时，对准备完成、显式修复实际退出、返回面板或相关新修订触发合并去重的 Git 核对。相同身份、operationId 与候选修订的核对 SHALL 共享进行中请求并限制重复；失败、离线或退出未知时 MUST 保留状态和手动查询入口，不无限轮询、不自动重放写入或启动模型。迟到结果 MUST NOT 更新另一会话或较新候选。

#### Scenario: 冲突已解决并提交
- **WHEN** 用户在整合空间解决冲突并提交，运行实际退出后返回合并面板
- **THEN** 面板自动核对当前候选并移除已经失效的冲突提示；只有当前候选通过核对才提供最终应用入口

#### Scenario: 输出结束但进程退出未知
- **WHEN** 修复出现完成文字但实际进程仍活动或退出未知
- **THEN** 面板继续显示活动或未知状态，不将文字当作退出或通过，不启动下一次修复/应用

### Requirement: 阻塞与验证结果可定位且不混淆

系统 SHALL 分别标明来源、主 Session 和整合空间的状态。未提交提示 SHALL 给出对应 Session、目录和有界路径列表，区分 Git 工作树、暂存区、未跟踪文件与编辑器未保存缓冲区；活动及未知状态 SHALL 指向实际运行或原操作。缺少详情或旧节点不支持时 SHALL 明确说明未知，不能输出“干净”。Git 核对与项目验证 SHALL 分别展示；只有带候选版本、执行结果和来源的可核对证据才能标记测试通过，失败、未执行、未知与旧版本证据 MUST 分别保留。

#### Scenario: 副本干净而主 Session 有改动
- **WHEN** 副本没有未提交内容但主 Session 有未提交文件
- **THEN** 提示明确写出“主 Session 有未提交文件”及实际文件列表，提供打开目标入口，不要求用户反复提交干净的副本

#### Scenario: 磁盘干净但编辑器未保存
- **WHEN** Git 工作树干净而主 Session 的文件缓冲区仍有未保存内容
- **THEN** 面板定位该缓冲区，并说明它与 Git 未提交列表不同，保留写入保护

#### Scenario: Git 核对通过但测试失败
- **WHEN** 候选的 Git 检查通过且可核对的测试执行有失败
- **THEN** 面板同时显示 Git 已核对和测试失败，给出失败测试/命令摘要及原证据入口；不显示“全部验证通过”，失败信息在最终审阅中继续可见

#### Scenario: 测试证据属于旧候选
- **WHEN** 候选提交变化或只剩模型文字总结，无法核对测试对应提交与结果
- **THEN** 测试状态标为过期或未验证，保留原始记录，不把新 Git 核对或模型自述升级为功能验收

### Requirement: 成功与未知以原操作真实回执为准

系统 SHALL 仅在原操作成功并核对目标实际分支与最终提交后宣告“已合并到主 Session”，保留来源和整合空间。应用中、超时、断线或响应未知 MUST NOT 显示成功或自动重试；恢复查询 SHALL 读取原 operationId 的真实结果。取消、关闭面板和完成合并 MUST NOT 自动推送或清理成果。

#### Scenario: 最终回执丢失
- **WHEN** 应用请求可能已完成但客户端没有收到响应
- **THEN** 面板显示结果未知并查询原操作，核实成功后显示真实目标分支/提交；不得再次提交应用

#### Scenario: 原主 Session 正在运行
- **WHEN** 最终应用时主 Session 仍有聊天、LOOP、队列、终端或其他受保护写入活动
- **THEN** 系统拒绝应用并指明实际活动，保留候选且不自动中断任务；待空闲并重新核对后仍由用户确认应用

### Requirement: 连续面板支持窄屏与键盘

系统 SHALL 复用应用现有按钮、主题、反馈和焦点规范，在桌面及窄屏保持来源、目标、当前阶段和下一步可见。历史、完整目录与日志 SHALL 按需展开；关闭或进入处理空间再返回 MUST 保留当前操作与用户草稿，不能跳回空白新建页或抢占其他会话焦点。

#### Scenario: 窄屏处理冲突后返回
- **WHEN** 用户在窄屏或键盘操作下打开处理空间并返回
- **THEN** 原操作及草稿仍在，焦点回到合理入口，没有横向溢出；状态更新不强行打开其他会话

#### Scenario: 完成页简明呈现结果
- **WHEN** 合入或同步已经成功并有真实最终提交回执
- **THEN** 面板 SHALL 只展示一张结果卡和一个继续操作主按钮，保留可见的 Git 与测试状态；完整计划、路径和证据按需展开，历史单独可查，完成后的新工作区改动不重新标成该旧操作的待办；刷新图标具有“核对原操作”的可访问名称

### Requirement: 合入后同步主干并继续原分支

系统 SHALL 在真实副本合入主干成功后的首屏提供“同步主干到此分支”，并允许下一轮开发前显式预览同步。同步 SHALL 冻结当前真实主干和副本提交，origin 保持副本身份，复用独立准备、Git 核对及最终应用确认。副本为主干祖先时 SHALL 快进到冻结的主干提交，不制造额外合并提交；分叉时 SHALL 在独立空间保留双方历史。合入和同步 SHALL 分别记录真实回执，失败不撤销前一次成功，不自动重试或同时写入其他副本。

#### Scenario: 合入后没有新增工作
- **WHEN** B 已成功合入主干且 B 仍干净空闲，用户确认同步的准备和应用
- **THEN** B 的原分支快进到冻结主干提交，使用原 Session 继续开发，主干和其他副本不被本次同步改写

#### Scenario: B 已继续修改
- **WHEN** B 已有新提交、未提交文件、活动或未知结果
- **THEN** 新提交分叉在独立空间整合；未提交、活动和未知结果保留原有保护，不 reset、stash、覆盖或自动中断

#### Scenario: 多副本先后合入同一主干
- **WHEN** A 已推进主干而 B 的候选基于先前主干
- **THEN** B 不能应用旧计划，须重新预览并保留 A 的已合入历史；并行开发不成为并发覆盖主干的授权

#### Scenario: 同步后继续开发再合入
- **WHEN** 副本保留上次同步成功的记录，同时副本或主干已产生新提交
- **THEN** 系统 SHALL 只读比较当前双方提交并核对仓库、分支和 HEAD 新鲜度，显示待合入与待同步数量；副本有新提交时首屏提供“预览本轮合并到主干”，仅主干有新提交时提供同步入口；上次成功、文件数和测试证据 SHALL 标为历史回执，不能宣称当前已经同步，状态未知时不推断零差异

#### Scenario: Session 重命名后查看旧操作
- **WHEN** 用户把分支副本重命名为 Bravo 或 Charlie 后打开既有合并
- **THEN** 面板和历史列表 SHALL 以真实 Session ID 获取当前显示名称，冻结计划中的原名称、指纹和提交回执保持不变；图中的分支标签保留可区分的名称尾部，不因截断共同前缀而无法辨认

### Requirement: 内嵌真实分支图与提交记录

系统 SHALL 在分支副本面板提供直接可见的“分支图”入口，上方按拓扑从左到右显示真实父提交连线，下方显示联动的提交记录和按需文件差异。图 SHALL 只读当前 owner/executor 的主 Session 和有权访问的普通副本，展示实际 HEAD、领先/落后及未提交状态，不根据标题、日期或模型判断虚构连线。读取 SHALL 有界且披露范围，未知/旧节点/离线不能冒充空图或干净；查看、选择节点和刷新 MUST NOT fetch、合并、切换分支或运行模型。

#### Scenario: 主干合入副本后的图
- **WHEN** 当前范围含有一个双亲合并提交
- **THEN** 图同时绘制两个真实父边，表格标记合并提交，选择节点或记录可查看该 OID 的文件差异

#### Scenario: 历史或分支超出范围
- **WHEN** 图仅返回最近 80 条提交或最多 16 个主干/副本，尚有其他内容
- **THEN** 明确提示有界范围、范围外父边以虚线表示，可显式扩大至最近 200 条提交；当前副本优先包含，不能将缺页当作断裂历史

#### Scenario: 图读取失败或分支变化
- **WHEN** 节点不支持、离线、权限/仓库读取失败，或读取中 HEAD/分支发生变化
- **THEN** 显示明确错误或对应分支未知，提供刷新入口，不切换节点、不自动重放写入，也不宣称并行修改不会冲突
