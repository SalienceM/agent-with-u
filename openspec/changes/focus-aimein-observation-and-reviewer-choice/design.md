# Design

## Context

参见 proposal.md。运行现场已有真实调用和输出投影，但日志、通道与入口占主导；任务地图修整正在 refine-aimein-task-landscape 实装。后端 resolve_reviewers、验收/恢复和进展观察固定三位，前端瓶与汇总亦如此。

## Goals / Non-Goals

**Goals:** 观察时先回答推进、当前行为和异常；评审人数贯通配置、执行、展示及历史。

**Non-Goals:** 不估算虚构完成百分比、性能或效率分，不改变模型投票为多数通过，不自动减少出错评委，不触发生产会话。

## Decisions

1. 新尝试记录 version=2 与 reviewerCount，取已保存的 1–3 位配置；reviews 本身继续冻结身份、模型和档案。缺少 reviewerCount 的老记录仍要求三位；字段非法或缺报告时不得获得验收信用。策略变化沿用原身份边界，不能热换正在评审的成员。
2. 配置列表长度即期望人数，首次空配置显示三个待填席位；人数按钮保留前面已填席位，增加时补空席；档案选择支持 1–3 个有效不同模型。单人显示独立核实，避免三方/共识措辞。后端不得以空数组 all() 获得通过。
3. 沙盘和静态回退只展示配置/本次记录对应席位，保留评委 1–3 稳定坐标，按存在席位过滤航线和观察入口；历史总数取记录，不取当前设置。
4. 运行现场顶部突出真实已保存步骤、全目标已核实覆盖和需介入事项。调用活跃、等待、断连、失败与验收状态分开；没有性能/效率测量时明确未测量，不画达标环。日志默认保留有限高度的最新输出，可展开完整通道/日志，保留滚动、跟随和历史读取。
5. 观察模式压低工具栏、任务定位和历史入口的占比；任务地图默认仅一条摘要，可展开进入此前完整操作，选择地块时自动打开对应详情。建设/装配状态仍保留直接操作。窄屏优先当前行为和异常，避免摘要挤没场景和输出。

## Risks / Trade-offs

- 单人评审独立视角较少 → 配置中明确说明，保留用户决定；所有启用评委必须通过，不自动降人数。
- 历史元数据缺失 → 固定按旧三位解释；人数改变不重新标记历史通过。
- 观察摘要可能与原始输出冲突 → 只统计已保存步骤/完整报告/真实调用，未知明确呈现，原文一键展开。
- 现有浏览器用例依赖全展开日志 → 区分默认观察与主动展开的回归，保留旧输出能力。
