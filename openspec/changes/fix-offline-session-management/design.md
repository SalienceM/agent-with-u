# Design

## Context

动机和范围见 `proposal.md`。已核对的实现事实：

- `Sidebar.updateAppearance` 先改组件状态，再调用 `api.updateSessionAppearance`；返回非 `ok` 即恢复旧值。
- `api.ts` 的 `sessionListCache` 持久化最后一次远端列表，离线可读；在线列表和 `sessionUpdated.summary` 都会替换收藏值，目前没有独立的本设备选择层。
- `BridgeWS._rpc_updateSessionAppearance` 将 `pinned` 与 `sidebarColor` 保存到 Session 索引，`touch_updated=False`，不重写消息正文。现有测试覆盖该约束。
- `Sidebar.confirmDelete` 忽略 `deleteSession` 返回布尔值；通用 `call` 将异常转成 `null`，而 home 离线的 `Conn.request` 可能落到模拟成功。不能只改按钮禁用状态。
- 普通删除会清理远端 Session、消息和相关状态，销毁另行删除工作目录；现有销毁检查和二次确认不是本次要替换的机制。
- 项目要求切换 Relay 用户时清除旧用户连接、路由和离线 Session 缓存。现有 `execKey` 不含 Relay 服务地址，新存储键不能单独复用它；本地直连与 Relay 别名也不能仅凭 Session 名称合并。

## Goals / Non-Goals

**Goals:**

- 独立管理“已观察的远端值”和“本设备未同步的最新选择”，在列表、推送和回执各入口保持一致。
- 用有界、字段级、带版本的同步避免并发覆盖；保留已有用户归属、窗口变更权限和执行端路由检查。
- 将删除提交前失败、明确失败、成功及提交后未知区分，修正界面清理时机。

**Non-Goals:**

- 不建设通用离线 RPC 队列、Relay 收藏数据库、跨设备推送服务或全量 Session 缓存迁移。
- 不新增隐藏 Session 功能；不让删除、销毁、改名、换色、执行、Auto 或文件写入获得离线授权。
- 不保证不同浏览器或设备在执行节点尚未恢复前同步收藏；本设备生效不等于全端生效。

## Decisions

### 1. 本设备选择独立存储，远端缓存不充当待同步队列

新增小型收藏状态模块，使用当前 origin 的 IndexedDB 事务保存版本化记录，键包含连接模式、规范化服务端范围、稳定用户标识、真实执行节点标识和 Session ID。禁止保存认证令牌、完整消息或文件内容。不能证明稳定身份的旧单令牌连接仅保存本设备选择并提示不可自动同步，不使用凭据正文构造存储键。

每个键只保留最后一次选择：`desiredPinned`、本地单调 `generation`、已观察的 `basePinned/baseRevision`、同步状态及当前请求标识。事务提交成功后才发状态通知；配额或写入失败保留原已保存状态并报错。每身份最多 2000 条待处理记录、每条最多 2 KiB，达到上限拒绝新增并说明原因，不能静默逐出未同步选择。同 origin 多窗口通过事务序号及通知重新读取最新记录，避免各窗口整表覆盖。

展示统一投影为“存在本设备待处理选择则采用该值，否则使用远端值”；对 `listSessions`、推送、元数据读取、侧栏刷新和操作回执都应用同一投影。列表缓存仍保存远端观察，不能被本设备值污染成同步基线。成功同步的覆盖层只有在当前 generation 匹配且远端值／版本已进入缓存后才移除。

选择此方式而非仅改 React 状态或直接改列表缓存：后两者分别会在刷新时丢失、在重连时被旧服务器列表恢复。IndexedDB 避免多窗口的普通 localStorage 读改写竞态；不引入新依赖。

### 2. 收藏采用字段级版本化更新

拟新增 `sessionFavoriteGet`／`sessionFavoriteSet` 作为 Session 级协议，首参数为 Session ID，沿用所有权校验及窗口写入门禁。Get 返回协议版本、当前收藏值及收藏专用修订；Set 接收布尔目标值、基线修订与 requestId，返回已提交、冲突、未找到或拒绝等明确结果。相同请求标识及相同参数可确认已提交结果；同标识不同参数拒绝。收藏修订不复用 `updatedAt` 或 LOOP 控制修订。

Session 索引保存收藏修订和至多一条最近收藏操作标识／参数摘要。旧数据初始修订为 0。旧 `updateSessionAppearance` 仍可设置 `pinned`，但必须经过同一收藏提交路径并在实际值变化时推进修订；只换色不推进收藏修订。无论从旧客户端还是新客户端更新，都不得改变活跃时间或重写正文。

条件核对、字段提交和持久化确认须串行化，并与 `SessionStore` 现有索引写锁协调；其它 Session 保存／延迟写不能恢复旧收藏值或修订。先确认原子索引落盘，再安装成功视图并发事件。持久化失败不得留下可被后续 timer 当作成功保存的未确认新值；回滚仅作用于本次收藏字段，不恢复整个旧索引覆盖其它并发变更。

选择版本化更新而不是“先读布尔值再无条件写”：后者存在读写间竞争及收藏值往返变化后误判基线的问题。无需为收藏增加无限历史日志；即使最近回执已被后续更改替换，旧基线也只能冲突，不能重复覆盖。

### 3. 重连只协调明确的收藏选择

协调触发点仅为新的收藏选择、原节点连接恢复和用户手动重试；同目标一次只运行一个协调请求，每节点并发上限 2，每次请求连同就绪等待最多 10 秒。重复列表刷新和推送不独立启动写循环，不增加定时轮询。

协调顺序：

1. 冻结完整身份、目标、generation 和 requestId；重新验证连接、所有权及操作资格。只对该节点使用严格请求路径，未知路由或离线不得走 home 或模拟响应。
2. 只读取得当前值与修订。若与本设备目标相同，记录当前状态已一致；若仍等于已知基线修订，提交条件更新；若基线未知或被其它操作改变且值冲突，保留本设备展示并进入需用户处理的冲突状态。
3. 冲突界面提供“采用远端值”和“保留本设备选择并同步”。后一选择基于新读取的修订重新提交，仍须条件核对，不是强制无条件覆盖。
4. 超时／断线后进入结果未知。恢复时先只读核对，不能因未收到回执就自动重放。若目标值已一致可收敛；若确认基线未变再安全协调；其余情况保留冲突或未知。
5. 任何回执只更新它绑定的 generation；用户在途再次切换时继续显示新选择，旧请求完成后再协调最新代际。已知由本客户端在途请求推进的版本可以成为下一代基线，不把它误判为外部冲突。

旧执行端不支持协议时保留本设备选择并提示待升级，禁止降级到旧无条件写接口后台覆盖；未找到、拒绝和能力不支持不是临时离线，不自动循环重试。

### 4. 身份清理与远端权威删除保留原边界

新模块接入 `clearRelayIdentityState`，清除旧身份的内存、持久待处理选择及在途协调资格，不削弱已有清理语义；回调同时核对身份 epoch。相同身份普通刷新／重开应用恢复保存内容，显式登出／切换用户不承诺保留未同步选择，并给出相应提示。

服务地址变化即使 userId 或 deviceId 相同也属于不同存储范围。仅对已验证的本机与 Relay 同一物理节点别名共享投影；无法证明时分别保存，不猜测合并。节点移除停止自动协调，不能因默认节点改变把待同步操作迁走。权威删除事件或明确已删除结果清理对应待处理收藏；无权限、缓存未命中和局部列表缺失不等于已删除。

选择本机有界覆盖层而不是 Relay 代写：现有 Session 数据属于执行端，Relay 不具备其真实删除／更新结果或替代授权。

### 5. 删除使用严格传输与显式结果状态

将前端普通删除调用改为结构化结果：`succeeded | failed | not_submitted | unknown`，冻结原执行端与身份，使用总时限包含连接等待的严格传输；拒绝 home mock。保留后端现有普通删除布尔协议，仅真实 `true` 为成功，`false` 为明确失败。请求发出后的连接丢失／超时属于未知，发出前已离线属于未提交。销毁的结构化回执同样经过严格传输，既有后端确认与安全检查不变。

`Sidebar` 的普通删除对话框增加进行中及内联错误；失败不关闭会话页签，不调用 `onDeleteSession`。对应删除成功推送与直接回执通过同一目标的一次性完成处理收敛，避免重复清理。输入历史、路由缓存及收藏覆盖只在确认删除后清理。迟到结果不能操作新身份的界面；默认节点离线不应拖住另一个健康目标节点的删除反馈。

未知结果只提供对原目标的只读核对，不保存或重放删除命令。普通 Session 的明确删除事件可确认记录移除；仅列表看不到、权限错误或 Session 不存在不能证明整个目录已销毁。没有证据时保留未知提示；用户再次删除仍需一次新的明确操作及原确认。

选择上述局部修正而非重写整个删除后端或通用 RPC：当前问题是路由、离线模拟和前端结果消费，不能借此扩展成破坏性离线任务系统。

## Risks / Trade-offs

- 本设备已保存不代表其它设备立即生效 → 分别展示待同步／已同步／冲突，旧执行端明确提示能力限制。
- 同一账号多设备离线作出相反选择 → 收藏专用修订及显式冲突处理，不以客户端时间戳判定胜负。
- 后台消息保存覆盖较新收藏索引 → 在统一存储边界保留收藏字段权威修订，覆盖旧对象、timer 和重启回归。
- 浏览器禁止存储、清理站点数据或用户登出 → 保存失败不冒充成功；只承诺正常持久存储和相同身份下的重开恢复。
- 删除结果未知且旧后端没有回执查询 → 保持未知并只读核对，不用自动重放换取确定性，不扩大本次协议为删除任务队列。
- 当前仓库有其它未提交改动 → 实施时仅修改本变更入口及必要测试，隔离验证不触碰生产 Session 或工作目录。

## Migration Plan

1. 先补收藏字段修订和兼容协议，旧记录按零修订加载，已有收藏与底色不改变；不批量重写消息文件。
2. 引入本设备覆盖层。没有覆盖记录时继续使用现有远端收藏，不把全部缓存自动转成待同步任务。
3. 接入侧栏、严格删除反馈与身份清理，执行 Node、Python 和隔离浏览器回归；部署不属于本次任务。
4. 回退前端时不自动重放或丢弃待同步数据；旧版本不会展示新客户端覆盖，需说明该限制。服务端新增字段保持可读；不通过回退恢复已真实删除的数据。
