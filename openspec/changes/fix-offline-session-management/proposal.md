# Proposal

## Why

Session 所属执行节点离线后，侧栏仍能展示缓存，但收藏／取消收藏依然要求向该节点保存，失败便撤回用户选择。普通删除的界面回调还忽略成功结果，容易把离线或失败呈现成操作结束；需要分离可离线的个人列表管理和必须在线确认的远端删除。

## What Changes

- 收藏／取消收藏先可靠保存在当前客户端，立即影响收藏分组；刷新、重开应用和离线列表读取不丢失同一身份下的选择。
- 区分“本设备已保存，待同步”和“已同步”。恢复原节点连接后，仅协调用户明确选择的收藏值；旧列表、旧推送和迟到回复不覆盖新选择，跨设备冲突不静默覆盖。
- 收藏状态按用户身份、服务端范围、执行节点及 Session 隔离；换用户、节点移除、授权失败时不借用默认节点或其它身份同步。
- 普通删除改为检查真实结果并显示失败／结果未知；只有确认成功才关闭对应会话并清理其缓存。已有销毁入口保留独立确认，并同样拒绝离线伪成功。
- 本次不新增“仅从当前列表隐藏”入口，不排队或自动重试删除，不改变删除聊天记录与销毁工作目录的区别；不扩展离线改名、换色、执行、Auto 或文件操作。

## Capabilities

### New Capabilities

- `session-offline-management`: 离线收藏的可靠保存、身份隔离、受控重连同步，以及在线删除的真实结果反馈。

### Modified Capabilities

无。当前主规格中没有侧栏收藏或 Session 删除反馈对应能力；本次不修改 AIMEIN 或工作区文件规格。

## Impact

- 前端：`frontend/src/components/Sidebar.tsx` 的收藏及删除交互；`frontend/src/api.ts` 的列表缓存／事件合并、身份清理、精确执行端请求和删除调用结果；新增可独立测试的收藏状态与协调模块。
- 后端：`src/backend/bridge_ws.py`、`src/backend/session_store.py`、`src/types.py` 中收藏元数据的版本化条件更新及持久化。继续复用 Session 所属用户权限，不增加 Relay 代理写入服务。
- 兼容：已有收藏值作为初始基线，旧客户端收藏／底色调用保持可用；旧执行端不支持安全同步时保留本设备选择并明确提示，不降级为无条件后台覆盖。
- 验证：扩展 `tests/test_session_appearance.py`，补充前端状态单测和隔离浏览器离线／重连／删除反馈用例，保留 `tests/test_session_destroy.py` 的销毁安全回归。不得使用真实用户 Session 做删除测试，不打包部署。
