# Design

## Context

后端 `aimein_bridge` 初始化并发布 `plan: {}`，紧凑推送不包含完整详情；按修订懒加载后才得到计划。`run_summary` 始终提供 criteria、reviews、issues 数组。问题集中在 plan 下的 targets、sprint 与 deferred 未检查便被读取。

## Goals / Non-Goals

**Goals:** 在类型层暴露尚未规划字段，所有读取点安全处理；明确等待、加载与失败反馈；检验真实推进入口。

**Non-Goals:** 不修改规划器输出、后台自动推进、目标覆盖证据或用户数据格式，不增加轮询与依赖。

## Decisions

1. 计划的 targets、sprint 和 deferred 在传输类型中可缺省。渲染读取使用空数组默认值或可选链，保留完整目标条目的必填字段。相比向后端伪造完整空计划，这与现有持久化和懒加载协议兼容。
2. 同一辅助函数为目标观察和执行记录生成无计划状态文案：未加载优先显示加载，已加载且运行显示规划，已停止显示尚无计划并查看阶段状态。错误仍由现有阶段结论展示，不当作成功或一直规划。
3. 动画投影只在真实目标存在时 ready；空计划不产生目标完成度、成果或电流。已有完整计划的动态行为不变。
4. 浏览器夹具可在真实推进 RPC 后发布初始 planning 记录，详情延迟时先消费紧凑状态，再消费 `plan: {}`。随后模拟完整计划、无计划失败与恢复。单元测试覆盖所有计划投影。

## Risks / Trade-offs

- 仅修复一个 JSX 读取会留下记录页或沙盘崩溃 → 审计所有 AIMEIN plan 访问，并通过 TypeScript 编译约束。
- 合成夹具脱离真实协议 → 按后端初始记录与摘要结构构造空计划，不直接从完整计划跳到执行。
- 浏览器验证不能证明生产模型验收 → 明确使用隔离假后端；冻结包另跑就绪与启动探针。

## Migration Plan

无数据迁移。验证后生成新的 Windows 安装包，保留旧安装包与哈希记录；不自动安装或修改用户会话。
