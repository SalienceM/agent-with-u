# Spec Delta

## Purpose

约束 AIMEIN 工作台在启动规划、详情传输、完整计划到达和规划失败之间的可观察行为，使用户始终能够观察真实执行状态、切换视图和操作工作台，避免将尚未产生的计划误判为成果或整体目标完成。

## ADDED Requirements

### Requirement: 尚无计划时工作台保持可用

工作台 SHALL 接受启动阶段空计划和暂缺的计划字段，在目标观察、执行记录及三维或静态沙盘中保持可用，区分加载、规划和已停止的无计划状态。缺少计划 SHALL 不产生已验证目标、成果或推进动画。

#### Scenario: 点击推进后的首次规划
- **WHEN** 用户点击推进，收到 planning 状态与空计划，完整详情可能延迟
- **THEN** 工作台显示对应的加载或规划状态，目标瓶保持未知，用户仍可切换记录及评委视图，不触发全局渲染异常

#### Scenario: 完整计划随后到达
- **WHEN** 当前阶段的完整目标与 Sprint 详情到达
- **THEN** 工作台显示真实目标与阶段范围，继续正常沙盘交互，不把规划本身作为完成证据

#### Scenario: 未生成计划即失败
- **WHEN** 规划失败并保留空计划与错误状态
- **THEN** 工作台保留失败信息与已有操作入口，显示尚无计划，不持续宣称正在规划或目标已完成

#### Scenario: 静态和窄屏体验
- **WHEN** 在窄屏或静态沙盘中经历上述空计划状态
- **THEN** 目标观察与执行记录仍可操作，状态含义与三维视图一致
