# Spec Delta

## Purpose

支持不能访问远端 Git、但安装本地 Git 的 AWU 节点接收独立项目，在本地开展多分支任务，并把具有明确出发基线的成果送回来源节点审阅合并，保持原项目、文件与执行身份可核验。

## ADDED Requirements

### Requirement: 显式跨节点建立独立项目

系统 SHALL 提供主 Session 的发送项目入口，使用当前可访问的真实节点与目标 Backend，自动分配目标目录。两端 SHALL 具备本地 Git；传输 SHALL 只通过 AWU 节点连接，不要求目标访问远端仓库。目标落盘前 MUST 展示独立冻结确认，不受普通跳过确认影响。

#### Scenario: B 不能访问远端仓库
- **WHEN** 用户选择在线 B、目标 Backend 和标题并确认传输计划
- **THEN** B 创建独立本地 Git 主 Session，能够使用既有分支副本功能，不执行 clone/fetch/push 或启动模型

#### Scenario: 节点或 Git 不可用
- **WHEN** 选定节点离线、版本不支持或缺少本地 Git
- **THEN** 明确提示所选节点的限制，不回退本机，不自动安装软件或创建空项目

### Requirement: 快照范围完整可校验

系统 SHALL 冻结已保存到磁盘的当前项目内容，包括已跟踪文件、非忽略新文件、修改和删除，保留原始字节及可执行模式；忽略文件不进入传输。系统 MUST 拒绝链接、子模块、凭据路径、路径穿越、大小写冲突、超预算及不完整快照，不静默省略。MUST NOT 复制 Git 配置、hooks、远端凭据、历史聊天、原生线程或临时授权。

#### Scenario: 未提交与二进制内容
- **WHEN** A 存在已保存的未提交修改、新增二进制和删除
- **THEN** B 获得完整快照，A 的 HEAD、索引与工作文件不变；确认页明确不包含编辑器未保存草稿和忽略文件

#### Scenario: 传输内容损坏
- **WHEN** 分块顺序、总长度、归档哈希、路径或文件哈希不匹配
- **THEN** 拒绝发布 Session 并保留失败/未知回执，不将部分目录标为可用项目

### Requirement: 成果回传保留来源基线

接收项目的主 Session 及本地分支 SHALL 能回传当前成果到原节点。来源节点 MUST 核对本地保存的原交接记录、执行节点与项目身份，从原出发基线建立独立候选分支，并复用现有合并预览、准备、冲突处理和应用确认；MUST NOT 直接覆盖主项目或自动合并。

#### Scenario: A 已经前进
- **WHEN** B 完成任务期间 A 增加提交，B 回传含增改删与二进制的成果
- **THEN** A 获得以原出发基线为父提交的候选，后续合并能区分双方更改并呈现冲突，A 当前文件和分支不变

#### Scenario: 原项目身份变化
- **WHEN** 原 Session 消失、仓库被替换或回传指向错误节点
- **THEN** 拒绝接收为原项目候选，不猜测替代 Session、基线或节点

### Requirement: 持久回执与未知结果

传输 SHALL 使用绑定所有者、执行节点、冻结计划及 requestId 的持久回执；相同请求不得创建第二个项目。已提交操作 SHALL 在面板关闭后保留状态。断线、超时或重启未确认结果 MUST 只读核对原请求，不自动重放写入；成功 SHALL 以文件核验与 Session 落盘核验为准。

#### Scenario: 完成响应丢失
- **WHEN** 创建已提交但客户端没有收到结果
- **THEN** UI 显示未知并提供原请求只读核对；查询成功回执后进入原创建的 Session，不产生重复分支

### Requirement: 按需紧凑交互

系统 SHALL 通过 Session 右键提供发送/回传入口，沿用现有主题、表单和按钮密度；默认只显示目标节点、Backend、标题和主要操作。确认页 SHALL 清楚显示来源→目标、文件数、大小与创建影响，技术细节按需展开。侧栏 MUST NOT 新增常驻传输/分支状态或后台 Git 轮询。

#### Scenario: 窄屏与键盘
- **WHEN** 用户在 390px 视口或使用键盘打开和关闭面板
- **THEN** 表单和确认按钮可用，无页面横向溢出，Escape 关闭并恢复焦点，重新打开可核对已提交操作
