# Design

## Context

见 proposal.md。TaskWorkspaces 只创建共享 commonDir 的同节点 worktree，Session 树要求同执行器父子关系。TaskGit 已封装不使用网络、hooks、外部过滤器的命令和私有索引快照。CollaborationStore 提供所有者/执行器隔离、CAS 与 requestId 回执。现有前端 strict RPC 可通过发起窗口中转节点数据。

## Goals / Non-Goals

**Goals:** B 为独立主 Session，继续使用两层本地分支；A 接收回传后成为普通 task 候选。两端主项目都不被传输覆盖。协议与文件内容分离，有界后台操作不阻塞消息处理。

**Non-Goals:** 不提供远端仓库代理、完整 Git 历史迁移、双向实时同步或自动 push；不安装 Git、不搬迁全局配置/依赖缓存。项目中忽略文件（含忽略的 Skills）明确不复制，所需环境由 B 自行准备。

## Decisions

1. 传输当前文件树快照，而非复制 .git 或完整 Git bundle。A 使用私有索引生成并固定基线提交；压缩包只含版本化清单与按序编号的文件正文。没有历史和仓库配置外泄，B 无需 Git 网络。预算为 2000 文件、单文件 20 MiB、正文合计 64 MiB，拒绝超出而非截断。
2. 导出固化为服务端工件；描述符绑定来源执行器/Session、目的执行器、哈希与原交接来源。256 KiB 分块严格核对 offset，目标先创建仅含元数据的计划，再经 UI 独立确认后接收。传输数据落在 scoped 管理目录，不能指定任意路径。接收完整且哈希正确后以 owned job 导入。
3. B 初始化无远端的本地仓库，完整清单构造 Git tree，核对实际文件，创建空消息主 Session；不复制源 Backend/原生线程/权限。记录来源而不伪造跨节点 parent。子分支通过本地根 Session 找到来源记录。
4. A 保留出发基线的专用 ref 防止 GC；回传只信任 A 自己的原记录。将回传文件树构造为该基线的后继提交，创建新的受管 worktree 和 task 登记。不会覆盖 A 的 HEAD/index/files；A 自己前进后的冲突继续由现有 merge 流程处理。
5. UI 采用 480px 有界对话框，选择节点/Backend/标题→预览→独立确认。跨节点结果通过明确目标执行器打开；模块级操作状态保留到窗口关闭，服务端持久状态支持重开查询。身份改变中止后续传输，未知不自动重试。
6. 新 RPC 不进入模型工具白名单，写入仍经既有 RPC 认证、维护门槛和相关 Session 窗口检查。目标新项目没有现成 Session，其计划由当前已认证所有者与真实目标执行器隔离。

## Risks / Trade-offs

- [快照生成耗时] → 后台线程执行并有界预算；一次导出反复读块，不反复扫描。
- [进程或连接中断] → 接收暂存与新目录保留，不重放写入；回执查询区分 receiving/importing/unknown/succeeded。
- [外部程序并发修改] → 来源前后 fingerprint、完整字节校验与仓库身份检查；不宣称跨机器原子事务。
- [B 不具备构建依赖] → 功能只保证代码与本地分支工作流，确认页说明忽略文件不复制。
- [接收端不支持符号链接或路径碰撞] → 两端统一拒绝不可移植路径，避免部分成功。

## Migration Plan

新增协作记录类型与 RPC，不修改旧 Session 结构。两端更新后入口可用，旧端明确报不支持。回退版本保留已有目录、Session、分支和回执，不自动删除成果。
