# Proposal

## Why

`refactor-loop-workbench` 将阶段轨道、面板/流程切换、轮次分数环及风险指标移除或降为详情，削弱了用户认可的 LOOP 可视化迭代体验；真正难懂的任务来源、工作流依赖和环境处理仍以整块配置呈现。当前前端还把“预检不支持但没有已知阻塞”误作恢复门槛，需要同时纠正交互层级和状态含义。

## What Changes

- 恢复原有风格的三阶段轨道、面板/流程切换、轮次卡与分数环、最近/最佳评分、风险和轮次预算；流程泳道、步骤耗时与实时输出重回主工作区。
- 恢复直接可达的目标编辑、Addon 补充、策略与心智、运行/断点恢复、Auto、停止和人工接管入口；两个视图共享状态与动作，不恢复重复请求或危险操作误触。
- 评分和风险仍用于观察迭代，任务勾选、实现、验收和人工待办独立表达；不恢复旧版按历史最高分直接生成“可交付/可输出”的错误判断。
- 将截图所示的大块任务设置拆为任务来源管理、运行诊断和定向问题处理：正常来源仅摘要，改绑/解绑按需确认，问题直接定位原因、受影响任务、解除条件与具体操作。
- 分离提示严重程度与运行资格：预检不支持/覆盖不足不单独禁用运行，已有故障和硬暂停不被弱证据清除，局部阻塞不由前端扩大为全局阻塞。
- 展示实际生效依赖及来源，区分正式任务绑定与显式工作流选择；已绑定 OpenSpec 时不再误提示还必须选择工作流。
- 保留懒加载、跨身份迟到响应隔离、阶段审计、控制权回执和测试隔离约束，不回滚后端保护或生产 Session。

## Capabilities

### New Capabilities

- `loop-workbench-experience`: 恢复以可视化迭代为主的面板和流程、稳定控制区、按需辅助操作及可验证的布局。沿用旧 change 中尚未同步到主规格的同名能力，不另建平行概念；本变更明确替代其相冲突的展示要求。

### Modified Capabilities

- `loop-execution-environment`: 分开展示检查覆盖与真实阻塞，显示生效依赖来源，按需诊断，不以覆盖不足制造运行门槛。
- `loop-openspec-task-reconciliation`: 明确正常来源、候选选择、范围冲突与解绑各自的交互路径，保留显式确认及只读核对边界。
- `loop-continuation-decisions`: 明确运行/恢复资格与问题显示优先级分离，问题操作直达对应处理对象，执行端仍在请求边界重新核验。
- `loop-milestone-progress`: 明确恢复的面板、流程和评分展示共用正式任务/子里程碑事实，不混算进度，并覆盖旧重构尚未同步的展示条款。

## Impact

- 前端：`LoopPanel.tsx`、`LoopWorkbench.tsx`、`loopWorkbenchView.ts`、`useLoopWorkbenchState.ts`、来源/环境/控制组件及相关类型和回归夹具。
- 后端：必要的有界动作资格、生效依赖与问题关联摘要，复用现有来源、环境、控制权和续跑核验；不新增独立调度器或绕过路径。
- 测试与文档：扩展合成状态、假 Backend、桌面/窄屏浏览器回归及 LOOP 入口说明；不新增 UI 框架。
- 基线为当前提交 `1800ae4`，恢复的交互参照 `26f3201`，只移植展示与交互，不整文件回滚。
- 与未归档的 `refactor-loop-workbench` 有明确规格冲突，后续同步应按旧变更到本纠偏变更的顺序合并，并以本变更的同名要求为最终文本；具体核对规则见设计。本轮不修改旧 change、不同步主规格、不归档、不实施代码。
