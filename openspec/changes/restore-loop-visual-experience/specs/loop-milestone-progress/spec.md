# Spec Delta

## MODIFIED Requirements

### Requirement: 子里程碑与正式进度分开展示并兼容历史

系统 SHALL 在面板、流程主视图及按需详情分别展示正式任务完成度、子里程碑状态及本轮被认可的增量与依据，使用同一身份和修订的记录。恢复的评分、分数环和风险指标 SHALL 作为独立观察数据，不替代任务或子项验收，也不与父子任务数量混算比例。新增数据 SHALL 版本化、按需加载并受节点/Session 隔离约束；旧记录缺失子项时 MUST NOT 自动构造历史里程碑或完成比例。

#### Scenario: 面板和流程视图一致
- **WHEN** 用户查看同一轮的面板、流程主视图或对应详情
- **THEN** 各处显示一致的父任务进度、子项结果、证据失效及调度原因，紧凑视图不混算父子任务百分比；两种主视图不因恢复评分或切换显示而产生不同验收结论

#### Scenario: 旧客户端保存策略
- **WHEN** 未识别新字段的客户端更新既有策略或加载历史记录
- **THEN** 已存里程碑及来源修订不被省略字段清空，历史缺失值显示为不可得，不改变普通聊天或人工接管行为

#### Scenario: 正式勾选不变但子项推进
- **WHEN** 正式任务仍为 7/25，一个有效子里程碑由待处理推进为已实现待验，且评审分数发生变化
- **THEN** 两种主视图分别展示正式任务计数、子项推进及评分变化，不提前勾选父任务，不将评分或子项数量换算为新的正式完成比例
