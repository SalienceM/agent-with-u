# Spec Delta

## MODIFIED Requirements

### Requirement: 来源快照展示与兼容

系统 SHALL 在 LOOP 用紧凑摘要展示绑定来源、当前/过期/冲突/不可用状态和正式任务勾选数量，按需显示最近核对时间、完整身份和与评审的差异。正常绑定、选择/更换来源、范围冲突及解除绑定 SHALL 有各自明确入口和确认表单；正常主视图及普通来源详情 MUST NOT 常驻解除绑定的处置输入。完整快照 SHALL 按需读取，不进入普通聊天历史或高频广播；跨节点、跨 Session 和旧修订响应 MUST NOT 相互覆盖。旧 LOOP SHALL 不被静默自动绑定。

#### Scenario: 旧 LOOP 加载
- **WHEN** 旧 LOOP 没有来源绑定字段
- **THEN** 系统以紧凑的可选来源入口维持通用行为，不常驻发现表单、不从历史自由文本自动猜测权威 change；用户可空闲时显式发现并绑定

#### Scenario: 切换会话后晚到快照
- **WHEN** 用户在来源查询未返回时切换节点或 Session
- **THEN** 晚到结果仅属于原请求身份，不修改当前绑定或展示为当前任务清单，重连与重复推送不形成轮询

#### Scenario: 正常绑定日常查看
- **WHEN** 来源已核对且没有范围冲突
- **THEN** 面板与流程均可读到同一来源和任务勾选摘要；点击来源查看核对记录，管理操作按需展开，不展示无变化差异的大段文字或暗示必须重新绑定

#### Scenario: 发现候选与更换来源
- **WHEN** 用户明确选择绑定或更换来源
- **THEN** 系统执行有界发现并展示真实候选，即使只有一个也须确认；更换时按既有规则说明旧范围处置，取消不写入，不选择最新 change 作为隐式权威来源

#### Scenario: 范围冲突直接处理
- **WHEN** 来源范围变化使工作等待核对
- **THEN** 问题入口直接定位新增、删除、改义或无法映射的差异及相应确认表单，保留来源修订和未解决事项；核对或确认不自动恢复任务

#### Scenario: 主动解除绑定
- **WHEN** 用户选择解除绑定
- **THEN** 单独展示解绑影响和处置依据输入，提交仍校验空闲、断点、权限及来源修订；取消不改变来源，成功也不抹除旧问题、损失或必要验收，不以解绑自动解除暂停

#### Scenario: 查看与管理权限不同
- **WHEN** LOOP 正在运行、存在不允许改绑的断点或处于人工只读总览
- **THEN** 仍可按需查看来源证据，管理和核对动作遵守既有执行端资格并给出具体不可用原因，不因界面移动放宽限制
