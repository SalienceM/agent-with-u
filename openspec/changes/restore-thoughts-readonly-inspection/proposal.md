# Proposal

## Why

「俺寻思」把“不干预主线”错误实现为“仅基于界面快照和常识”，用户已经给出当前项目及 OpenSpec 目录，仍被要求手工补充 tasks 内容；运行摘要也未接入新 OpenSpec 驱动的进度。需要恢复其作为项目旁路助手的价值：独立答疑、看到实际运行状态，并按问题主动只读查证，而不是让用户搬运本可读取的数据。

## What Changes

- 普通 Session 与 LOOP 共用只读查询能力：可按需查看当前 Session 工作区的目录、相关文本及 OpenSpec 任务；界面附带文字不再是唯一信息源。
- 查询请求冻结所属用户、执行节点、Session、工作目录和 Backend；由执行端核验并执行受限读取，不开放任意 shell、写工具或主线控制。支持的模型通过统一查询协议读取，不能仅靠“请勿写入”提示词保护。
- 每次提问获取当前运行摘要，涵盖 LOOP 轮次、阶段、步骤状态、阻塞、原任务勾选、人工待办及最新 verify 缺陷；区分采样时刻、文件事实与模型判断。
- 明确/已关联/唯一 OpenSpec change 可直接只读查看；多候选时列出候选并按问题选择或汇总，不要求来源绑定、不修改现有绑定、不因读取启动 LOOP。
- 原 tasks 勾选统计与业务验收分开；人工项保持原标记。文件不可读、过大、变化中或真实来源不支持时说明具体原因，不能虚构进度或索要“补快照”。
- `@SKILL` 只增加参考资料，不改变 Session 焦点或剥夺同一只读查询能力；Skill 市场独立文档解读仍保持无工具行为。
- 用“当前关注对象 / 项目只读查询 / 正在读取 / 回答完成或失败”等清晰反馈替换“已带入 N 字快照”的能力暗示，保留固定注意力、历史、附图和停止回答。

## Capabilities

### New Capabilities

- `thoughts-readonly-inspection`: 定义俺寻思的独立只读项目查询、当前运行证据、OpenSpec 进度解释、来源身份及可观察交互。

### Modified Capabilities

无。此能力只消费 LOOP 状态及工作区文件，不改变 `loop-openspec-task-reconciliation` 的权威绑定/调度/验收规则，也不修改尚未归档的 `refactor-loop-openspec-driver`。

## Impact

- 后端：`bridge_ws.py` 的 LOOP/普通旁路入口、摘要、取消和事件；`aside_context.py` 的有限项目读取；新增共享只读查询协调层及证据模型；复用 `text_only.py` 的隔离推理，不放开其通用文档解读权限。
- 前端：`ThoughtsAssistant.tsx`、`attentionContext.ts`、旁路事件/类型的增量兼容；不重做主面板，不修改 LOOP 启动/控制权协议。
- 测试：扩展 thoughts/aside/Skill 参考测试，新增临时项目安全读取、真实 tasks 统计、并发身份/取消、浏览器反馈回归。验证不使用生产 Session 或付费模型。
- 不迁移主聊天上下文，不增加自动安装、写文件、勾任务、启动/停止主线、跨节点回退或凭据读取。SSH 远端及外部工作区在没有经过验证的只读传输时明确不支持，不读取执行端同名目录。
