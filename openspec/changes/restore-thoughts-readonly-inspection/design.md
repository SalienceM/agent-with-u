# Design

## Context

动机见 proposal.md。已确认的实现事实：

- `bridge_ws.py::_run_aside` 明确要求“仅基于快照和常识回答”，普通旁路的约束稍弱，但两者均未建立统一的只读执行能力。普通分支传入 `working_dir`、`skip_permissions=True` 和 Session 沙箱开关，不能据此宣称具有强制只读保证。
- `_loop_context_digest` 只有旧阶段、编排描述、结果及评分分析，没有消费新 `openspec_run` 中的原任务计数和 verify 问题；步骤描述也不能替代正在执行/失败等状态。
- `@SKILL` 走 `_send_skill_manual_answer` / `text_only.send_text_only`。后者确实禁用了原生工具；它适合隔离文档推理，但目前外部没有按需查询协调层，造成项目能力退化。`aside_context.project_reference_snapshot` 仅检查浅层目录与少数固定文档，不会读取 change 的 tasks。
- `ThoughtsAssistant` 已具备固定注意力、独立历史、附图、独立窗口和停止入口；“已带入 N 字界面快照”只统计关注对象正文，不代表全部实际上下文或权限。
- `tests/test_thoughts_attention.py`、`tests/test_aside_context.py` 和前端 attention/skill-groups 用例已覆盖身份、历史、参考 Skill、有限读取和部分越界，缺少主动查询与强制只读的端到端契约。
- 主规格 `loop-openspec-task-reconciliation` 与未归档 `refactor-loop-openspec-driver` 存在已知的绑定/调度新旧语义。此变更不统一或覆盖它们：旁路只消费状态并读取文件，不调用权威绑定/核对/调度入口，其查阅目标不是主线来源。

## Goals / Non-Goals

**Goals:**

- 用统一受限查询边界满足 CLI 型与 API 型 Backend 的项目答疑，不依赖模型是否碰巧遵循“不要写入”。
- 运行状态、文件证据与界面上下文分层；提供新鲜度、范围、故障信息，避免“快照外一概不知道”。
- 将当前主线与旁路生命周期隔离，沿用实际节点路由，保持 UI 响应和旧历史兼容。

**Non-Goals:**

- 不让俺寻思实施、验收或操纵主线；“加入主流程队列”仍是用户另行点击的既有动作，不能由回答或查询协议调用。
- 不做任意终端、全盘搜索、浏览器操作、凭据读取、全仓库索引或持续监控；不为 SSH 和外部 store 新增文件系统传输。
- 不改变全局沙箱设置、主聊天工具权限、Skill 市场纯文档答疑、LOOP 接管/恢复或 OpenSpec 收口规则。

## Decisions

### 1. 统一只读查询协调层，保留无原生工具的模型推理

新增共享的 aside 查询协调层，由普通 Session 和 LOOP 入口共同调用。模型通过有界结构化查询包请求 `runtime_status`、`list_directory`、`search_text`、`read_text`、`openspec_tasks`，执行端仅分派这些操作；不得把输出字符串解释成 shell、任意 RPC 或 Python 表达式。

复用 `send_text_only` 作为隔离推理通道：模型决定需要什么资料，服务端实际查阅并把有界结果传回，再生成答案。它不再等同于“仅回答初始快照”。每轮协议只接受 `query` 或 `answer`，查询包严格校验类型、参数、请求归属和预算；协议损坏最多一次纠正，计入总预算。最终正文输出与内部查询包分开，原始协议不展示给用户。

现有六类文本 Backend 沿用隔离推理适配；不支持的类型明确报错。API 的工具接口或 Codex `execution_access=read-only` 可以作为未来适配参考，但本次不再并行建立另一条原生 agent 查询路径。原生只读模式并不天然限制读文件范围、网络或 MCP，单独设置它不足以实现本需求；也不通过 `skip_permissions=True` 恢复项目能力。独立 Skill 市场继续直接使用原 `send_text_only`，不获得查询协调层。

### 2. 冻结执行身份，不让注意力数据决定权限

入口从服务端 Session 和已认证连接取得 owner/executor/session/root/Backend，生成旁路 request/turn 身份，携带当时控制范围及可用读取约束。前端的 `detail`、模型输出的绝对路径、`@SKILL` 或资料中的链接不能改写该身份。每次执行查询重新校验 Session 存在、路由/工作目录未变化及请求未取消；配置改变则终止本次后续查询。

固定注意力冻结“问哪个对象”，不冻结未来每次提问的运行状态。用户切换面板不会把已发送请求搬到另一节点；已结束结果只回填原问答。另选的 aside Backend 创建失败时返回错误，禁止原有静默改用主 Backend 的行为。SSH Session 不读取执行端同名路径；Relay 到正常执行节点时只在该实际节点内查询，不回退本机。

### 3. 读取边界由受限文件服务执行

从 `aside_context.py` 的路径约束复用思路，新增按需目录/文本服务，不把现有固定 README 白名单当作唯一可读文件。允许相关源码、规格、任务和配置文本；拒绝凭据类文件（如 `.env`、私钥、认证/token 文件）、二进制、设备/UNC 特殊路径、Windows ADS，以及 `.git`、依赖和构建产物的自动递归遍历。显式普通文本请求仍须过同一敏感文件策略。

绝对路径须归一化为当前 root 内路径。路径检查不使用字符串前缀；遍历时不跟随链接或重解析点。实际打开文件时验证句柄对应的最终目标与文件类型，不仅先 `resolve` 再盲读，避免检查/读取间替换导致越界。无法安全确认时拒绝返回内容，不改 ACL、不换身份。相关系统调用放到有界工作线程/受拥有权管理的读取任务中，不持有 Session 内存锁进行磁盘 I/O。

服务仅有读取入口；既有正常聊天的权限/工具配置不被修改。Session 的明确读取限制只能收紧查询范围。需要扩大到项目外时不在本需求内默许。

### 4. 三类证据分别组织，不把资料大小当能力

每次提问构建有界 evidence envelope：

1. 当前运行证据：采样时间、轮次/阶段/步骤状态、running/Auto/stop reason、真实阻塞摘要、来源身份、OpenSpec 计数及最近 verify 结论；从内存状态和已有持久化详情投影，不触发模型或来源绑定。普通 Session 只提供可见聊天/运行摘要。
2. 当前关注对象：原界面文本/图片以及固定状态，仅用于解释“这里”。保留截断标记。
3. 本次实际查询结果：相对路径、定位、读取时间、修订、返回范围、是否完整及失败分类。需要当前事实时可刷新运行证据，但每次操作仍受同一预算。

优先本次事实而非历史旁路中“不能读取”的答复。文件读取结果与旧运行报告冲突时并列标出时刻/修订，不修改主线记录，也不宣称最新文件自动证明实现验收。持续运行不能获得事务级全局一致视图；明确是某次采样，不能声称实时订阅。

### 5. OpenSpec 进度使用只读本地事实，不借道执行器

查询顺序为本轮明确目标 → 当前有效关联 → 工作区唯一真实候选。请求另一个合法 change 只改变本次查阅对象，不改变主线绑定。目标缺失/关联失效不自动替换；多个候选返回清单，明确“全部”才分项汇总。

`openspec_tasks` 在当前工作区读取标准 change 的 tasks，复用适用的现有解析/人工策略纯函数，但不调用 `_loop_openspec_*` 调度或来源绑定写方法。排除代码围栏内示例，按项目 checkbox 约定仅将去空白后为 x/X 的标记计为完成，其余合法任务标记计为未完成，并保留编号和行号；完整文件按同一修订统计。自定义 schema、外部 store、找不到 tasks 时只能说明观察到的事实，不能凭目录存在断言没有任务。此入口不运行 CLI、不初始化 OpenSpec；已有 CLI 状态可以标明原采样时间引用。

返回总任务、已勾选、未勾选、任务位置和百分比；无任务时百分比为空而非 100%。有明确用户/既有策略依据才标人工排除，独立人工项与混合实现项分开。原清单 6/10 与自动范围 6/8 必须分别命名。模型 verify 是另一种证据，不由统计服务生成或启动。主线读取期间发生更改，最多一次重新读取；不能把多次分段结果跨修订累加。

### 6. 统一预算、取消与错误语义

初始预算作为集中可测试常量：一次提问总处理 180 秒，最多 4 个查询决策轮次及 1 次最终回答（协议纠正也占决策额度），最多 24 次只读操作。单次目录页最多 200 项、限定搜索最多访问 200 个合格文件、文本页最多 16,000 字符、单文件完整核对最多 256 KiB、累计读取最多 1 MiB，送入模型的项目证据累计最多 64,000 字符；超出分别标记覆盖不足，不能省略后冒充全量。

以已有请求级旁路登记扩展拥有权：提交时登记，防止后台任务开始前的双击竞态。查询任务、模型调用、计时器和取消均属于该 request，不使用主线 agent_session_id。停止后不再调度下一次读取或模型；已在运行的读取/模型必须确认结束，未知则保留本旁路预留并显示待确认，不把未知当完成。该预留不锁主 LOOP 或其他 Session。总时间预算不代表 OS 操作一定立即退出。

缺失、拒绝、超限、变化中、unsupported、身份失效及模型错误分别返回；部分模型输出后报错仍是失败，不因为已经收到文字就标记 done。查询失败可带已获得证据解释原因，但不通过换 Backend、节点、权限或自动重试无限补救。已有 Session 暂停、任务阻塞不阻止纯旁路读取，旁路失败也不得暂停主线。

### 7. Skill 参考与项目查询合流，保留 UI 能力

`manual_content` 只作为 evidence 的参考资料，不再决定是否绕过统一查询流程。显式引用 Skill 不授予执行该 Skill 的权限；普通项目问题也不要求引用 Skill 才能读项目。保留 `_skill_reference_snapshot` 的实际注册命令事实，避免把手册命令宣称为已安装入口。

`ThoughtsAssistant` 主面不再以“已带入 N 字界面快照”描述能力，改为当前关注对象与只读查询状态。内容长度/截断可留在详情。提交立即显示“正在准备”，由真实事件驱动“正在读取 <相对路径>”“正在回答”，结束显示完成/失败/已取消；未知清理显示待确认。来源详情按需展开，不增加常驻诊断面板或让用户逐文件批准正常范围内的读取。失败保留问题文本及必要的重试入口，重试是新请求，不自动重放。

复用旁路事件通道，增量加入 request 身份、阶段和有界 provenance；组件按 owner/executor/session/turn 过滤。保留悬浮/停靠/分离窗口、固定注意力、按对象历史、附图与停止入口，跨窗口固定的是目标不是权限。

### 8. 元数据可回看，全文保持瞬时

AsideTurn/ChatAside 只扩展可选查询摘要和来源元数据，不存文件全文、全部查询包、隐藏思维、凭据或重复图片。正文作为本次上下文，用完释放；最终答案允许必要引文，不由系统额外复制全文。老记录默认“未记录查询来源”，不回填假的时间或能力，不打开历史即重新查盘。

## Risks / Trade-offs

- [多轮查询增加延迟和费用] → 明确进度问题优先执行确定性 tasks 查询；相同请求/修订复用结果，设置轮数与时间预算，不为已充分的答疑强行查文件。
- [模型输出查询协议不稳定] → schema 校验与一次有界纠正；失败如实结束，不退回拥有写工具的调用。不同 Backend 使用相同 fake 协议矩阵验证。
- [路径竞态和 Windows 路径语义复杂] → 验证真实句柄目标、不跟随重解析点、特殊路径拒绝；Windows 专用夹具必须执行，平台不支持的行为不能伪造通过。
- [运行与文件同时变化] → 保留各证据修订/时间，任务统计使用同一文件版本；不追求停止主线来取得一致读。
- [既有用户可能依赖旁路的意外写能力] → 明确将其视为不受支持行为；保持主聊天权限不变，不静默放开。
- [任务格式超出标准解析] → 显示可读文件及不支持的格式；不将失败算成零任务，不按正文猜测验收。

## Migration Plan

1. 先实现并测试受限查询/证据模型，再接入普通与 LOOP 旁路；不得只先删除提示词限制并留下原无约束分支。
2. 同步更新前端可选事件字段、来源详情及说明。旧记录可读，无需重写用户数据；旧客户端忽略新增字段仍能显示原问答。
3. 使用 fake Backend、临时仓库与隔离浏览器验证成功、拒绝、取消、并发和故障路径。记录自动化与实际部署验收的边界，不运行付费模型或生产项目进行自动验收。
4. 更新项目文档与 AGENTS，随后由用户独立决定部署。回退时保持只读约束或明确关闭项目查询，不能回退到 unrestricted agent；不删除旁路历史或改动 LOOP 主线状态。
