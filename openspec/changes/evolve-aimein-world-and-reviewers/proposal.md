# Proposal

## Why

AIMEIN 已有动态 Sprint 和三模型验收，但卡片式界面没有表达产品逐步建成的过程，用户意见与评委经验也没有可复用的结构。需要让目标、成果、反馈和评委共同成为可观察、可追溯的持续建设场景。

## What Changes

- 用方块工坊场景呈现目标灯塔、目标瓶、功能区、基础设施、成果架和评委席；点击对象查看依据、历史并提出建议。
- 目标瓶依据当前目标的三方共同核实结果，阶段成熟度独立显示；成果保留，缺口和未知不能伪装成进度。
- 将对象意见保存为带来源的补充，进入下一次规划，关联验收条件并显示处理结果。
- 建立版本化评委档案：模型与运行配置、口味、聚焦、领域和校准记录。冻结每次评审使用的版本。
- 根据任务匹配与用户校准证据推荐模型和档案组合，解释理由及样本不足；支持主动选择与档案 JSON 导出/导入。

## Capabilities

### New Capabilities

- `aimein-world`: 场景、目标容器、对象观察与反馈闭环。
- `aimein-reviewer-growth`: 版本化评委档案、校准和可解释推荐。

### Modified Capabilities

无。依赖尚未归档的 `add-aimein-execution-mode`，延续其执行与工作台要求。

## Impact

涉及 AIMEIN driver、LoopState/Addon 持久化、BridgeWS RPC、前端工作台和评审设置、隔离后端与浏览器验收。复用 OrderedLoopWrites、节点/会话身份和原有执行门槛。无需新游戏引擎、外部服务或模型训练。档案默认限于本会话，跨会话复用由用户显式导入；不会自动收集其他项目内容。
