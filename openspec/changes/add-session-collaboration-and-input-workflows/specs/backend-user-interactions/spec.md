# Spec Delta

## Purpose

使各 Backend 的原生结构化提问和执行审批能够在正确的 Session 中被看见、回答并回传，同时让自动跳过的过程可追踪。区分真正的协议请求与普通文字提问，防止空答案、错会话响应及隐式扩大授权。

## ADDED Requirements

### Requirement: 交互种类与能力真实表达

系统 SHALL 区分执行审批、结构化用户问答及需要独立确认的产品操作，并按实际 Backend、协议版本与连接模式声明支持的问答字段、回传方式及跳过语义。普通文本中的问号 SHALL 不被推断为原生请求；未知协议 SHALL 明确报告，不静默丢弃或伪装成功。

#### Scenario: Codex 发出原生输入请求
- **WHEN** 受支持的 app-server 发出带关联 ID 的结构化用户输入请求
- **THEN** 界面显示完整问题与真实选项，可提交协议匹配的答案，不能走“未实现远端请求”或布尔审批响应

#### Scenario: 仅有普通文字提问
- **WHEN** 助手正文写“是否继续？”且没有原生请求事件
- **THEN** 按普通对话显示，不弹原生问答卡、不自动代表用户回答

### Requirement: 正确呈现和提交答案

系统 SHALL 按协议支持单选、多选、自由输入、多问题及必填校验，保留问题顺序与真实选项 ID；提交前用户可修改，提交后显示接收状态。单个 Session 多个请求与多个 Session 同时等待 SHALL 独立呈现，响应必须绑定原运行和原请求，不仅依据 Session ID。

#### Scenario: 多问题一次提交
- **WHEN** 原生请求包含多个问题且其中一个必填答案尚未完成
- **THEN** 保留已填内容并指出未完成项，不能发送空答案或只回传最后一题

#### Scenario: 两个窗口同时回答同一请求
- **WHEN** 两个控制端对同一真实请求分别提交答案
- **THEN** 第一份有效响应至多消费一次，后续重复得到已有回执或冲突说明，不覆盖原选择或回答另一个请求

### Requirement: 跳过有明确语义和可见反馈

系统 SHALL 在用户开启跳过确认时，自动处理当前权限范围内可跳过的执行审批；对于结构化问答，仅使用原生协议明确支持的 skip/defer/取消本次问题但允许继续语义，或协议明确标注为可自动采用的非授权默认值。系统 MUST 展示自动处理方式及依据，不伪造必填答案、不把推荐选项当作用户选择。不能安全跳过时 SHALL 保留待回答并说明原因。

#### Scenario: 协议允许跳过提问
- **WHEN** 用户已开启跳过确认且原生问答声明可跳过
- **THEN** 系统自动返回对应协议响应，在对话流显示“已按设置跳过”及可展开的问题，主轮按实际协议继续

#### Scenario: 必填输入没有跳过语义
- **WHEN** 提问要求目录、名称等必要答案且原生协议无跳过能力
- **THEN** 显示“此问题仍需回答”的简要原因，不默认填空、不选择第一个选项、不将许可布尔值充当答案

#### Scenario: 请求是 Kit 或跨工作区确认
- **WHEN** 跳过确认开启但收到发布、安装或跨 Session/节点的独立确认
- **THEN** 保留该操作原有确认边界，不从普通跳过设置推导对应授权

### Requirement: 各 Backend 的支持与降级可验证

系统 SHALL 对 Codex app-server/旧 exec、Claude SDK/CLI、Qwen、Harness 和 API Backend 分别提供基于真实协议的兼容结论。可接通的原生问答 SHALL 双向适配；协议确实不能回传答案时 SHALL 保留清晰可见的受限状态及普通下一轮文字答复路径，不宣称原生支持。工具聊天 API SHALL 使用受控结构化问答通道；纯聊天/图片路由不得伪造工具能力。

#### Scenario: Qwen 通道不能回传答案
- **WHEN** 所选 Qwen 版本的确认接口仍只有允许/拒绝而无法提交答案
- **THEN** 保留有原因的降级提示并引导正常结束本轮、下一轮回复，不把 ask_user_question 自动 allow 成功返回空答案

#### Scenario: 支持情况变化
- **WHEN** Backend 或连接模式变化
- **THEN** 重新使用对应能力结论，旧请求不转移到新原生线程，未知版本不沿用未经验证的支持声明

### Requirement: 有界等待与恢复回执

系统 SHALL 持久记录可重建的交互摘要和状态，区分等待、发送中、已响应、自动处理、过期、取消、失败及结果未知。重连 SHALL 查询原请求真实状态，不能自动重放用户答案；原生连接已消失的请求不得伪造可续接。停止及超时 SHALL 按协议关闭原等待，保留未知退出保护。

#### Scenario: 用户回答时发生断线
- **WHEN** 答案可能已经到达原生运行但回执缺失
- **THEN** 显示结果未知并保留答案草稿，核对同一请求状态；不向新轮次发送相同答案，不自动重启任务

#### Scenario: 非当前 Session 等待回答
- **WHEN** 后台 Session 收到有效提问
- **THEN** Sidebar/标签显示待回答提示，打开后定位原问题，不能把卡片放到当前聚焦的另一会话
