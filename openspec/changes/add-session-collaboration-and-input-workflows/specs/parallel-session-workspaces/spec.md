# Spec Delta

## Purpose

让同一项目的多个独立需求以二级子 Session 组织，并通过独立分支和 worktree 同时工作，避免文件相互覆盖。成果汇合提供明确来源、目标、冲突和真实回执，保持任务独立性与已有项目数据。

## ADDED Requirements

### Requirement: 项目任务组与独立子会话

系统 SHALL 允许从主 Session 右键创建多个分支副本，并在 Sidebar 父项下折叠展示；子项右键提供合并到主 Session 和打开主 Session。仅支持两层，服务端 MUST 拒绝子 Session 再派生。创建默认继承 Backend、模型、推理、Skills/Prompts、约束及持久运行偏好，并冻结在可审阅计划中；主配置变化必须重新预览。原生线程、聊天历史、队列、定时任务及临时授权不复制；关闭/折叠父项不得停止或删除子任务。旧 Session SHALL 保持可达。

#### Scenario: 同时运行多个需求
- **WHEN** 用户为同一项目提交三个独立需求
- **THEN** 三个子 Session 分别显示活动、待回答和完成状态，可独立切换及停止，父项提供汇总且不抢占当前焦点

### Requirement: 分支与工作目录同时隔离

系统 SHALL 为每个并行任务创建唯一分支与独立 worktree，绑定项目真实仓库、基线提交、执行节点及子 Session。创建成功 SHALL 以 Git 和 Session 落盘回执为准，不以路径已存在作为成功。系统 MUST NOT 通过在共享目录反复 checkout 冒充并行隔离。

#### Scenario: 同时修改同名文件
- **WHEN** 两个子任务同时编辑相同相对路径
- **THEN** 各自磁盘内容、暂存区和提交保持独立，主目录不受子任务写入影响；用户能看到每个任务的分支与工作目录

#### Scenario: 主目录有未提交修改
- **WHEN** 用户创建任务时主目录含未提交或未跟踪文件
- **THEN** 创建副本默认选择当前受控项目文件，包含修改、删除及未跟踪文件，以私有索引形成新分支基线；主目录文件、暂存区和 HEAD 不变。忽略的项目 Skills 独立复制，缓存、依赖、构建产物及其他忽略内容不自动复制。预览列明范围和受阻文件，超限、凭据、链接或读取失败不得被静默跳过并宣称完整；用户可显式改选部分路径或仅提交基线。

#### Scenario: 从子 Session 合并
- **WHEN** 用户右键子 Session 选择合并到主 Session
- **THEN** 界面按真实父子 ID 固定来源和目标并展示计划，沿用独立准备、核对和应用确认；整合 Session 在数据上仍归属目标主项，不产生孙级关系。存在可核对合并关联时，普通列表与副本计数收拢整合空间，通过合并历史按需打开；活动提示、已有标签、收藏、搜索及无关联/孤儿恢复入口保持可用，不删除或重写关系。

#### Scenario: 无仓库或不支持 worktree
- **WHEN** 目录不是 Git 仓库、没有可用基线提交或目标节点缺少必要能力
- **THEN** 提供具体原因和可选的显式准备入口，不伪称已经隔离、不静默初始化仓库或换节点执行

### Requirement: 汇合具有可审阅计划和一致操作入口

系统 SHALL 支持从界面或聊天提出“将任务 A 合入 B”等请求，解析真实来源、目标和提交，生成包含变化范围、脏状态、活动状态及冲突检查的计划。明确请求和无歧义计划满足既有权限边界时 SHALL 可执行，无须把同一句授权再写一遍；存在歧义或需要独立授权时 SHALL 显示具体候选或计划。所有入口 MUST 使用相同核验和执行服务。

#### Scenario: 安全汇合已提交成果
- **WHEN** 用户请求将已完成且提交的任务 A 合入空闲、干净的任务 B，计划核对通过
- **THEN** 系统按冻结的来源/目标提交执行合并，保留来源任务，展示目标新提交及真实结果，不自动推送远端

#### Scenario: 目标仍在写入或计划已过期
- **WHEN** 目标仍有 Agent、队列、编辑器未保存改动或相关写入活动，或预览后任一提交/工作树发生变化
- **THEN** 系统不按旧计划合并，保留现有任务并提示等待或重新预览，不暗中中断运行、stash、reset 或覆盖文件

#### Scenario: 自然语言目标不唯一
- **WHEN** 聊天中的任务名对应多个 Session
- **THEN** 返回真实候选供选择，不根据当前窗口或默认分支猜测目标

### Requirement: 冲突可处理且失败不丢成果

系统 SHALL 将汇合冲突作为可见待处理状态，显示文件和处理入口，允许在独立整合空间解决并验证后再应用。原目标 SHALL 在结果验证前保持不变。用户取消、失败或断线不得自动删除分支/worktree或丢弃未提交修改；结果未知时不得自动重放。

#### Scenario: 两个任务修改同一行
- **WHEN** 冻结计划在整合空间产生冲突
- **THEN** 主目标不变，保留冲突及两个来源，可在独立整合 Session 处理；解决冲突和测试通过仍需核对目标未变化才能应用

#### Scenario: 合并回执丢失
- **WHEN** 执行已可能发生但响应断线
- **THEN** 同一请求可查询真实提交与回执，界面显示未知直至核实，不启动第二次合并

### Requirement: 生命周期与项目工具兼容

系统 SHALL 让文件浏览、搜索、预览、Git 比较与原生 Backend 在各自 worktree 下使用正确项目身份。归档 Session SHALL 保留成果；清理 worktree/分支 SHALL 明示未合并、未提交、活动及未知状态并单独执行，不借关闭会话删除数据。

#### Scenario: worktree 的 Git 元数据位于共享目录
- **WHEN** 用户在托管子任务搜索或查看 Git 内容
- **THEN** 对已验证属于该仓库的元数据提供兼容读取；未知链接或外部仓库仍明确拒绝，不能放开任意外部路径
