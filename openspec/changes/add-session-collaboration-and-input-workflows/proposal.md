# Proposal

## Why

用户需要在同一个工作台中复用角色评估回答、并行完成项目任务并顺畅汇合成果，同时减少长文本编辑、重复说明授权和遗漏原生提问的摩擦。当前旁路问答、普通 Session、Git 操作和输入确认各自独立，尚不能组成这条完整工作流。

## What Changes

本变更包含六组功能，按可独立验收的阶段实施，共享 Session 身份、上下文引用和输入交互基础。

1. **角色评议**：维护角色的名称、职责、Backend 和运行参数；输入 `#` 可一次选择多个角色评估选中的回答，默认使用最近一个已完成回答及必要前文。每个角色在当前来源 Session 下拥有独立的持久 Session、上下文和产出目录，原生 Backend 使用独立线程。结果默认收起为晴雨状态与文字摘要，展开后左侧角色列表、右侧意见详情；可把指定意见引用回主输入框。
2. **分支副本与合并**：主 Session 右键创建二级副本，默认带入当前项目修改、新文件和项目 Skills，继承可审阅的运行配置；每个副本使用独立 Git 分支、worktree 和聊天线程，禁止再派生下一级。子项右键合并到主 Session，复用差异预览、独立冲突处理和真实合并回执。依赖缓存、构建产物与秘密不自动复制，不能把项目快照称为磁盘完整克隆。
3. **影子续写**：每个 Session 可开启回答完成后的输入建议，默认关闭，开关与 Kit 代确认同排；Tab 接受、Escape 隐藏，用户输入优先，绝不自动发送。
4. **多文本编辑**：可展开主输入、切换和编辑多个文本块、调整顺序、查找、撤销与恢复；保留原附件与发送语义，避免长文自动收纳后难以修改。
5. **Kit 代确认反馈**：独立开关直接决定本次结构化委托，不要求正文补充“同意”；显示待发送、已接收、已绑定运行、已使用、不可用或到期等真实状态。需要人工处理时在原运行提供直达入口，保留单次授权边界。
6. **原生交互问题**：建立区分执行审批、结构化问答和独立操作确认的请求模型，逐 Backend 校验真实协议，正确展示选项/自由文本和响应回执。“跳过确认”按协议自动处理可跳过请求并留下可见记录；缺少必要答案且无法跳过时明确展示待回答原因。

## Capabilities

### New Capabilities

- `session-role-reviews`：角色维护、独立评议 Session、冻结上下文、并行意见与可追溯引用。
- `parallel-session-workspaces`：项目子 Session、Git worktree 隔离和有回执的成果汇合。
- `session-followup-suggestions`：按 Session 启用的回答后影子输入及键盘接纳。
- `composer-text-editing`：主输入和多文本块统一编辑、草稿保护及键盘交互。
- `kit-delegation-feedback`：单次结构化委托的可见生效状态和等待确认处理入口。
- `backend-user-interactions`：跨 Backend 的真实提问/审批适配、响应与可见自动跳过。

### Modified Capabilities

无。本变更不把既有 `thoughts-readonly-inspection` 改造成完整 Agent，也不放宽 `deepseek-harness-backend` 的历史恢复、权限、图片或退出确认约束；新交互契约作为各 Backend 共用的附加能力。

## Impact

- 后端：`Session` 与持久化索引、`BridgeWS`、Backend 接口/适配器、上下文摘取、运行注册与取消、Git 服务、`ChatKitTools`、普通聊天和队列边界。
- 前端：Sidebar 二级组织、ChatPane/ChatInput、文本附件编辑、引用选择器、Kit 详情、原生交互卡片及紧凑评议面板。采用用户截图中的左列表/右详情组织，避免增加六个常驻大面板。
- 存储：增加向后兼容的角色、评议、任务组、汇合及交互回执记录；旧 Session 无需重建。敏感动态令牌和单次委托不进入角色上下文、草稿历史或建议。
- 依赖：Git worktree 为并行编码前提；复用现有 CodeMirror 依赖和 Backend，不因浏览功能自动安装 CLI、调用模型或创建工作区。
- 验证：隔离临时 Git 仓库、fake Backend/原生协议 fixture、桌面与窄屏交互验收。生产模型/真实发布/真实项目的成功不由这些测试代替。
