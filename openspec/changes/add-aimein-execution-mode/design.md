# Design

## Context

设计基于 `docs/aimein-execution-mode.md` 与本次明确实装请求。现有 LOOP 的活动保护、任务协议与隔离前置相互关联，直接增加第三种 session_type 会绕开多处判断；调用和推送按阶段归属，三评审需独立身份。

## Goals / Non-Goals

提供真实动态阶段与评审闭环，复用现有权限和工作台控制。首版使用单执行者、三个独立只读评审会话，不增加并发写入或外部服务。

## Decisions

- 新建入口接受 aimein，内部仍为自动 loop 会话，增加轻量模式镜像；权威模式在 LoopPolicy。已有记录后不允许原地切换框架，旧字段缺失保持 LOOP。
- 独立 `aimein.py` 定义有界协议，`aimein_bridge.py` 负责驱动。每个 LoopRecord 记录一次 Attempt，包含冻结 Sprint、评审和结果；从历史推导当前 Sprint，避免额外持久化副本及丢弃后残留。
- 新 Sprint 由只读规划生成目标图、阶段范围、FlowBuild/Infra、成熟度文字锚点和验收项。同阶段修补沿用冻结计划；新目标或补充进入新范围修订，旧记录留存。
- 通用实施复用完整任务协议的 prepare/execute、来源复核和测试隔离前置；OpenSpec 来源直接复用原生 apply/verify，不要求重复 taskPlan。Sprint 边界作用于实际执行，原任务保持权威，整体收口同时核对原生 verify。
- 评审配置必须显式指定三个不同模型；校验配置和可用 Backend，不自动兜底。各自新会话、同一提示基础和成果版本，不传入其他评审结论。首版依次运行，保持共享环境检查及退出保护的确定性；每位评审独立流和状态。
- 评审只读。以有界工作区指纹及证据文件指纹检查评审期间漂移；检测不全或变化时不接受结果。模型逐条评审阶段条件和整体目标，三个有效通过才推进；最终完成还要求完整目标条件和来源自动任务完成。
- 停止、未知退出、真实阻塞优先；缺失评审与调用失败不能通过。预算、风险和证据支持的条件状态推进限制空转。使用现有调度器且不在读取时续跑。
- 已完成实施但评审失败时保留同一 Attempt 的评审断点；共享展示、请求和执行入口使用同一续跑判定。恢复重查冻结身份与成果，有效评审不重发，失败评审每次用新会话且最多三次，保留有界失败记录。未知活动不因恢复而解除。
- 停滞按当前轮同一目标范围跨 Sprint 累计。共同核实的完整子目标首次成立，或新阶段条件有此前未核实的文件版本支持，才记进展；条件编号和阶段号不作为进展身份。完整验收仍优先于停滞退出。
- UI 在现有 LoopPanel 共享控制器内增加 AIMEIN 阶段视图与模型设置；使用响应式网格、可选历史、可展开证据及明确的空状态，不复制控制权逻辑。初始配置随创建请求保存并等待写队列完成；设置写入失败返回明确错误、保留草稿。
- 新增规划与评审输入使用文字目标、冻结条件和工作区证据，不自动分发历史图片。图片多目的地分发曾被自动审批审查拒绝，未纳入本次实现。

## Risks / Trade-offs

- 模型评分主观 → 明示评审判断，以逐条条件与证据约束，成熟度不冒充整体进度。
- 三路成本与延迟 → 显示每路状态和统计，复用有效断点，不默认调用真实模型验证。
- 文件指纹有覆盖界限 → 有界扫描失败明确暂停，不能当作 OS 隔离或全面证明。
- 大量现有未提交修改 → 只修改必要锚点，保留用户与其他任务修改。

## Migration Plan

新增字段缺省兼容，旧 LOOP 不迁移运行行为。验证使用临时目录、fake Backend 和隔离浏览器；发布后用户重启执行端生效，本次不重启生产会话。
