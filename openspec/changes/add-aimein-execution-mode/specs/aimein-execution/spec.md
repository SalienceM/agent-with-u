# Spec Delta

## Purpose

在保持用户控制、执行环境和任务来源约束的前提下，以动态 Sprint 建设产品功能流程与基础设施，并使用三个独立模型评审阶段成熟度，支持修补、恢复及真实的整体收口。

## ADDED Requirements

### Requirement: 动态阶段与尝试分别保存
系统 SHALL 动态规划 Sprint，保存范围、子目标依赖、成熟度文字条件与验收项；同阶段修补 MUST 保持条件，成功后才选择下一阶段。新目标与补充 SHALL 留有范围变化依据。

#### Scenario: 未通过后继续
- **WHEN** 当前阶段有必修缺口
- **THEN** 下一次尝试沿用该阶段条件并携带问题，已有成果保留，阶段号不因尝试增加而前进

### Requirement: 三模型独立评审同版成果
系统 SHALL 要求三个不同模型，在新会话中独立只读评审同版产物和证据，分别保存状态、判断及问题。三份有效通过且条件齐备才允许阶段通过；无法解析、缺失、调用失败和成果变化 MUST 不得算通过。

#### Scenario: 两人通过一人否决
- **WHEN** 三位评审中一位指出未满足条件
- **THEN** 阶段保持待修补，并展示否决条件及依据，不以平均分通过

#### Scenario: 配置缺失或重复
- **WHEN** 模型不足三个、身份重复或 Backend 不可用
- **THEN** 执行前显示具体问题，不静默替换模型或启动写入

#### Scenario: 评审期间成果改变
- **WHEN** 工作区或证据在评审期间改变
- **THEN** 结果不作为通过依据，保留原评审并提示重新核对

### Requirement: 共享保护与有界恢复
系统 MUST 保留用户停止、控制权、未知退出、执行环境、来源、任务协议和隔离前置；预算和停滞导致的退出 SHALL 保持未完成。恢复 SHALL 不重放已完成写步骤，未确认评审只允许在旧调用退出核实后显式继续。

#### Scenario: 重启与恢复
- **WHEN** 阶段执行已完成但评审未完成，用户重新打开后显式恢复
- **THEN** 保存的写步骤不再次执行，读取本身不启动工作，未确认活动仍阻止新调用

#### Scenario: 评审失败后显式继续
- **WHEN** 一位评审格式无效或调用失败，实施已经完成且目标、配置、成果版本保持一致，用户显式继续
- **THEN** 保留原 Attempt、已完成步骤及有效评审，只补齐失败或未运行评审；每位最多三次调用，未知退出保持门槛，旧失败依据保留

#### Scenario: 连续重复已通过阶段
- **WHEN** 连续 Sprint 重复已核实范围，没有新增共同核实的完整子目标或有新证据支持的阶段条件
- **THEN** 同目标范围累计停滞并按 progressPatience 暂停 Auto；新阶段号、条件编号、改写报告或提高分数不能清零

### Requirement: 阶段成熟度与整体完成独立
系统 SHALL 按阶段范围解释成熟度，以完整当前目标条件、有效三方评审、来源进度及无未处理补充判断最终完成。

#### Scenario: 阶段通过但目标仍有缺口
- **WHEN** 当前 Sprint 达到成熟度且有未覆盖目标条件
- **THEN** 展示阶段通过与剩余目标，预算和 Auto 允许时继续规划，不显示整体完成
