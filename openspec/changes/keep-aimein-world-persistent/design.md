# Design

## Context

AimeinWorkbench 的 world 条件分支会卸载 Canvas；对象选择通过 scrollIntoView 将场景推离视口。LoopWorkbench 窄屏详情隐藏 main。准备层另建 World，开始后重建；创建入口打开 BackendManager 时自身 display:none。

## Goals / Non-Goals

**Goals:** 使用同一会话沙盘承载准备和观察，详情独立滚动；通用 LOOP 布局不变。

**Non-Goals:** 不改变三模型调度、执行权限、进度定义和持久化协议；不新增模型请求或图形依赖。本变更不打发行包。

## Decisions

- AimeinWorkbench 始终持有 World，把准备和正常观察作为面板内容。准备卡片复用现有校验与保存逻辑，提供 panelOnly 模式。避免保存与重放相机来掩盖 Canvas 重建。
- World 增加 contained 布局，容器占剩余空间，工具栏横向滚动而非挤占小屏；静态场景同样适配。桌面分列、窄屏上下分区，面板独立滚动，取消对象选择的页面自动滚动。
- LoopWorkbench 增加仅 AIMEIN 使用的非模态场景面板；保留原通用 LOOP 的焦点陷阱。打开设置时收起内层观察面板，不隐藏 World；关闭恢复原内层面板。
- 创建入口保留世界，连接配置采用边缘面板，在窄屏下半区域呈现。配置只从当前执行端读取，原创建校验与返回刷新不变。
- 评委编辑器继续延迟加载且关闭不卸载；对象建议保持对象和阶段键。原操作控制器、失败草稿与显式开始仍是执行边界。

## Risks / Trade-offs

- 小屏可用空间减少 → 精简重复标题，工具栏单行，长内容只在面板内滚动；验证 360×640。
- Canvas 调整大小影响构图 → 同一实例保持相机与焦点，不因面板导航触发回到全景。
- 非模态面板键盘语义 → 不给可交互沙盘 aria-hidden，不困住 Tab，Escape 收起当前面板并返回入口。
- 会话切换和显式退出允许销毁世界；首次创建前后属于身份建立边界，保持同样的沙盘交互体验，不冒充已绑定执行状态。
