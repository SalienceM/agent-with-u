# Design

## Context

动机和行为范围见 `proposal.md` 与两份 delta spec。当前实现存在以下可复用基础和缺口：

- `Sidebar.tsx` 的 `collapsedGroups` 是内存中的集合；分组包含真实 `execKey` 和 `__pinned__`，刷新即复位。搜索会补齐父会话，收藏按整组父子关系聚合，需要在这些步骤之前和之后落实私密过滤。
- `utils/workbench.ts` 已有版本 1 快照、身份隔离、标签顺序及分屏规范化。`scopedWorkbenchStorageKey` 使用 URL 或 sessionStorage 中的窗口 ID；保存仅写当前窗口键，普通入口虽然可读取旧共享回退，但不会持续更新该回退。冷启动的新窗口可能无法定位上次主窗口快照。
- `App.tsx` 在初始状态和身份变更时恢复快照，通过 effect 保存。导航集合同时驱动标签、分屏及保活的 `SessionWorkbench`，需区分保存的导航意图和当前允许显示的投影。
- `workbenchWindows.ts` 已有持久 `clientId`、临时 `windowId` 和严格窗口交接；本次不得改变发送权、窗口租约或交接确认。
- 收藏已有 IndexedDB 本地选择、身份/节点范围、状态读取、字段修订 CAS 和原 requestId 回执。`session_store.py` 防止旧 Session 对象及异步正文保存覆盖收藏。私密采用同等语义，不搭建另一个通用离线写队列。
- 当前主规格没有导航/私密能力，活动变更中的窗口隔离与收藏契约继续适用。已有源码未提交修改属于前序工作，本次实施必须保留。

## Goals / Non-Goals

**Goals:**

- 在已有导航和元数据边界补足恢复与显示投影，避免把视图隐藏当成标签删除。
- 通过一处可测试的可见性判定保持各 Session 入口一致。
- 利用当前轻量元数据保存与同步协议，避免收藏和私密互相覆盖。

**Non-Goals:**

- 不把导航布局同步到后端或其它设备，不更改模型协议、Session 所有权、窗口归属或后台执行。
- 不增加密码、加密、保密存储或 API 访问控制；不清理已经发送给模型的引用、导出数据或公开会话中的历史文本。
- 不持久化私密显示的开启状态，不把本次新增标记隐式继承给父子 Session。

## Decisions

### 1. 用稳定客户端范围和主窗口回退补全导航保存

新增一个版本化客户端导航偏好模块，与 `workbench.ts` 的纯规范化逻辑协作。作用域至少包含部署/认证范围、登录用户和现有持久客户端 ID；节点折叠使用可验证稳定节点标识，不使用名称。读取在首次保存之前完成，身份切换采用独立 generation，迟到数据不能写入新身份。

导航分为两个层次：

- 客户端级偏好保存分组折叠集合，同客户端窗口按字段协调；不因列表暂时缺失删除键。
- 窗口快照保存标签、当前页、分屏位置和布局。普通主窗口的明确导航操作同时更新客户端主窗口回退；独立窗口只写自己的快照。窗口刷新优先自己的记录；新的普通主窗口没有窗口记录时读取客户端回退。多个主窗口以最近明确导航提交为冷启动回退，后台推送/重渲染不更新该次序。

使用现有窗口身份工具，但为导航读取提供不启动工作台、不触发 RPC 的稳定身份解析。不得为恢复主窗口而复用旧 `windowId` 抢占工作台。快照只保存导航 ID 与轻量偏好，设置格式、数量及字节上限，写入失败提供去重提示而保留窗口内状态。

替代方案：只保存节点折叠无法满足标签冷启动；仅使用一个全局标签键会让独立窗口覆盖主窗口；让每个新窗口生成新键仍会丢失恢复入口。

### 2. 标签成员是导航意图，私密过滤是显示投影

保持完整 `workbench` / `paneSessions` 为导航意图，新增可见标签、可见 pane 和可见焦点投影。自动隐藏导致的首页回退不写回删除私密标签；用户明确关闭、切换、重排等操作才更新相应导航意图。用户在隐藏期间选择公开 Session 时，保留私密标签成员但更新真正的当前选择。

关闭私密显示时，已挂载的私密 `SessionWorkbench` 进入不可见状态，复用 `isVisible`、`isFocused` 和 `AppModalVisibilityContext`；禁止隐藏实例保留浮层、快捷键和注意力焦点。未挂载的恢复标签先核对元数据和本地私密选择，再决定是否懒挂载，避免初始化时闪现。已有草稿及文档缓冲区继续保留，不把隐藏实现为 close/unmount/abort。

离线/加载中保留导航 ID，只显示中性占位；确认删除或撤销访问后清理对应 ID。再次开启只恢复之前打开的标签，不打开全部私密 Session，也不自动切回私密焦点。

替代方案：直接从快照移除私密项会丢失用户的打开集合；全局过滤原始 `api.listSessions()` 会影响后台调度、归属和同步，故只过滤展示消费方。

### 3. 私密是独立的会话元数据字段

新增 `isPrivate`、`privacyRevision` 及专用请求回执，使用 `sessionPrivacyGet/Set` 和能力声明。后端继承当前身份检查与窗口写入边界，按字段比较修订、落盘成功后发布；`Session` 序列化、索引加载及后台保存保留已确认的私密版本。写私密不推进收藏修订，写收藏/底色/正文也不能覆盖私密。

前端新增窄范围私密协调层，沿用 `sessionFavorites.ts` 的仓储接口、目标身份和有界协调方式；可抽取稳定的布尔元数据协调公共逻辑，但保持现有收藏 API 兼容且不纳入其它写操作。私密本地选择先持久化，再更新投影并同步；状态包括待同步、未知、冲突、仅本设备和受阻。回执未知先读原状态，冲突需要显式处置；不盲目写重试。旧节点保留本设备标记，并如实显示同步限制。

替代方案：直接扩展无版本的 `updateSessionAppearance` 写入无法避免两客户端竞态；仅用一个全局 Session ID 的 localStorage 集合会跨节点串号且失去收藏同级同步语义。

### 4. 私密分组和开关共享可见性服务

新增 `sessionVisibility` 纯判定及当前窗口订阅状态：输入是已确认元数据、本地私密选择、身份和临时显示开关；输出区分公开、私密、未知，不把未加载当成 false。开关属于客户端当前窗口，初始化和身份切换固定关闭，不进远端配置或导航快照。私密元数据变化可同步到同客户端其它窗口，但不携带开启显示的指令。

侧栏右键菜单提供标记/取消；搜索栏附近放带文本/无障碍名称的开关，不依赖 hover。分组次序为收藏、私密（开启时）、普通节点；私密优先于收藏归类，保留收藏星标。父子关系仅在同一可见分类内构树；公开子项的私密父项不补回，作为公开根项显示，不修改持久关系。

复用该判定过滤 `App.tsx` 标签/分屏/导航函数、Sidebar、`HomeDashboard`/`useDashboardData` 的列表和活动、ChatInput 的会话候选以及完成通知。链接和独立窗口入口在元数据确认前使用中性占位，关闭状态提供显式开启操作。私密工作台的文件栏、窗口标题、弹窗和通知正文同步退出展示；已有公开正文中的引用不做文本扫描或重写。

替代方案：只在 Sidebar 加 filter 会从收藏、首页、恢复标签和通知重新露出；全局 CSS 隐藏不足以阻止键盘和 portal 展示。

## Risks / Trade-offs

- [私密被误认为加密/权限] → 在开关或说明中明确“仅控制本客户端显示”，不改变服务端授权；旧客户端不保证识别新标记。
- [旧元数据和后台保存反复揭开私密] → 使用字段修订、本地最新选择覆盖和保存保护；以并发、迟到回复及正文保存交错测试证明。
- [隐藏导致未保存编辑丢失] → 保持原工作台实例与缓冲区，仅关闭显示/交互；验证 Chat 与 Engine 两种模式。
- [启动顺序覆盖有效快照] → 恢复就绪后才启用写入；主窗口回退只由明确导航更新；测试清空 sessionStorage 后保留 localStorage 的真实冷启动。
- [多窗口同键覆盖] → 分组偏好和窗口快照分层，按字段协调分组选择，主窗口回退采用确定的最新导航提交。
- [离线和存储失败] → 保留 ID 及窗口内选择，错误可见；不将临时列表缺失视为删除，不对其它节点补写。

## Migration Plan

1. 先提供后端可选私密能力及字段级兼容，缺失字段的已读旧记录按 false 处理。
2. 引入新版本地偏好与导航快照读取：优先读新格式，再迁移同身份当前窗口 v1 记录或原共享主窗口记录。旧格式没有 client/realm 的记录只在身份和当前入口可确定匹配时迁移；不扫描任意其他用户的窗口快照猜测归属。
3. 导航初始化完成后启用写入，再接入各处私密显示投影，保持 reveal=false 的首屏门禁。
4. 通过 fake Backend、临时存储和隔离浏览器验证后更新说明；部署/安装作为另一个显式请求处理。
5. 回滚保留新元数据和新快照，不反向覆盖为 false；旧前端可能显示私密 Session，回滚说明必须指出这一兼容边界，不能宣称旧版本仍具备隐藏保证。
