# Proposal

## Why

Session 栏的执行节点折叠状态只保留在内存中；已有标签页快照依赖窗口身份，缺少冷启动时稳定恢复客户端主窗口的完整约定。用户需要重开客户端后保持自己的展开、折叠及已打开标签集合，并能主动隐藏被标记为私密的 Session。

## What Changes

- 按客户端及登录身份保存 Session 栏节点、收藏及私密分组的折叠状态；节点改名或暂时离线不丢失选择。
- 补全主窗口重启恢复：保留已打开的 Session 标签、顺序、当前标签和分屏位置；未打开或已关闭的 Session 不因列表刷新而自动进入标签栏。独立窗口仍保有自己的导航与归属。
- 增加与收藏同级的私密标记、右键标记/取消入口和“显示私密 Session”开关。私密与收藏互不修改；开启时私密项集中在私密分组，关闭时隐藏。
- 私密标记参照收藏的身份隔离、持久化及离线同步语义；显示开关只控制当前客户端，初次打开、刷新和重启默认关闭。
- 隐藏规则覆盖侧栏及搜索、收藏、标签页/分屏、首页 Session 卡片、会话选择候选和通知入口。隐藏保留已打开集合及后台任务；恢复显示不自动执行或重发。
- 兼容旧导航记录及未提供私密字段的旧 Session；存储失败、同步冲突和结果未知必须如实反馈。

## Capabilities

### New Capabilities

- `client-session-navigation`: 客户端 Session 分组折叠和标签页成员、顺序及布局的可靠恢复，包括窗口、身份和离线边界。
- `private-session-visibility`: Session 私密分类、客户端显示开关及一致的导航隐藏规则，包含持久标记、离线同步和收藏交互。

### Modified Capabilities

无。当前主规格没有对应能力；本变更新增规格，并保留活动变更 `add-session-engine-workbench` 的窗口归属约束和 `fix-offline-session-management` 的收藏同步行为。

## Impact

- 前端：`Sidebar.tsx`、`App.tsx`、`utils/workbench.ts`、客户端/窗口身份、Session 元数据投影与收藏协调层；首页、会话候选、通知和独立窗口的显示边界。
- 后端：Session 元数据及轻量保存、私密标记读取/写入能力和受身份保护的推送；保持既有收藏、底色、运行状态和消息保存互不覆盖。
- 验证：临时存储单测、fake Backend 的元数据/并发回归，以及隔离浏览器的刷新、冷启动、多窗口、身份切换与私密显示验证。
- 不新增第三方依赖。本次私密是显示分类，不新增认证、加密、密码、后台访问权限或历史内容清除机制。
