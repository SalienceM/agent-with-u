# Design

## Context

见 proposal.md。两个 Windows 批处理入口清理共享根目录，Web/Linux 直接使用 PyInstaller `--clean`，未发现同类根目录删除。共享冻结入口目前仅封装命令，适合统一承担专属目录清理。

## Goals / Non-Goals

**Goals:** 重跑时继续保证干净冻结，只删除 `build/agent-with-u-backend`、对应 dist sidecar 及其自检回执，完整保留已准备的 Harness 输入及其他包。

**Non-Goals:** 不修改 Harness 版本、模型调用、Kit 授权或远端发布行为；不把 Windows 验证视为 Linux 运行验证。

## Decisions

1. 共享 Python 入口负责定点清理，批处理删除广域清理命令。沿用现有 workpath 和产物路径，不迁移清单根目录，也不在清理后重复安装来掩盖误删。
2. 删除前先验证全部候选的绝对路径在项目内、父路径及目标无链接/Windows reparse point；拒绝不合约路径后不启动冻结。显式传播清理和构建失败。
3. 资源恢复只使用已记录 wheel SHA-256 或已有受校验发行资源，核对锁定版本、提交及完整资源校验；保留审计来源。缺失/损坏时报告可操作错误，不自动混用其他版本或绕过门禁。
4. 以临时工程哨兵验证缓存删除而输入和其他发行包保留，并验证链接路径拒绝、失败传播；实际执行 Windows sidecar 冻结及隔离自检，条件允许完成 Tauri 安装包。用原 Kit 命令/成功标志确认接口兼容，但不调用链中的远端发布能力。

## Risks / Trade-offs

- 旧脚本已删除输入 → 修复代码之外恢复本机资源，不能仅报告“脚本已改”。
- 缓存/产物占用 → 清理失败明确退出，保留错误；不结束其他应用。
- 本机存在未提交前端改动 → 原样保留，构建使用当前工作树，并记录验证范围。
- 不能完整恢复某平台源码构建资产 → 保持该平台未验证，不能伪造收据或 checksum。
