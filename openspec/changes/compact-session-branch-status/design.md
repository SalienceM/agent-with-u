# Design

## Context

前版已将状态压为单行标签，但用户要求进一步移除常驻状态。现有分页 RPC 与真实 Git 状态投影可直接用于手动检查。

## Goals / Non-Goals

**Goals:** 列表零状态占位、零后台状态查询；主 Session 右键一次核对全项目。

**Non-Goals:** 不改 Git 计算、合并审批、任务运行或原合并记录提示。

## Decisions

1. Sidebar 不再调用状态 hook；主项右键加入“检查分支状态”，点击才挂载检查窗口。子项、整合和评审 Session 不重复提供入口。
2. 控制器改为单项目、每次显式请求读取；保留节点确定路由、两读并发上限、分页主干/成员一致性和完整性校验。关闭或身份/节点变化后迟到结果作废。
3. 不使用定时器、焦点或重连刷新；相关状态变化、断线仅使结果失效并提示手动检查，不安排读取。窗口标记本次核对时间。
4. 窗口复用 WorkflowControls 和 AppModalPortal，宽度不超过 580px，名称、Git 分支和完整状态按行展示，提供重新检查与关闭。键盘焦点受限于窗口，Escape 关闭。
5. 移除不再使用的家庭列表发现与短标签投影，保留原完整状态算法。旧合并成功记录仍不参与当前关系判断。

## Risks / Trade-offs

- [没有自动更新] → 显示核对时间，相关事件使结果失效，明确手动重新检查。
- [状态读取中关闭或换节点] → effect 清理与 owner 检查拒绝迟到结果；不回退其他节点。

## Migration Plan

无数据迁移；保留前版任务完成记录，新增修订任务并以本版规格和新验证报告为准。
