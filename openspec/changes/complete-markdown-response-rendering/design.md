# Design

## Context

动机与实测见 `proposal.md`。本次横跨共享 HTML 生成、App 全局样式、阅读器、导出和消息 DOM 增强，因此需要设计约束，而非仅修改一段 CSS。

`markdownToHtml` 使用 marked v9 的位置参数 renderer；`MessageBubble` 对完整正文和有序正文块分别调用它。代码复制、命令填入、文件定位、Session 导航及图片加载依赖既有选择器。基础 CSS 位于 `App.tsx`，而 `main.tsx` 的独立预览/俺寻思窗口可不挂载 App。阅读器和导出有独立主题，不能强制改成聊天气泡外观。

## Goals / Non-Goals

**Goals:**

- 形成一个共享的语法输出和基础样式契约，修复现有错配，并补足最容易复发的浏览器级回归。
- 保持解析函数可独立测试、无 DOM/网络副作用；界面增强继续由各自组件负责。
- 只动渲染层，不回写消息、重新请求模型或迁移 Session。

**Non-Goals:**

- 不换解析库，不实现另一套 Markdown tokenizer，不引入通用插件注册系统。
- 不把 Thinking、工具日志、用户消息强制转换成助手正文，不跨工具边界猜测 Markdown 是否应合并。
- 不把标准 GFM 的支持等同于所有方言或任意网页兼容；不重构 Skill 手册 iframe、可运行 HTML 预览及全量原始 HTML 安全策略。

## Decisions

### 1. 继续复用 marked，仅补齐输出契约

为表格增加 marked v9 兼容的 renderer，生成 `.md-table-wrap > table.md-table`，保留 `thead/tbody/th/td` 语义以及解析器提供的对齐。无需重写列表、转义竖线或单元格解析。

对齐使用受控的 left/center/right 规则或属性选择器，显式优先于默认左对齐；聊天、阅读器、导出都不能再以更高优先级无条件覆盖。宽表在 wrapper 滚动，不把 table 改成破坏表格语义的布局容器。

替代方案：仅增加 `.md-content table` 样式可以恢复边框，但缺少局部滚动边界且无法修复跨页面契约，因此不采用。完整替换 Markdown 库会扩大兼容风险，也没有必要。

### 2. 基础样式独立于 App，阅读外观仍分层

抽出纯 TypeScript CSS 字符串模块（例如 `utils/markdownStyles.ts`），通过一个小型样式组件在 `main.tsx` 各窗口分支之外统一挂载；使用项目现有嵌入式样式方式，不新增全局外部 CSS 文件。解析函数本身不负责向 document 写样式。

基础选择器限制在 `.md-content` 下，包括标题层级、段落、嵌套列表、只读任务框、引用、强调/删除线、代码和表格。移除 App 中对应重复规则；不得修改工作台全局排版或给所有标签增加字体缩放。

基础颜色通过局部 `--md-*` 令牌与 `--theme-*` 回退提供；阅读器映射其现有局部主题和排版，俺寻思保留面板外观但删除冲突的内容规则。代码高亮继续复用 `hljsThemes.ts`，在独立阅读窗口按当前主题提供，而非因主 App 未挂载而失去高亮。非 Markdown 的代码预览不受作用域收缩影响。

导出仍是自包含 HTML，不依赖运行时组件；调整其表格对齐与滚动规则以接受新 wrapper，同时兼容现有传入的裸 table。避免双滚动条和重复外边距。目录、打印和导出主题继续保留。

替代方案：把同一 CSS 复制到每个页面会继续漂移；把所有阅读器变成同一字号/外观又超出了本次需求。采用共享基础＋局部外观。

### 3. 长内容与主题的边界在内容层解决

普通文字、长链接和行内代码可换行；`pre` 保留空白与缩进，代码和表格区域允许横向滚动。为相关 flex/grid 子项补足 `min-width: 0` 和最大宽度，只在实际需要的祖先节点调整，避免给整个应用添加 `overflow-x: hidden` 掩盖溢出。

表格、表头与代码使用本地主题底色，边框不依赖背景图片恰好够暗或够亮。可滚动表格提供可辨的可访问名称及键盘访问方式，不改变列内容。检查控件焦点、长列表缩进和嵌套引用，不使用固定高度裁切正文。

### 4. 修复元数据，但不破坏既有 DOM 增强

链接/图片的可选标题写回 HTML，属性与说明文本经过上下文正确的转义，测试引号、实体、中文和空格，避免二次转义造成可见文本变化。文件链接增强不再无条件删除所有标题；生成的辅助描述与作者标题分别管理。

围栏信息先取首个语言标识用于高亮，其余信息作为转义后的说明。未知的显式语言使用普通转义代码；未声明语言可保留现有自动高亮。高亮异常退化为该代码块文本，不让整条消息失去 Markdown。代码正文仍可由 `pre.md-pre > code` 取出，语言说明采用有效的非正文节点，不进入复制/命令识别文本。

保留 `.md-link`、`.md-img`、`data-skill-file`、`.md-code-inline` 和必要的代码节点契约。图片仍由所属执行节点 RPC 加载；本次不新增 URL 代理、外部请求或从 Markdown 参数获得操作授权。原始 HTML 并非本次完整安全审计的对象，不能据此宣称任意输入已全面净化。

替代方案：只在 UI 上补 tooltip 会漏掉导出和其他消费者；用字符串拼接未转义标题会产生新缺陷，因此在共享 renderer 处理，在交互增强处保留。

### 5. 流式更新复用同一路径，不改传输结构

维持 `contentHtml` 和 `orderedTextBlockHtml` 既有分块及 memo 策略。以逐步到达的表格、围栏、列表和链接作为测试输入；完成后的同一正文块与一次性渲染进行结构比较，不要求未闭合半句提前呈现最终形态。

继续由 React 替换对应正文 HTML，现有 DOM 增强负责重新绑定且清理旧节点。检查完成后的代码复制和命令填入没有重复按钮；流式阶段不提前启用命令填入。不得将工具记录和多个独立正文块拼接成一大段以掩盖语法边界。

### 6. 保留有界失败路径，以真实浏览器验证呈现

大内联 data image 的保护必须仍在 marked 之前，恢复图片在解析之后；不把巨型 payload 重新塞进 tokenizer。保持损坏图片提示、解析失败 200,000 字符回退和转义，测试通过注入失败或隔离依赖模拟覆盖异常，不使用真实会话制造错误。

验证分两层：

- Node 结构测试：标准语法矩阵、表格 wrapper/对齐、标题与属性、围栏信息、代码文本、图片保护/回退、流式前缀与完整正文、导出兼容。
- 隔离 Playwright：真实生产样式和组件，计算边框/对齐/尺寸，检查页面无横向溢出、局部区域能滚动；深浅主题、背景图、桌面/360px、内嵌/独立阅读器/导出都覆盖。交互用 mock bridge 和合成图片，不请求模型或真实文件。

视觉证据保存截图并人工查看；DOM 结构正确不等于显示正确。已有 `markdown-render-safety.test.cjs`、`markdown-export.test.cjs`、图片及命令填入测试作为回归入口。构建验证与应用验收分开报告，不以测试通过冒充已发布。

## Risks / Trade-offs

- [共享样式被阅读器或导出覆盖] → 用真实计算样式检查列对齐、边框和滚动，不只比 HTML 字符串。
- [DOM 变化影响复制、填入或图片加载] → 保留选择器契约，复制结果对比原代码，流式到完成验证按钮唯一性。
- [链接标题被增强逻辑再次清掉] → 在增强后的实际 DOM 检查，外链与文件链接分别覆盖。
- [用户期待公式/流程图也属于完整] → 在支持范围说明中明确本轮是标准 Markdown/GFM，不把未实现扩展宣称为支持。
- [流式未闭合结构短暂变化] → 接受解析器正常的阶段性结构变化，验收最终等价和无丢失，不新建流式解析引擎。
- [现有工作区大量无关改动] → 实施只修改列明的渲染与测试区域，保留现有 token 用量、文件面板、Kit 等变更。

## Migration Plan

无需数据迁移：历史 Markdown 下次打开即走新渲染；原消息不改写。先合入解析/样式与回归，再由用户另行决定打包发布。若需回退，只回退本变更的渲染、样式和测试，不回滚工作区其他变更或删除历史数据。
