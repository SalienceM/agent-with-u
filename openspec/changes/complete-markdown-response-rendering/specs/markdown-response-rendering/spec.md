# Spec Delta

## Purpose

使助手返回的标准 Markdown/GFM 内容在聊天和共享阅读界面中完整、可读地呈现，避免语法已经解析却因样式或布局缺失而丢失表格边界、层级和对齐。同时保持流式展示、历史回放、导出和既有链接/图片/代码交互的一致性，不改写用户保存的原始消息。

## ADDED Requirements

### Requirement: 基础 Markdown 和 GFM 语义完整保留

系统 SHALL 呈现一至六级标题、段落、现有单换行显示规则、强调、删除线、分隔线、引用、无序/有序/嵌套/任务列表、行内/围栏代码、链接、图片和表格。嵌套关系、非默认起始序号及任务勾选状态 MUST 保留；任务框是内容展示，不能因此触发任务执行或写回原始消息。未承诺的扩展语法 SHALL 按已有普通文本或代码规则呈现，而非执行额外程序。

#### Scenario: 混合内容保留层级

- **WHEN** 同一回答包含从 3 开始的有序列表、嵌套列表、引用中的段落、强调和删除线
- **THEN** 列表从 3 显示，层级和段落可辨，引用和强调不吞掉后续正文

#### Scenario: 任务状态是只读内容

- **WHEN** 回答包含已完成和未完成的任务列表
- **THEN** 两种状态均可辨且保持只读，不因查看或点击而调用任务接口或改写消息

### Requirement: 表格边界和列对齐可见

系统 SHALL 显示可辨的表头、单元格网格与内边距，并尊重各列的左、中、右对齐声明；默认列左对齐。表格内的强调、代码和链接 SHALL 保持可读及既有交互。不得用统一左对齐覆盖显式列对齐。

#### Scenario: 三种列对齐

- **WHEN** 同一 GFM 表格分别声明左、中、右对齐
- **THEN** 表头和对应数据单元格保持三种对齐，所有单元格有可见边界，表头与正文有视觉区分

#### Scenario: 转义与空单元格

- **WHEN** 单元格包含转义竖线、空内容、行内代码和链接
- **THEN** 保持标准解析结果，不因样式补齐新增列、丢失空单元格或破坏链接

### Requirement: 宽内容不破坏容器布局

系统 SHALL 在桌面及 360px 窄屏下限制内容宽度。长普通文本、URL 和行内代码 SHALL 能在容器内换行；无法合理容纳的宽表和代码块 SHALL 在自身区域横向滚动，不让整个聊天/阅读面板被撑宽或把内容直接裁掉。代码缩进和文本 MUST 保留，不能通过改写代码或全局缩小字号实现适配。

#### Scenario: 窄屏查看宽表和长代码

- **WHEN** 360px 视口显示多列表格与包含长行的围栏代码
- **THEN** 可通过局部滚动访问全部列和代码字符，外层面板无新增水平溢出，相邻正文和操作按钮仍可访问

#### Scenario: 背景与主题变化

- **WHEN** 切换深浅主题或启用背景图片
- **THEN** 正文、代码、引用与表格边界仍可辨，表格和代码使用足够的局部底色，不修改用户的背景设置或全局字号

### Requirement: 代码内容与语言说明分离

系统 SHALL 使用围栏信息中的语言标识进行支持的高亮，额外信息仅作文字说明。未知语言或高亮失败时 SHALL 回退为转义后的可读代码，不能使整条回答消失。代码复制和命令填入 MUST 只取代码正文，不包含语言说明、按钮或高亮标记；填入仍只修改当前会话草稿，不发送或执行。

#### Scenario: 语言后带附加信息

- **WHEN** 围栏声明为 `js title="demo"`
- **THEN** 使用 JavaScript 高亮，附加信息不会被当作语言名或 HTML，复制结果只包含原代码

#### Scenario: 未知语言与标签字符

- **WHEN** 围栏语言不受支持，或说明包含尖括号和引号
- **THEN** 代码仍完整可读，说明按文字展示，不生成由说明注入的 HTML 元素或属性

### Requirement: 链接和图片元数据及交互不丢失

系统 SHALL 保留 Markdown 链接/图片的目标、可见文本、替代文本及可选标题，正确处理引号、实体和空格而不破坏属性。现有工作区文件定位、Session 导航、普通链接打开、图片按执行节点加载和放大行为 MUST 保留；渲染本身不得启动模型、发布或执行命令。

#### Scenario: 带标题的外链和文件链接

- **WHEN** 回答包含带标题的普通外链和合法工作区文件链接
- **THEN** 标题在增强之后仍保留，普通链接按原方式打开，文件链接仍按原工作区边界定位，不能仅因新增标题而变成另一类链接

#### Scenario: 经中继加载生成图片

- **WHEN** 回答包含执行节点的短图片引用
- **THEN** 仍经所属节点的数据通道加载，不改成客户端直连执行节点 HTTP 地址；图片替代文本/标题保持可读，既有图片放大入口可用

### Requirement: 共用渲染的界面保持基础能力一致

系统 SHALL 让普通助手正文、使用相同 Markdown 能力的 LOOP/俺寻思正文、内嵌及独立 Markdown 阅读器拥有相同的基础语法和内容边界。阅读器可保留更适合文档的字号、间距和目录，但不能依赖已打开主聊天窗口才获得基础样式。独立 HTML 导出 SHALL 自包含地保留表格网格、列对齐和宽内容访问能力。

#### Scenario: 独立预览直接打开

- **WHEN** 未挂载主聊天 App 的预览窗口显示同一 Markdown 文档
- **THEN** 列表、代码和表格具备基础样式及局部滚动，阅读器目录和主题正常，不要求先打开聊天页

#### Scenario: 导出后离线阅读

- **WHEN** 将含对齐表格和代码块的文档导出并独立打开
- **THEN** 不依赖应用运行时样式即可看到相同的内容结构、网格和列对齐，保留已有目录与主题功能

### Requirement: 流式与历史渲染可恢复且不改写原文

系统 SHALL 对流式当前正文使用与已完成正文一致的语法规则。未闭合结构允许临时普通显示，在同一正文块完整到达后 SHALL 与直接加载该完整正文保持等价的内容结构。工具前后独立正文块和 Thinking MUST 保留原有顺序与边界，不跨块补写原文或重复输出。

#### Scenario: 表格或围栏分多次到达

- **WHEN** 表格分隔行或围栏结束标记分批到达同一正文块
- **THEN** 每次更新可显示已有内容且无应用级异常，完成后与直接渲染同一完整正文结构一致

#### Scenario: 工具调用穿插正文

- **WHEN** 回答在两个正文块之间包含工具记录
- **THEN** 渲染改善不合并或重排这些块，不重复展示累计正文，也不把工具输出转成可执行 Markdown 交互

### Requirement: 既有大图片和失败回退保护保留

系统 MUST 保留对历史大内联图片的解析前保护、对不完整载荷的可见说明和解析失败的有界转义文本回退。单条消息异常不能击穿整个会话或应用；降级原因 SHALL 可见，不能把丢失内容伪装成正常完成。

#### Scenario: 历史大内联图片

- **WHEN** 历史消息包含约 8MiB 的合法内联图片及前后正文
- **THEN** 不因 Markdown 解析栈溢出导致白屏，图片和前后正文保持可呈现

#### Scenario: 损坏载荷或解析异常

- **WHEN** 内联图片不闭合或解析发生异常
- **THEN** 显示相应提示或有界安全文本，其他消息仍可阅读，原始存储正文不被自动替换
