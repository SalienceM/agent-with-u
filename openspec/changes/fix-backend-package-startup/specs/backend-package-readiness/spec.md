# Spec Delta

## Purpose

保证 AgentWithU 后端发布制品在进入安装包或便携分发包前具备目标平台必需依赖，并通过隔离的真实启动与连接验证；让构建者收到可定位的失败结果，避免将缺少模块或无法运行的 backend 交付给用户。

## ADDED Requirements

### Requirement: 构建依赖与声明及目标平台一致

后端构建入口 SHALL 使用实际打包解释器同步并校验项目声明的适用依赖及版本约束；缺少依赖、版本不符、安装失败或必需模块不可导入时 MUST 非零退出并禁止继续打包，不得仅凭历史依赖抽查成功跳过校验。

#### Scenario: 老依赖齐全而新增依赖缺失
- **WHEN** 构建环境中历史依赖可用但新版必需依赖不存在
- **THEN** 构建流程补齐并重新校验依赖，或明确失败；不得直接生成候选制品

#### Scenario: 同一解释器验证失败
- **WHEN** 依赖被安装到其他解释器或当前环境版本不满足声明
- **THEN** 实际打包环境的校验失败并停止，输出所用解释器和依赖类别

#### Scenario: 平台条件依赖
- **WHEN** 构建 Windows 或 Linux 后端
- **THEN** Windows 校验其必需 PTY 组件，Linux 不因 Windows 专属依赖缺失而失败，但仍校验其适用依赖

### Requirement: 冻结制品完整性

构建流程 SHALL 验证目标制品所需的模块、原生组件和声明携带的工程资源可在冻结环境中使用。必需项缺失 MUST 阻止封装；可选或其他平台依赖警告不得被无差别视为当前制品失败。

#### Scenario: 必需搜索模块缺失
- **WHEN** 冻结产物缺少必需搜索依赖
- **THEN** 验证失败并明确模块类别，即使打包器此前返回成功也不得通过

#### Scenario: 延迟导入的终端组件缺失
- **WHEN** Windows 后端能够导入主服务但无法加载必需终端组件或其原生库
- **THEN** 制品完整性验证失败，不以主服务启动成功掩盖终端依赖缺失

#### Scenario: 工程辅助资源缺失
- **WHEN** 制品声明携带的工程辅助资源未实际包含或无法读取
- **THEN** 验证失败；不要求未声明随包分发的用户 Java、Node 或语言服务环境已安装

### Requirement: 最终后端的真实启动连接验证

进入分发封装前，流程 SHALL 运行将被分发的后端二进制，并在限定时间内验证其正常服务启动和只读 WebSocket RPC 响应；仅文件存在、归档内容检查、帮助输出或工程 helper 运行成功均不足以通过。进程提前退出、连接失败、响应不匹配或超时 MUST 失败。

#### Scenario: 后端启动后连接成功
- **WHEN** 最终冻结后端正常启动且返回匹配请求的只读 RPC 成功响应
- **THEN** 记录该制品通过真实启动连接验证

#### Scenario: 导入阶段崩溃或监听超时
- **WHEN** 后端在监听前因缺少模块退出，或超过启动预算仍无法响应
- **THEN** 门禁失败，输出有界诊断，后续封装和候选登记不执行

#### Scenario: 端口被其他后端占用
- **WHEN** 验证地址已被其他进程占用或连接到非本次启动的服务
- **THEN** 验证拒绝将其他服务的成功响应当作该制品通过

### Requirement: 验证隔离与有界清理

验证 SHALL 使用独立临时用户目录、数据根、日志、配置及本机连接端点，禁止读取或写入生产用户数据、连接真实 Relay、调用模型或自动运行用户工程。验证 MUST 有限时和有界输出，结束时确认所属进程退出；清理结果未知时不得报告成功或终止无关进程。

#### Scenario: 生产配置存在
- **WHEN** 构建机存在真实会话、Relay 凭据或桌面配置
- **THEN** 验证使用隔离配置且不触碰这些数据，不访问真实 Relay 或模型

#### Scenario: 验证失败后清理
- **WHEN** 启动验证超时或失败
- **THEN** 仅清理本次拥有的进程树，记录清理结果；未知结果使门禁保持失败

### Requirement: 所有封装入口不可绕过就绪门禁

普通、fat、sidecar-only、lite 和 Web 冻结分发入口 SHALL 在封装或候选登记前执行适用的就绪门禁，复用已有二进制也不得豁免。缺少 sidecar、校验失败或验证后制品被替换时 MUST 非零退出，不得警告后继续产出成功结果。

#### Scenario: 复用缺失或损坏的 sidecar
- **WHEN** 包装入口跳过编译但选中的 sidecar 缺失或不能启动
- **THEN** 停止封装，不从另一份未经验证的文件静默回退

#### Scenario: 校验后替换产物
- **WHEN** 待装入安装包的二进制与已验证制品身份不一致
- **THEN** 重新验证或拒绝封装，不复用旧成功结果

#### Scenario: 子构建失败传播
- **WHEN** 被上层包装入口调用的依赖或启动门禁失败
- **THEN** 上层同样非零退出且不执行候选登记

### Requirement: 可追溯且如实的验证结果

流程 SHALL 保存有界的制品路径、散列、平台、版本、验证阶段、结果及失败类别，不保存凭据或真实用户内容。未在目标平台运行的验证 MUST 明确标记未验证，不能用模拟测试或 helper 测试替代完整发布制品通过记录。

#### Scenario: 成功与失败记录
- **WHEN** 制品门禁完成
- **THEN** 记录可核对的制品身份与各阶段结果，失败时显示缺失依赖、启动失败、连接失败或清理失败等可操作类别

#### Scenario: 目标平台不可用
- **WHEN** 当前环境不能运行某一目标平台的冻结制品
- **THEN** 保持该平台验收未完成，不声称已经通过
