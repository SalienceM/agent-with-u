# Proposal

## Why

DeepSeek Harness 当前在发现图片附件时一律拒绝，尚未进入运行时便显示“附件能力尚未验证”；锁定 rc.3 的 SDK 已有图片内容块协议，但 AWU 尚未接入真实传输及路由能力核对。输入框又在调用发送后立即清空内容，使拒绝提示所说的“保留附件”不等于保留可继续编辑的草稿，需要同时修复图片接入和发送反馈。

隔离原生契约测试还发现：rc.3 图片上传遭遇配额错误时会按 `dsh-` 文件名前缀删除当前 API-key 命名空间中的旧文件，可能包含其他 Session 的文件。图片发送授权不能覆盖这种远端清理；启用图片前必须验证能够阻止未经独立授权的删除。

## What Changes

- 将无条件拒绝图片改为基于实际执行节点、锁定运行时、Backend 配置及本轮有效模型路由的能力校验；区分支持、不支持和未知，不以 Backend 名称、用户自填模型名或 SDK 接收成功证明视觉能力，不伪造模型目录。
- 对已确认支持且满足远端副作用安全边界的路由，将本轮文字和图片通过原生图片内容块提交并保留其关联，支持纯图片输入及原生会话续聊；不将附件变成模型无法访问的控制端 URL，不删除图片后改发纯文本，不用另一 Backend 或 OCR 悄悄替代原请求。
- 对图片格式、实际字节、数量、解码尺寸和请求总量实行有界校验，并核对现有 1 MiB JSON-RPC 帧限制与图片传输的兼容性。损坏、超限或不支持的输入须明确拒绝，不能静默截断、无限放大协议限制或按附件提供的任意路径读取文件。
- 在请求尚未接受而被拒绝时保留同一 Session 未被编辑的文字与图片草稿，提供可操作原因；迟到回执不得覆盖用户后来编辑的内容或另一身份的草稿。内部区分请求已接受、结果未知与未发送，必要失败或未知反馈复用现有错误提示；正常添图、发送、排队及完成不增加图片状态栏、限额说明、详情、刷新或恢复按钮。不自动重发、不重复入队，不把请求接受当作模型完成。
- 保持现有执行器归属、原生会话恢复、取消与未知退出保护，附件不得扩大工具权限或复制本轮临时授权。新增诊断和 trace 只记录必要的受控元数据，不复制图片 Base64、完整请求或凭据。
- 图片发送、配额恢复、重试、失败和停止均不构成远端清理授权；`dsh-` 前缀不是当前 Session 归属或删除授权证据。必须在不改 SDK、不另建模型通道的前提下验证安全隔离接缝；无法保证阻止未授权删除时明确拒绝，保留附件、回执及原生关联，不能先执行危险路径再补救。
- 补充隔离回归：覆盖支持／不支持／未知路由、文字加图片／纯图片、格式和大小边界、续聊、排队、拒绝时草稿保留、身份切换及未知回执，以及 Files 上传成功、配额耗尽、跨 Session 文件、错误和停止时的零未授权删除；以锁定运行时和本地假服务核验真实图片传输，不把模拟通过当作生产模型识图能力已验证。

## Capabilities

### New Capabilities

无；沿用现有 Harness Backend 能力，不另建重叠能力。

### Modified Capabilities

- `deepseek-harness-backend`：细化“完整 Agent 与真实能力”的图片准入、原生传输、未知／不支持反馈及草稿保留要求，并补充与原生恢复、排队和终态真实性相关的图片场景。

## Impact

- 后端：`deepseek_harness_turn.py`、SDK 协议边界及必要的 AWU 适配桥，关联 `BridgeWS` 的发送准入／回执与能力反馈；继续使用现有锁定 SDK/runtime，若桥有调整须验证配套资源一致性。
- 前端：`ChatInput.tsx`、`useChat.ts`、`api.ts` 及必要的会话能力反馈，保持目标执行节点、草稿身份和其他 Backend 的发送行为。
- 测试：Harness 轮次、SDK 契约与原生假服务测试，以及聊天输入与草稿回归；共享入口的既有 LOOP／辅助调用限制不得因本次改动被绕过。
- 范围限于用户提交的图片附件及其失败反馈。不包含任意文件附件、新模型发现平台、SDK 升级、自动安装、用户配置改写、历史失败消息重放、打包发布或本机更新；不新增远端清理或清理授权界面，不从聊天中的方案确认、附件或旧权限推断删除授权。
- 已归档的 `2026-11-01-fix-harness-diagnostics-and-preflight` 保持 0/14 未完成且未同步主规格；本变更不继承其地址校验、通用错误分类和环境检查任务，也不将其视为已实现前提。
