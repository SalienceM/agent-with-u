# Design

## Context

动机见 proposal.md。当前 `QueryBudget` 将所有准备、读取和模型调用计入同一个 180 秒预算，`InspectionRunner` 最多四个决策轮加一次最终回答，没有回答时间预留。`ReadonlyFiles.search` 通过全文读取搜索，共用 1 MiB 总读取额，且捕获读取限制后继续遍历。`InspectionQueries` 记录来源时经白名单丢弃具体错误信息；前端仅凭 offset 展示字符范围。`AsideInspectionBridge` 的清理完成路径重复发布原超时文案。

这次跨预算、任务拥有权及前端元数据，需设计文档。原能力的未归档规格已要求有界、安全、真实终态；本变更追加具体收尾保障，不扩大访问权，不修改原 change。

## Goals / Non-Goals

**Goals:**
- 在总预算内尽可能形成有依据的回答，阻止耗尽预算后的无效查询循环。
- 让用户区分读取了什么、哪里没覆盖、为何受限、调用是否确认退出。

**Non-Goals:**
- 不保证模型必定在时限内答复；不提高为无限轮数/时间，不引入全仓库索引。
- 不变更主聊天工具、路径/凭据防护、节点选择或用户数据；不部署发布。

## Decisions

### 1. 预留回答窗口，但不重叠启动未知调用

默认仍为总共 180 秒，其中最后 60 秒预留给一次最终回答，查询发现阶段至多 120 秒；小预算测试按总时长三分之一计算预留。准备时间也计入总计时。每次模型决策和每个文件查询前核对发现期限、剩余操作数、读取量和上下文量；一旦不适合继续发现，转入只回答模式，不再接受新读取。保留最多四个决策轮加一次最终回答。

发现阶段中的调用也受发现期限约束，不能靠一次慢调用穿透预留。若到点时调用仍运行，取消并确认该请求拥有的模型/读取任务；只在确认退出、身份仍有效、用户未取消且总时间尚有余额时才允许一次总结。无法确认时保留原 unknown 占用，不并发开启第二次模型调用，也不将请求级取消标志复位。用户停止/身份失效/总超时与内部发现阶段结束分开处理。

最终回答仍受总期限约束，必须为有效 answer 对象。模型失败/无效协议/超时保持失败，可提供确定性的“已读取范围与未完成原因”说明，但不伪造业务答案或将失败改成 done。直接无需查询的问题仍可在首轮回答。

备选：只延长总超时会扩大资源消耗且无法解决无效查询；因此保留总边界并增加收尾窗口。

### 2. 搜索子预算与定向读取保留

累计新磁盘读取仍不得超过 1 MiB，搜索最多占用其中 512 KiB；剩余额度用于定向读取，直接读取仍同时受总额约束。检查安全句柄和文件大小后，在实际读取前核对剩余额度；缓存复用不重复收取磁盘字节，但需维持修订检查，返回模型的证据仍计入上下文上限。

搜索保留现有目录/文件/命中数边界。遇到搜索级或请求级额度耗尽立即停止扫描，返回已取得匹配及结构化覆盖不足原因；单个超大/不可读/不支持文件不当成整个项目失败。取消、身份失效和时间截止不能被通用跳过逻辑吞掉。为模型提供当前可用查询类别、剩余额度及聚焦目录的简短提示，不把提示当访问授权。

搜索额度耗尽后禁止再次执行搜索，但允许尚有预算的定向读；总读取量/上下文/操作数耗尽直接总结。单文件限制允许换合法目标，重复相同不可恢复的失败查询在本次请求内去重，记录一次并要求转向或收尾。不同 offset 的有效分页不误判为重复失败。

备选：搜索与读文件各给一套 1 MiB 会放大原总边界；完全共用且无保留会重现本问题。选择现有总额内的搜索子预算。

### 3. 安全且可解释的来源元数据

保留现有 status=limit 兼容旧客户端，追加可选的有限枚举原因（单文件、累计读取、搜索、上下文、操作数、轮数、时间预留等），并由服务端/前端固定文案解释。只白名单保留已核验的相对路径和有界数值，不能把原始异常、未经核验输入路径或文件正文复制到来源。

目录结果携带分页偏移、返回项数和下一页存在性；搜索携带访问数/命中数及是否完整；文本携带字符 offset/end。前端按 operation 显示：目录是“目录项/分页”，搜索是“搜索覆盖”，只有文本才显示“字符范围”。旧记录缺字段时不猜测数量或具体超限原因，不能再显示无意义的 0–?。

### 4. 失败原因与退出状态分离

异常原因不附带会过期的“正在确认停止结果”。桥接层依据拥有任务和 Harness 原生退出状态决定：未确认时 phase=unknown 并保留占用，确认后显示失败/已停止以及“退出已确认”含义。延迟清理更新 inspection 与错误答案区域，避免顶部已经结束但正文仍说正在确认。终态不重放查询、不释放其他 Session/主线占用，旧历史文案不批量迁移或虚构确认。

## Risks / Trade-offs

- [发现时间变少，复杂问题覆盖更有限] → 回答明确已知/未查到范围，允许用户新提问；不能保证完整架构分析。
- [阶段截止与用户取消混淆] → 独立原因与 owned-task 清理测试；未知退出不启动总结调用，不清空请求取消标志。
- [预算检查遗漏缓存或内部搜索读] → 统一计数并以临时文件验证每条实际读取路径，保留现有单文件限制。
- [元数据泄漏或旧客户端不兼容] → 原 status 保留，新增白名单枚举/数字；凭据、越界、原文不进入持久化来源。
- [生产超时也可能来自模型服务] → 只承诺受限收尾和准确状态，不声称本修复保证生产模型速度。

## Migration Plan

先落地预算/拥有权单测，再接入执行流程、可选元数据和 UI，最后更新文档并执行隔离回归。无需数据迁移、新依赖或用户配置。发布需另行授权，本变更不重启生产服务。回退代码时保留原只读与未知退出保护，不回退为 unrestricted agent。
