# Design

## Context

动机和用户选择见 [proposal.md](proposal.md)。当前实现已核对：

- `FileTreePanel.runCompare` 取得 `localFs.scan` / `syncManifest` 清单；`statusOf`、`differentPaths` 和 `dirSyncFreshness` 解释差异。比较结果目前是松散组件状态，读取结束缺少完整审阅修订约束。
- `FileTreePanel` 的 `diffPanel*` 调用 Git diff；`DiffViewer` 解析 unified diff 并固定使用旧版/新版标题，不是两端目录内容比较。
- `utils/diff.ts` 用二维 LCS，超过 500 行就全量删除/新增，不能作为可信源码审阅算法。
- `dirSync` 基线只有 hash、size、mtime，键为本机目录 ID 与远端工作目录，没有历史内容，也没有完整用户/执行节点/Session 隔离。不能据此构造三方正文或让新面板盲信旧基线。
- 现有 `pull` / `push` 在组件内分块复制，`syncWriteFinish` 验大小后替换目标，`bumpBaseline` 使用旧 manifest。浏览器 `writeFinish` 只关闭 writer，未提供目标版本前提或精确未知结果回执。
- `fileTransfers` 提供同工作区单个活动任务和跨面板反馈，但只有 running/done/error/cancelled，没有未知结果状态。
- `workspace_documents.py`、Tauri `local_documents_core.rs` 和本机文档适配已有文件身份、原子替换、属性保留及回执经验；文档编码保存不是原字节传输，而且远端文档 UI 明确只读。新能力是显式同步，不通过开放远端编辑实现。
- `docs/engine-document-contract.md` 明确存在外部程序最终核验与替换之间的竞争窗口。文件复核不是跨机器或全系统事务。
- `simplify-workspace-file-panel` 未归档规格要求默认树顶部 80px 内、按需工具、不闲置轮询；本方案补充审阅，不修改该变更或绕过其契约。

## Goals / Non-Goals

**Goals:**

- 分离“清单比对”“当前文件内容审阅”“显式单文件传输”三个阶段，只有最后一阶段允许写入。
- 提供从目录差异队列到双栏内容再到准确回执的连续操作，协议、计算、缓存和 UI 都有边界。
- 复用现有来源、主题、反馈和原子文件能力，不把更多业务状态继续堆入 `FileTreePanel`。

**Non-Goals:**

- 不建立三方内容历史库，不加入编辑器、整目录写计划或自动推拉策略。
- 不声称旧普通传输已经获得本方案的审阅保护，也不在本变更中重写所有普通上传下载。
- 不新增常驻监听器、后台预读整个目录、模型调用或外部 Git/diff 进程。

## Decisions

### 1. 独立审阅控制器，文件面板只负责接入

新增 `DirectorySyncReviewPanel` 与 `useDirectorySyncReview`，将队列、选中项、读取、diff、确认及结果归约为单一受身份约束的状态。`FileTreePanel` 传入不可变比对快照和已有来源连接，不把 Git diff 状态复用给同步审阅。

入口位于“本机副本与同步”的“审阅差异 N”；已比对的文件/目录菜单提供“审阅此文件/目录差异”。完成比对不自动弹出；文件普通点击保持既有预览/打开语义。快捷动作必须有非 hover 等价入口。

打开后默认定位首个未处理项；指定文件入口定位该项，目录入口用 `rel === dir` / `dir + '/'` 的分段边界筛选两端路径并集。排序为冲突优先、其余相对路径稳定排序，处理后不重排原队列。文件名筛选和“未处理/全部”只是当前快照投影；默认仍可返回已跳过、成功和失败项目。列表按 100 项分页，不截掉后续差异。

当前项可返回 `pending / skipped / stale / transferring / pushed / pulled / failed / unresolved`；上一项/下一项不隐含跳过。成功复核或显式跳过后转向下一未处理项；失败、过期和未知停在当前项，禁止自动发送下一项。关闭只关闭视图，不取消已提交传输。

备选：直接在窄文件树逐行展开 diff 会破坏紧凑布局；复用 Git 弹窗会混淆来源和权限。因此采用独立按需面板，共用于 Chat/Engine，不新开原生窗口。

### 2. 两端身份和快照是所有异步结果的边界

`ReviewScope` 绑定当前用户、Session、明确 `execKey`、执行端实例/工作区修订、服务端规范目录、本机适配真实 bindingId，以及 Git 元数据开关。`CompareSnapshot` 包含该 scope、单调 `compareRevision`、时间、两端 manifest 和可信基线。`runCompare` 在发起与返回时检查相同 scope/请求代次；失败不覆盖上一份快照为“空”。重新比对产生新修订，清除未提交决定并重新阅读当前项。

`ReviewPair` 保存相对路径、两端存在/类型状态、原字节哈希及版本、格式元数据和当前读取代次。路径/作用域变化即取消可取消的只读工作，并通过代次丢弃无法取消的迟到结果；确认框也必须绑定相同 pair。单端不存在是经核实的 `missing`，不能由网络错误推导。

新基线格式以完整 scope 的稳定用户/节点/Session/目录/副本维度和策略为键，另存来源协议/修订有效性。旧 `localId::workingDir` 数据保留但在新审阅内视为来源未确认，不据此给出两端冲突或方向结论。只有本期受保护推拉成功且两端复核一致才写新基线；未覆盖条目保持未知。比较状态解释共用 `dirSyncFreshness`，旧端/普通传输导致的未知基线不被升级为可信。

备选：仅给当前选中文件加 requestId 无法解决换用户、节点同路径或换副本造成的串用，因此 scope 与文件代次必须共同核对。

### 3. 有界完整原字节读取，展示层不承担传输编码

计划添加版本化 `syncReviewCapabilities` / `syncReviewRead` / `syncReviewCheck`，由 `BridgeWS` 路由到独立 `sync_review.py` 服务；参数以 Session 和服务端签发的工作区身份为准，不能用模型/客户端任意绝对路径取代。每次调用核验当前用户所有权、实际节点、工作目录及路径策略。只读 I/O 放在有界 worker，不阻塞聊天事件循环。

本机 `LocalFs` 增加可选 review adapter，Tauri、浏览器目录和托管 IndexedDB 各实现同一读取/版本/提交契约。浏览器读取 File 快照并使用实际 handle 身份；托管空间使用记录修订；原生端使用打开句柄的对象身份。版本包含存在性、完整原字节 SHA256、字节数及可靠文件对象/修订证据；mtime 仅作显示与辅助变化提示。`syncReviewCheck` 必须真实复读哈希，不能复用 size+mtime 的 manifest 缓存。

默认每端最多 2 MiB 原字节、20,000 行；服务端与适配先检查大小，再有界读取并核对前后版本。单行超过 64 Ki 字符、二进制、专用文档类型或解码不完整时显示明确限制。本期支持严格 UTF-8（可有 BOM）及带 BOM 的 UTF-16 LE/BE，复用 `documentCodec` 的解码判定，但传输始终使用原字节，不把 LF 规范化后的显示文本重新编码覆盖目标。混合换行可只读展示并明确标注。

缓存只保留当前文件 pair，不保存正文到 localStorage、Session 或历史记录；返回上一个文件重新进行受控读取。同一 scope/path/version 的在途请求合并，快切有取消/丢弃机制。网络/权限错误、真实 missing 和非普通文件分别返回，不将失败端补成空字符串。浏览器目录权限失效时仅提示手动处理，不自动弹出授权或切换离线空间。

旧节点可以保留原文件树与原传输入口；新审阅不偷偷用无界 `syncReadFile` 或无版本写降级。只读信息和“跳过”仍可用，缺能力的方向按钮显示原因。

### 4. 有界行差异在 worker 中计算

新增结构化 diff 数据层，采用可取消、有预算的行级 Myers/锚点分段算法；不沿用 `utils/diff.ts` 的 >500 行全删除/全新增降级。通过 Vite worker 按 pair 修订返回精确行映射、差异块和统计，计算设置操作预算和 2 秒总截止；预算耗尽明确返回 `diff_unavailable`，禁止基于未完成审阅提交，不伪造完整差异。

只读视图可抽取 `DiffViewer` 的样式/行渲染思路，但使用结构化数据和可传入两端标题，避免把任意源码拼成 unified diff 再解析。Git 原调用保持原样。真实行号包括空行；末尾换行、BOM/编码及行尾差异单独展示，显示文字相同不等于字节一致。长行横向滚动不省略，未改段默认折叠且可展开，行渲染窗口有界；当前块导航同时定位左右，滚动联动有反馈锁。源码始终作为文本/安全高亮结果显示。

桌面主体为可折叠文件列表和左右内容，顶部固定两端身份/当前路径/序号，底部为明确方向动作。窄屏使用“本机/执行端”切换及共享差异块导航，不强挤两列；保留两端来源摘要。主题用项目变量，键盘 Tab/方向导航、关闭与 Escape 回焦、焦点圈和触屏尺寸均沿用现有规范。

备选：Monaco/外部小乌龟引入新进程、重量级依赖或节点文件落地，本需求不需要；直接在主线程做无界二维 LCS 不满足性能边界。

### 5. 新面板使用受保护的单文件原字节提交

现有 `push` / `pull` 的无条件覆盖不能直接挂到“已审阅”按钮。新增 `syncReviewApply` / `syncReviewGet` 和本机 review adapter 的 `apply/get`，以新增能力版本隔离旧协议。首版直接提交最多 2 MiB 的完整原字节，避免为小文本另建长时分块协议；明确传输上限，不复用普通传输的大文件上限。

单文件过程如下：

1. 点击方向后显示当前路径、两端真实位置、创建/覆盖影响及冲突提示；确认只绑定当前 pair，不预选时间较新的一方。
2. 确认后在同工作区取得既有传输互斥，检查当前窗口已知相关脏文档/未确认保存、Session/权限与目标身份，重新读取/核对两端与 pair 完全一致。变化即 stale，保持新文件，不自动更新确认。
3. 固定本次原字节、源版本、目标预期版本、方向、scope 与 requestId。执行端通过 `syncReviewApply` 接收推送，本机 adapter 接收拉取。来源在预检后再变化无法跨机器原子阻止，但实际提交只使用已展示的冻结字节，绝不边写边重新读取未审阅的新内容。
4. 目标服务按规范路径与相同 requestId 去重，保存有界回执；提交前再次核验目标对象/哈希/存在性、父目录与权限。现有文件走保留属性的同目录原子替换；不存在目标用不覆盖同名文件的创建。仅创建本次必要且通过验证的父目录，不删除/替换阻塞父路径。类型冲突、链接/junction、越界、只读或身份不可证均失败。浏览器目标创建若无法证明安全不覆盖，则该创建方向不支持，不能改用弱写。
5. 目标核验落盘字节 hash/size 与冻结源一致后给出成功回执；再对两端做单文件复核，仍一致才推进可信基线和“已同步”。源已产生新版则显示本次传输完成但仍有差异，不消除新版本。

底层复用/提取现有 `workspace_documents.py` 和 `local_documents_core.rs` 的路径身份、属性与原子替换原语，但新增原字节提交入口；不通过文档文本编码路径转换源格式，不开启远端编辑。浏览器目录沿用真实 handle + Web Lock + 提交前版本复核，close 后异常为未知；托管空间用事务内 revision CAS/commitId。所有适配的写能力必须真实可用才暴露。

AWU 内部同路径锁与传输占用防止本应用重入，不能阻止不合作外部程序。最终目标复核到替换仍有操作系统竞争窗口，遵循既有文档契约如实说明；发生提交后验证失败不自动回滚覆盖后来修改。

### 6. 结果未知有独立回执，不污染队列和基线

向 `fileTransfers` 添加兼容的 preparing/unresolved 展示或等价扩展，让新审阅任务只有权威终态才能解除同工作区写互斥；旧普通任务行为不变。相同 requestId/相同输入返回原回执，输入不同拒绝。回执绑定作用域、相对路径、方向、源摘要及预期目标版本，不记录正文。

执行端最多 32 个在途/未核对请求，终态保留最近 256 条；本机使用同类有界日志，托管存储用原子事务。原生 worker 尚未结束时取消请求只是取消意图。关闭 UI、网络超时不终止 worker，也不等于失败可重发。

正常任务等待其拥有的完成结果；异常未知最多自动只读核对一次，之后由“核对结果”显式查询。禁用以新 requestId 自动重试、自动覆盖或强行释放未知任务。重启/旧实例回执缺失仍为 unknown；只能只读核实与提示处理，不根据相同字节猜测原请求必然成功。UI 和回执状态保留在原工作区，切换后的迟到回执只更新原任务，不改新队列。

当前会话关闭审阅后清除正文缓存，已提交任务由独立传输控制器持有。重新打开同 scope 的审阅可看到已有任务结果，不要求留着整个文件树组件。所有列表和当前项变化按相对路径键归约，不能因自动下一项把旧成功写到新文件。

### 7. 以隔离夹具验证，不拿用户目录做验收

- 纯单元：目录边界/队列导航、hash/mtime/基线解释、scope/代次、EOL/BOM、空文件/缺失、真实 >500 行 diff、超预算、状态归约、相同请求去重。
- Python 临时工作区：新协议所有权/路径边界、有界读取、同大小内容变化、对象替换、创建竞争、属性/只读、提交前变化、错误/取消/未知结果及回执查询；原 `test_file_transfer.py` 回归保持兼容。
- Tauri 原生临时目录、浏览器 File System Access 合约夹具与真实托管 IndexedDB：三个适配共同验证原字节保持、目标前提、失败不覆盖和未知不重放。未覆盖平台明确记录为未验收，不能用 mock 冒充原生能力证明。
- Playwright 新增同步审阅场景，在现有 `.qa` 隔离 fixture 中使用合成远端/副本：1366px 与 390px 截图；跨文件导航、确认取消、跳过、方向准确、单端、格式差异、失败/未知、快速切换、关闭焦点、Git 与普通预览不回归；计数确认进入/退出/闲置不全量扫描或写入。
- 执行 `npm run test:home`、目标 Playwright、`npm run build`、相关 Python/原生测试和 OpenSpec 严格校验。验收报告分清真实本机文件核心、浏览器夹具和未验证生产节点，禁止真实模型或用户项目同步。

## Risks / Trade-offs

- [新面板带来的协议工作多于纯 UI] → 只为当前单文件文本提供新协议，不改旧大文件/目录传输；目标前提不满足时明确只读，不借 UI 名义提供弱覆盖。
- [双栏看到的是采样时的内容] → 标注版本与时间，确认前复核两端、目标提交前再核验；说明外部竞争窗口，不承诺全局事务。
- [编码与换行导致文字相同但字节不同] → 单独展示格式差异并原字节复制，hash 相同才算一致。
- [大文件/重复行引起计算或布局卡顿] → 每端读取/行数/长行限制、worker 截止、窗口化行和单 pair 缓存；超限禁用本面板提交，保留跳过及原普通传输入口。
- [旧基线作用域不足] → 新审阅只信完整 scope 基线，旧数据不删除也不自动视为可信；暂时失去方向提示比串用其他节点基线更可解释。
- [已知草稿只覆盖当前应用可观察范围] → 明确当前窗口脏稿门槛并保留文档版本冲突检测，不声称检测所有外部编辑器或其他窗口未保存内存。

## Migration Plan

1. 先增加能力协商、只读/提交原语及隔离测试，再接入前端控制器和面板；不在部署/页面加载时扫描项目或转换文件。
2. 新节点/适配可用时启用对应方向；旧端保留既有浏览和传输，新面板显示限制而不是自动回退。既有 Session、副本绑定和旧基线不破坏性迁移。
3. 回退时隐藏新入口但保留已提交任务的完成/核对能力和回执，不自动撤销成功传输、不删除基线或用户文件。本变更的 apply 不包含打包、发布或部署。
