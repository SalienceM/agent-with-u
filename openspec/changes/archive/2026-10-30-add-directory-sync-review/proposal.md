# Proposal

## Why

文件面板比对后只能看到颜色、新旧提示和推拉按钮，无法连续查看本机副本与执行端同一路径的实际内容差异，用户难以判断该覆盖哪一边。已有 Git diff 比较的是仓库版本，不能替代这项两端同步审阅；首次比对的修改时间也不能决定正确同步方向。

## What Changes

- 新增按需打开的“同步差异审阅”面板：差异文件列表、两端只读双栏 diff、行号/差异块导航、上一项/下一项及处理进度；支持整次比对、指定目录子树和单文件定位。
- 明确标注“本机副本”与“执行端”的节点、目录、文件状态和判定依据，不沿用 Git 的“旧版本/新版本”命名。无基线只说明内容不同及时间参考，不默认替用户选择方向。
- 当前文件可显式选择“推送到执行端”“拉取到本机”或“跳过”。推拉先确认精确来源和目标，仅处理该文件；成功核验后可继续下一项，跳过不等于已同步。
- 为该审阅入口补齐有界完整读取、两端版本复核、原字节传输与目标最终校验。审阅后内容变化即失效并要求重新审阅；提交结果未知只查询，不自动重放或更新同步基线。
- 单端文件显示另一端不存在；文件/目录类型冲突、二进制、大文件或不可完整解码内容显示真实限制，不把缺失或读取错误伪装成空文本。本期面板内写入仅开放给已完整审阅且具备受保护传输能力的文本文件。
- 保持文件树紧凑布局、显式比对、按需读取、无闲置轮询、Session/节点/副本隔离和已有普通传输入口；不自动运行 Git、模型或后台目录同步。

### Non-goals

- 用户已选择方案 1：不做逐行采纳、手工编辑、三方内容合并或合并结果保存。
- 不引入批量自动决策、目录镜像删除、重命名推断、Git 冲突解决、外部小乌龟程序调用或独立原生窗口。
- 不迁移整个同步引擎，不改变其他普通传输的既有行为，不把文件级复核宣传为跨机器或全系统原子事务。

## Capabilities

### New Capabilities

- `directory-sync-review`: 对显式目录比对结果逐文件审阅本机/执行端内容差异，并作出受版本保护的单文件推拉或跳过决定。

### Modified Capabilities

无。现有主规格没有目录同步审阅能力；本变更与尚未归档的 `workspace-file-panel` 增量互补，保留其紧凑布局、按需同步和来源隔离要求，不覆盖或归档该变更。

## Impact

- 前端入口：`FileTreePanel.tsx` 及新的同步审阅控制器/面板；复用 `dirSyncFreshness.ts`、本机副本适配、主题与传输反馈。Git diff 和已有文件预览继续独立。
- 文件协议：`api.ts`、`bridge_ws.py` 与独立同步审阅服务，以及 Tauri / 浏览器目录 / 托管 IndexedDB 的本机适配。新增受能力协商约束的读取/单文件提交/回执查询，不借用远端编辑入口绕过只读规则，不降级到无条件覆盖。
- 状态与安全：显式比对快照、当前审阅版本、精确身份的同步基线，以及传输结果未知状态；保留现有未提交文档草稿和其他传输互斥。
- 测试与文档：同步边界/新旧判断、单文件传输、文件面板布局及新增审阅单元/浏览器/原生适配测试；只使用临时文件和隔离夹具。
- 不需要 Docker、外部 diff 程序、模型请求或发布部署。计划使用项目内有界 diff 计算与已有展示基础，不引入重型编辑器依赖。
