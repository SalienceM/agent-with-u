# Design

## Context

动机见 `proposal.md`。任务 1–4 的手工维护基线已完成；本次确认只修订规划，新增目录同步尚未实现，不能用基线验收代替同步能力验收。

与扩展相关的基线和约束：

- `modelOptions` 已贯穿 Backend 序列化、固定官方及普通保存分支和导入导出；内置/null、自定义、空数组三态及旧客户端缺字段合并保留不变。
- 前端已有共享候选解析器和编辑草稿。Backend 默认模型、新建 Session、聊天和 LOOP 角色按各自 Backend 消费候选，仍允许自由输入；不再新增模型常量表。
- 保存经目标节点路由、回读校验及节点范围刷新；同步可复用此持久化路径，无需另建自动保存或全局候选库。
- 项目已有 Codex app-server 进程传输。`model/list` 是待核验的目录接口候选；尚未验证实际响应、分页、刷新行为或缓存新鲜度，不以接口名称推断“官方最新”。
- 现有隔离后端、home 单元和 Playwright 测试设施可用于同步扩展，不读写生产认证或发起付费模型调用。

## Goals / Non-Goals

**Goals:**

- 用节点上的 Backend 配置作为候选数据的权威来源，所有消费者共用相同解析规则。
- 明确内置、自定义、空列表和旧客户端缺字段的区别，使保存、回读、导入和重启不丢数据。
- 保持模型运行参数与 UI 候选分离：不改变解析优先级、原生 thread、权限或已在运行的请求。
- 用户一次点击从目标 Backend 环境读取目录，校验后更新草稿；来源、新鲜度及失败状态可见，保存继续走既有路径。

**Non-Goals:**

- 不启动后台或定时目录同步，不直接抓网页维护模型表，不验证账号访问资格，不为候选发起试运行。
- 不维护各模型推理档位、上下文容量或价格，不修改 Codex CLI 安装/配置，不改其他 Backend 的候选机制。
- 不承诺旧版本执行端具备此功能，也不新增跨所有控制窗口的常驻轮询或实时同步服务。

## Decisions

### 1. 可选 `modelOptions` 存于 Backend，而非浏览器或 Session

Python 增加可选 `model_options`，线上 JSON 使用 `modelOptions`。每项形如 `{ "id": "custom-model-id", "label": "我的常用模型" }`；`label` 可省略。数组顺序就是展示顺序。字段与 `model` 独立，不把首项当作默认模型。

| 场景 | 语义 |
| --- | --- |
| 磁盘旧记录缺字段 / 值为 `null` | 使用内置候选 |
| 值为自定义数组 | 完整替代内置列表，保留顺序 |
| 值为 `[]` | 明确不展示候选，仍允许手填 |
| 更新已有同类型 Backend 时省略字段 | 保留现有值，兼容旧客户端 |
| 更新时显式传 `null` | 恢复内置候选，不修改默认模型 |

选择原因：候选依赖账号/连接环境，同一执行节点的 Backend 已是管理边界。浏览器 localStorage 会导致换窗口、换设备丢失；全局单表会把不同节点/账号的候选混在一起；Session 各自维护会重新制造重复配置。

### 2. 校验与缺省合并分别处理，写入沿用现有原子流程

后端建立单一候选规范化函数，供保存 RPC、配置解析和导入使用；前端用对应规则提供即时错误。约束与规格一致：最多 100 项；ID 去首尾空白、非空、最长 200 字符，无内部空白或控制字符；名称可空、最长 120 字符，无控制字符；精确重复 ID 拒绝，不以固定品牌或版本前缀校验。

规范化不改写大小写，不静默截断或去重；空名称统一省略。读取和序列化保留 `None` 与 `[]` 的差异。固定 Codex 分支、普通分支及其他字段的重建均不得意外复位新字段。

缺字段不能在解析时提前折叠成显式 `null`：导入覆盖需保留原始条目是否包含该字段的信息，再按目标已有 Backend 及类型决定合并。旧文件添加新 Backend 时使用内置模式；覆盖同类型已有 Backend 且字段缺失时保留已有候选；显式 `null`/`[]` 按其各自语义覆盖。既有受保护 ID 跳过策略不变。采用增量字段，不升级导出 envelope 版本，也不放宽原导入校验。

替代方案：把缺字段和空列表都当“恢复默认”更简单，但会清除旧客户端无法表达的配置，因此不采用。

### 3. 共用候选解析器，保留现有自由输入

新增纯前端工具模块（建议 `utils/codexModelOptions.ts`）承载选项类型、单份内置候选和有效列表解析；迁移当前两份常量的消费者，不引入第三份默认表。这里只声明软件内置推荐，不暗示它是实时官方可用列表。

`BackendManager` 使用正在编辑 Backend 的草稿列表；其默认模型仍是原有独立输入。`BackendRuntimeFields` 从传入 Backend 解析候选，因此新建会话、聊天和 LOOP 角色自然共享规则。保留现有解析函数及模型/推理档位继承优先级。

自定义列表不与内置列表强制合并，也不把被删除的当前模型重新加回候选；输入框仍显示当前值并接受手填。只把模型 ID 传给调用端，显示名称只用于 UI。

替代方案：改成不可手填的 select 会让尚未维护的新模型无法使用；维护多个入口常量仍需跟随模型升级修改代码，两者均不采用。

### 4. 编辑体验与刷新范围保持明确

Codex 专属配置块新增“模型候选”区域，展示当前为内置模式还是自定义模式。行编辑提供 ID、可选名称、删除与上下移动操作；另有添加和恢复内置候选按钮。沿用 Backend 保存/取消，不增加隐式自动保存。编辑、从内置模式开始修改和复制时深拷贝列表项，不能原地改动来源。窄屏按行折叠字段，按钮提供明确名称和键盘操作。

保存继续使用原 `saveBackend` / `getBackends` 路由。回读必须比较目标 Backend 的候选与提交值；自定义值或空列表被旧执行端丢弃时保留草稿并提示执行端升级/保存失败。此检测不承诺回滚旧端已接受的其他字段，因此错误文案明确针对候选保存结果。

在完成保存及回读校验后，向当前控制窗口发出带 `execKey` / `backendId` 的轻量 Backend 配置修订通知。`ChatPane`、新建 Session 与相关 LOOP 入口只刷新匹配节点的数据；同节点并发读取可合并，不能借远端更新覆盖默认节点列表，不增加轮询。异步结果保留取消/代次检查，避免切换节点后旧回包覆盖新节点。刷新列表不重建运行参数草稿。

其他窗口在重新打开或重新加载入口时向目标节点读取，无需为本功能实现新的跨窗口推送协议。节点不可达时保留明确错误，不回退其他节点或伪造成功。

### 5. 回归围绕配置与行为，不依赖真实模型

后端用临时数据目录覆盖 ModelBackendConfig / BackendStore / 保存 RPC 的往返、错误、缺字段合并、固定官方分支、复制和导入导出。沿用既有 Session/LOOP runtime 测试，确认移除候选后原模型和 thread 不变。

前端纯函数测试内置/null/[]/自定义解析和边界输入；隔离浏览器夹具覆盖新增、排序、恢复、取消、候选同步和删除当前模型。模拟两个节点拥有同 ID Backend、旧执行端丢字段、离线与迟到回包。检查 datalist 数据和实际提交 ID，而非依赖截图证明原生浏览器候选弹窗。补桌面和窄屏编辑可用性截图，不使用真实账号、付费调用或生产 Backend 配置。

### 6. 显式查询目标 Backend 的 Codex 目录

固定官方和普通 `codex-office` 编辑页增加“从 Codex 同步”。请求沿当前编辑目标的执行节点路由，复用对应 Backend 的 CLI、环境、认证和 provider 配置解析；不使用控制端或默认节点的 Codex 代替。查询不能偷偷保存 Backend。若连接相关字段尚未保存，先明确提示保存这些字段后再查询，避免界面展示的目标与实际查询环境不一致；仅修改候选不构成此限制。

通过独立、短生命周期的目录查询通道使用现有 app-server 传输，不复用正在执行的会话 stdout、不创建 thread/turn、不试运行模型。设置有界总超时、结果大小和分页上限，并在成功、失败、取消后清理该查询拥有的进程/连接；不能终止其他活动请求。沿用执行节点权限检查，不新增登录流程、不修改认证及 Codex 原生配置；响应和错误日志不携带密钥、环境变量原文或原始敏感异常。

实现先核验实际安装版本支持的模型目录协议、ID 字段、分页终止及刷新语义，再选用受支持的请求参数。接口不支持、CLI 过旧、未登录或节点离线时显示明确错误并保留手工维护，不通过其他节点、账号或网页静默替代。不能为声称“最新”而臆造刷新参数。

替代方案：直接使用通用模型 API 或网页表格不能保证与该 Backend 的 Codex/provider 环境一致；共享活动会话进程会增加读取竞争，因此不采用。

### 7. 完整结果只填草稿，来源信息保持诚实

查询结果将实际可调用的模型标识映射到候选 `id`，可选显示名称映射到 `label`，保持源目录顺序，不将展示 ID、标签或首项误当默认模型。分页须先收齐，再按决策 2 的现有规则完整校验；空结果、重复、非法数据、超出 100 项或分页未完成均失败，不截断、不部分替换、不伪装成用户显式清空。

非空、完整且有效的结果一次性替换当前候选草稿为自定义列表，并提示“已填入草稿，保存后生效”。用户可继续编辑、保存或取消；只有正常保存及回读成功才刷新其他入口。同步不改默认模型、Session/LOOP runtime、推理档位或原生 thread。失败时原草稿及生效配置都保持原样。

来源信息作为同步结果的临时 UI 状态，不新增持久化目录数据库。显示可核实的来源类型、读取时间及上游明确提供的新鲜度；未知项标为未知。读取时间不等于上游更新时间，缓存/内置目录不能标为“官方最新”，列出模型也不是账号资格保证。用户随后编辑草稿时标注已修改，重新打开配置只展示已保存候选，不伪造已丢失的同步来源证据。

按钮提供加载状态并阻止重复请求；请求关联执行节点、Backend 编辑实例及草稿修订号。切换节点/Backend、关闭编辑、保存、取消或用户产生新修改后，迟到结果不得覆盖新状态；能够取消时取消，否则丢弃结果并按适用情形提示重新同步。测试覆盖响应乱序及新建/复制编辑实例，不能仅用 Backend ID 判定归属。

替代方案：同步后直接保存、默认合并内置列表或自动选择第一项会扩大操作副作用；只更新草稿并复用保存边界可保留用户控制。

## Risks / Trade-offs

- [用户填入账号不可用的模型] → 明示候选不是可用性保证，继续由原调用端报真实错误，不静默换模型。
- [旧端接受保存却忽略新字段] → 保存后回读核对；本次新增能力要求目标执行端支持，不宣称向后端旧版本降级成功。
- [候选被删除但已有 Session 仍使用它] → 有意保留显式运行值；说明删除候选不是迁移会话，避免意外改变执行。
- [导入时缺省/空数组合并错误] → 保留字段存在性并测试三态和原子失败，不改变受保护 ID 规则。
- [多个 Pane 或节点回包串线] → 节点范围修订与代次检查；不从默认节点补齐远端候选。
- [内置推荐及 Codex 返回目录也可能过时] → 支持显式同步与手工编辑，区分目录来源、读取时间和可证实的新鲜度，不承诺“官方最新”。
- [Codex 版本或 provider 返回不同协议/不完整目录] → 实现前核验实际协议；有界分页及全量校验，不支持或超限时保留草稿并说明限制。
- [同步中切换编辑目标或产生新修改] → 编辑实例/节点/草稿代次检查与重复请求保护，晚到响应不覆盖新状态。
- [目录查询触碰活动会话或暴露认证] → 独立只读查询生命周期，复用权限和配置解析但不共享活动输出，不返回敏感上下文。

## Migration Plan

1. 后端先支持新字段及兼容合并，不批量重写旧配置、不改已有模型值。
2. 前端接入共享候选工具、编辑区域及节点范围刷新；旧记录直接使用单份内置候选。
3. 通过配置、运行参数、隔离浏览器及生产构建验证后再按单独授权发布。本规划不执行发布。
4. 回滚前保留包含候选字段的配置导出备份；旧后端可能在再次保存时丢弃未知字段，降级期间不继续编辑这类配置。会话原有模型字段不依赖新字段，候选丢失不应触发模型自动迁移。
5. 在已完成的手工维护基线上新增只读目录查询和前端按钮，不迁移旧候选、不自动执行首次同步。旧执行端不支持查询时提示升级，手工编辑仍可继续。
6. 同步扩展单独完成协议核验、隔离测试与验收记录；原 `verification.md` 仅证明任务 1–4。撤回同步功能时保留通过正常保存得到的候选，不能因功能降级自动删除配置。
