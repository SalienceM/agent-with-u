# Spec Delta

## ADDED Requirements

### Requirement: Harness 连接地址校验与协议说明

系统 SHALL 在 Harness 配置中说明其使用 Messages 协议而非普通 Chat Completions 协议，并对非空连接地址进行结构校验。无效绝对 HTTP/HTTPS 地址、控制字符及内嵌用户名密码 SHALL 在保存与执行边界被拒绝且不得回显敏感地址；空配置 SHALL 明确采用执行节点的默认解析规则。系统 SHALL 对可疑接口路径给出非阻断提示，允许合法自定义代理，不自动补写路径、迁移已保存配置或猜测可用模型。静态校验 SHALL 不发送网络请求，也不得宣称账号或模型可用。

#### Scenario: 地址无效
- **WHEN** 用户填写相对地址、非 HTTP/HTTPS 协议或包含内嵌凭据的地址并尝试保存
- **THEN** 保存被阻止且字段旁显示受控原因，不回显凭据
- **AND** 绕过前端直接提交同类配置时，后端同样拒绝；已保存的无效配置在执行前明确失败而非静默改写

#### Scenario: 自定义代理与可疑路径
- **WHEN** 用户填写结构合法的自定义代理，或填写看似 Chat Completions 接口的完整路径
- **THEN** 系统保留原草稿，说明 Messages 协议及路径检查建议，非阻断提示不被呈现为服务不可用结论
- **AND** 不自动追加 `/v1/messages` 或其他未经核实的路径，不发起探测或模型请求

#### Scenario: 空地址与默认值
- **WHEN** 用户清空连接地址
- **THEN** 系统按锁定运行时已核实的空值／未设置及执行节点环境优先级解释默认行为
- **AND** 默认来源不确定时明确未确认，不展示猜测的官方地址或覆盖节点配置

### Requirement: 执行节点上的手动只读环境检查

系统 SHALL 在 Harness 配置提供显式环境检查入口，针对当前用户、目标执行节点和当前草稿检查锁定的 SDK/runtime、适配桥、必要发行资源及配置结构。检查 SHALL 区分通过、阻塞、警告、未知、不支持和离线，说明检查范围及源码／发行包对应处理建议。检查不得自动安装、下载、修复权限、写配置、建立原生会话、启动运行时或调用模型；依赖完整不等于远端服务、凭据、模型或权限能力已验证。

#### Scenario: 缺少依赖或版本不匹配
- **WHEN** 目标节点缺少 SDK、runtime、桥或必要资源，版本或校验不匹配，或缺少可执行权限
- **THEN** 检查指出受控组件名称、已知预期版本及对应失败类型，不只显示泛化的 error
- **AND** 源码模式建议准备锁定的配套依赖，发行包模式建议修复或更换匹配发行包，不要求安装最新任意版本、系统 Node/pnpm 或自动下载

#### Scenario: 环境检查通过
- **WHEN** 所检查的本地配置和依赖均通过静态检查
- **THEN** 界面标为“环境检查通过”，同时明确远端连接、凭据和模型可用性未检查
- **AND** 未启动模型或原生会话，用户配置、文件权限和 Session 历史未被更改

#### Scenario: 目标节点离线或旧版本不支持
- **WHEN** 用户请求检查的节点离线、检查超时或节点不支持检查接口
- **THEN** 系统显示对应的离线、未知或不支持结果，不回退本机、默认节点或另一 Backend
- **AND** 不将检查不可用误判为依赖缺失，也不因未检查阻止合法配置保存

#### Scenario: 草稿与身份变化后的迟到结果
- **WHEN** 检查期间用户切换账号、节点、Backend、关闭面板或修改影响检查的草稿
- **THEN** 旧结果不能更新新对象的状态，先前结果失效且新草稿不会被覆盖
- **AND** 多次点击被合并或禁用；检查有时间和并发上限，不启动无限轮询或后台自动重试

### Requirement: 安全且可操作的 Harness 故障诊断

系统 SHALL 根据当前根会话本轮的可信结构化终态、受控启动检查和类型化异常展示有界错误分类、可验证的 HTTP 状态及中文处理建议，不丢失已知原因，也不从自由文本猜测确定根因。原始响应正文、请求头、完整 URL、环境变量和运行时 stderr SHALL 不直接进入聊天或检查回执。未知或格式损坏的错误 SHALL 显示“原因未确认”，不可伪装为认证、缺依赖或成功；部分输出、原生会话关联与原有退出保护 SHALL 保留，诊断不得触发自动重发或节点切换。

#### Scenario: 原生终态携带 HTTP 404
- **WHEN** 当前根会话本轮以 error 结束且结构化状态为 HTTP 404
- **THEN** 用户看到 HTTP 404 和核对 Messages 连接地址／路径、模型名称的建议，而非仅“未成功结束: error”
- **AND** 系统不宣称一定是依赖缺失、路径错误或模型不存在，不替用户修改配置或重发消息

#### Scenario: 认证限流和服务端错误
- **WHEN** 当前轮的可信结构化状态分别为 401、403、429 或 5xx
- **THEN** 系统保留相应数字状态，分别提示核对凭据／权限、限流或服务端情况，不把所有错误归为缺 SDK
- **AND** 仅展示受控建议，不展示原始响应正文或自动重试

#### Scenario: 网络超时与未知原因
- **WHEN** 类型化错误能证明网络故障或超时，或未提供可识别结构化原因
- **THEN** 前者显示对应类别，后者明确原因未确认
- **AND** 不根据含有 404、API Key 或 Access denied 的任意正文猜测错误类别

#### Scenario: 敏感与恶意错误内容
- **WHEN** 错误对象含凭据、带查询令牌的 URL、完整环境、超长消息或未识别字段
- **THEN** 回执与聊天只包含白名单类别、合法数字状态和受控有限长度文本，未知字段不被直接转发
- **AND** 日志不新增这些敏感内容；若有合法状态码仍保留其可操作提示

#### Scenario: 子代理与过期事件隔离
- **WHEN** 收到子代理、另一会话、旧运行或重复终态错误事件
- **THEN** 这些事件不能覆盖当前根会话本轮的诊断和成功／失败结果
- **AND** 根会话的部分输出、失败状态、原生关联及退出未确认保护继续按原有生命周期处理
