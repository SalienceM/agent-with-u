# Design

## Context

动机见 `proposal.md`。只读取证显示原生根轮次终态含 `reason.kind=error`、`reason.error.code=HTTP_404` 和 `status=404`，但 `deepseek_harness_turn.py` 仅保留 kind，随后抛出“未成功结束: error”。这证明本次已进入模型请求阶段，不证明 SDK 缺失，也不能仅凭 404 判断路径还是模型有误。

当前基础：

- `deepseek_harness_config.py` 对 baseUrl 只做字符串／NUL 校验；`HarnessBackendFields.tsx` 没有协议说明和环境检查入口。
- `BackendManager.tsx` 已有明确的 `targetExecKey`、节点切换清理及草稿状态；`api.ts` 有严格节点路由和用户身份纪元隔离模式。
- `deepseek_harness_sdk.py` 提供锁定版本和桥检查；`create_harness_config()` 在 frozen 环境会调用权限修复，不能直接作为只读检查入口。
- `deepseek_harness_distribution.py` 支持 manifest、资源摘要、平台和 runtime override 校验；`verify_bundle(repair_executable=False)` 不做权限修复。部分导入和文件读取仍需审计，不能以“检查”名义启动 SDK 或初始化用户目录。
- 现有主规格已经要求可操作错误、不泄漏凭据、取消归属和无自动重放。本次增加精确行为，不改变这些要求，也不重新执行最初接入时的版本选型；继续沿用现有 rc.3 锁定制品。

## Goals / Non-Goals

**Goals:**

- 以结构化、有限输出贯通配置检查、环境检查和聊天错误展示，保留可验证信息。
- 在无需保存草稿、无需启动进程或使用凭据的情况下，检查所选节点本地依赖。
- 保持执行身份、原生终态、进程退出保护及既有 Backend 兼容性。

**Non-Goals:**

- 不新增连通性／账号／模型探测，不自动下载或安装，不触发 Kit。
- 不修改用户现存 Backend、API Key、运行环境或原生历史，不恢复失败输入。
- 不升级 SDK/runtime，不提供模型发现或通用 Backend 健康平台。

## Decisions

### 1. 地址规则分为硬校验与提示，不提供自动纠正

前后端保持一致的结构规则：非空值须为合法绝对 HTTP/HTTPS URL、有有效主机／端口、不含控制字符及 userinfo；允许合法自定义代理、回环假服务和路径前缀。对疑似完整 Chat Completions／Messages 方法路径给出非阻断说明。仅凭路径或域名不判定服务不可用，也不建立只允许官方域名的白名单。

空值采用锁定 SDK 的真实默认解析规则；实施先对本地锁定 SDK/runtime 的默认地址、环境变量优先级和路径拼接做定点核对，并以隔离测试固定结果。若空字符串与 unset 不同，仅修正用户明确提交空配置时的适配语义，不批量迁移现存配置。无法证明官方默认时只显示默认来源未确认，不写猜测 URL。地址中的 query 不直接回显到诊断；非空地址不自动追加或删改路径。

后端保存和执行边界使用相同校验；前端反馈便于编辑但不是权威安全门槛。正常读取旧配置不失败、不覆写，下一次保存或执行遇到无效配置给出具体字段提示。

备选：自动把域名变成某个协议路径、发 HTTP 请求验证。未采用，因为合法代理路径不统一，探测会使用凭据／网络且不能由 404 推导唯一修复。

### 2. 新增显式、只读、精确路由的检查接口

在 BridgeWS 注册拟定的 `harnessEnvironmentCheck`，由小型 Harness 专用检查模块实现。接口沿用已认证的 Backend 管理边界，不接受客户端伪造 owner；使用当前目标节点的 Backend 管理授权，而非 Session 身份猜测。可检查未保存草稿，输入使用受限配置投影，不发送 API Key、任意 env、聊天或附件。需要读取已保存配置时只按已授权 Backend ID 定位；检查不枚举其他用户配置，也不以完整 Backend 对象作为通用文件读取参数。

检查项包括配置结构、当前平台、配套包元数据版本、适配桥、manifest 与必要资源摘要、runtime override 及只读可执行权限检查。拆出可复用的纯检查函数，不经过 `create_harness_config()`、Layout 初始化、原生客户端构造或权限修复入口。按源码和 frozen 模式返回不同处理建议；缺失匹配发行资源不能建议随意安装 latest 或用系统 Node 兜底。

输出采用有版本、有限大小的结构：总体状态、部署模式、已知预期版本、检查项代码与状态、受控建议、未检查范围。检查项标识和文案均由应用生成；不输出原始异常、绝对资源路径、用户环境或完整连接地址。某项无法验证标为未知，不能影响其他已完成项的真实性；存在未知项不能整体标为全部通过。

文件 I/O 移出事件循环，限制为可信 manifest 和已授权 runtime override 的配套资源，禁止递归扫描、符号链接越界、无限文件量或任意路径摘要读取。同节点／用户只允许有界在途检查，设置总时限；超时后保留工作者归属直到停止或完成，防止重复点击形成积压，不无限重试。检查结果只用于显示，执行时仍须重新做原有权威检查。

前端调用使用必填 `targetExecKey` 和 `callOnStrict`，不使用 home fallback；记录 userId／identity epoch、Backend 编辑身份、草稿版本和请求序号。修改相关字段、关闭、切换或断线后使结果失效。结果不落入配置或 localStorage；不逐字发远端检查，不轮询，点击检查期间禁用重复提交。旧节点未知方法显示“不支持”，离线与超时分别显示对应状态，不直接回显传输异常。

备选：复用真实启动路径做试运行、保存时强制预检。未采用，因为会启动进程／修复权限，且旧节点或离线环境仍应允许保留合法草稿。

### 3. 在可信事件边界产生安全故障投影

在专用诊断模块定义有限错误类别与固定中文建议。HTTP 状态只接受合法整数；类型化 SDK 异常只读取已核实字段，固定已知 code 使用白名单匹配，不把任意字符串当安全 code。404 建议检查 Messages 地址／路径及模型名，401／403 提示凭据／权限，429 提示限流，5xx 提示服务端；不对其中任一情况作唯一根因承诺。网络／超时依类型化证据判断，其他情况归入未知。

`deepseek_harness_turn.py` 在已接受当前 receipt 后，只从本次 worker、当前根 session 和有效事件序列提取终态错误；增加运行／序列防串和重复终态测试。子代理终态不得写入根轮诊断。保留 `session/wait` 和 owned worker 清理：错误详情不提前宣告清理完成，也不以取消等待者替代实际退出确认。`aborted`、`blocked`、token 上限和缺失终态维持各自失败提示，不因缺少 HTTP 状态被重新解释为成功。

格式化结果经现有 `emit(error)` 和失败返回通道输出，前端沿用既有错误展示，不新增第二个重复聊天气泡。启动检查使用相同受控错误代码生成“缺少哪个组件／如何准备”的提示。审计 `error_evidence`、trace 和异常边界，确保新结构不把原始 message／stderr 引回日志；保留配置密钥替换作为纵深防护，但不能仅依赖已知密钥字符串替换来保证安全。固定文本及合法数值为默认策略，未知供应商 message 不显示。

备选：直接展示 `reason.error.message` 或正则扫描异常正文。未采用，因为服务端文本不可信，可能含凭据、URL 或误导性代码；只显示 kind 又会丢失必要证据。

### 4. 用隔离夹具证明信息和副作用边界

扩展现有 fake runtime 的 `turn/end` 错误、部分输出、子代理／旧序列／重复事件及未知退出场景；新增诊断纯函数和环境检查测试，配合现有本地假 Messages 服务。测试使用隔离用户目录与假密钥，不访问生产 Session 或真实模型。

前端沿用 Backend 配置验收夹具，覆盖地址反馈、显式按钮、检查结果、离线／旧节点、草稿与账号切换、迟到响应和窄屏展示。对安装、网络、进程启动、权限修复和配置写入设置禁止调用断言；检查后证明目标文件／权限未被改变。跨平台未实际运行的环境标为未验证，不能把平台 mock 当发行验收。

## Risks / Trade-offs

- 静态检查无法证明运行时一定启动或模型可用 → 明示检查范围，不提供“已连接”结论，保留真实发送时校验。
- 原始错误可含敏感信息 → 固定类别／建议、数字状态白名单，有界输出及恶意内容测试，不放开 stderr。
- 资源摘要读取较慢或超时 → 有界文件集合、事件循环外读取、单次并发限制和归属回收，不靠前端超时堆积后台任务。
- 严格 URL 校验会使旧无效配置在执行时失败 → 保留原值可编辑，明确提示；合法自定义代理不被启发式警告硬拦截。
- 前后端升级不同步 → 检查能力不支持单独显示，不阻断合法配置保存，不回退其他节点。
- 同仓库的打包修复尚有工作项 → 本变更只消费配套资源检查接口和夹具，不修改打包清理规则或将其进度记为本次完成。

## Migration Plan

无需数据迁移。先加入安全诊断及只读检查、再接入配置 UI；代码验证后才进入另行授权的发布流程。回退本变更只撤销新增诊断／检查入口，不需要恢复用户配置或原生历史。新检查结果不持久化，不形成跨版本数据负担。

## Open Questions

- 锁定 rc.3 的精确默认 URL、空值／unset 和执行节点环境优先级，需要在实施任务 1.1 中用本地锁定源码及隔离配置测试核对；此信息只决定默认来源文案及空配置适配，不影响“不改写非空地址、不探测真实服务”的方案。若无法核实则保留“未确认”，不得猜测具体地址。
