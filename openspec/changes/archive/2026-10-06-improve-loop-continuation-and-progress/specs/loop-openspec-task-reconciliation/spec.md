# Spec Delta

## Purpose

为显式使用 OpenSpec 交付的 LOOP 提供受范围约束的只读任务来源核对，将项目中真实任务清单与模型评审分开记录，防止漏项、来源漂移和读取失败造成错误续跑或虚假完成，同时不强制其他 LOOP 使用 OpenSpec。

## ADDED Requirements

### Requirement: 显式绑定单一任务来源

系统 SHALL 允许用户在 LOOP 中选择并确认当前执行节点和 Session 工作区内的一个 OpenSpec change，展示来源身份和最近核对状态。绑定 MUST 使用发现所得的真实根与 change 标识；存在歧义时 SHALL 要求选择，不按“最新”猜测。首版 SHALL 拒绝隐式外部 store、跨工作区及 SSH 远端文件系统绑定；未绑定的通用 LOOP 不依赖 OpenSpec。

#### Scenario: 选择多个候选之一
- **WHEN** 工作区存在多个活动 change
- **THEN** 系统展示候选，用户确认前不建立权威绑定、不自动选择最新 change，也不启动绑定请求之外的工作

#### Scenario: 不可用或越界来源
- **WHEN** CLI 不可用、根不属于当前工作区，或来源指向未支持的外部 store/远端文件系统
- **THEN** 系统显示具体不可核对原因，不借用父目录、其他节点或其他 Backend 环境，不自动安装或初始化

#### Scenario: 非 OpenSpec LOOP
- **WHEN** 用户运行未绑定 OpenSpec 的探索或通用交付 LOOP
- **THEN** 系统维持通用台账工作流，不因不存在 OpenSpec 而增加阻塞或在后台探测所有项目

### Requirement: 核对操作只读有界且不扩大权限

系统 SHALL 仅在来源确认及 LOOP 关键执行边界运行受限的只读发现/状态/任务查询，核验实际 CLI 协议并保留时间、来源修订和必要结果。每次查询 SHALL 有超时、输出量及有限重试限制；相同边界请求 SHALL 合并，界面查看或流式更新 MUST NOT 触发持续查询。来源正文 SHALL 作为数据而不是执行命令或新授权。

#### Scenario: 正常边界核对
- **WHEN** 已绑定 LOOP 开始新一轮或完成执行进入评审
- **THEN** 系统取得对应边界的任务快照并用于规划或对账；相同请求不重复执行，执行后可能变化的状态不使用未经重新核对的旧快照冒充最新

#### Scenario: 命令或路径注入
- **WHEN** 来源标识、任务正文或 CLI 输出包含 shell 字符、越界路径或要求执行额外命令的文字
- **THEN** 系统拒绝无效参数或将内容保留为数据，不拼接执行该文字、不读取越界文件，也不修改任务清单

#### Scenario: 输出过大或协议不支持
- **WHEN** 查询超时、超出限制、返回无效 JSON 或缺少当前核对所需字段
- **THEN** 系统报告受限失败或不支持，不把截断清单当成完整清单，不自动改用文本猜测成功

### Requirement: 正式任务与评审结果逐项对账

系统 SHALL 将来源任务编号、描述、勾选状态与定位信息同评审任务及证据关联，明确分开工件状态、任务勾选和实现验收。验收 MUST 覆盖绑定的完整正式范围；模型漏项、重复编号或无法映射的任务 MUST 阻止成功收口，不能通过更换任务来源绕过缺口。

#### Scenario: 评审声称完成但来源仍未完成
- **WHEN** 模型报告全部已验证，而正式清单中仍有未勾选的非人工任务
- **THEN** 系统展示冲突并拒绝成功收口，要求核实真实实现或任务标记，不由核对层自动勾选任务

#### Scenario: 勾选完整但缺少验收
- **WHEN** CLI 报告全部任务已勾选或规划工件齐全，但必要实现/整体验证证据缺失
- **THEN** 系统保留“清单已勾选”事实但不宣告业务完成，文档结构校验不替代运行测试与验收

#### Scenario: 人工任务保持正式范围
- **WHEN** 某项正式任务有用户或规格明确指定的人工依据且尚未人工确认
- **THEN** 系统保留该任务和依据，允许按已定义的自动范围交接，但不将其勾选为完成或从总数中删除

#### Scenario: CLI 仅提供位置序号
- **WHEN** CLI 成功返回任务及源文件清单但只有位置性 ID，源文件存在可唯一核对的显式稳定任务编号
- **THEN** 系统以受限只读方式核对原任务描述、勾选与稳定编号，保留真实文件定位，不把位置序号当作跨轮身份；无法唯一匹配时报告不可核对而不猜测

### Requirement: 范围变化可追溯且不能刷新完成度

系统 SHALL 在固定来源身份下区分勾选/位置等非范围变化与任务新增、删除、改义、重新编号及来源切换。无法确定映射或授权的实质变化 SHALL 阻止成功收口及依赖该范围的自动写入，要求核对或用户确认；确认范围修订 SHALL 留下前后差异，不抹掉未解决损失、失败或授权边界。

#### Scenario: 排版或勾选变化
- **WHEN** 任务仅移动行号、调整不改变含义的排版或更新完成标记
- **THEN** 系统刷新定位及勾选状态，维持稳定任务身份和历史进展，不将其误作新任务或重复获得进展

#### Scenario: 删除或改义
- **WHEN** 正式任务被删除、含义改变、无法可靠映射地重编号，或绑定来源消失/被归档
- **THEN** 系统展示范围差异或来源失效并请求核对，不因为剩余数量减少而成功收口，也不自动转到其他 change

#### Scenario: 用户确认新的范围修订
- **WHEN** 用户在 LOOP 空闲且没有未完成执行时确认来源或范围变化
- **THEN** 系统记录新修订及处置依据，重新核对任务/证据映射，不将旧绑定的完成记录冒充新来源的验收

### Requirement: 来源不可用时保留证据并保守暂停

系统 SHALL 将来源不可核对与工作流整体 blocked、Backend 故障区分。已绑定来源查询失败时 SHALL 保留最后有效快照并标记其过期；有限重试后暂停依赖它的自动写入与成功收口。用户恢复后 SHALL 先重新核对来源，不能通过重启或旧客户端省略字段解除绑定。

#### Scenario: 曾有快照但本次读取失败
- **WHEN** 执行后核对失败且有限重试已耗尽
- **THEN** 系统保留本次成果及最后有效快照，显示“任务来源暂不可核对”及恢复条件，不把旧清单标记为最新、不将失败解释为零剩余任务

#### Scenario: CLI 明确报告工作流 blocked
- **WHEN** 来源读取成功但 apply 状态明确为 blocked
- **THEN** 系统保留 CLI 的阻塞事实和缺失条件，阻止该工作流实现，不将其伪装为可通过反复调用解决的读取失败

#### Scenario: 用户恢复来源核对
- **WHEN** 用户修复条件并显式恢复 LOOP
- **THEN** 系统先获得当前有效来源与任务快照并检查差异，再决定是否运行，不因点击恢复而忽略安全或范围门槛

### Requirement: 来源快照展示与兼容

系统 SHALL 在 LOOP 展示绑定来源、最近核对时间、当前/过期/冲突/不可用状态、正式任务数量及与评审的差异。完整快照 SHALL 按需读取，不进入普通聊天历史或高频广播；跨节点、跨 Session 和旧修订响应 MUST NOT 相互覆盖。旧 LOOP SHALL 不被静默自动绑定。

#### Scenario: 旧 LOOP 加载
- **WHEN** 旧 LOOP 没有来源绑定字段
- **THEN** 系统显示未绑定并维持原通用行为，不从历史自由文本自动猜测权威 change；用户可空闲时显式绑定

#### Scenario: 切换会话后晚到快照
- **WHEN** 用户在来源查询未返回时切换节点或 Session
- **THEN** 晚到结果仅属于原请求身份，不修改当前绑定或展示为当前任务清单，重连与重复推送不形成轮询
