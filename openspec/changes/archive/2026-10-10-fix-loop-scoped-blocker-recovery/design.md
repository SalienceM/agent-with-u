# Design

## Context

动机和范围见 proposal.md。已核对的现状：

- `bridge_ws._loop_pause_control` 只处理 `loopControl.pause=true`，调用 `_loop_wait` 关闭 Auto 并保存整轮等待；无 kind 时为 `unclassified_pause`，现有规格明确要求保守暂停。
- `LoopStep` 有访问级别、调用/任务结果，但没有可执行的稳定任务映射、依赖和隔离前置。执行器只按顺序/只读并发执行，失败后停止后续步骤。
- `loop_delivery.assess_progress` 已按评审台账区分局部阻塞和独立就绪任务，但执行步提前硬暂停时不会到达普通 analysis；其中的就绪判断也必须纳入新持久阻塞及传递依赖，不能仅查本轮数组。
- 自动 Codex 的 prepare/read 为 `read-only`，write/analysis 为 `workspace-write`；当前角色说明已禁止用一次真实数据读取失败推断整个项目无法交付。`SAFETY_CONSTRAINTS` 要求核对隔离，未统一要求真实存档基线。
- `LoopPanel.tsx` 承载面板/流程详情和紧凑合并；现有决定摘要可复用。当前工作树包含其他 LOOP/工作台未提交修改，实施必须保留。

本变更涉及持久模型、自动调度和安全边界，因此需要设计文档。真实 Godot 任务/启动器不在本仓库，不能断定其基线要求无效，也不能承诺此变更直接解除已暂停的那一轮。

## Goals / Non-Goals

**Goals:**

- 给执行模型一个不等于整轮停止的任务阻塞通道，由受控规则决定是否换批次。
- 在模型调用边界强制检查冻结的任务映射、阻塞闭包及隔离前置；原生访问策略仍是实际执行边界。
- 避免额外无界模型调用和无限重规划；解释为什么其他工作继续、为什么某些任务仍未验收。

**Non-Goals:**

- 不将模型评审升级为操作系统级隔离证明，不声称能拦截单次模型调用内部所有工具行为。
- 不实现 Godot 专属测试器，不猜测其命令参数，不访问真实存档，不为拒绝的资源寻找替代通道。
- 不放开沙箱/ACL、修改用户验收范围或接管其他 Session，不自动重启、恢复旧暂停、发布或归档。

## Decisions

### 1. 保留硬暂停，新增独立的任务阻塞协议

使用顶层版本化 `taskBlockers` 对象，内容为有界 `items`：稳定 `id`、`affectedTaskIds`、`reasonCode`、事实说明、`evidenceRefs`、`resolution`；输出不能提供可信的用户/节点/权限身份，身份由拥有该调用的执行器补上。协议归一化放进纯模块，未知版本/格式不用于放行。

建议上限沿用现有台账预算：50 个阻塞、100 个任务编号，每条原因/解除条件 1200 字、证据引用每项 240 字并限制数量；拒绝超限而非截断后假装完整。正文仍保留在既有步骤详情，不复制文件内容/凭据进紧凑状态。

`loopControl.pause=true` 与用户控制/原生环境硬门槛始终先判定。两种信号同时返回时硬暂停胜出，不能用字符串匹配“局部”“Access denied”自动降级。旧 JSON 的语义不变。

**替代方案：** 仅修改提示词不能约束调度；直接忽略或重解释 pause 会违背现有规格及安全约定，因此不采用。

### 2. 在执行前冻结任务映射和前置

给计划步骤增加有界 `taskIds`、`dependsOn`（稳定任务编号）及 `preconditionIds`。正式 OpenSpec 来源绑定时按当前来源修订/快照校验编号，不改绑 change；未绑定时采用本轮冻结的有界任务台账，明确其为模型规划，不声称正式来源已确认。

计划解析检查缺失节点、重复/循环依赖、越界任务和来源漂移。既有里程碑登记可提供编号线索，但不能用子里程碑替代父任务验收。旧计划仍可按原行为运行；一旦发生阻塞而没有足够映射，不自动放行独立写步骤，进入只读复核并保守等待。

**替代方案：** 仅用步骤顺序推断依赖会让每一步都卡住；仅看任务标题无法稳定识别依赖或阻塞，因此新增显式映射，但不建立第二套正式任务源。

### 3. 复用本轮 analysis 作一次只读阻塞复核

有效任务阻塞返回后，本轮不再启动剩余执行步骤。受阻步骤保留 `callResult=normal`、`taskResult=blocked`，未执行步骤不伪装为完成；已经启动的只读并发批次仍先按原语义收集/确认退出，不承诺撤销已产生的影响。

在没有硬暂停、未退出调用或共享 runner 故障的前提下，本轮 analysis 切换到显式 `execution_access=read-only`，使用新的独立模型上下文，核对冻结范围、原始步骤证据和旧阻塞。这是任务评审，不是 `loopEnvironmentCheck`，不更改固定原生检查“不额外调用模型”的契约。

该分支每个执行边界至多一次，使用既有调用超时、输出预算、调用诊断与取消规则；失败不通过递归重试补造结论。角色说明明确不重试拒绝资源、不运行应用测试或修改文件。只读复核成功不能证明未来 `workspace-write` 路径可用，后续调用仍独立通过原环境门槛。

纯归约器在有效完整台账上计算阻塞任务及依赖闭包，剔除不满足前置、已受阻或依赖未验收的候选，并重新核对当前停止/控制权、Auto、来源、预算与风险。只有剩余任务有适用独立性证据时保存 `replan` 决定、由既有去重调度器进入下一轮 prepare；没有就绪任务或范围不明则等待。不能顺着模型原 plan 直接跳到第 4 步。

**替代方案：** 新增第二个并行规划器或持续诊断代理增加成本和状态竞争；同轮动态跳步难以复核已冻结范围，故选择复用 analysis、下一轮重规划。独立任务仍可自动继续，但不以放弃验收为代价。

### 4. 未解决阻塞是跨轮保护，不靠每次模型重新记忆

在 LOOP 持久状态中保留有界的未解决阻塞及其来源/执行身份修订，轮次详情保存相应只读快照和复核结论。所有后续 prepare、step 和 analysis 都获得适用阻塞提示；调度器同样应用阻塞闭包，不仅靠提示词。

同一阻塞 id、范围和证据修订重复返回只合并，不形成新进展；新一轮、刷新或改写措辞不解除阻塞。解除必须引用适用的新核实证据或用户对验收范围的明确处置，既有环境硬阻塞只能由其原机制解除。来源/环境改变使旧放行证据失效，但不悄悄丢弃旧问题。

复核状态与调度决定沿用边界身份、`decision_dispatched` 和既有持久写排序；重启后未知的复核/写调用保持未确认，不能重放。新增字段省略时保留既有值；旧存档没有字段按未知处理，不倒推失败或完成。

**替代方案：** 只记录单轮分析会让下一轮忘记受阻条件，历史全文注入又不可靠且昂贵；采用有界结构化记录及按需原文引用。

### 5. 测试隔离前置是任务证据，不是全局真实存档扫描

规划输出的测试前置记录：`id`、`affectedTaskIds`、数据写入类型、隔离数据根、实际路径核对方法、必要配置/产物修订、证据引用及真实基线依据（若适用）。初始状态为未核实，消费它的测试步骤不能在同一次调用里自行宣布前置通过后直接运行；需要前置准备/核对步骤返回，再在调用边界核验。

对于已识别的用户数据写测试，准备可在原已授权的 write 步内完成；在未确认隔离前不启动应用进程。验证配置和路径必须考虑平台别名/链接及实际应用机制，不能只相信一个环境变量、目录名或模型 `safe=true`。不知道应用隔离方式就保留未知，不猜参数。

核验记录明确区分受控检查、工具观察及模型评审；AWU 可以验证字段完整性、身份、证据引用/修订和调度依赖，不宣称自动证明任意第三方应用所有写入目标。有效模型评审仍是有限观察，不能解除更强的原生拒绝证据。

真实用户文件基线只有在用户、项目规则或规格明确要求时才纳入相应验收。读取被拒只冻结必要基线及依赖项；没有这项要求且隔离路径已按原策略核实时，不追加全量真实存档读取。禁止以换 cwd、宿主代读、复制被拒资源或变更 ACL 完成同一拒绝操作。

**替代方案：** 通用“启动前后扫描真实目录”既扩大隐私读取又不能证明过程中从未写入，故不设为默认。若原验收明确要求它，不能在此替用户取消。

### 6. 保持紧凑界面并保留诊断入口

复用当前决定/进展摘要，显示“部分任务受阻，已选择独立工作”或具体等待原因；展开详情查看任务、依赖、前置、证据级别和解除条件。面板与流程使用同一数据，不新增常驻大卡片、轮询或自动恢复按钮副作用。紧凑合并不能用空摘要覆盖历史详细证据。

## Risks / Trade-offs

- [模型继续误用显式 pause] → 保留其硬暂停；新提示明确局部通道并增加协议回归，不能为了降低停机率牺牲安全，也不承诺彻底消除模型误分类。
- [局部范围或独立性误判] → 冻结任务图、依赖闭包、单次独立只读复核、来源修订与原生门槛共同约束；不可靠就等待。
- [只读复核本身失败或 runner 不可用] → 不换策略/通道、不无限重试，保留真实失败和暂停条件。
- [复核可能延迟独立工作到下一轮] → 复用既有 analysis 而非增加无限调用，沿用轮次预算，先保证可追溯与不盲跑。
- [用户数据隔离不能由通用声明完全证明] → 显示证据级别，调度门槛不冒充 OS 隔离；未识别测试和单次模型内工具仍依赖原有安全约束与原生策略。
- [旧记录或旧客户端丢失新增阻塞] → 增量兼容、未知不放行、跨轮持久化与重启测试；部署前停止受影响自动迭代并采用匹配版本。

## Migration Plan

1. 添加纯协议/依赖归约和兼容字段及其测试，保留旧 pause 处理与已有未提交修改。
2. 接入计划前置与执行返回分支，再接入只读 analysis、跨轮保护和去重调度；完整通过硬暂停与环境失败回归前不声明实现完成。
3. 接入轻量详情与文档，运行 fake Backend/文件系统和浏览器测试、前端构建与 OpenSpec 严格校验；不操作真实存档。
4. 由用户另行选择部署/重启时间。已暂停 Session 仍等待显式恢复，恢复先重新 prepare 核对原证据与来源，不自动重试原拒绝读取。
5. 回退前保留阶段记录并关闭受影响自动执行；旧版本不理解新任务级阻塞，不得直接用旧版本恢复这类未解决记录。
