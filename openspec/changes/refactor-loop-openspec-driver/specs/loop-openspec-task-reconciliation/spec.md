# Spec Delta

## MODIFIED Requirements

### Requirement: 显式绑定单一任务来源

系统 SHALL 将当前用户目标明确指定的 OpenSpec change，或明确要求 OpenSpec 时工作区唯一候选，作为任务来源而不再要求二次绑定确认。来源 SHALL 来自真实 CLI 查询；已有明确绑定可复用。只有多个候选且目标无法消歧时要求选择。首版 MUST 保持当前节点/工作区边界，不借用 SSH、外部 store 或其他执行端；通用 LOOP 不依赖 OpenSpec。

#### Scenario: 目标指定或唯一候选
- **WHEN** 用户要求 LOOP 完成指定 change，或明确使用 OpenSpec 且只有一个候选
- **THEN** 点击执行或开启 Auto 后系统采用该真实来源并显示名称，不增加确认弹窗；仅查看不会自动运行或绑定

#### Scenario: 选择多个候选之一
- **WHEN** 工作区有多个候选且当前目标不能确定其中之一
- **THEN** 系统提供候选选择，不猜最新、不启动模型实现

#### Scenario: 不可用或越界来源
- **WHEN** CLI 不可用、根越界、change 不存在或来源指向未支持的 store/SSH
- **THEN** 系统显示具体原因，不换节点、环境或自动安装/初始化

#### Scenario: 非 OpenSpec LOOP
- **WHEN** 用户未要求 OpenSpec 且没有已选来源
- **THEN** 保持通用工作流，不后台扫描所有项目

### Requirement: 正式任务与评审结果逐项对账

系统 SHALL 以 OpenSpec 的真实 tasks 及勾选状态作为实现阶段唯一进度台账，直接按 apply 工作流推进原任务，不要求模型重建完整 taskPlan、重复逐项验收或满足 LOOP 的 1–4 步 JSON 才能启动。实现完成后 SHALL 使用 verify 技能审查规格与实现；critical 和需修复的 warning 进入修复再 verify，纯建议不阻止结束。用户明确排除的人工验收 SHALL 保留任务和依据、不伪造勾选。

#### Scenario: 单轮只完成一批任务
- **WHEN** apply 正常返回且还存在自动任务
- **THEN** 重新读取实际进度，Auto 和预算允许时继续 apply，不因正常回答结束宣告完成

#### Scenario: 评审声称完成但来源仍未完成
- **WHEN** 模型报告完成但正式清单仍有非人工任务未勾选
- **THEN** 以实际清单为准继续实现，不由核对层自行勾选，也不成功收口

#### Scenario: 勾选完整但缺少验收
- **WHEN** tasks 全部勾选但当前 verify 尚无完整有效结论
- **THEN** 保留清单完成事实并进入 verify，不以结构校验代替实现核验

#### Scenario: 人工任务保持正式范围
- **WHEN** 用户明确排除的人工项尚未确认
- **THEN** 该项保留在总数中、保持未勾选；自动范围结束仍显示待人工核验

#### Scenario: 勾选完整但尚未 verify
- **WHEN** 自动任务已勾完
- **THEN** 进入 verify，不生成另一套实现任务图，不将清单完成等同于 verify 通过

#### Scenario: 人工任务与验证修复
- **WHEN** 用户明确忽略人工验收，verify 同时报告人工缺项、需修复缺陷和纯建议
- **THEN** 只让需修复缺陷进入修复闭环，保留人工缺项与建议说明；无待修复项时显示自动范围完成、人工未验收

#### Scenario: CLI 仅提供位置序号
- **WHEN** CLI 成功返回任务而原文有稳定编号
- **THEN** 以真实编号和定位跟踪；无法唯一对应时显示来源问题，不猜测或重写原任务

### Requirement: 范围变化可追溯且不能刷新完成度

系统 SHALL 在已明确的同一 OpenSpec change 内自动读取最新任务及规格，记录范围差异而不把正常 apply/update 的改动变成重复确认门槛。删除和改义不计为实现进展，最新 verify SHALL 覆盖当前范围。来源切换、越界、权限变化和旧调用未退出 MUST 继续受保护，不借范围更新清空真实阻塞。

#### Scenario: 正常任务演进
- **WHEN** 同一来源的任务勾选、位置、描述或规格随授权工作更新
- **THEN** 系统刷新并记录差异，无需再次确认来源；任务减少不产生完成信用，verify 使用新范围

#### Scenario: 排版或勾选变化
- **WHEN** 任务移动行号、调整排版或更新勾选状态
- **THEN** 刷新真实定位和进度，保留稳定身份，不把排版当作实现进展

#### Scenario: 删除或改义
- **WHEN** 同一来源任务删除或含义改变
- **THEN** 自动记录范围差异，删减不计完成信用，新 verify 覆盖当前范围；不静默转到其他 change

#### Scenario: 用户确认新的范围修订
- **WHEN** 用户在空闲时显式确认来源或范围处置
- **THEN** 保留新修订及处置依据，不能以旧来源验收代替新范围 verify；同来源正常演进不强制重复确认

#### Scenario: 来源消失或切换
- **WHEN** change 已消失/归档或请求指向另一个工作区/change
- **THEN** 显示准确状态；不静默采用其他来源，不清除未解决权限或执行风险

### Requirement: 来源快照展示与兼容

系统 SHALL 展示所用 change、最新任务进度、apply/verify/修复阶段及人工待办；详细来源证据按需读取，迟到或跨 Session 响应不得覆盖当前对象。旧 LOOP 仅在用户下一次显式执行且目标明确时采用新 OpenSpec 路径，查看不会迁移或启动。

#### Scenario: 旧任务映射暂停
- **WHEN** 旧记录仅因内部任务映射失败暂停，用户对明确 OpenSpec 目标再次执行
- **THEN** 采用真实 tasks 推进，保留旧失败审计，不要求先修复重复模型台账；真实权限、未知退出和未解决阻塞不因切换路径解除

#### Scenario: 旧 LOOP 加载
- **WHEN** 仅打开没有来源绑定的旧 LOOP
- **THEN** 仍显示未绑定，不从历史模型文本猜测来源，不启动模型；用户下一次明确执行时才按当前目标选真实来源

#### Scenario: 切换会话后晚到快照
- **WHEN** 来源查询返回时用户已切换节点或 Session
- **THEN** 结果归属原对象，界面不串状态、不轮询或重放写操作

## ADDED Requirements

### Requirement: 验证修复闭环有终点

系统 SHALL 记录有界 verify 结论与问题清单，明确区分待修复、人工和建议。只有正常完成的当前 verify 且无待修复项时可收口；无法解析、调用失败或未确认结果不得算通过。修复后 SHALL 再 verify，重复无进展、预算耗尽或真正阻塞时明确暂停，不能无限优化或自动归档发布。

#### Scenario: 缺陷修复再验证
- **WHEN** verify 发现一个 critical 缺陷
- **THEN** 下一适用自动轮修复该缺陷，之后重新 verify；前次结论保留，不通过提高分数绕过缺陷

#### Scenario: 无问题与未知结果
- **WHEN** verify 只剩建议，或反之没有可用结论
- **THEN** 前者可明确结束自动范围，后者明确验证未完成，不伪造通过
