# Spec Delta

## MODIFIED Requirements

### Requirement: 完整验收控制成功收口

系统 SHALL 区分通用 LOOP 与 OpenSpec 驱动的收口规则。通用模式保留完整稳定范围、验证证据、分数及独立复核要求；OpenSpec 模式以当前原任务自动范围完成和当前 verify 无待修复缺陷为收口条件，不额外要求评分或重复完整任务台账。两者均 MUST 保留未解决权限/安全/未知执行结果及未处理 Addon；人工项保持未验收，不因建议无限续跑。

#### Scenario: 高分但仍有任务缺口
- **WHEN** 分数很高但仍有自动任务或需修复缺陷
- **THEN** 不报告整体完成，继续适用工作流

#### Scenario: 自动范围完成但仍需人工核验
- **WHEN** 自动任务及 verify 已完成，只剩用户明确排除的人工项
- **THEN** 显示“自动范围完成，待人工核验”，不伪造人工通过

## ADDED Requirements

### Requirement: 工作台写操作反馈确定且局部化

系统 SHALL 在按钮触发请求时立即显示操作名与等待状态，收到结果后明确显示已接收、已完成、失败或结果待确认。已接收 MUST NOT 冒充执行完成；失败不得只留无说明的禁用按钮。相同在途动作去重，超时不得自动重放写请求；状态按用户/执行端/Session 隔离，迟到响应不覆盖新对象。同步导航动作仍即时生效。

#### Scenario: 点击执行和 Auto
- **WHEN** 请求尚未返回、已排队或已改变 Auto
- **THEN** 分别显示正在提交、已接收并展示启动阶段、Auto 已开/关；不以无变化按钮让用户猜测

#### Scenario: 拒绝断线和切换
- **WHEN** 结果拒绝、超时断线或用户切换 Session
- **THEN** 原请求明确失败或结果待确认，可只读核对；不能重复启动、串入其他 Session 或阻塞其他操作区域

### Requirement: 单 Session 启动不得阻塞共享服务

系统 SHALL 将耗时快照和文件 I/O 从共享事件循环移出，提供启动阶段反馈；一个 Session 的启动、取消或慢快照不得阻塞其他 Session RPC、心跳和停止处理。取消或超时 SHALL 确认所拥有工作退出；未知结果保留原 Session 保护，不允许后续写工作抢跑。

#### Scenario: 慢快照期间其他会话操作
- **WHEN** 一个 LOOP 快照尚未结束
- **THEN** 其他 Session 心跳/查询及时响应，当前 Session 显示正在准备工作区；同一 Session 不重复启动

#### Scenario: 快照取消或退出未知
- **WHEN** 用户停止启动阶段或快照清理无法确认
- **THEN** 不开始模型执行，保留可核对状态，其他 Session 仍可操作
