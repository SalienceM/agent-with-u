# Design

## Context

现有 LoopPanel.once 只设置 busy，成功无回执，错误使用阻塞式 alert；Run/Auto RPC 缺少一致的有限超时。迭代协程内直接 git_snapshot/dir_snapshot：fake 350ms 快照使 10ms 心跳延迟到 359ms。OpenSpec 真实清单已由 TaskSourceReader 提供，但 prepare 又要求完整 taskPlan，analysis 又建立 delivery 映射；这不是用户需要的续跑器。

## Goals / Non-Goals

目标是兑现已确认的任务驱动闭环和响应性，不只加重试。保留通用 LOOP 和安全边界。不操作生产 Session、Godot/真实用户存档、版本配置、发布或归档，不引入新框架。

## Decisions

1. 在原迭代入口选择 OpenSpec 专用路径，复用原任务登记、模型调用、环境/停止/访问策略，不另建调度器。显式来源或当前目标/用户补充中的明确 change 优先；要求 OpenSpec 且只有一个真实候选可自动采用，歧义才要求选择。旧历史任意模型文本不能成为授权。查看不选择。
2. 同一来源范围变更自动记录差异并刷新，不要求用户再次确认。源文件和命令仍有边界、超时、大小限制。来源不可读/CLI blocked 不放行。OpenSpec 路径不走 taskPlan/milestone/delivery 逐项重新建图；历史真实阻塞继续保护，纯模型格式问题保留审计但不永久阻止原任务执行。
3. prepare 为确定性选阶段：剩余自动任务→apply；自动任务完成→verify；当前 verify 有需修复项→修复。模型按对应真实 Skill 工作流操作，apply/修复可写，verify 只读；只有终态成功才采纳结果。人工排除来自明确用户目标或策略，任务仍保留未勾选；模型不能自行把缺陷变成人工项。
4. verify 使用精简有界结果（问题严重性、是否需要修复、具体依据、人工范围），不是另一份任务图。原始输出保留；解析失败显示验证未完成。勾选变化和缺陷消除用于进展判断，建议和分数不驱动无限续跑。Auto/单轮行为、预算/风险/停止继续受原调度器控制。
5. 启动快照复用 owned helper 思路，后台执行并持有 Session 预留，超时/取消不把尚未确认退出当作空闲；状态修改仍在事件循环、有序保存。普通快照不直接 copytree/subprocess.run 阻塞事件循环。紧凑推送不构造无界历史全文，保存不在主循环同步刷大文件。
6. 工作台操作反馈统一显示操作名及 sending/accepted/done/error/unknown，Run accepted 后由权威运行阶段继续反馈。有限等待后仅做一次只读核对，不重试写入；输入草稿失败保留。导航本身不套等待。重用单控制器、组件局部状态和现有推送，避免全应用刷新。

## Risks / Trade-offs

- [verify 仍是模型审查] → 明确证据和未知状态，不声称机器证明；非建议缺陷闭环。
- [人工排除误伤自动工作] → 仅明确人工任务加用户排除指令；不按 Access denied 推断人工，不伪造勾选。
- [旧暂停迁移] → 只在下一次显式操作选择专用路径，未知退出/真实权限仍阻止执行。
- [缓存和并发] → 绑定身份/修订，取消迟到只归原对象，单 Session 去重、有序提交。
- [范围删减] → 记录差异、不计新增进展，新的 verify 才能收口。

## Migration Plan

增量增加可选驱动状态和启动反馈；缺字段保持旧行为。先纯函数/假后端测试，再前端状态与多 Session 浏览器验收。无自动改写生产数据。部署后需用户显式运行。新规格优先于此前变更中针对 OpenSpec 的重复建图及确认要求；旧通用模式要求仍保留，后续同步需按变更先后核对，本次不执行同步。
