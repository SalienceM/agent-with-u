# Design

## Context

动机和行为范围见 `proposal.md`；验收契约见 `specs/file-preview-window-lifecycle/spec.md`。

当前独立窗口只是原文件面板的远程视图：

- `FileTreePanel.detachPreview` 把读取、解析、定位、审阅和版本化文档操作闭包交给 `openPreviewWindow`。闭包检查 `mountedRef`、`previewScopeRef`、当前用户和 `localFsRef`，因此文件身份与组件存活被绑在一起。
- `previewWindow.ts` 通过 BroadcastChannel 代理全部操作，源页面 `pagehide` 或 `dispose` 只发一个 `disconnected`。`FileTreePanel` 的卸载、Session/工作目录/节点依赖变化，以及任何 `onCurrentUserChanged` 回调都会 dispose。
- `FilePreviewWindow` 收到该消息后清空快照并拒绝请求。`rememberRelayUserProfile` 的昵称/头像刷新会通知 `identityChanged=false`，但源端没有区分。
- 单独 `closePreview` 不直接 dispose 独立窗口；不能把关闭原弹窗说成已经确认的直接触发点。截图具体操作时序未知，以上为源码确认路径。
- `api.workspaceDocuments`、`LocalDocuments`、`DocumentStore`、本机目录适配器和 `DetachedTextDocument` 已有来源、版本、草稿和保存保护，必须复用。`restoreLocalDir` 读取的是 Session 最近绑定，部分失败会回落 managed 模式，不能直接拿来恢复冻结的旧文件来源。

本变更承接多格式布局改造，不重新设计查看器、不扩大文件读取上限。完整 Session 窗口交接仍由 `workbenchWindows` 管理，与本文件窗口的访问能力分开。

## Goals / Non-Goals

**Goals:**

- 将不可变来源、资源访问、阅读状态和可选的主界面导航拆成独立职责；主界面不是资源服务端。
- 独立窗口自己创建并释放固定来源适配器，在主界面不存在时仍能验证和读取实际可用的来源。
- 断线不销毁已加载的同身份内容；真正授权失效不因保留快照而泄露正文或草稿。
- 生命周期状态和保存状态正交，未知保存回执可以在原请求上核对，不因重连重写。

**Non-Goals:**

- 不新增常驻代理服务、SharedWorker 文件服务、新登录体系或通用窗口工作流。
- 不把已加载快照当成离线完整文件缓存，不持久化新的正文副本；既有草稿存储保持职责。
- 不让文件窗口接管 Session 发送权、自动申请租约、自动选目录、上传或调用模型。
- 不改变整个 Tauri 应用退出时停止进程/sidecar 的语义；不承诺浏览器撤销权限后仍能读写磁盘。

## Decisions

### 1. 用版本化来源描述代替组件闭包

引入小型文件预览来源描述及校验器，明确包含协议版本、窗口标识、原身份域、owner、固定执行端键、Session、工作目录/工作区修订、初始相对路径、来源类型和本机实际绑定标识。主题、窗口标题和初始展示模式为展示元数据，不参与授权。

身份域不能只比较 `userId`，还要区分连接模式、Relay 身份域及有效身份代际；昵称/头像不属于身份键。预览自身的 generation 用于失效迟到响应，不替代权威来源校验。初始文件固定，HTML 等既有显式相对导航仍可在同一已授权根内进行，不能随主窗口当前选中项漂移。

描述不携带密码、token、工具授权或会话控制租约；随机窗口 ID 仅是查找键。每次访问都使用独立页面正常获得的现有连接/认证上下文，服务端或本机适配器仍执行原权限校验。未知字段版本、非法相对路径及不匹配身份拒绝初始化。

不选“只删除报错/忽略 disconnected”：那只能保留一张静态快照，后续资源读取、重新加载和保存仍依赖已消失的闭包。

### 2. 窗口拥有访问适配器，复用现有文件协议

将 `detachPreview` 中与 UI 无关的访问组装提取成可由独立窗口实例化的来源适配层，提供预览读取、结构化兼容解析和 `DocumentClient`：

- 执行端来源：固定 `execKey`，通过现有连接池和 `api.workspaceDocuments` 核对 Session 所属及工作区身份。二进制/结构化预览继续走已有有界文件接口，并在调用前后核对冻结来源，不能因目标缺失改用默认执行端。
- 本机副本：固定实际目录/存储 binding，而非 Session 的“最近目录”。复用 `LocalDocuments` 和既有适配器，以 bindingId/实际根校验恢复结果。
- 远端只读包装、完整读取才可保存、文件版本检查、原子提交和相对路径限制保持不变。不通过预览接口添加弱保存兜底。

`isCurrent` 改为独立窗口来源/身份 generation 校验，而不是原组件是否 mounted。资源释放由独立窗口关闭、真实授权失效或显式来源退出负责；源面板卸载只清理自身监听及未完成的初始化交接。

不选把 broker 移到主窗口顶层：虽然可避开 React 卸载，主窗口关闭仍中断全部文件操作，不能满足独立窗口契约。

### 3. 有界初始化和刷新恢复，不持久化新正文

在同源已有存储能力内增加按身份隔离的版本化描述登记，供 `?filePreview=<id>` 查找；登记只存来源和必要展示元数据。本机浏览器目录句柄使用既有 IndexedDB 能力保存单独的不可变绑定引用，不能序列化成凭据或从 URL 注入路径授权。Tauri 目录绑定和 managed 存储同样保留实际 binding，缺失时明确失败，不能调用会自动回落其他目录模式的恢复路径。

窗口必须在用户点击调用栈内打开，以保留浏览器弹窗许可；描述准备/连接核验异步完成，窗口创建成功不等于初始化完成。BroadcastChannel 可传递一次性初始快照和就绪通知以加快展示，但不再承载长期必需的读写。接收方核验身份后才能展示快照。

登记有数量上限、版本校验和失效清理；成功交接有回执，失败有截止时间。窗口正常关闭清理自己的登记和订阅；刷新按原标识保留恢复机会，不能把每次 `pagehide` 都当作永久关闭。异常退出残留按有界过期清理，活动窗口维护自身记录，不依赖主窗口心跳。具体上限作为受测常量，不能无限累计记录或扫描目录。

刷新后重新核验并读取同一来源，草稿走原有恢复流程。若网络已离线且页面内快照随刷新丢失，应如实显示尚未加载，不声称从未持久化的正文中恢复成功。存储不可用时报告可恢复能力受限，不隐式转回依赖原面板的常驻代理。

### 4. 区分访问状态，不卸载正常阅读器

采用有限状态归约：`initializing`、`ready`、`offline`、`invalidated`、`revoked`、`closed`；读写错误保留独立原因码和操作结果。

| 事件 | 处理 |
| --- | --- |
| 原面板关闭/卸载、Session 导航、主窗口消失 | 不改变文件访问状态；只失去可选的主界面导航目标 |
| 同身份资料刷新 | 更新必要展示信息，不改来源、不重建查看器 |
| 传输断开、来源暂时不可达 | 进入 offline，保留现有同身份快照/草稿；禁用不可用操作并提供显式重连/重读 |
| 原工作区实际修订或绑定不匹配 | 进入 invalidated，停止旧操作；同身份下保留带提示的最后内容，不自动改绑 |
| 退出账号、身份域切换、明确权限撤销 | 进入 revoked，取消/隔离响应并遮蔽旧正文、标题等身份敏感信息与草稿 |
| 独立窗口关闭 | 执行原关闭守卫，允许关闭后才释放资源 |

单纯网络故障不是权限撤销；明确的权限撤销也不能伪装成“离线可看”。身份变更监听需要覆盖跨窗口的既有身份通知来源，不能只依赖原面板转发。`identityChanged=false` 不触发撤销，但最终判断仍基于不可变身份域，不盲信消息中的布尔值。

offline 状态不改变查看器 key、不清空 snapshot，从而保留页码、网格选择、缩放和滚动。错误/恢复控件位于既有有界提示区，关闭入口始终可达。资源重新读取前经过现有脏草稿导航保护；重新连接本身不重新解析、丢弃文本或自动重载文件。

### 5. 保存与源界面导航分开处理

`DetachedTextDocument` 继续使用真实 `DocumentClient`、既有草稿身份和版本化保存回执，不另建保存状态机。写操作发出后遇到断线/关闭源面板，未确认状态及 requestId 保留；恢复只通过 `saveGet` 核对原请求，核对不成功仍未知，禁止自动提交同内容的新写请求。

关闭按钮、Tauri 原生关闭、页面退出和显式文件导航沿用已有草稿/未知保存守卫。授权变更可以遮蔽 UI，但不删除原身份可靠保存的草稿；切回原身份后仍需核对来源及恢复条件。

“定位/审阅”是可选的 UI 导航能力，不是文件可读性的前置。有同身份、同来源的主界面接收者时可发显式导航提示；没有接收者时说明该操作需要工作台或给出用户主动打开入口，不清空文档、不自动创建 Session/窗口、不启动审阅模型。接收者必须校验目标，不根据导航消息授予文件权限。

### 6. 用真实两窗口链路验收，旧协议显式降级

在现有隔离 Playwright 宿主夹具上增加两页面测试，真实执行 `openPreviewWindow` 和独立页面入口，再卸载源组件/关闭源页面，不能只手工向接收端发送 snapshot 就认定完成。服务端仍使用 fake API/合成文件，不触及生产 Session。

以状态/来源单测覆盖身份、binding 和迟到响应矩阵；以浏览器验证 Excel/Word/PDF/文本已加载后的状态保持，以及 HTML 附属资源和显式导航的后续读取。更新旧 `disconnected` 清空断言，保留身份撤销隔离断言。真实 Tauri/浏览器目录权限能力另列人工复核，模拟结果不能冒充真机通过。

协议版本不兼容时不从旧 URL 或当前 Session 猜测新来源。旧 broker 连接仍可用时只按其原权限提供兼容行为；若无法建立完整、可核验的新来源，明确标为旧版窗口需重新打开。仅在旧身份仍可可靠验证时保留已加载内容，否则遮蔽。旧存量窗口不承诺无刷新热迁移，新创建窗口使用独立协议。

## Risks / Trade-offs

- [独立连接增加窗口资源开销] → 复用现有连接池实现，单窗口请求并发有界（不放宽现有 8 项保护），超时与关闭释放监听/请求，不增加常驻服务或无限业务轮询。
- [同账号跨 Relay 域混淆、迟到消息泄露] → 完整身份域键、generation 和每次访问校验；撤销立即遮蔽，回执不能自行解除保护。
- [原 Session 重新选择副本导致旧窗口读错目录] → 不可变 binding 恢复，禁止 `restoreLocalDir` 的最近绑定/managed 自动回落；明确测试同名目录和权限丢失。
- [离线快照被误解为最新内容] → 持续标明最后加载状态，重新读取需明确操作；保存成功只依真实版本化回执。
- [刷新/浏览器崩溃留下登记或丢失未持久化内存] → 刷新与最终关闭分离、有界登记清理；只按既有可靠草稿恢复，不承诺新正文缓存。
- [主应用退出同时终止 sidecar] → 如实进入资源离线；不能通过偷偷启动后台进程维持“在线”。

## Migration Plan

1. 先增加来源描述/状态归约及精确绑定恢复测试，再提取不依赖 UI 的访问组装；此阶段不改变文件保存协议。
2. 切换新窗口创建与接收端到独立生命周期；移除源面板对新窗口的销毁依赖，保留有界初始化失败处理及旧协议版本判断。
3. 联合验证多格式布局、两窗口访问、真实失联、身份撤销、保存未知和退出保护；记录人工能力未验证项，不自动发布。
4. 回退以成对恢复原创建/接收协议为单位，不能让一个端只支持新协议、另一个端只支持旧协议。新描述登记可忽略并到期清理，不删除现有文件、本机副本或草稿；回退不宣称修复已生效。
