## Context

见 proposal.md。LoopPanel 已有统一运行/Auto/控制权控制器，useLoopWorkbenchState 已按身份订阅 progress、诊断及按需回放。当前 AimeinWorkbench 与 RecordView 只认 sprintId，过滤准备记录；详情页仅部分步骤/评审输出可折叠查看。上层 LoopWorkbench 固定渲染 header，叠出另一套通用控制区。

## Goals / Non-Goals

**Goals:** 使沙盘、控制和实时观察形成一个连续工作区；呈现实际活动且支持读取和历史核对。

**Non-Goals:** 不新增执行器、日志轮询、权限放宽或任务验收规则；不把 JSON 规划流解释为已保存目标，不凭动效填充成熟度；不改普通 LOOP 操作布局。

## Decisions

1. 新增纯投影工具统一选择 AIMEIN 当前记录（含无 sprintId 的准备）、阶段标题与输出通道；当前活动只取当前轮最后记录与真实调用状态。复用已有字符串流和原文，不新增后端事件协议。
2. AIMEIN 使用空外层 header，将其必要控制投影到沙盘内同色控制条；主运行继续复用 hotbar 和现有回执，Auto/停止/问题保持直接可达，其余设置按需打开。普通 LOOP 保持原 header。
3. 运行现场作为沙盘侧栏默认页，准备/规划无数据时显示当前工作而非 onboarding。侧栏可切对象观察、阶段记录和评委工坊。历史选取不跟随新记录跳回；实时页明确历史身份。外部详情和收起面板不卸载场景。
4. 现场包含阶段路径、模型活动/耗时、通道选择与有界纯文本输出；自动跟随只在用户仍在底部且选择跟随时进行。用户选定通道后保持选择，提供跟随当前操作。独立评委保留独立通道，不混合。
5. 流式缺失用已保存原文回退；回放继续沿用受身份和修订约束的详情请求。局部秒表只在可见活动时更新，无数据轮询；断线清晰标记状态未核对。长文本最多展示已有 50K 尾部窗口，历史全文通过原详情入口。
6. flowProjection 的活动不再以计划 ready 为总门槛；实际 prepare/aimein-plan 调用活动可以驱动基础设施→工坊、目标→工坊两条细航线。保存堆积和目标瓶仍受原有落盘及完整评审证据约束。连接不可核对、历史、停止和错误停止活动；已有 reduced-motion/隐藏视图门槛保留。
7. 三方整体意见由保存的报告确定性汇总，不增加第四次模型调用或多数票验收。共同认可需要三份完整报告同一条件均 verified；分歧保留各评委依据，未知/失败保持未知；阶段通过仍使用后端 accepted 与三方结果。运行现场在评审阶段提供整体意见入口，评委席和阶段记录展示完整汇总。
8. 默认装配根来自已冻结 Sprint criteria.targetId，自动加入传递依赖。用户可主动进入调整草稿，提交仍是下一次规划建议，不更改当前执行范围。没有已保存计划时说明系统正在规划，不要求手选。将探针改为“成果与验证”，入口说明已做步骤、验证依据及待处理缺口。

## Risks / Trade-offs

- 运行初期没有 Sprint → 使用实际最后一条尝试与目标原文，保持目标瓶未知，具体活动由现场表达。
- 新阶段打断阅读 → 自动跟随与手动选通道分离，保留阅读位置和历史选择。
- 窄屏空间不足 → 场景与日志纵向分区、独立滚动，紧凑工具栏折行但不堆积说明卡。
- 已安装桌面版本与源码不同 → 截图注明隔离构建；如交付安装包需核对包含新界面，不声称运行版本已替换。

## Migration Plan

纯前端兼容更改，旧记录允许缺少诊断/阶段详情。使用隔离浏览器构造实际准备、规划、执行及并行评审事件，覆盖桌面和窄屏、重连回放与历史状态；原生产会话恢复核验独立留在既有修复变更中。
