## Why

AIMEIN 上方保留通用 LOOP 控制区，下方另起沙盘，界面割裂。实际准备已在运行，但没有 sprintId 的记录被过滤，实时 prepare/aimein-plan 输出没有常驻入口，用户看到的仍是入门说明和“待核实”，无法判断是否在工作。

## What Changes

- 将运行控制、来源、问题与设置入口统一为沙盘内紧凑控制条，保留原控制器和权限语义。
- 新增默认展开的实时执行面板，展示当前阶段、模型、调用活动、耗时、实际流式输出及历史输出；准备阶段也可观察。
- 将实际运行活动直接映射到沙盘流动，未生成计划的准备/拆解也有对应航线；等待、断线和受阻停止活动，不以动效伪造完成。
- 当前运行与历史观察明确区分，运行时不显示未配置的入门文案；保留目标原文、有效来源与已选评委信息。
- 支持跟随最新/暂停跟随、收起/展开；窄屏保留场景及可用日志阅读空间；重连通过原有详情回放恢复。
- 以隔离浏览器覆盖真实事件形态、阶段切换、历史/身份隔离和错误恢复，并提供实际界面截图。
- 将三方报告汇总为整体意见，列明共同认可、分歧、待修补与下一步；默认显示系统按当前计划及依赖形成的装配，手动修改仅作为可选建议；将探针明确为成果与验证。

## Capabilities

### New Capabilities

- `aimein-run-observability`: 沉浸沙盘中的统一控制与可核对的实时执行观察。

## Impact

影响 LoopPanel、AimeinWorkbench、AimeinRecordView、场景布局及前端状态投影。复用 useLoopWorkbenchState 的有界流、调用诊断和详情回放，不增加轮询或模型调用，不改变 LOOP 调度、环境权限和验收规则。普通 LOOP 界面保持既有操作布局。
