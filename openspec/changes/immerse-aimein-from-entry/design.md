# Design

## Context

入口由 App 内 NewSessionDialog 管理，AIMEIN 会话持久化为 LOOP + executionMode。LoopPanel 仅在非 loopidea 阶段渲染 AimeinWorkbench；AimeinWorld 已支持空记录、键盘对象导航、静态降级及按可见性暂停渲染。已有创建字段、目标确认、策略保存与执行动作分别有权威 RPC，不新增执行入口协议。

## Goals / Non-Goals

**Goals:** 让创建前、准备目标、配置评委与开始建设共享同一沙盘视觉和四步导航；草稿和动作回执由已有控制器持有。

**Non-Goals:** 不自动调用模型、不默认选择三位模型、不创建假进度，不改变后端验收、权限和来源保护，不在本变更重建评委档案体系。

## Decisions

- 新建共享准备场景组件，复用 AimeinWorld 的真实空态并提供沉浸布局。桌面场景与紧凑引导卡同屏，窄屏上下排列；使用容器尺寸而非固定桌面宽度。
- NewSessionDialog 选择 AIMEIN 即展示场景，原节点/目录/Backend 控件提取为可复用 slot，默认摘要、按需展开。创建仅在明确点击后发生，继续保留节点归属和重复提交保护。
- LOOP 初始目标阶段和首轮执行前都渲染准备场景。工坊、目标、评委、开始各步骤映射场景对象；当前需补字段使用细红框、编号、原因，不通过跳过引导绕过运行条件。
- 目标和评委采用分开的显式保存，确认成功才推进引导。执行按钮仍走 LoopActionController 与原 runIteration；设置保存不启动执行。失败/未知保留草稿，未确认保存不显示已就绪。
- 修改评委使用现有 LoopPolicyEditor，复用 aimeinReviewerIssue 验证三个不同模型；后端始终最终校验。已存在成果保持现有观察、历史和建议工作台。
- 纯视觉导航、收起/恢复、静态切换不发写请求。引导卡非模态，不锁住场景；新建全屏弹层具备键盘关闭和焦点约束。

## Risks / Trade-offs

- 空场景被误认为成果 → 明确“建设准备/尚未开始”，目标瓶保持未知，工坊不表示已建成。
- 配置卡遮挡场景 → 桌面限制卡宽，窄屏保留可见场景并允许纵向滚动。
- 刷新/推送覆盖草稿 → 依 Session 隔离；仅成功保存清除脏状态，失败保留；已开始执行切回既有工作台。
- 评委配置存在不等于服务凭据可用 → 就绪仅表示配置齐全，文案说明开始时再次核对，外部认证失败沿用实际执行回执。
