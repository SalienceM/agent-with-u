# Design

## Context

见 proposal.md。当前 World 方块只共同打开 flow 观察，拆分/聚合只控制视觉。Workbench 拥有意见草稿、按版本记录、评委库，LoopPanel 拥有真实 primary 门槛，目标细节懒加载。现有常驻 Canvas、按需渲染、航线实例与三方共同核实不可退化。

## Goals / Non-Goals

**Goals:** 新建轻量操作层，共享真实目标、步骤与意见通道；把对世界的操作变为可审计的下一步意图。

**Non-Goals:** 不允许任意移动实体改写冻结 Sprint，不新增自动执行、能力经验值、模型训练或无依据完成奖励。不改后端控制协议，不重新打包。

## Decisions

1. 装配是下一次规划的建设意图，通过已有 onFeedback / loopAddAddon 提交，文本含尝试、计划目标与验收。直接改 Sprint 会破坏冻结验收；单纯视觉组合没有后果。两者均不采用。显式选择与传递依赖分开存储，按真实计划内容及尝试键保存草稿，缺失/环阻止提交，最多 40 个现有目标。运行、只读、历史禁止提交；新推送不覆盖旧草稿。一次请求在途用 ref 防重；失败或未知保留并提示核对意见流。
2. World 可接收工具状态、目标选择、装配 ID、历史标记与开工动作；业务仍在 Workbench。目标单独可点，抬升并展示高亮依赖；装配时移动至工作区插槽，采用现有 Move 动画。观察/装配优先拾取重叠的目标，探针/评委优先拾取航线。底部工具栏具 1–4 键和语义按钮，表单不截获快捷键。静态视图共享 HTML 模块清单与装配业务。
3. 新增独立操作面板：模块验收/依赖清单、装配槽、错误/步骤探针、评委席快速入口。保存输出不假定属于哪个目标。已有完整观察、意见、记录仍可访问。开工由 LoopPanel 传入资格、解释和 primary 回调，历史只允许回到最新。
4. 世界沿边缘显示最近真实尝试标记，颜色区分保存、通过和未完成；未加载输出保持未知，点击复用历史选择。评委校准使用显式请求定位对应 report，保留档案草稿且不把自动聚焦当作保存。
5. 不加图形依赖。可动目标和历史有界，沿用 demand frame 与 reduced/active 策略；材质共享，新增几何释放。保留常驻 Canvas 和原有薄航线。

## Risks / Trade-offs

- 建设意图不等于已改变 Sprint → 明确“交给下次规划”和保存回执，展示现有意见流处理结果。
- 实时目标变化 → 草稿按内容身份隔离，保存使用冻结的来源文本；不自动重发。
- 触屏场景小 → 工具栏紧凑、可滚动目标清单等价点选；验收手机实际截图。
- 好玩是主观判断 → 交付自动操作真实浏览器的录像，说明隔离数据范围，最终由用户体验判断。
- 之前隔离创建曾有一次 Windows replace 异常，根因未确认 → 本变更不声称修复，不碰生产 Session。
