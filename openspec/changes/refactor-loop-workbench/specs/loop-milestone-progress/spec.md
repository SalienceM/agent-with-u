# Spec Delta

## MODIFIED Requirements

### Requirement: 子里程碑与正式进度分开展示并兼容历史

系统 SHALL 在统一 LOOP 工作台分别展示正式任务勾选、子里程碑状态及本轮被认可的增量与依据，总览使用有界摘要，过程与证据详情使用同一身份和修订的记录。新增数据 SHALL 版本化、按需加载并受节点/Session 隔离约束；旧记录缺失子项时 MUST NOT 自动构造历史里程碑或完成比例，评分 MUST NOT 替代验收进度。

#### Scenario: 面板和流程视图一致
- **WHEN** 用户查看同一轮的工作台总览、过程或证据详情
- **THEN** 各处显示一致的父任务进度、子项结果、证据失效及调度原因，不混算父子任务百分比，也不要求通过两套顶层面板切换查阅

#### Scenario: 旧客户端保存策略
- **WHEN** 未识别新字段的客户端更新既有策略或加载历史记录
- **THEN** 已存里程碑及来源修订不被省略字段清空，历史缺失值显示为不可得，不改变普通聊天或人工接管行为

#### Scenario: 总览尚未取得完整证据
- **WHEN** 总览只有正式勾选计数或紧凑摘要，完整评审详情尚未读取
- **THEN** 明确计数属于勾选或已知子项状态，不倒推出业务完成百分比；展开后按当前有效证据呈现详细验收
