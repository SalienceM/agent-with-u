# Spec Delta

## MODIFIED Requirements

### Requirement: 环境状态轻量展示并安全持久化

系统 SHALL 在 LOOP 工作台的按需执行设置/诊断、过程详情及恢复后展示一致的访问策略、检查覆盖、原因和解除条件，提供空闲时的显式重新检查入口。正常或尚未检查且没有已知阻塞的环境 SHALL 不占用常驻大卡；实际环境阻塞、检查进行态和退出未确认 SHALL 在统一需要处理区或当前状态区可见。记录 SHALL 按用户、节点、Session 及修订隔离，使用有界摘要和按需详情，不保存完整环境变量、凭据、授权令牌或额外历史正文；旧记录 SHALL 保持未知。

#### Scenario: 重新检查不等于执行
- **WHEN** 用户在空闲且有操作权限的 LOOP 点击重新检查环境
- **THEN** 系统仅运行所选环境的固定只读检查并更新证据，不开启 Auto、不发送任务模型调用、不自动恢复暂停；运行中或人工接管只读视图不提供此操作

#### Scenario: 延迟响应与配置修订
- **WHEN** 用户切换 Session、节点或环境配置后旧检查返回
- **THEN** 旧结果只属于原身份和修订，不覆盖当前就绪状态、不解除新暂停，重复推送和隐藏视图不形成详情轮询

#### Scenario: 旧记录及敏感信息
- **WHEN** 加载无环境字段的旧记录，或异常包含密钥、完整环境和私有正文
- **THEN** 系统在环境详情显示旧环境未知；新记录仅保留白名单化类别及必要身份引用，敏感正文不进入环境详情、紧凑推送或日志

#### Scenario: 无环境问题的通用工作
- **WHEN** 未选择特定工作流且没有可靠环境阻塞
- **THEN** 工作台不常驻依赖选择和环境警示文字，不擅自显示已通过，用户仍可从执行设置查看支持范围

#### Scenario: 环境问题被提升
- **WHEN** 已知环境故障或旧调用退出未确认影响当前执行
- **THEN** 主界面显示问题与解除条件入口，即使诊断尚未打开也不能把任务显示为正常就绪；关闭详情不会清除检查活动或保护
