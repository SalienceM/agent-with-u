# 首页第 10 步：运行态问题集中修复

验收日期：2026-07-25  
结论：通过

## 闭环修复

1. **多空分屏重复挂载首页**
   - 修复前：`1×2` / `2×2` 的每个空 pane 都挂载一套 `HomeDashboard`，重复执行全量详情 RPC、实时事件订阅和渲染。
   - 修复后：可见空 pane 中仅第一个挂载全局首页，其余 pane 显示可直接新建会话的轻量空状态。
   - 回归断言：在真实 Chromium 中恢复 `2×2` 且四个 pane 全空，页面恰有 1 个命名主地标、1 个首页和 3 个空 pane。

2. **局部数据源失败丢失最后成功快照**
   - 修复前：一轮 Loop / 待办详情读取中任一源失败，该源会从本地聚合快照中消失。
   - 修复后：成功源采用新数据、失败源保留上一份成功快照，并继续剔除已经离开会话清单的旧源；页面仍以 `stale` 明确提示部分数据不可用。
   - 回归断言：覆盖“成功刷新、失败保留、新增写入、已移除清理”的混合场景。

3. **首次连接固定重复读取配置**
   - `useConfig` 的首次加载保持不变；`App` 只在真实断线重连后调用 `reloadConfig`，不再在首次连接时重复读取 `getAppConfig`。
