# 俺寻思：当前项目只读答疑

可以直接问“在当前目录检查 OpenSpec 进度”或“这个源文件是怎么实现的”。界面附带内容只是帮助识别
你指的“这里”；不需要先打开文件、复制 tasks 或补充所谓“快照”。仅打开助手不会扫描项目或调用模型。

## 能查什么

- 所属 Session 当前执行节点的项目目录、有限文本搜索和 UTF-8 文本分段读取。
- 当前 LOOP 轮次、阶段与步骤、Auto/停止原因、已知阻塞、原任务进度及最近模型 verify 问题。
- 项目内标准 OpenSpec change 的真实 tasks 勾选；不需要 CLI 或绑定来源。
- 显式 @SKILL 手册参考、当前关注对象和附图。引用资料不会执行 Skill。

每次提问重新采样。固定注意力固定的是目标 Session/节点/对象，不是过时的运行数据。
后续模型可在本次有限查询内刷新运行事实，但不存在后台持续轮询。

## 如何理解结果

“查询来源”可展开查看文件位置、修订、读取时间、覆盖范围和读取结果。旧问答没有这类元数据时显示
“未记录”，不会自动补查。完整正文只作为本次模型上下文，系统不另外复制进历史或广播；回答可包含必要引文。

目录来源显示本页目录项与分页位置，搜索显示检查目标数与命中数，只有文本读取显示字符范围。
“已读取目录”不等于读完目录下的源码。受限来源区分单文件大小、累计读取、搜索额度、项目证据上下文等原因；
旧记录没有具体原因时仍显示通用“达到查询上限”，不补造原因或 `0–?` 范围。

文件勾选不等于功能验收。比如原清单 6/10（60%）、4 项未勾选，其中 2 项是用户明确排除的独立人工项，
则另列自动范围 6/8；人工项仍未完成。混合实现与人工验收的任务不会整项剔除。模型 verify 是有界评审，
也不是机器证明。空清单、读取不全、文件变化或未知格式不产生伪精确的完成率。

目标选择为本轮明确 change、当前有效关联、唯一真实候选；多个候选时询问范围，明确要求“全部”才分项汇总。
查询不会改变 LOOP 的权威来源，不调用 apply/verify，也不会启用 Auto。

## 反馈与停止

发送后显示提交/准备、正在读取及目标、正在回答，最后为完成、失败或取消。错误会区分缺失、访问拒绝、
超限、身份变化、读取失败和模型故障。失败的问题仍在记录中，“编辑后重新提问”仅填回草稿；发送才是新请求，
附图需按需重新添加。点击“加入主流程队列”仍是独立的用户操作，答案不会自动转交主线。

停止只影响旁路。不确认真实退出时显示“结果待确认”并保留旁路占用，主 LOOP 与其他 Session 不被暂停。
确认结束后显示“旁路退出已确认”，不继续显示正在确认。回答超时仍是失败，退出确认不表示答案成功。
连接超时最多自动只读核对一次，不重放提交。进程重启后残留的未确认旁路也不会自动重新执行，需核对原执行端。

## 硬边界与预算

模型推理无原生工具；执行端只接受五类结构化查询，不解释任意命令或 RPC。主聊天即使允许写入，旁路也不能
写文件、勾任务、安装、修改权限、发布或控制主线。文件、手册和历史中的命令都只是数据。

读取固定在提交时的用户/节点/Session/目录/Backend；身份改变则停止后续查询。实际文件句柄必须属于工作区，
拒绝符号链接/Windows 重解析点、路径穿越、设备/UNC/ADS、已知凭据文件、私钥和二进制。
依赖/构建目录、`.git` 不参与读取；当前仅支持 UTF-8。凭据识别是明确的路径/类型及私钥标记策略，
并非任意文本的通用秘密检测器。SSH 和外部 OpenSpec store 不在本次范围，不回退本机同名目录。

单次问题最多 180 秒、4 个查询决策轮及 1 个最终回答、24 次读取操作；单目录页 200 项，搜索最多
200 文件/40 目录，文本页 16,000 字符，单文件 256 KiB、累计读取 1 MiB、项目证据 64,000 字符。
其中查询发现（包括参考资料准备）至多使用前 120 秒，最后 60 秒预留给一次总结；搜索的新磁盘读取最多
占用总额中的 512 KiB，其余留给定向读文件，不额外增加总额。读取前检查额度，缓存复用仍核验文件修订。

请求级额度耗尽即停止新增查询，基于已有证据回答，并提示未覆盖部分。单文件受限可换其他合法目标；
搜索额度耗尽后仍可在总预算内定向读取，重复同一不可恢复的超限查询不会再次读盘。
发现阶段到时仍在运行的模型/读取必须先确认退出，才能开始总结；无法确认则保留待确认状态。
用户主动停止不会触发总结。模型或总时间仍可能超时，预留窗口不保证一定生成答案，也不保证大型项目完整覆盖。
文件变化最多重读一次；协议损坏最多纠正一次，均受总预算限制。总时间上限不保证 OS 调用立即退出。

这些测试不证明生产模型始终正确遵循查询协议，也不代表真实项目/生产 Session 已验收。
