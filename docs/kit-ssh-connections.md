# Linux Kit 的已保存 SSH 连接

打开 **Kit → SSH 一键更新 AgentWithU Docker → 详情 → 标准输入 → Linux 连接**。

1. 点「添加连接」，填写主机、端口和 SSH 账户。
2. 选择执行节点上的 **SSH Agent**，或填写该节点上已有私钥的绝对路径。这里的节点是执行此 Kit 的 Windows 设备，可能不是当前浏览器所在设备。
3. 点「读取服务器指纹」，通过服务器管理端或管理员核对显示的 SHA256 指纹。勾选核对后保存。读取公钥本身不会证明服务器可信，也不会自动保存。
4. 点「测试连接」。这只检查指纹和密钥登录，不部署、不改服务器。
5. 旧密码版 Kit 先在详情顶部「停用」，再点「保存为密钥版」，最后重新启用。原执行版本和记录保留；部署目录、Git 分支和代理的默认值继承。

设为默认连接后，重新打开面板、重启应用及聊天调用此 Kit 都复用它，无需重复输入 SSH 密码。运行时可选其他已保存连接；要永久更改默认连接，停用 Kit 后点「设为默认连接」，会生成新版本。自定义过部署命令的 Kit 不会被自动改写；可新建标准 SSH 更新 Kit 并明确使用密钥或免密连接。

服务器账户必须已将对应公钥加入 `~/.ssh/authorized_keys`。应用不会替你安装公钥、创建或读取私钥内容。加密私钥可先加入并解锁执行节点的 SSH Agent，然后选择 Agent 登录。SSH 登录成功不等于取得 Docker 权限；远端账户还需要直接使用 Docker，或已有免密 `sudo -n docker` 权限。

服务器指纹变化时停止连接，不会自动接受新指纹，也不会回退到密码。确认服务器更换了密钥后，添加并核对新连接，再显式选用。连接测试不会自动执行 Kit。

## 实现边界

- 连接属于保存它的执行节点和 AWU 账号，保存在 `ssh-connections/<owner-hash>/`。只保存名称、主机、端口、账户、主机公钥/指纹、认证方式和私钥路径；不保存密码、私钥内容或私钥口令。
- 使用不可变记录、请求 ID 幂等保存，最多 64 个连接。保存回包丢失时不自动重写；重新打开列表核对，手动重试复用请求 ID。指纹待确认记录十分钟失效。
- 连接管理和使用都校验 Session 所有者及执行节点管理权限；普通共享用户无法使用节点上的凭据。前端固定执行器路由，身份/节点/Session 变化后丢弃迟到结果。
- 新版 Kit 不含 `secret` 输入，因此可以走现有聊天 Kit 执行器；旧密码版的聊天拒绝规则不变。修改/切换执行版本仍要求停用且无活动运行。
- 每次计划冻结完整连接及修订，启动前重新核对。实际部署仍由原 Kit 执行器管理进程、日志、验收和取消，不增加旁路部署器。
- OpenSSH 使用独立的临时 known_hosts、固定 HostKeyAlias、`StrictHostKeyChecking=yes`、`BatchMode=yes`；不读用户 SSH 配置，不使用全局 known_hosts，不自动更新主机密钥，不转发 Agent，不回退密码或键盘交互。Agent 模式不隐式尝试默认私钥文件。
- 目前标准部署模板面向 Windows PowerShell → Linux，主机字段支持 DNS 名称和 IPv4。

测试使用隔离数据目录、模拟服务器公钥和模拟连接；本机 OpenSSH `-G` 及 PowerShell 解析检查不连接网络。真实 Linux 认证、Docker 权限和部署结果需在用户配置连接后验收。
