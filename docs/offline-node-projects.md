# 在无法访问远端 Git 的节点开发

A 保存原项目，B 只能通过 AWU 连接 A、不能访问远端 Git 时，可以把项目交接到 B。两端都需要安装本地 Git，并更新到支持项目交接的 AWU；B 的模型 Backend 和构建依赖需要自行准备。

1. 在 A 的主 Session 上右键，选择 **发送项目到节点**。
2. 选择真实在线的 B 节点、B 的 Backend 和会话标题，点击 **预览交接**。
3. 核对来源、目标、文件数量和大小，点击 **确认传输并创建**。目录自动分配；普通“跳过确认”不会省略这一步。
4. 校验成功后点击 **打开目标项目**。这是 B 的独立本地 Git 主 Session，可右键 **新建分支副本**，在各分支对话中分别执行任务，再用现有合并流程汇集到 B 的主项目。
5. 在 B 的主 Session 或某个分支上右键 **回传项目成果**，选择原 A 节点并预览、确认。
6. 完成后点击 **打开待合并分支**。A 下会新增一个审阅分支，从原发送基线出发；使用 **合并到主 Session** 审阅差异、处理冲突并确认合并。

整个交接不运行 clone、fetch 或 push，不启动模型，不复制聊天历史或原生会话。B 的 Git 历史从本地初始提交开始；回传到 A 的是当前成果快照，不包含 B 的全部提交历史。A 的当前 HEAD、索引和工作文件不会被传输覆盖。A 在此期间产生的提交会参与后续三方合并，不会被 B 的旧版本静默替换。

## 文件范围

传输预览时已保存到磁盘的项目文件，包括 Git 跟踪文件、未忽略新文件、修改和删除。保留实际字节、二进制和可执行模式；私有 Git 索引按快照中的属性生成提交，原索引不变。编辑器中未保存的草稿不包含在内。

Git 忽略的新文件不复制，包括依赖缓存、构建产物和被忽略的 Skills。需要这些内容时，应在 B 准备。链接、子模块、凭据路径或不可移植路径会明确阻止快照，不会静默漏传。预算为 2000 个文件、单文件 20 MiB、正文总计 64 MiB；当前 Git 检查仍有未提交路径最多 500 项的上限。

## 连接中断与核对

关闭面板不取消已经提交的传输；当前窗口仍会继续完成已授权的工作。关闭发起窗口会中断中转，但已经接收的文件、目录和回执保留。重新打开后可选择原目标节点，点击 **核对最近交接**；当前面板中的未知结果使用 **核对原请求**。

核对只读取原节点和请求，不重新发送块、不重放创建。目标已完成且文件及 Session 均核验成功时，可打开原创建的会话。尚未完整接收或进程退出未确认时显示未知，保留暂存和成果，不自动删除或覆盖。离线节点不会回退到本机。

仅在打开交接面板或主动核对时加载记录。会话列表不常驻显示这些状态，也不会后台轮询 Git。
