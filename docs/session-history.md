# 同目录新会话与历史

普通对话的输入栏 **更多 → 新会话 · 同目录** 和 `/new` 保留当前 Session，创建同一执行节点、同目录的新 Session，然后在当前标签位置切换。无需再选择目录或模型，也没有清空旧记录的确认框。新会话保存成功前保留原界面。

旧会话保留原标题、聊天记录、附件、原生线程和用量；输入草稿、排队任务和定时任务仍属于旧会话。新会话继承 Backend、模型/推理设置、约束、能力绑定、自动继续/执行确认设置、自动提交设置、影子建议设置、收藏、底色和私密标记，但不继承模型上下文、任务、工具授权回执或原生线程。切换不会自动发送消息或执行任务。

输入栏 **历史** 显示这一组会话的时间轴，按创建/开启时间倒序排列。保留原标题，不自动给用户的标题追加时间戳。点击历史项通过正常会话入口回看；也可以从侧边栏打开旧会话。普通重命名和回看不会重排时间轴。只按需读取轻量元数据，每页 30 条，不为打开时间轴加载全部消息。

时间轴沿用当前窗口的私密 Session 显示开关，不更改权威列表或私密标记。新会话替换当前标签，旧会话仍保存在侧边栏；从历史重新打开时再加入标签。其他窗口和其他标签不随之切换。

LOOP、评议、任务/整合工作区使用各自的工作流入口。工程视图先返回 Chat 才能续建。执行尚未结束或退出状态未知时，拒绝续建，不借此解除活动保护。新建失败不改变旧会话。请求在当前窗口保存 ID 后提交；断线只自动查询一次结果，显示未知时可手动核对。需要继续未完成的创建时仍使用同一 ID，不生成重复会话。迟到回执不会抢走别的会话焦点。

## DSH 日志

在 **历史 → DSH 原始日志位置** 可查看、选中复制当前会话的原生 ID 和路径。这些路径位于实际执行节点，不一定是当前浏览器所在电脑。该操作只读元数据，不启动 DSH、不恢复线程、不读取整份原生日志。

默认数据根为 `~/.agent-with-u`，配置了 `AGENT_WITH_U_DATA_ROOT` 时使用该目录：

| 路径 | 内容 |
| --- | --- |
| `deepseek-harness/<身份哈希>/home/sessions/` | 原生会话日志；`.jsonl` 为逐行 JSON，`.jsonl.zst` 需使用支持 Zstandard 的工具解压查看 |
| `deepseek-harness/<身份哈希>/session.json` | 当前原生会话绑定，包含 `nativeId` |
| `deepseek-harness/<身份哈希>/bindings/` | 旧版显式清理上下文前保留的原生绑定；未清理过时可能不存在 |
| Windows `%APPDATA%/AgentWithU/logs/backend.log` | AWU 执行与报错日志，与会话原始日志分开 |

切换到旧会话后，日志入口对应那条旧会话。新会话第一次运行前可能尚无 DSH 原生日志。目录中的日志不要直接修改；原生日志包含对话和工具活动，复制分享时按实际内容处理。

## 兼容范围

新入口调用 `sessionRenew`，不调用旧的 `clearSessionContext`，也不会通过 `createSession` 的默认节点路由降级。旧节点不支持时显示更新提示。旧版已清空的 AWU 聊天记录不会凭空恢复；保留的 DSH 原生日志仍可按上述路径查找。显式 `/clear`、`/compact` 及删除/销毁操作保持各自原有语义。

来源关系存于新 Session 的 `historyRootId` / `historySourceId`，与项目协作父子关系分开。新 Session 持久化 `historyRequestId` 作为幂等回执；原 Session 不需改名或重写，因此没有跨两个会话文件提交一半而丢失旧记录的窗口。

验证使用临时 Session 存储及隔离浏览器的假 API，不清理真实 Session，不调用生产模型。
