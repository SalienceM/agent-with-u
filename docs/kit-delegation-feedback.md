# Kit 单次代确认

输入行的开关仅作用于本次直接发送，默认关闭。只开启开关并提交明确 Kit 任务即可，不需要在正文再写“我同意”。正文、历史、附件、语音、排队、评议和建议均不构成委托。

发送后开关复位。原消息下的回执区分等待接收、已接收待绑定、已绑定运行、已用于运行、已结束/过期、不可用和结果未知。它是展示证据，不是授权来源。需要确认时可直接进入原运行/步骤；面板确认后由 Kit 继续运行，不必补发聊天。

提醒偏好可以记住，授权值不会记住。收起面板或结束聊天不停止已提交的 Kit。一个运行/链的委托最长六小时，依然核对完整计划、指纹、目标和配置，安装与跨工作区操作保持各自独立确认。未知结果只查询，不自动重发。

本次修复的实测：普通直接发送能够携带开关；原组件将 `isFocused` 放进清零 effect，改变同一输入的焦点状态会丢掉未发送选择。现在实际 Session/Backend/忙碌/队列变化仍清空选择，普通焦点变化保留；发送入口先同步捕获布尔值。旧链没有独立接收回执，也没有给 Agent 注入服务端已接收事实，现增加无秘密的 sidecar 记录与指引，`list/status` 仍是当前授权事实来源。

验证使用 fake Backend、临时数据目录和隔离浏览器，未执行真实发布。`test_chat_kits.py` 覆盖开关/正文、绑定、使用、过期、计划变更、单次运行、安装独立确认和面板人工批准；`chat-kit-feedback.spec.ts` 覆盖直接发送、焦点/忙碌变化、图片读取、异步完成、回执定位和提醒偏好。
