# 定时任务发布说明（待发布）

此说明对应 `add-session-scheduled-prompts`，不指定新版本号，也不表示已有安装包通过验收。目标入口为普通 Session 顶部 **定时**；内置 **使用手册 → Session 定时任务** 可离线查看使用说明与本文。

## 用户可见变化

- 在已有普通 Session 中安排单次、每日、每周或最短一分钟的固定间隔指令，按指定 IANA 时区预览下一次时间。
- 到点使用执行时的 Session 模型、上下文和工作目录；忙时排到现有任务后，每个计划最多保留一个未开始实例。
- 默认合并补跑一次，可改为跳过。原聊天提供真实流式输出，定时入口显示运行、排队、暂停及待输入状态，历史保留原消息关联。
- 网络超时保留草稿和原请求标识，重连只核对回执；已领取但结果无法确认的任务不会自动重跑。

## 升级与数据迁移

首次使用支持版本时创建独立 SQLite v1 账本 `session-schedules/state.sqlite3`。既有 Session、聊天和普通队列不转换为定时任务，也不自动创建或启用计划。新的可选 `scheduleRef` 只用于定时来源；无此字段的旧消息和普通队列仍按原规则读取。

普通队列仍沿用既有迁移规则：`seqSchedulerVersion=1` 才有持久暂停语义；更早数据缺少此标记时，旧 `seqAuto=false` 不被解释为新版暂停。升级很旧的版本前应先处理未完成的普通队列，不能把这个旧字段当作升级后不派发的保证。此规则不会创建定时计划。

升级同一执行节点应保留其原数据目录、用户归属和 executor 身份。备份需在服务与原生任务确认退出后进行，至少一致保留 `sessions/`、`chat-extras/`、`session-schedules/` 以及原身份配置；只复制 SQLite 或只复制队列不能构成可恢复快照。定时数据库包含指令与回执，属于用户数据，不应随安装包携带。

启动时，未领取实例以原 ID 对账；claimed/running 缺终态时转为未知并保留暂停。发现高于 v1 的数据库版本时拒绝定时写入和派发，不降版本、不覆盖文件。来源冲突或损坏同样停止该目标派发。

将数据目录直接复制到另一个 executor 不是计划迁移功能。此版没有跨节点转移、身份重绑定或通用数据库版本降级工具；不能靠改节点名或修改数据库字段恢复调度。

## 新旧版本兼容

| 组合 | 行为与建议 |
| --- | --- |
| 新客户端 + 新执行节点 | 支持配置、状态、历史与实时原生待输入；仅普通 Session 可配置 |
| 新客户端 + 旧执行节点 | 显示能力不支持或原 RPC 错误，不调用旧队列接口模拟保存；需要升级目标节点 |
| 旧客户端 + 新执行节点 | 已保存计划仍由节点运行；旧界面没有完整配置/历史入口。新节点拒绝旧队列编辑、删除、引导或重置定时错误项。建议同时升级控制端 |
| 新程序 + 旧 Session/队列 | 默认无计划，保留普通排队、暂停和手动重试语义 |
| 旧程序 + 含定时数据的目录 | 不支持直接降级。旧队列解析器可能丢掉来源字段，旧“继续”可能将失败项再次执行 |

## 回滚前必须处理

1. 在当前支持版本停用所有受影响的计划，获得实际保存回执。停用只取消未领取实例，不停止正在运行的任务。
2. 检查主轮次和原生进程退出。存在 claimed/running 或未知退出时，先停止并核对原聊天和实际副作用；无法确认就不要降级。
3. 核对“结果未知”后结束该次记录，保持队列暂停。对失败/中断项在定时历史选择 **取消本次**。不能只移除 pending 项：旧版本重置 error 项也会重放指令。
4. 确认所有待处理定时队列项已经对账移除；先保留或处理普通队列，只有确认无需保留的已完成/已中断显示项时才使用队列清空，避免一起清掉手动任务。保留账本、原消息和回执，不手工删库解除保护。
5. 确认服务退出后保存一份完整、同时间点的数据备份，再进行受控降级。若当前状态无法满足上述条件，保留当前版本。恢复升级前全量备份会丢失之后的新聊天、配置和执行证据，不能与当前数据混拼。

此功能不提供一键回滚，也不回滚模型已执行的外部文件修改、部署或其他副作用。

## 已知限制

- 执行节点必须保持运行；不唤醒休眠机器，不由云端代跑，不保证机器过载时准点。关闭控制端页签与完全退出承载 Backend 的应用不同。
- 仅支持普通 Session 和文本；不支持 LOOP/AIMEIN、评议会话、新建 Session、附件模板或任意 cron。
- 采用每计划合并，不会逐次补齐所有漏跑时点。默认补跑可能执行已经过时的指令，时效性任务应选跳过。
- 自动触发使用当前 Session 的普通权限；新的原生审批与问题仍需可用通道，不继承历史 Kit 单次委托或 workspace lease。原生输入通道不支持时会明确失败。
- 触发去重不等于外部副作用 exactly-once。失败后的显式重试仍可能重复原轮次已经完成的部分操作。
- 原输出从原聊天读取；聊天被清空或消息已不在原生镜像范围时，定时历史仍保留引用，但不会重造正文。较早的完整工具记录需在原聊天加载。
- 90 天前的终态指令快照可归档；去重身份、游标和请求回执继续保留，数据库不会自动缩减为固定大小。
- Windows 与冻结包依赖随包 tzdata，Docker 独立依赖清单也已纳入。时区规则升级可能改变未来当地时间的换算，应核对下一次预览。源码上的时区测试、前端构建通过，不等于最终安装包和目标操作系统已验收。

## 制品验收边界

发布候选需要来自同次构建的前端、Backend sidecar 与桌面安装器。内置说明由源 Markdown 在前端构建时嵌入，不依赖仓库路径或外部网页；Tauri 取 `frontend/dist`，Web 冻结包取 `frontend_dist`。

打包自检需检查四个定时模块与 tzdata 中实际时区文件，不能仅用宿主机时区数据库掩盖缺包。必须以最终 sidecar/安装器的 SHA-256 绑定验收记录。用旧制品或临时前端目录检查，不能宣称新安装包已经通过。

最终发布前建议在隔离用户目录安装候选包，断网打开内置手册，核对普通 Session 定时入口和不支持类型隐藏入口，再验证一个停用计划的保存、读取及重启恢复；测试中不启用真实模型任务。Linux Web 制品还需在目标平台做同类冒烟。本轮未执行发布、安装或真实用户计划。
