# Harness 外部运行时

## 使用

新的桌面/Web 冻结包不再携带大型 Harness runtime-bin。只有使用这个 Backend 时，才需要在 Session 所属执行节点安装兼容的 CLI；控制端已安装不代表远端已就绪。

准备 Node 24（至少 24.10；当前实际验证基线为 24.10.0），然后手工执行：

```shell
npm install -g @deepseek-ai/dsh@0.2.1-rc.3
```

Windows 自动检查常见 npm 全局目录及 PATH 中的 npm 入口，Linux 支持 PATH 符号链接。非标准目录可在既有 CLI 路径字段指定 `dsh.cmd` 或包内 `lib/bin.js` 的绝对路径。Node 必须可在该执行进程的 PATH 中找到（或与 shim 同目录）；不要填写带参数的命令字符串。

AWU 不执行安装或升级、不使用 `npx`，也不修改 PATH。无效显式路径不回退；错误版本、关键资源变化或安装不完整会拒绝提交。安装后需要用户重新提交，不重放失败输入。不要改装 `latest` 来规避校验。

从内置运行时版本升级时，既有 Session/历史和 Backend 配置保持原样。未指定 CLI 路径的冻结安装改为寻找外部 npm；若原配置指向旧包的临时解包目录，该路径失效会明确报错，需要用户清空该覆盖或改为实际 npm 入口，不会暗中改配置。仍保留独立旧配套目录的显式路径则继续严格校验。

建议将 npm 安装在执行节点本地文件系统。Linux 容器测试中，位于 Windows bind mount 的 npm 树曾触发初始化超时；复制到容器本地文件系统后通过。同一版本安装成功并不保证慢速挂载盘的启动延迟满足当前预算。

原生会话 ID、历史、权限、停止及图片准入保持原机制。图片保留明确的能力/资源校验和远端 DELETE 防护；哈希校验不等于 OS 沙箱证明。原生协议握手失败仍停止，不切换其他 Backend 或节点。

## 调用失败排查

Harness 支持原生文件读取、编辑和命令工具；工作目录必须位于 Session 所属执行节点。
普通调用失败显示失败阶段、固定错误码及可用的 HTTP／RPC 状态，不再统一提示“核对图片能力”。
例如 `workspace_missing` 表示执行节点工作目录不存在；模型执行阶段的 HTTP 404 提示核对
Base URL 的 Messages API 路径和模型名。RPC 错误文本里出现“401”不作为 HTTP 状态证据。
只有明确的图片准入／资源错误保留图片专用提示。

带图片历史的自动压缩也经过同一模型调用保护。桥保留温度、停止词等完整调用参数，
使用原生 `prepareCall()` 返回的有效配置发送，包含原生补齐的推理强度及输出上限；
已有的冻结 Agent 请求配置一致时保留原对象，辅助调用不改写原请求。
这避免压缩请求因缺少默认参数而报 `prepared LLM call config changed before adapter dispatch`。

受保护调用失败使用已挂载运行时的 `LlmError` 类型，仅保留白名单错误码和合法 HTTP 状态，
去掉供应商正文、requestId、cause、重试与删图指令，不再统一包装为 `image_model_failed`。
认证、限流、额度、上下文超限、网络、空响应及调用配置问题可分别诊断；
未知错误仍保持未知，不从正文猜原因。失败直接结束本次调用，不触发自动重发；
`IMAGE_OFFLOAD_REQUIRED` 仍明确拒绝，不能通过删除图片恢复。

流式错误独立于模型正文显示，并随回复保存；重新打开 Session 仍能看到错误。
半截 Markdown 不会吞掉提示，只有错误而没有正文的回复也保留。`done` 表示流结束，
不证明任务成功；不会为了补全回复自动重放已执行的工具。

DSH 接收队列仍限制为 256 个事件及原有字节预算。队列暂满时最多等待 0.5 秒让消费端
释放容量，持续积压则以 `event_overflow` 失败；不扩大缓存或静默丢帧。
`stream_gap`、`stream_mismatch`、`stream_backpressure` 分别表示缺帧、内容不一致和
处理持续堵塞。后端日志的 `[HarnessTurn]` 保存 Session／消息关联、错误码和阶段，
无需开启正文采集；不记录供应商原始响应或凭据。历史版本漏存的错误无法据此追溯恢复。
投影失败另记固定方法／帧类型、序号、异常类别和有限的本地代码行号，不记录帧正文、
隐藏思考、工具参数、用户路径或异常原文。已知的协议形状错误和投影容量限制有明确分类。

长会话压缩会以新的事件序号重发历史 `tool/result`，包括本次提交前的旧轮次，可能在
首个模型请求前发生。rc.3 的 `surfaceOp: {op: "replace", startSeq, endSeq}` 表示上下文
替换；AWU 校验替换范围和 `sourceEventSeqs` 后只保留原生上下文变化，不将其当成新工具结果
或新回复展示，不重复累加用量，也不覆盖已经显示的完整输出。普通结果缺少对应调用、
错误替换标记和越界引用仍报告协议错误。诊断可在临时目录用状态副本、本地假模型、
禁用工具复现；不会向生产 Session 或真实模型提交诊断输入。

流式投影失败或用户停止时，聊天可能先返回，所属 worker 随后才完成退出。
AWU 在确认进程退出且 worker 任务结束后移除同一缓存记录；下一次发送也会核对已结束的
遗留记录。仍在运行或退出未知时继续阻止重入，旧回调不能清除新运行；不会自动重发输入。
`FS_NOT_OBSERVED` 是工具要求先读文件再编辑的正常拒绝，不代表整轮失败；模型可在当前轮
读取后重试。工具参数增量按共享 `inputDelta` 字段保存和显示。

一次聊天提交可以包含多个 DSH 原生轮次。原生 goal／inbox 在短暂空闲后继续执行时，
AWU 按匹配的 `turn/start`／`turn/end` 继续接收，不会从第一次空闲起另计 120 秒并中断。
`session/wait` 与执行共用原有 30 分钟总预算，续跑不重置预算；只有根会话和受管子任务
稳定空闲、所有已观测轮次正常完成、所属进程确认退出后才报告成功。
后续成功不抹掉先前失败，用户停止和未知退出保护仍有效；AWU 不为续跑另发用户输入。
相关回归使用假运行时及真实 rc.3 配合本地假模型、临时数据目录，不恢复或重放用户 Session。

根轮 `turn/end.reason.error` 中的受控代码和数字状态用于生成建议；供应商正文、URL、凭据、
原始 stderr 不进入新诊断。未知错误仍标记未知并保留失败阶段。启用现有调用跟踪时可在
`harness-failure` 中查看相同的安全字段，不需要扩大日志内容。失败不会自动重发、替换原生历史
或放宽工具权限。错误提示修复不表示原来失败的生产请求已恢复成功。

## 构建与兼容

运行中的 DSH 对话支持原生插话：与 Codex 一样，点击输入框 **引导当前轮**，或按 **Ctrl+Enter / Cmd+Enter**。
普通 **Enter** 仍排到下一轮；Seq 队列中的 **引导** 也使用同一原生能力。
插话可带文本附件，在后续步骤交给模型，不会中断已经开始的工具，也不会撤回已执行的操作。
图片暂不支持插话，仍使用排队发送。轮次已经结束时会保留草稿，不自动启动新轮。

固定 rc.3 的 SDK `session/prompt` 实际调用 `followup()`。AWU 桥通过 `awu/steer`
调用同一根 Agent 的 `steer()`，核对运行代次、配置、原生轮号和取消信号，并返回真实消息 ID。
仍由 SDK 唯一 reader 接收 stdout；插话等待回执不会阻断流式通知消费。
接收超时最多用 `awu/steerStatus` 只读核对一次，不重放写入。未知结果保留原输入与回执；
转换中的 Seq 项在重启后不自动恢复为待发项。旧桥未声明能力时明确拒绝，不模拟中断重启。
输入框沿用持久提交回执，只在接收及保存确认后清除匹配修订的草稿。
Codex 与 DSH 共用输入框、Seq 转换、`steerMessage` 和“当前轮引导”消息标记；
连续引导按接收顺序串行投递，投递前再次核对当前轮与停止状态。DSH 的原生接收等待
不阻断流式通知。图片支持按后端能力显示，操作流程无需因切换后端而改变。

插话回归使用真实 rc.3、本地假模型与临时数据根：运行中修正进入同一轮的下一次模型请求，
只创建一个客户端、发送一次初始 prompt，重复插话请求不重复入箱。这不等于生产模型或已安装客户端验收。

压缩与错误分类回归也使用合成图片、临时 home 和 loopback 假模型，核对真实 `compaction/end`，
以及图片历史下纯文字续问遇到 HTTP 401/429/503/400 时的原生终态、脱敏及单次请求数。
已丢失的历史错误类别不会由新版本追溯补造；已有业务会话不会由测试自动续跑。

包内保留 Python SDK、AWU bridge、许可证与版本/资源清单。`deepseek-harness.external.json` 记录固定 npm 制品来源及 26 个关键包的资源摘要；只校验关键代码和配置，不声称验证所有第三方插件或系统 Node 二进制的可信性。版本和资源校验之后仍必须通过真实协议握手。

`scripts/export_harness_external_contract.py <隔离安装目录>` 只输出待审阅契约，不安装、不启动 CLI。更新锁定版本须重新验证协议、图片、防护和生命周期，不能单独更新摘要来接受不兼容运行时。

构建准备仍可安装配套 wheel 以保持上游 SDK 的依赖元数据真实；实际冻结收集只带 SDK。PyInstaller Analysis 排除并检查本地语音及 Harness runtime，防止构建机已有安装被 hook 再次带入。两个冻结入口共用策略。

源码/Docker 默认配套模式和显式旧运行时继续验证其原始资源，不自动迁移、卸载或清理用户数据；Docker 镜像瘦身不属于本次变更。

## 验证命令

```shell
python -m unittest tests.test_harness_external_runtime tests.test_stt_packaging tests.test_harness_image_privacy
python scripts/check_backend_package.py <冻结后端>
python scripts/check_harness_package.py <冻结后端> --cli <npm入口绝对路径> --node <Node绝对路径> --report <报告路径>
```

最后一条使用独立测试 home 和本地假模型，先验证无 CLI 情况，再检查工具、允许/拒绝权限升级、恢复和停止；不传 `--cli/--node` 只检查缺失依赖。真实 npm 图片测试另用 `AWU_TEST_DSH_NPM_ROOT` 和 `AWU_TEST_DSH_NODE` 显式选择隔离安装，运行 `tests.test_harness_external_runtime_native.ExternalHarnessNativeTests`。

本轮验证结果、制品大小与平台限制见[归档验证记录](../openspec/changes/archive/2026-11-04-externalize-harness-runtime/verification.md)。这些测试不连接生产模型，不等于应用安装/发布验收。
