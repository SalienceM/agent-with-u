# Session 协作与输入工作流

本功能包含六组能力。现有 Session 无需重建；创建任务、召集角色和汇合均由明确操作触发。打开面板不会启动模型。

输入区顶部统一放置“项目任务 / 评议”和“交互 / 提醒”入口。确认策略、通道说明和 Kit 提醒偏好默认收起；新的待答问题会展开浮层，保留原草稿焦点，收起后仍有待答数量。低频输入操作放在“更多”中；窄屏的执行确认与模型设置也从这里进入。

## 召集角色评议

先在输入区的角色库维护名称、职责、Backend 和运行配置。日常评议按以下顺序使用：

1. 在想核对的回答下点击“请角色评议”，选择一个角色；“添加角色”可继续选，最多 8 个。也可输入 `#` 选角色，默认显示最近完成的回答。
2. 核对输入区的“评议对象”摘要。需要评其他回答或多条回答时点“更换回答”；这个动作不会运行模型。
3. 可在下方填写关注点，例如“这些结论有证据吗？”，也可留空。点击“开始评议”才启动所选角色；主助手不会收到这次评议问题。已有草稿附件会保留。
4. 在“评议”入口查看进度，展开后逐个比较意见，点击“引用完整意见”或“引用所选要点”带回主输入区继续修改。

“退出评议”恢复普通发送并保留问题文字。默认目标绑定当前预览的回答，主线出现新回答不会悄悄换掉它。完整可见上下文最多 20 条、64000 字符；超限时缩小范围，或在“更多评议设置”中明确生成摘要。摘要会显示遗漏。草稿附件不会随评议发送；历史工具授权、控制段、隐藏推理不会传入。

角色在同一执行节点拥有独立 Session 和产出目录；同一角色对同一来源继续自己的上下文，可显式另开上下文。每节点最多 3 个角色同时运行，同角色串行。支持受限原生运行时使用受限证据目录，否则使用可见历史的纯文本评议；目录不同本身不是操作系统沙箱。失败和未知不会被算成同意。

“评议”入口默认收起。展开后左侧选批次/角色，右侧查看同意、部分同意、不同意、未知及逐项理由。“置信”是角色自评，不是正确率；多个角色也不构成自动验收。“查看原文、证据与角色历史”中可以进入有产出的历史会话，再返回来源对话；角色历史页用于查看记录，发起评议在来源对话中完成。关闭面板不会停止任务，仅正在运行的评议提供停止动作。

运行时会显示当前阶段、耗时、证据读取进度和最近收到正文的时间。展开“实时输出”可查看模型已返回的正文，边生成边更新；“运行记录”保留文件查询与校验过程。正在生成的内容尚未完成引文与证据校验。断线时保留最后输出，重连只核对原任务；长时间没有正文会如实提示，不用计时器冒充新活动。

引文核对允许原文加粗、斜体标记造成的排版差异，仍要求实际文字、来源回答和证据编号相符。旧记录因排版差异校验失败时，可点击“重新解析已有意见”：使用当时冻结的材料和已保存输出重新核对，不调用模型，也不重新读取项目。原始工件与旧校验记录保留；真正不匹配的意见仍显示具体错误。

准备失败时会显示“评议未能开始”和具体原因；返回输入区调整角色或配置后明确开始新评议，旧记录保留。接收结果未知时使用“核对原评议”，不重新发送。已有空角色会话不需要删除或重建，更新后的运行状态管理可继续复用未运行的上下文；真正的原生退出未知仍须先核对。

用 `@ → 角色意见` 或详情中的引用按钮把完整意见/选定要点插入当前光标。正文、附件和既有草稿保留。引用冻结报告 ID、版本、要点与摘录；消息旁“查看固定意见来源”按原 ID 懒读取，删除来源后显示“源已不可访问”，不会替换为同名角色的新报告。

## 主 Session 与分支副本

在左侧 Session 列表右键主会话，选择 **新建分支副本**。需要本节点安装 Git、工作目录是仓库根目录且至少有一个提交；无仓库时显示原因，不会自动初始化。副本在同节点 AWU 数据目录的 `task-workspaces/<用户和节点范围>/<副本ID>` 下拥有独立目录、索引和 `awu/task/<副本ID>` 分支。主、子目录各自编辑和提交，Git 对象库共用。

不需要的“待确认创建”记录，选中后点击 **移除预览**。记录从列表移除，旧计划不能再用于创建；此操作不删除 Session、目录或分支，后台保留原回执。回复丢失时点击“核对副本状态”，不会自动重发。已提交创建、结果未知或已经就绪的副本不适用此操作。

表单默认继承主会话的 Backend、模型、推理档位、Skills/Prompts、约束、工具开关、普通确认及自动继续/提交/建议偏好。可以修改副本名称、初始需求及运行配置；预览会列出实际配置，主配置改变后须重新预览。副本是独立聊天线程，不复制原生线程 ID、聊天历史、队列、定时任务或单次 Kit/工作区授权；普通工具开关不代表独立操作已获批准。

**项目文件默认带入当前修改、新文件和删除状态**，使用私有索引形成副本基线；不修改主目录文件、暂存区或 HEAD。`.agents/skills`、`.claude/skills`、`.qwen/skills` 中被 Git 忽略的普通文件另行复制并核对哈希，修改副本 Skill 不会改动主目录。其他 Git 忽略文件（包括常见依赖、缓存、构建产物）不复制，需要在副本按项目说明准备环境；这不是整个磁盘目录的克隆。凭据路径、链接、子模块或超限文件会明确受阻，不能静默略过。可切换“手动选择未提交路径”，全部取消则仅使用已提交基线，项目 Skills 仍单独复制。

分支副本就是普通 Session，特殊之处是创建时派生 Git 分支与独立 worktree，以及可以合并回主 Session。聊天、模型、Skills、设置和工程视图沿用普通 Session；创建与合并记录面板不是日常工作入口。

先预览，再确认创建；接收请求不等于创建完成，成功以 Git 与 Session 落盘回执为准。从主项右键创建成功后直接进入子 Session 对话，不自动运行模型；发送消息或在记录中明确选择“启动初始需求”才运行。左侧只显示主、子两层，普通副本缩进并默认收在主项下，点击主项箭头展开；从标签页等入口切入副本会展开所属主项。子项不能再次派生。收藏普通主项或副本时整组保持在一起，搜索保留父项，旧多层记录展平显示且不改写历史。折叠或关闭父项不停止子项。

整合 Session 的父关系仍归属主项。已有可靠合并关联的整合空间默认收进 **合并历史**，不计入普通副本数。来源和目标旁显示 **待解冲突、待审阅、合并受阻、结果待核对** 等具体状态，点击直接打开对应记录；状态随合并事件更新。搜索、收藏、当前打开的处理空间和已有标签仍可达；缺少关联或父/来源丢失的旧记录保留可见恢复项。

同一发起 Session、同一双方的普通提醒以最新创建记录为准，合入与同步一起比较；旧失败和已结束记录不会一直显示为待办。运行中、应用中、结果未知和仍在输出的处理空间始终保留提示；旧节点没有创建时间时不猜测先后。这只整理显示，不取消旧操作、不删除 Session 或成果。完整记录仍可从 **分支与合并 → 合并 → 合并历史** 查看。

当前限制：只支持同节点、本地可访问的 Git 工作区；SSH Session 不支持创建。未提交路径最多 500 项、单文件 20 MiB、合计 100 MiB；额外 Skill 副本最多 10000 文件、单文件 20 MiB、合计 100 MiB。超限不截断创建。Git 忽略的 Skill 文件不通过 Git 合并自动回传；需要将应共享的 Skill 纳入版本控制后再按提交合并。自动推送偏好若从主会话继承，预览会明确显示；新分支的上游与依赖环境须按实际项目准备。旧客户端的显式选路径请求继续保持原语义，新客户端遇到不支持配置继承的旧节点会提示更新。

## 汇合成果

右键副本选择 **合并到主 Session**，来源与真实父目标固定。重新打开会恢复原选中操作，或自动接回唯一关联的未完成操作；有多条时按状态、创建时间、提交和操作 ID 选择，不自动新建。主 Session 右键统一使用 **分支与合并**，在同一面板切换 **副本 / 合并 / 分支图**；不再并列两个合并记录入口。选择 **合并** 可只读查看副本发起的关联记录，点击 **返回原合并入口** 后才进入原发起上下文。通用入口仍可发现其他同节点、同仓库 Session；也可在聊天提出“把 A 合入 B”，重名会列出候选。

旧版提示「Git 元数据超过检查范围」可能是元数据超过 20000 项，也可能是检查超过 8 秒，两种原因原先共用一条提示。Windows 下逐文件反复核对祖先目录，会让几千个正常 Git 对象在并发预览时也接近时限。现在改为逐目录核对边界、逐条目读取不跟随链接的属性，共享的 common-dir/git-dir 不重复扫描；保留两个限制并分别显示原因。链接、外部对象库和不可读元数据仍会拒绝。检查不会自动运行 Git 清理，也不会改动提交或执行推送。

2026-11-07 元数据检查修复验证：当前仓库约 5100 项，主工作区与实际 linked worktree 的并发只读仓库检查由约 8.2 秒降至约 1.3 秒；这是本机观测，不是所有设备的耗时保证。`python -m unittest tests.test_task_git_metadata tests.test_task_git tests.test_project_merges` 共 48 项通过（171.939 秒，包含测试模块导入的评议用例）。新增覆盖 5120 个模拟对象并发扫描、重叠目录去重、超时/数量分别报错、不可读条目、链接/Windows 重解析点和外部对象库拒绝。写入与合并测试仅使用临时用户根和临时仓库；实际主/子目录只做读取，没有执行用户项目合并、push、GC、安装或发布。

面板顶部根据当前状态显示下一步。若提示 **主 Session 有未提交文件**，点击 **打开主 Session 处理** 查看改动，将需要保留的改动提交到该分支；仅保存文件不会清除 Git 未提交状态。回到原面板后，点击 **重新预览合并** 获取当前内容的新计划，再审阅并确认准备；原记录和成果保留。“已提交差异：0 个文件”不表示没有未提交改动。文件列表默认收起，展开后可定位具体文件。已有候选仅因活动或未保存缓冲受阻时，处理后点状态卡右上角的刷新按钮（**核对原操作**），继续原候选。

1. **查看变化并确认准备**：展开 **查看完整准备计划与变化文件**，审阅双方提交、目录、分支、配置与文件范围，点击 **确认准备独立整合空间**。这一步从原目标提交建立独立候选，原目标保持不变。
2. **核对候选**：无冲突且处理空间已确认空闲时，面板自动核对 Git。存在冲突时点 **打开处理空间**，修复必须另行明确启动；完成并提交后，用该会话的 **返回合并记录** 回到原操作。打开空间本身不启动模型。
3. **确认应用**：核对通过后在同一面板审阅原目标分支、目录和候选提交，点击 **确认快进应用到目标**。服务端再次检查提交、配置、控制权、工作树和所有受保护写入方，然后仅快进原目标；成功显示真实最终提交。旧文件缓冲需要重新读取。

自动检查只在准备完成、修复实际结束、返回可见面板等边界执行，重复事件合并，失败/离线/退出未知不会轮询或重发写入。仍可点击状态卡右上角的刷新按钮核对原操作。主 Session 正在聊天、运行 LOOP 或存在其他写入时会阻塞应用；切换页面不会让它停止。阻塞按来源、原目标、处理空间分别列出，区分暂存区、工作树、未跟踪文件和编辑器未保存缓冲，文件入口定位到对应 Session。文件已删除或无权限时保留错误，不自动创建或覆盖。

完成后只显示一张结果卡、实际提交摘要和一个继续操作按钮。完整计划、路径、提交回执与测试证据放在 **变更与验证详情**，历史单独展开。完成后继续开发产生的新改动不会把旧成功记录重新标成“需要处理”；新的合并仍会重新检查当前工作区。

Git 核对和项目测试分开显示。没有可核对的候选提交、执行结果、时间和原日志引用时，项目测试保持 **未验证**，可进入整合记录查看；模型说“通过”不会改变它。已知失败保留醒目提示，候选提交、文件或活动变化使旧证据过期。本流程不自动运行项目测试，也不把缺少测试证据新增为永久应用门槛。

聊天入口与界面共用服务：`project_sessions` 发现真实 Session，`merge_operations` 分页查询关联记录，`merge_inspect` 只读查看计划和诊断；原发起 Session 使用 `merge_preview`、`merge_prepare`、`merge_verify`、`merge_apply`、`merge_status`、`merge_cancel`。关联查询不会授予主/整合 Session 冒用发起身份的权限。准备和应用各自显示冻结计划并独立确认；普通“跳过确认”和 Kit 委托不能替代这项确认。旧节点保留原发起 Session 的历史和手动核对，提示关联详情及自动核对不可用，不自动另建合并兜底。

提交接收不是完成。断线或超时后用状态卡右上角的刷新按钮核对原操作，不自动重复合并。应用预留落盘保存；最终回执丢失时，只有确认原 Git 进程退出并核对最终 OID/分支/工作树，才能解除预留。没有足够证据时保持未知。外部程序不受 AWU 的排他控制，Git 前后检查也不是全机文件锁。

同机同时使用本地和 Relay 连接时，窗口缓冲核对需要每条连接各自回应，不能按重复广播丢弃。核对超时会明确提示未回应的连接数量和“尚未开始 Git 合并”。已落盘为确定失败的应用记录可点 **重新核对原候选**：服务端确认没有仍在运行或未知的写入预留、来源/目标仍匹配原计划后，复用原整合目录核对候选，保留失败回执。核对不会自动应用；通过后仍须单独确认。来源/目标已变或退出未知时继续阻止恢复，不能通过改状态跳过保护。

取消尚未应用的操作保留所有成果；已经可能执行时不宣称撤回。不会自动 push、stash、硬重置或删除任务。

## 持续多分支开发与分支图

B 合入主干后，在合并面板顶部点击 **同步主干到此分支**。这会预览当前主干 → 原 B 分支，审阅并分别确认准备和应用后，点击 **返回此分支继续开发**。无需新建 B Session。没有新提交时直接快进；B 已继续提交时，在独立处理空间合并双方历史。同步与合入各自保留结果，同步失败不会撤销已经合入的主干。

下一轮开发前也可以在副本的合并面板同步主干。未提交文件、未保存缓冲、运行活动和未知退出仍需先处理；不能用同步覆盖它们。多个副本可以并行开发，但向同一主干应用时逐个核对：主干一旦变化，其他基于旧主干的候选必须重新预览。这减少遗漏与冲突积累，不能保证同时修改相同代码没有冲突，功能兼容仍要通过项目测试确认。

打开 **分支副本 → 分支图**，上方是从左到右的 Git 分支线，下方是提交记录。点击节点或提交短 ID，再点击文件即可看差异。分支卡显示相对主 Session 的领先/落后和未提交状态，点名称进入对应 Session；点 **合并与同步** 直接进入该副本与主干的操作面板，打开不提交操作。默认读取最近 80 条，必要时点击 **查看最近 200 条提交**；范围外父提交显示虚线。最多显示主干和 15 个普通副本，优先当前副本；超出数量明确提示。整合空间不混作普通分支。

查看图不会拉取远端或修改工作区。旧节点、离线和不可读分支明确报错或显示未知；合并后点击 **刷新分支图** 获取新位置。页面不轮询，不承诺外部 Git 变化实时刷新。这一流程不创建远端 PR，也不自动 push。

## 输入编辑与影子建议

展开输入编辑器，在左侧切换主消息和文本块，右侧编辑、查找、重命名、排序与撤销。紧凑和展开共用草稿。长文本收纳可撤销，恢复到正文后不会再次自动收纳。

中文组合输入优先；展开编辑器 Enter 换行、Ctrl/Command+Enter 提交。`#`、`@` 和 Slash 菜单优先于影子建议，普通 Tab 保留焦点导航。未知发送只查回执，不重发；迟到的旧回执不会清掉新草稿。

“影子建议”位于 Kit 同排，按 Session 默认关闭。开启后，仅在新成功回答完成时生成一条短建议；历史加载、失败和重复完成不补调用。最多 8K 字材料、300 字建议，有独立调用用量和频率限制。开始编辑、有附件/菜单/待回答问题时不展示；Tab 只填入草稿，Escape 隐藏，不会自动发送或携带 Kit 委托。

点击旁边的“建议模型”可单独选择本节点的 Backend、模型和支持的推理档位，适合使用轻量模型。全部留空时跟随主会话；明确指定模型或 Backend 后，未填写的推理档位使用该 Backend 默认值，不沿用主会话的高档位。保存只影响后续建议，主对话模型不变，也不会当场生成建议。模型需要所选服务实际支持；Backend 被删除、停用或不可用时显示原因，不切换其他模型重试。

建议默认最长等待 30 秒，包含程序启动、连接及生成。慢网络可在同一设置中改为 60 或 120 秒。超时提示会给出实际上限，并指向轻量模型和等待设置；不会自动重发生成。保存结果未知时保留编辑内容，重新打开会话核对，不自动重放设置。旧执行节点仍可开关建议，独立模型设置需要更新节点后使用。

## Kit 委托与原生提问

Kit 代确认仍只来自本次独立开关。发送边界冻结 opt-in，消息和运行记录显示接收、绑定、使用或过期状态；开关复位不代表已接收委托被撤销。可以记住提醒偏好，不能记住授权。队列、语音、角色、建议、刷新和跨窗口草稿不会继承 opt-in。详情见 [Kit 委托反馈](kit-delegation-feedback.md)。

原生问题以专用卡片显示，多题、选项和自由文本按对应协议回传同一个请求，不发送成新的聊天消息。后台 Session 有待答提示。跳过策略只使用真实协议支持的 skip/default；推荐选项不会自动选中，必要问题仍待答并显示原因。重连后只查原请求，不重发未知答案。逐 Backend 支持范围和证据见 [原生提问兼容记录](native-user-interactions.md)。
