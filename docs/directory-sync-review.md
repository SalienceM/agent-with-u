# 逐文件同步审阅

在文件面板打开“更多文件工具 → 本机副本与同步”，绑定副本后点“比对”，再点“审阅差异 N”。比对本身不打开审阅、不传输文件。比对后也可从文件或目录菜单进入审阅；目录按路径段筛选，`src` 不包含 `src2`。

已勾选“仅不同”时，文件树、差异计数和审阅均包含仅本机、仅执行端及两端内容不同的文件（包括冲突）。单端的空文件也属于差异；两端一致的文件不显示。仍保留“仅本机／仅执行端”来源标识，未完成比对不能把未知的一端当作空目录。普通预览中，已知存在差异的文件会显示“对比”按钮，直接定位到该文件；未比对或已知一致时不显示，不自动扫描或传输。

## 先限定扫描范围

在“本机副本与同步 → 扫描范围”中编辑两栏，点“保存扫描规则”，再点“比对”：

- **只扫描这些前缀**：每行一个根目录相对路径前缀。例如 `src/`、`frontend/src/` 只扫描对应目录；`config` 会匹配 `config.json`、`config-old/` 等前缀。目录边界需要末尾 `/`，留空表示全部。
- **排除规则**：类似 gitignore 的有限语法。`#` 开头为注释；`*`、`?` 不跨 `/`，独立路径段 `**` 可匹配零至多层；`cache/` 排除任意层同名目录，`/cache/` 仅根目录；带路径的规则相对工作区根目录。后面的 `!规则` 可以重新纳入，但必须先重新纳入被排除的父目录。
- 规则区分大小写；支持 `/` 和 Windows `\` 路径分隔符，不支持字符组 `[]`、花括号扩展、反斜杠转义或越界路径。每栏最多 128 行、16 Ki 字符，单条最多 512 字符。保存时规范化规则并去掉注释和空行。

例如前缀填 `src/`，排除填 `**/cache/` 和 `*.log`。本机和执行端都在遍历子目录、读取文件和计算哈希之前应用规则。浏览器离线空间按前缀查询索引键，不读取范围外的 Blob。不是下载完整清单后再隐藏结果。

规则仅保存在本设备，按账户、节点、Session、工作目录和视图隔离，不写项目 `.gitignore`。修改后旧比对、差异审阅和迟到结果失效；保存本身不扫描、不传输，下一次显式比对或刷新使用新范围。已有规则也用于副本恢复时的元数据扫描。

“仅不同”、差异计数和审阅只处理已扫描范围；范围外文件不表示缺失或一致。当前比对下的目录推拉也只使用该清单，并显示待传文件数；普通执行端浏览仍可查看范围外文件。规则不会触发删除。原同步忽略规则及 `.git` 的独立授权仍然生效，`!` 不能解除这些保护。旧执行端或桌面端不支持范围协议时明确失败，不回退全量扫描；需要更新两端应用。

## 看差异，决定方向

- 左边是本机副本，右边是执行端；不是“旧版/新版”。顶部保留真实来源与相对路径。
- 文件列表支持普通文本或“正则 .*”筛选、只看未处理、每页 100 项。正则匹配相对路径，忽略大小写，例如 `^src/.*\.(ts|tsx)$`；不带 `/…/` 分隔符。无效表达式明确报错，最多 512 字符，隔离 worker 超过 1.5 秒终止，不冻结主界面。上一/下一文件不表示跳过；显式跳过保留标记，仍可返回。
- 面板采用主题的不透明底色，不受全局背景透明度影响。
- 正文提供行号、增删颜色、差异块导航、同步滚动、未改段折叠和窗口化渲染。窄屏切换“本机副本/执行端”。
- 推送：本机文件复制到执行端。拉取：执行端文件复制到本机。确认框列出具体路径、来源、目标及创建/覆盖影响。
- 只传当前文件的完整原字节，保留编码、BOM 和换行。不编辑正文、不逐行合并、不做三方合并、不隐含删除或 Git 操作。
- 单端不存在不等于空文件；只允许把存在端复制过去，不会把“不存在”同步成删除。文件/目录类型冲突不可推拉。

审阅关闭后焦点返回触发入口；已提交传输仍归属于文件传输反馈，并不因关闭面板而取消。

## 切换 Session 后继续查看

当前窗口按账户、执行节点、Session、工作目录和 Chat/Engine 来源分别保留目录展开、选中、滚动、文件搜索、仅不同筛选和上次比对。重新打开审阅还原筛选、正则开关、当前文件及跳过标记；从具体文件入口进入则优先定位该文件。不会重新打开推拉确认框、重发操作、继承 `.git` 高风险同意，也不会为恢复状态重新全量扫描或比对。

目录的展开／收起状态另存于本设备的 localStorage，刷新或重启后继续保留，按上述身份隔离（最多 32 个视图、每个视图 512 个展开路径、合计 256 Ki 字符）。恢复时只根据当前目录清单逐层读取展开分支，不恢复旧文件内容或自动比对。收起父目录不会清除子目录原来的展开选择；“全部折叠”则清空该视图的展开选择。浏览器存储被禁用、清理或超过上限时，可能无法跨刷新恢复。

其余浏览／比对状态仍是有上限的窗口内缓存（最多 24 个视图、合计 150,000 个加权元数据项），关闭／刷新应用、切换账户或缓存淘汰后需重新读取。正文不写入这份缓存；Git 状态仍在重新进入时轻量核对。上次比对带时间且不是实时同步证明，打开审阅重新读取当前文件，推拉前仍完整核验两端版本。手动刷新会使旧比对失效，需再次比对，但不会重置目录的展开／收起选择。

## 保护与限制

每端最多 2 MiB、20,000 行、单行 64 Ki 字符。支持严格 UTF-8（可有 BOM）和带 BOM 的 UTF-16 LE/BE。编码、BOM、EOL、末尾换行差异单独标出。二进制、专用文档、解码失败、超限或计算超预算只能查看限制/跳过，不能用不完整内容提交。

差异计算在 worker 内执行，默认 2 秒计算截止、200 万操作/追踪单元预算；客户端另有 2.5 秒等待保护。超过 500 行不会降级成整文件伪删除/新增。

提交前复核两端完整哈希、对象/修订及存在性，目标在提交前再核验。当前窗口已知的脏文档或未确认保存会阻止传输，不替用户保存草稿。旧决定过期时要“重新审阅”，不会自动刷新后沿用旧确认。

这些检查不是跨机器事务，也不能封锁所有外部程序。外部程序仍可能在最终核验与替换之间抢先修改；提交后校验失败不会自动回滚覆盖后来修改。成功后再复核两端，源已产生新版时显示“传输完成，但需重新审阅”，不推进虚假共同基线。

旧 `localId::workingDir` 同步基线保留不动，但不作为新审阅的可信证据。新基线隔离用户、Session、节点、执行端实例/工作区修订、目录、副本真实绑定及 Git 策略，只按已核验文件增量更新。没有基线时不按修改时间自动选择方向。基线只保存摘要，不保存正文或历史版本。

## 不同本机存储

| 来源 | 替换已有文件 | 缺失文件创建 |
| --- | --- | --- |
| Tauri Windows/Linux 原生核心 | 版本复核、同目录原子替换；保留原生属性 | 不覆盖同名文件的创建；只创建必要父目录 |
| Chromium 设备目录 | 实际 handle、Web Lock、提交前复核与 writer close | 禁用：浏览器 API 无法提供这里要求的无覆盖创建保证 |
| 浏览器托管离线空间 | IndexedDB 事务内 revision CAS | 同一事务内检查存在性/路径冲突并写 commitId |

Linux 文件系统若不提供可靠对象代次会拒绝，不退回仅大小/时间判断；其他原生平台不支持新审阅。浏览器权限被撤回时需手动处理，不自动申请授权或切换到另一份副本。旧节点或旧本机协议不能提供所需能力时显示限制，原文件树和原显式传输保留；新按钮绝不回退无版本覆盖写。

## 结果未知怎么办

“已接收”“传输中”不代表成功。断线或等待超时后，最多自动核对一次原 requestId；之后用文件传输反馈里的“核对结果”，只读查询，不重发写请求。未知结果继续占用工作区传输锁；不能靠关闭、取消等待或换新 ID 清掉保护。

执行端和原生回执属于当前进程实例；重启后找不到原回执仍是未知，不凭内容碰巧相同猜测原请求成功。浏览器托管空间可用事务 commitId 核对；设备目录 close 异常若没有提交证明仍保持未知。回执最多保留 32 个活动/未确认项和最近 256 个终态项，不提供无限历史；不应重放已淘汰的旧请求。
