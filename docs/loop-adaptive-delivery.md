# LOOP 自适应交付与停滞诊断

## 解决的问题

旧默认策略把每轮限制为“唯一最小焦点”，上轮评审又不断把局部缺口传回规划。
对已有 OpenSpec 任务表的实现工作，这容易形成审计、补证据、再次审计的串行队列，
即使还有大量独立实现任务可以推进。独立模型上下文也不能继承普通对话中全部工作流决策，
更不等于文件或用户数据隔离。

## 新行为

- **工作流交接**：普通 Session 转为 LOOP 时保留最近 12 条可见消息的有界、脱敏摘录及绑定 Skill ID。
  旧 LOOP 在下一次 prepare 补建交接。当前 Session 约束和 Skill 提示随调用传入；历史文本只是定位线索，
  不是新指令、完成证据或旧授权的复用。不会复制附件、隐藏思考、工具结果或整份历史。
- **按依赖选择批次**：策略支持自动识别、任务交付、探索验证。交付模式以真实任务来源和稳定编号为准，
  每轮仍最多编排 4 步，但一步可以完成多个相关就绪任务，不固定为审计→实现→复核→文档。
  探索模式可以推进可验证的假设，不强迫所有工作套用 OpenSpec。
- **阻塞有范围**：评审台账区分局部、全局、安全和人工输入阻塞，并记录影响任务及解除条件。
  局部阻塞不自动阻止独立任务；安全事故未遏制或全局阻塞则暂停 Auto。历史数据无法恢复的损失
  与仍在持续的风险分开记录，不能静默豁免，也不能无限重复相同恢复尝试。
- **证据复用**：顺序步骤沿用本轮上下文，新上下文、并发后的步骤和重试补传已有步骤证据。
  分析获得有界原始输出首尾，保留末尾失败信息；移除额外的模型汇总调用。
  历史证据只有版本、环境和影响范围仍适用才能复用，否则定向复查。
- **识别空转**：依据稳定任务状态和整体 verify 状态与证据比较推进，不把分数上涨、改写描述或工具活动当作进展。
  无推进时要求换路规划，并重新检查方向；默认连续 3 次无推进暂停 Auto，可设置为 2–8 次。
  暂停原因、可继续任务和范围丢失警告在面板及流程视图显示。用户补充条件后可显式再次运行。
- **收口验收**：分数不能单独宣告完成。新记录还需完整稳定范围、任务已验证或明确人工依据、
  整体 verify 通过且有证据、无剩余阻塞和未处理 Addon。任务台账按需加载，可展开查看依赖与证据。
  风险/预算导致的退出仍不是成功交付。

## 安全与限制

自动 Codex 迭代为规划和只读步骤请求原生 `read-only`，写步骤与分析请求 `workspace-write`；
不支持时按失败处理，不自动降级为全权限。普通聊天权限不受此项修改影响。
这项实现有协议回归测试，但实际操作系统隔离依赖安装的 Codex 版本与平台能力；
其他 Backend 目前只获得相同的执行约束，不应宣称具备相同的原生隔离。

每次调用的角色说明与实际请求访问模式使用同一来源。规划阶段只读不代表整个 Session 无写权限：
规划器可以安排已获授权的 write/sequential 步骤，由执行器后续单独请求工作区写入；
不能仅凭规划阶段只读或一次真实用户文件读取失败而全局暂停，也不能因此绕过实际拒绝。
旧记录中的“下一唯一焦点”应结合更新的明确用户处置范围重新判断，而不是永久锁定队头。
历史损失不会自动被清除、豁免或视作已恢复，真实持续风险及必要授权仍保留暂停门槛。

可能写入用户数据的测试必须使用独立测试用户目录并核实实际写入位置。
项目 Git 快照不能保护工作区之外的真实用户目录。模型返回明确 `loopControl.pause` 时，
系统在模型调用返回后停止后续步骤/阶段；这不是调用执行中的即时写操作拦截器。
已经并发启动的调用不因另一调用返回暂停信号而自动撤销。

Backend 在部分文本后报错不会被记为成功；失败后的潜在依赖步骤停止盲目执行并进入评审。
自动收口或评分下降不再触发恢复所谓“最佳”Git 快照，避免覆盖后续成果；
用户显式丢弃/恢复的独立流程保留。

台账来自模型评审和引用的证据，不是系统自动验证的哈希证明。
长任务若始终没有可记录的状态推进也会触发保守暂停，应在真实任务边界拆分或调整耐心值，
不能通过虚假勾选来规避。报告上限为 100 项任务、50 项阻塞；超过或未完整清点不能自动收口。

## 兼容与生效

- 旧记录不被倒推为“已停滞”；新报告的首次有效清点建立比较基线。
- 已知旧默认策略迁移到批次策略；用户自定义策略和默认策略之后追加的要求保留。
- 旧客户端保存策略时不抹掉新增模式和耐心值；进度暂停随 LOOP 状态持久化。
- 更新并重启 AWU 后端后，新 prepare 开始使用上述逻辑。修改代码本身不会改变已运行进程。
- 本次实现不重启服务、不干预正在执行的其他 Session，也不恢复历史已损坏数据。
