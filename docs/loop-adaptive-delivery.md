# LOOP 自适应交付与停滞诊断

## 解决的问题

旧默认策略把每轮限制为“唯一最小焦点”，上轮评审又不断把局部缺口传回规划。
对已有 OpenSpec 任务表的实现工作，这容易形成审计、补证据、再次审计的串行队列，
即使还有大量独立实现任务可以推进。独立模型上下文也不能继承普通对话中全部工作流决策，
更不等于文件或用户数据隔离。

## 新行为

- **工作流交接**：普通 Session 转为 LOOP 时保留最近 12 条可见消息的有界、脱敏摘录及绑定 Skill ID。
  旧 LOOP 在下一次 prepare 补建交接。当前 Session 约束和 Skill 提示随调用传入；历史文本只是定位线索，
  不是新指令、完成证据或旧授权的复用。不会复制附件、隐藏思考、工具结果或整份历史。
- **按依赖选择批次（通用 LOOP）**：策略支持自动识别、任务交付、探索验证。交付模式以真实任务来源和稳定编号为准，
  每轮仍最多编排 4 步，但一步可以完成多个相关就绪任务，不固定为审计→实现→复核→文档。
  探索模式可以推进可验证的假设，不强迫所有工作套用 OpenSpec。
- **OpenSpec 原生续跑**：已经明确 change 时直接跟踪原 tasks，剩余自动任务继续 apply，完成后 verify；
  必修问题进入修复再 verify，纯建议不无限优化。此路径不再要求模型重复拆解 taskPlan/交付台账。
- **阻塞有范围**：评审台账区分局部、全局、安全和人工输入阻塞，并记录影响任务及解除条件。
  局部阻塞不自动阻止独立任务；安全事故未遏制或全局阻塞则暂停 Auto。历史数据无法恢复的损失
  与仍在持续的风险分开记录，不能静默豁免，也不能无限重复相同恢复尝试。
- **证据复用**：顺序步骤沿用本轮上下文，新上下文、并发后的步骤和重试补传已有步骤证据。
  分析获得有界原始输出首尾，保留末尾失败信息；移除额外的模型汇总调用。
  历史证据只有版本、环境和影响范围仍适用才能复用，否则定向复查。
- **识别空转**：依据稳定任务状态和整体 verify 状态与证据比较推进，不把分数上涨、改写描述或工具活动当作进展。
  无推进时要求换路规划，并重新检查方向；默认连续 3 次无推进暂停 Auto，可设置为 2–8 次。
  暂停原因和范围问题汇入工作台的“需要处理”，就绪任务与依据在详情中查阅。用户补充条件后可显式再次运行。
- **收口验收**：分数不能单独宣告完成。新记录还需完整稳定范围、任务已验证或明确人工依据、
  整体 verify 通过且有证据、无剩余阻塞和未处理 Addon。任务台账按需加载，可展开查看依赖与证据。
  风险/预算导致的退出仍不是成功交付。

## LOOP 工作台入口（2026-10）

全局“俺寻思”现可按提问只读查询当前 Session 的项目目录、文本及 OpenSpec 原任务进度，
不要求把文件正文预先放入界面“快照”，也不要求绑定来源。查询不运行 apply/verify、不修改任务或 Auto；
每次提问重新采样，运行报告、文件勾选和验收结论分别表达。读取、回答、失败及取消有明确状态，
来源详情可展开核对。范围与限制见 [俺寻思只读查询](thoughts-readonly-inspection.md)。

一级“面板 / 流程”与三阶段轨道已恢复。两个视图共用状态、草稿、控制权反馈和按修订读取的
详情缓存，不会因切换而重新执行。视图选择在当前浏览器窗口按用户/节点/Session 保存。
面板直接显示轮次卡、分数环、最近/最佳评分、风险与预算；流程泳道占主工作区，阶段与步骤分别可选。
评分与预算来自当前轮权威摘要，历史卡标明轮次；无评分显示“未评审”，99 分也不代替正式任务验收。

| 入口 | 内容 |
| --- | --- |
| 面板 / 流程 | 轮次卡 / 完整泳道、阶段/步骤原文、耗时、已完成步骤产出、返回最新 Loop |
| 成果与证据 | 正式任务勾选、已实现待验/已验证/待人工/受阻、子里程碑、评审和调用诊断 |
| 目标与补充 | 目标编辑与模型微调、版本演变、原始想法和图片、已纳入补充历史 |
| 来源：change / 未绑定 | 紧凑核对状态；按需查看、发现/更换、确认冲突；主动点“解除绑定…”才填写处置依据 |
| 运行诊断 | 已知阻塞、检查覆盖、生效依赖及其依据；技术细节折叠；额外工作流选择不是必填项 |
| 策略与心智 | 原策略编辑器、Backend 与模型分档，保留自定义文本 |
| 人工接管 | 直接入口，仍经过共享控制权门槛和回执 |
| 更多操作 | 危险的丢弃记录及独立的可选磁盘恢复确认 |

Auto 与停止当前轮不是一回事。“停止后续自动执行”只关闭 Auto；“停止本轮并查看结果”
调用原有停止/收口流程并保留成果，不发送丢弃/文件恢复请求。断点使用“恢复 Loop #序号”；
结果页使用“开启新一轮”，旁边明确沿用的 Auto 设置。结果页可能是预算用尽、止损或
部分成果，不等于验收完成。人工总览只读，返回人工工作区后继续；交还仍不启动模型。

需要处理区按控制权/退出确认、环境、来源、调度/停滞、任务阻塞排序，显示其余问题数量。
只有同身份/修订及 `basisRefs` 证明同因才归并，不按相同文案猜故障；关联依据仍可查阅，
局部阻塞不被前端提升为全局停止。点击问题直接打开该检查、来源差异或受影响任务；旧目标修订改变后
禁止将旧操作应用到新对象。处理后用稳定的运行/恢复按钮显式请求，
执行端门槛不变；检查/绑定/确认范围本身都不会恢复 Auto 或执行。

`iterationRequest` v1 表示“可请求”，不是授权或工具已就绪。它携带 Session、轮次、记录及控制/来源/环境修订，
复用提交入口的无 I/O 判断；真正执行仍复验来源、环境、授权、Auto/预算等门槛。无阻塞的 unsupported/stale
只在诊断中说明，不按警告排序禁用恢复。真实故障、未确认退出和旧暂停不被移除；允许显式请求重新核验的
路径保持不变。旧端沿用原提交核验并保留已知硬门槛，离线不回退其他节点。

宽工作区按需打开最大 580px 辅助浮层，窄工作区使用全宽操作面；只有一个标题，无“详情分类”。
Escape 或“返回”会把焦点还给入口，Tab 在操作面内循环。阶段输出留在主视图，不挤进配置面。
目标、策略与补充草稿不因打开/关闭详情而丢失。新增补充可带图片，只纳入下一次适用规划，
不会修改已经开始的当前调用。详情缓存按用户/执行节点/Session 隔离，仅可见选中记录的
有效修订变化触发合并读取；流式文本、相同推送、隐藏详情和空闲时间不会新增历史/来源/环境轮询。
摘要新增每项最多 240 字符的 `analysisPreview`；旧记录无字段时不补造结论，完整原文仍按需读取。

上述视觉恢复不迁移或删除 Session/阶段文件；后续原生 OpenSpec 驱动改动见下节。
验收命令、截图及真实平台限制见
[`restore-loop-visual-experience` 实施记录](../openspec/changes/restore-loop-visual-experience/implementation.md)。

## 安全与限制（执行层）

自动 Codex 迭代为规划和只读步骤请求原生 `read-only`，写步骤与旧协议分析请求 `workspace-write`；
具有冻结任务协议的新计划，其验收及任务阻塞复核均独立请求 `read-only`，测试留在受前置保护的执行步。
不支持时按失败处理，不自动降级为全权限。普通聊天权限不受此项修改影响。
这项实现有协议回归测试，但实际操作系统隔离依赖安装的 Codex 版本与平台能力；
其他 Backend 目前只获得相同的执行约束，不应宣称具备相同的原生隔离。

每次调用的角色说明与实际请求访问模式使用同一来源。规划阶段只读不代表整个 Session 无写权限：
规划器可以安排已获授权的 write/sequential 步骤，由执行器后续单独请求工作区写入；
不能仅凭规划阶段只读或一次真实用户文件读取失败而全局暂停，也不能因此绕过实际拒绝。
旧记录中的“下一唯一焦点”应结合更新的明确用户处置范围重新判断，而不是永久锁定队头。
历史损失不会自动被清除、豁免或视作已恢复，真实持续风险及必要授权仍保留暂停门槛。

可能写入用户数据的测试必须使用独立测试用户目录并核实实际写入位置。
项目 Git 快照不能保护工作区之外的真实用户目录。模型返回明确 `loopControl.pause` 时，
系统在模型调用返回后停止后续步骤/阶段；这不是调用执行中的即时写操作拦截器。
已经并发启动的调用不因另一调用返回暂停信号而自动撤销。

Backend 在部分文本后报错不会被记为成功；失败后的潜在依赖步骤停止盲目执行并进入评审。
自动收口或评分下降不再触发恢复所谓“最佳”Git 快照，避免覆盖后续成果；
用户显式丢弃/恢复的独立流程保留。

台账来自模型评审和引用的证据，不是系统自动验证的哈希证明。
长任务若始终没有可记录的状态推进也会触发保守暂停，应在真实任务边界拆分或调整耐心值，
不能通过虚假勾选来规避。报告上限为 100 项任务、50 项阻塞；超过或未完整清点不能自动收口。

## 兼容与生效

- 旧记录不被倒推为“已停滞”；新报告的首次有效清点建立比较基线。
- 已知旧默认策略迁移到批次策略；用户自定义策略和默认策略之后追加的要求保留。
- 旧客户端保存策略时不抹掉新增模式和耐心值；进度暂停随 LOOP 状态持久化。
- 更新并重启 AWU 后端后，新 prepare 开始使用上述逻辑。修改代码本身不会改变已运行进程。
- 本次实现不重启服务、不干预正在执行的其他 Session，也不恢复历史已损坏数据。

## 调用结束后的决定

LOOP 分别保存调用结果、任务验收和调度决定。`normal` 只表示一次 Backend 调用正常结束；
非空总结、一次测试或一次提交都不代表完整目标已经验收。步骤的验收无法可靠映射时显示“尚未核实”，
累计台账可显示部分成果。阶段、恢复和轮次边界的决定及引用保存在详情中，紧凑推送只传最新摘要。

决定依次服从用户停止/控制权、旧调用退出确认、安全/授权/全局阻塞、绑定来源核对、完整验收，
再考虑预算/风险/真实连续失败、Auto 和无进展。完整验收恰在预算最后一次满足仍可如实完成；
预算耗尽而验收不足只显示停止和未完成。独立评审开启时仍需至少两次有效评审及原有收敛门槛。
明确人工项保留正式分母和原文依据，显示“自动范围完成，待人工核验”。

等待用户、无进展、来源不可核对采用 `terminalKind=paused`，不写成 Backend 错误。
明确恢复后从新的 prepare 复核已有成果；真正中断的未终结记录仍按原断点恢复。
旧调用退出未确认时禁止新增写调用。重复结束事件按决定身份和原任务注册表去重；打开面板、
重连或重启不会重放历史继续决定。取消不承诺撤销工具已经产生的副作用。

## 任务协议纠正与显式修复

新计划在接受前同时校验步骤、完整任务台账、依赖和隔离前置。正式台账必须完整，
本次步骤仍可只执行其中一部分。仅有可解析的步骤不再显示规划成功。

- 当前输出缺字段、漏任务或映射不一致：在同一次迭代内只读纠正，初次规划和纠正合计最多 3 次，
  prepare/execute 共用持久化计数。正在纠正时不提前关闭 Auto；耗尽后暂停，不添加写入兜底或失败轮次。
- 来源真实变化、身份变化、授权暂停、实际环境故障和退出未确认：保留各自的处理入口，不能用重写 JSON 解除。
- 历史无效任务协议：在“需要处理”中查看具体字段、任务和原始依据，明确点击“修复任务映射”。
  一个请求最多 2 次只读候选纠正；原文缺失或影响范围无法核对时直接说明缺失，不浪费纠正调用。
  旧原文与无效聚合保留在懒加载修复审计中，全部真实未解除阻塞继续受保护。
- 修复成功显示“映射已修复，尚未运行”。它不表示验收通过、不重放已有步骤、不启用 Auto；
  用户另行点击原运行入口，仍须核对来源、控制权、旧调用、授权、风险和预算。

决定和暂停守卫仅在当前 `causeRef` 与修订一致时合并为一个问题；同文异因和历史数据不猜测合并。
查看详情不触发修复。请求包含问题/控制修订和 requestId；重复点击不重复提交，
超时仅合并一次只读回执查询，无轮询、写重试或节点回退。未知调用/落盘结果保持活动保护，
不会因浏览器超时或后端重启而自动解锁；可手动查询原回执，不能用普通运行绕过。

验证使用 fake Backend、临时阶段文件及浏览器夹具。未核实生产 Loop #11 的具体根因，
也未访问真实用户存档、启动外部 Godot 或自动恢复生产 Session。

## 任务级阻塞与单次只读复核

执行步可在同一顶层 JSON 返回 `taskBlockers`，不再只能用整轮暂停表达局部失败。
调用正常返回与任务验收分开保存：例如基线读取失败、Godot 未启动、没有截图，
可记录 `callResult=normal`、`taskResult=blocked`，不能显示为测试通过。

```json
{
  "taskBlockers": {
    "version": 1,
    "items": [{
      "id": "baseline-unavailable",
      "affectedTaskIds": ["T"],
      "reasonCode": "check_unavailable",
      "reason": "必要基线读取被拒；应用未启动，用例和截图均为零。未确定沙箱或 ACL 根因。",
      "evidenceRefs": ["step1:exit23"],
      "resolution": "取得原验收要求下的合法基线及新核实证据；不绕过拒绝。"
    }]
  }
}
```

这不是权限申请或授权。身份、工作区、执行节点、Backend/运行参数、来源修订与计划指纹由执行端绑定，
模型不能提供可信身份。最多 50 个阻塞、100 个稳定任务；原因/解除条件各 1200 字，证据最多 16 条、
每条 240 字。未知版本、超限、越界、循环依赖和旧身份都不能成为放行依据。

规划同时提供 `taskPlan={version:1,tasks:[{id,title,dependsOn,status,evidence}],preconditions:[]}`，
每步提供 `taskIds`、`dependsOn`、`preconditionIds`、`testWritesUserData`。正式来源按当前快照核对编号；
未绑定时明确标为模型冻结台账。受阻任务的编号、标题和依赖跨轮保持稳定，不能通过换名清除。
旧计划没有映射仍兼容旧执行行为，但发生局部阻塞后不能靠步骤顺序猜出独立写任务。

执行边界的规则：

1. `loopControl.pause=true`、停止/接管、原生安全/授权门槛先判定，旧的未分类 pause 仍是硬暂停。
2. 局部阻塞停止启动本轮所有剩余步骤，不沿原计划直接跳到“看起来独立”的下一步。
   已启动的只读并发批次先收集结果并确认退出，不承诺撤销其影响。
3. 复用本轮 analysis，至多一次独立只读复核；不运行应用、构建、测试，不重试被拒资源，
   不改权限或换 Backend。沿用超时/取消/进程退出确认，文本预算 262144 字符；超限不采纳截断结论。
4. 复核完整台账和传递依赖：T 受阻、D 依赖 T、U 有独立就绪证据时，只能把 U 交给既有调度器，
   在 Auto、预算、风险、来源及环境门槛允许后，下一轮重新 prepare。T/D 保持未验收。
5. 范围未知、无独立任务或复核失败就等待，不递归追加复核。普通 analysis 首次报告新阻塞时，
   保留阻塞并暂停；本轮评审额度已经用过，不再追加第二次模型调用。

未解决阻塞持久进入后续规划、步骤和评审。重复结果、遗漏、新轮次或重启不解除保护，
也不计为进展。解除仅接受独立复核引用的适用新证据：工作区内有界文件 SHA256 与新增时间核对，
并保留原阻塞及解除理由；不接受模型 `waived`。用户改变验收范围需走显式范围处置/来源核对，
一句“继续”不是豁免。模型评审和文件修订校验仍不证明内容正确，更不能清除原生环境硬门槛。

复核在调用前持久标为 running；重启后的 running/unknown 不自动重放。调用结束、异常或文件核对后，
再次检查当前身份和控制修订；迟到结果只留原记录，不改新决定或 Auto。只读阻塞复核不产生完成度评分，
界面不显示虚构的 0 分，也不把它计为额外一次独立收口验收。

### 隔离准备和测试必须分开

已识别的用户数据写测试需在计划中声明前置：稳定编号、影响任务、写入类型、独立数据根、
应用真实路径核对方法、配置修订、证据引用及适用的 `baselineBasis`。
独立准备调用可在原授权写步骤中创建测试配置，但不能启动尚未核实隔离的应用。
准备返回 `isolationEvidence` 后，消费前置的后续测试调用才可通过边界核对。

核对检查工作区子目录真实解析路径、链接/别名逃逸、配置与证据文件 SHA256、准备步顺序、
计划/身份/访问策略一致性。仅有变量、目录名或 `safe=true` 不算证据；准备与测试同次调用无效。
核对记录为“有限模型观察 + 文件修订检查”，不是任意第三方应用的 OS 隔离证明，
也无法拦截单次模型调用内部所有工具行为。原生策略始终保留。

保护用户数据不隐含扫描真实存档。只有用户、项目规则或正式规格明确要求真实基线时，
才保留其依据和相应验收；必要基线不可读就继续受阻，不能用隔离测试通过来代替。
无该要求且独立隔离证据适用时，不额外读取真实目录。禁止宿主代读、换节点/通道、
复制被拒资源、改 ACL 或扩权限来重试同一拒绝操作。

### 展示、升级与验证边界

工作台和详情复用既有决定摘要，展开详情才加载任务、依赖、解除条件和证据级别；
不新增常驻大横幅、不轮询、不因打开详情而启动执行。
已暂停的旧 Session 必须由用户显式恢复并重新 prepare，新代码不会自动解除旧 pause。
部署前停止受影响 Auto，保留阶段文件；旧版本不理解任务阻塞协议，不应降级后直接恢复此类记录。

本仓库通过 fake Backend、临时文件和隔离浏览器夹具验证同类失败；
**未读取真实 Godot 存档、未启动 Godot 矩阵、未恢复示例 Session，不能把夹具通过当作外部项目验收。**
实施结果和场景映射见
[`fix-loop-scoped-blocker-recovery` 验证记录](../openspec/changes/archive/2026-10-10-fix-loop-scoped-blocker-recovery/verification.md)。

## OpenSpec 原生任务驱动

先在普通聊天完成 init、explore、propose，然后把目标设置为“完成 OpenSpec <change> 的任务”。
点击运行或开启 Auto 后，LOOP 从真实 CLI 候选采用目标指定的 change；目标要求 OpenSpec 且只有一个
候选时也可直接采用，不要求重复确认来源。多个候选无法消歧、来源消失或切换环境时才需要选择/处理。
手动“发现/更换来源”仍可使用；查看和绑定本身不启动模型。未要求 OpenSpec 的通用 LOOP 不主动扫描项目。

每次按原任务进度选阶段：剩余自动任务→apply；自动任务勾完→只读 verify；verify 有必修问题→修复→再 verify。
critical 必修，warning 默认需修复，明确纯建议不阻止收口。模型正常结束只代表本次调用结束，LOOP
重新读取真实文件，在 Auto 和预算允许时继续原任务。没有重复的 1–4 步 JSON、taskPlan 或逐项第二台账。
旧协议格式失败在用户下一次明确执行时可转入此路径；旧审计保留，真实阻塞、修复在途和未知退出不解除。

可在目标/补充/策略明确写“跳过人工验收”。独立人工项保持未勾选，界面说明人工未验收；混合实现与人工
工作的任务不会整体排除。“不要跳过人工验收”以及后续恢复指令不视作排除。全部自动工作且当前 verify
无必修问题才结束；无可用结论、调用失败、验证期间范围变化都不能算通过。verify 仍是模型评审，不是机器证明。
预算、风险、重复无进展、停止/权限和未处理 Addon 继续生效，不自动归档、发布或提高权限。

- 仅支持该 Session 执行节点的工作区内项目。经 Relay 访问执行节点可用；SSH 文件系统、父项目、
  外部/声明式 store、越界符号链接不支持。不回退别的节点或 Backend，也不安装 CLI 或初始化项目。
- CLI 优先使用工作区 `node_modules/.bin`，其次是实际 execute Backend 的 PATH。
  工作区、Backend 环境变化需核对；不会借用规划/评审 Backend 的 CLI。
  同一 change 的范围演进自动记录差异并刷新，删除/改义不计完成信用；不静默改绑，不清除未解决问题。
  显式来源操作重新查询 CLI 版本，不复用失败操作的旧版本缓存；同边界的在途查询仍合并。
- 只执行固定的版本、list、status、instructions apply 查询，不执行任务正文或返回指令。
  Windows 使用受限的 `.cmd` 包装；可执行文件路径中不支持的 shell 元字符会明确拒绝，cwd 不经 shell 拼接。
- 单进程查询超时 20 秒、快照流程 60 秒，最多一次瞬态重试；超时后关闭并确认进程退出。
  stdout/stderr 和规范化快照各最多 1 MiB，正式任务最多 100 项。超限或协议不支持是不可核对，不是零剩余。
- 绑定、prepare 前、execute 后、恢复时取只读快照；写调用/收口前检查文件依据是否变化。
  相同边界合并并仅复用仍有效的快照，无计时器扫描或流式轮询。不是文件锁，无法排除外部并发修改。

1.13.1 的 CLI `tasks.id` 是位置序号。本适配器逐项核对 `contextFiles.tasks` 中的真实 checkbox，
提取显式编号（例如 `1.1`），记录实际路径和行号；忽略围栏内的示例任务。支持逐项 sourcePath/line
的协议也要核对真实文件。无稳定编号、重复编号、多文件歧义和清单不一致均明确失败。
勾选、空白、任务位置变化更新状态，不创造新范围或新进展；描述、验收依据、增删和重编号变化显示范围差异。

手动改绑或解除绑定仍须记录旧范围处置，历史和未解决问题保留在来源详情。
查询失败保留旧快照并标不可核对，CLI `blocked` 单独显示工作流阻塞；二者都不能用于自动写入或成功收口。
适配器绝不自行勾选 tasks.md；apply 模型按真实结果更新。完整原文和验证问题按需读取，主面板/流程
显示 change、原任务勾选、剩余自动项、人工未验收数及当前 apply/verify/修复阶段。

## 操作回执与启动响应

工作台写操作立即显示“正在提交”，然后显示已接收、已完成、失败或结果待确认。Run 的“已接收”不是
任务完成，后续会显示正在准备工作区快照及实际调用阶段；Auto 明确显示已开/关。草稿只有成功才清空。
相同在途点击去重，12 秒包含连接等待；结果未知最多自动只读核对一次，也可手动核对，不重放写请求。
来源歧义或真正阻塞会明确指出条件；不能用换节点、重装或提高权限来掩盖失败。

启动 Git/目录快照由有明确拥有权的后台 helper 执行，阶段写盘进入异步有序队列；普通保存、控制权转交
和协议修复共用队列，避免晚到旧写覆盖新提交。其他 Session 心跳/查询不等待当前快照。
取消先等待实际退出，清理未知仍保护原 Session；进程退出未确认时不启动模型或另一份快照。
紧凑推送不先完整拷贝历史原文和来源快照，再把它们扔掉。读来源文件/哈希同样移出共享事件循环。
详情按修订读取，不新增后台轮询；通用 LOOP 的独立台账/隔离协议与原生权限约束继续保留。

## 自动 LOOP 执行环境

**Skill 已安装不等于 CLI 可用，人工成功也不等于自动路径可用。** Skill 提供工作流说明；
CLI 还需要能被当前 Backend 解析、访问并在实际原生策略内启动。
自动规划/只读步骤的 `read-only` 与写步骤/分析的 `workspace-write` 分开核对；
人工模式的权限可能不同。旧 Layer-2 沙箱开关或“跳过确认”不能改变这项区别。

“运行诊断”按需显示已知阻塞、覆盖和解除条件；Backend、角色、访问策略、传输/CLI 版本放在
“技术证据”，历史检查在轮次详情中按需读取。无阻塞时主工作区不常驻警告卡。覆盖级别不是成功等级：

| 证据 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 仅宿主发现 | 当前 Backend 环境能定位候选入口 | 受限策略能访问或执行它 |
| 原生策略内检查（部分覆盖） | 固定检查命令在所示策略下通过 | 所有模型工具/helper 路径均正常 |
| 实际工具事件 | 该次原生工具成功或发生可识别故障 | 其他命令可用、任务已验收或已知故障已恢复 |

空闲、自动控制态下的操作：

1. “选择额外工作流…”只读取当前证据和有效声明。
2. 需要 OpenSpec 工作流时，显式选择已安装且已绑定的有效工作流，再“确认依赖选择”。
   这不会绑定 change、执行工作流或继承历史授权。通用 LOOP 不必选择，绑定 Skill 本身不强制探测 CLI。
   已绑定 OpenSpec change 时显示“来自任务来源”；没有额外选择不代表缺依赖。相同依赖的正式来源、
   显式声明核验和实际调用观察分别显示；声明待核对/失效不会被有效来源掩盖。清空可选选择不解除来源依赖或历史故障。
3. 用户处理入口、访问或 runner 问题后，点击“重新检查环境”。检查不打开 Auto、不发任务模型请求，
   也不解除用户暂停。运行、检查、人工接管或只读总览期间不能发起该操作。
4. 再通过原有运行/恢复入口显式继续。系统仍核对旧调用退出、同故障路径证据、控制权、
   来源、授权和预算；终结的暂停记录从新 prepare 复核，真实断点保留已核实完成的步骤。

明确环境故障会停止受影响调度，不进入“规划重试→降级执行→新一轮再失败”的回路。
共享 runner 故障阻塞其相关调用；只有可靠映射为独立的工作才可按原有授权继续。
`callResult=normal` 与 `taskResult=blocked` 可以同时成立：模型正常返回不是任务完成。
检查等待不新增 Backend 失败，真实调用错误也不会被后续复查抹掉或重复计数。
命令未解析不等于整台机器未安装；原生 helper 初始化失败不能被归咎于 OpenSpec 缺失。

原生确定性检查当前只验证了 Windows `codex-cli 0.154.0` 的 executor-local app-server。
入口按项目 `node_modules/.bin`、实际 Backend PATH 的顺序发现，再在原策略中检查；
拒绝后不换通道、不借宿主代执行、不安装 CLI，也不修改全局 PATH/ACL 或放宽权限。
独立检查不创建 thread/turn；实际调用的检查串行放在原连接的 turn/start 前。
仅运行固定启动/解析/访问和版本查询，不运行 OpenSpec status/apply 等工作流动作。
无法确认的版本、有效配置、SSH/legacy/API 等路径显示“不支持或覆盖不足”：无已知故障时
保留原受限路径及真实事件观察，但不得用不支持或弱覆盖清除已有阻塞。

单命令上限 10 秒、检查流程 30 秒，收尾宽限单独有界。Windows 原生默认每流捕获 1 MiB；
AWU 仅接受每流严格小于 32 KiB 的完整结果，解码前限制协议帧，规范化检查记录最多 16 KiB。
小帧限制仅用于固定预检请求；同一连接的正式 thread/turn 响应与事件保留正常 128 MiB 上限。
每记录保留最多 16 条检查，依赖/阻塞有界；超限标为不完整。Windows 此版本不支持
command/exec/terminate：停止后续检查、有界等待原生终态，并用本次拥有的进程/Job 句柄收尾。
未确认退出时保持活动锁，不能启动新写调用。仍持有句柄时首次复查可只尝试收尾，
不会清除环境阻塞；确认退出后再显式复查。重启本身不是旧调用已退出的证明。
已确认入口不存在、启动权限拒绝或资源忙且未创建进程时，不登记虚假活动锁；
取消或未知启动结果不能仅凭进程对象为空就认定已退出。
只对确认尚未创建进程的瞬态资源忙重试一次；拒绝、helper 失败、参数不支持或请求已开始均不自动重试。

相同身份/轮次/角色的在途检查合并，成功结果最多复用 60 秒；新轮、显式恢复、故障和相关配置
变化使缓存失效。页面打开、流式更新和重复推送不触发检查或轮询。过期的 Session/节点/修订响应
不能覆盖当前环境。记录只保存白名单摘要，不保存完整 PATH/env、原始异常、凭据或额外历史正文。
成功、错误、超时、取消和最终收尾通知使用同一新鲜度校验；旧结果只更新原记录历史，
停止旧检查流程。历史收尾修订可刷新详情，但不改变当前环境；真实未确认退出的活动锁仍保留。

原生隔离夹具已验证正向启动、空格/Unicode 合成入口、独占句柄拒绝后同策略恢复及超时/取消收尾；
本地假 provider 也驱动了真实 runner 的正向工具路径，付费模型请求为零。
**真实 ACL 拒绝与原故障 helper 路径等价性仍未验证**，不能用这些通过项宣称真实会话已修复。
完整命令、覆盖矩阵和上线边界见
[`fix-loop-execution-environment` 实施记录](../openspec/changes/archive/2026-10-07-fix-loop-execution-environment/implementation-status.md)。

## 子里程碑与正式分母

prepare 可登记可独立验收的子条件，关联稳定父任务和原条件原文；执行前冻结，评审核对映射及证据。
每个父任务最多 20 个、范围内累计最多 200 个子项。漏报旧子项不会抹掉已登记条件；超限明确不完整。
规划重试耗尽后的只读诊断也继承历史范围，包括已登记但尚无有效评审的子项；遗漏不能绕过验收。
范围登记与成果基线分别继承：无效整体报告不提供已验证状态或证据，也不消耗后续有效推进的信用。
登记已经存在的成果只建立基线；执行后新发现的子项保留为待核对基线候选，不算本轮新增。

正式任务仍可为 **2/25**，同时显示“外壳子项已实现待验/已验证”。首次有证据的实现或验证推进
可重置无进展计数，但子项不进入 25 的分母、不自动勾选父任务，也不替代父任务的集成验收。
相同父任务/原验收条件按高水位去重，换名、重复测试、重复证据和恢复旧高水位不重复计信用。
只有经过映射核对的交付条件计入，不按文件、命令、提交或字数计量；自然语言等价仍依赖评审判断。

证据记录工作区相对路径、内容 SHA256、实际验证命令/结果和环境指纹。这里只读核对身份，
不会运行证据里写的命令，不访问工作区外用户目录。相关文件变化、缺失或环境变化会使对应子项待复验；
无关文件或 Git HEAD 变化不会要求全量重验。历史高水位保留，不能覆盖当前回归或支持错误收口。
这些仍是有边界的评审观察，不是内容正确性的机器证明。

## 新协议兼容与回退

### 人工接管与交还的状态核对

人工接管只在 LOOP 空闲、既有断点门槛满足且旧调用/环境检查已退出后开放；
loopout 可开启新人工轮。按钮旁直接显示不可用原因，人工回答或待发任务阻塞交还时，
菜单提供“返回聊天”或“查看队列”，导航不会停止回答、发送或清空任务。

确认后的会话状态条立即显示申请中，随后显示执行端的快照、记录整理与提交阶段。
关闭菜单、切换工作台详情不会丢失反馈。5 秒慢提示只是耗时说明，不是超时失败或成功证明。
接管会关闭 Auto；**交还仅返回 LOOP，不自动运行**。继续执行与开启 Auto 都是独立操作。

请求等待上限为 12 秒（包含连接等待）；超时或断线显示“结果待确认”，仅查询原请求，
不自动重新转交。进入会话、重连、返回 Tab 和手动检查触发合并读取，无常驻轮询。
如果已切换但聊天/LOOP 面板加载失败，请使用“重试加载”，不会新建或再次封存人工轮。

不能解除新请求的等待状态，检查点告警与阶段耗时也不沿用上一笔操作。

执行端按会话预留转交，快照由拥有明确进程树的 helper 运行，落盘使用异步有序队列。
Git 保持临时索引/不改 HEAD 的策略；非 Git 接管保留原目录备份 fallback。

控制权、人工记录、轮次与回执以 LOOP stage 文件为权威，列表元数据可在状态核对时修复。

写锁排序，冻结内存副本后在内存锁外原子落盘，慢磁盘不阻塞转交镜像或轻量索引读取。
